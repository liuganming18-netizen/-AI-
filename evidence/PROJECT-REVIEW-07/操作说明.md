## 二、启动 / 停止 / 重启

```bash
# 只启接口和 worker（不开放自动交易）
sh 框架/backend/start.sh

# 连模拟盘运行时一起启（日常就用这条）
sh 框架/backend/start.sh start --enable-paper --arm 3a --symbol all

# 受控重启（采集器不动）
sh 框架/backend/start.sh restart --enable-paper --arm 3a --symbol all

# 安全停止（只停本实例管理的进程）
sh 框架/backend/start.sh stop
```

或者直接用服务管理器（`start.sh` 只是它的薄壳）：

```bash
/Users/boos/.workbuddy-ai/binaries/python/envs/default/bin/python \
  框架/backend/service_manager.py restart --enable-paper --arm 3a --symbol all
```

**参数含义**

| 参数 | 作用 | 什么时候改 |
|---|---|---|
| `--arm 3a` | 用哪本账本（`paper_3a.sqlite3`） | 不要随便改，改了就换账本 |
| `--symbol all` | 全池 526 标的 | 调试单个币时才传具体名字 |
| `--enable-paper` | 开启模拟盘运行时 | 不加就只起接口，不产生信号 |
| `--stop-collector` | **显式**停采集器 | 一般不加；加了要自己记得再启 |
| `--json` | 状态输出为 JSON | 给脚本用 |

**恢复方式**：服务管理器对运行时有三层探测（PID 文件 → `paper_runtime_3a_status.json` → `.lock`），任一能证明存活就不重启。所以「重启没生效」通常是**它认为还活着**——这时先 `status` 看 matched，再决定要不要手工停。

## 四、查「为什么没有信号」——按漏斗逐层读，不要猜

### 4.1 先看标的状态分布

`state_counter` 的四个状态加起来必须等于 526：

| 状态 | 含义 | 实测 |
|---|---|---:|
| `IDLE` | 空转，没在跑事件链 | 167 |
| `BOX` | 正在等 4h 箱体形成 | 320 |
| `SWEEP` | 已扫低，等回踩 | 5 |
| `RETEST` | 已回踩，等突破 | 34 |

**IDLE 167 个为什么空转？** 看 `idle_breakdown`：

```bash
curl --noproxy '*' -s http://127.0.0.1:8787/api/v1/paper/status \
 | /Users/boos/.workbuddy-ai/binaries/python/envs/default/bin/python -c \
 "import json,sys;print(json.dumps(json.load(sys.stdin)['data']['item']['signal_engine']['idle_breakdown'],ensure_ascii=False)[:800])"
```

实测：`IDLE_COOLING 140`（刚结束事件，24 小时冷却中）+ `IDLE_WAIT_BOX 27`（还没走出箱体）= 167。
`sample` 里逐个币给了 `remaining_hours`（如 `0GUSDT` 还剩 9.0 小时）——**这是可解释的等待，不是故障**。

### 4.2 再看漏斗卡在哪一层

`funnel` 是一条链，逐层递减是正常的：

```
BOX 4262  →  SWEEP 1085  →  RETEST 649  →  CANDIDATE 18
```

- 卡在 `BOX`：箱体没形成，正常等待。
- 卡在 `SWEEP`：扫低后没回踩（`MISSED_WITHOUT_RETEST`）。
- 卡在 `RETEST`：回踩后没突破。当前 34 个 RETEST 距突破线**中位 16.2%**（6.9%~33.0%）——差得远，不是快突破了。
- 出现 `VOLUME_REJECTED` / `OI_UNAVAILABLE` / `OI_REJECTED`：被成交量或持仓量条件拦下，字段里直接写了原因。

**`since_start` 全是 0 是什么意思？** 表示「本次进程启动以来没走出新事件」。这不是没数据——`history` 有 4,262 个箱体、18 个候选，说明引擎在算。差别在：`history` 是 bootstrap 补算的历史（18 个候选按规则**不入账**，字段 `history_candidates_discarded=18`），`since_start` 只算启动后的新增。

### 4.3 三种「假故障」先排除

| 现象 | 先查这个 | 怎么判断 |
|---|---|---|
| 全池 0 候选 | `atr_caliber.n_warmed` 是否 = 526 | 实测 525/526，1 个标的因数据不足未预热 |
| 有候选没下单 | `new_entry_gate.allow_new_entries` | 实测 `true`、`reason=user_ui_resumed` ⇒ **闸门是开的，不是被拦** |
| 闸门开着仍 0 单 | `orders_routed_total` | 实测 0 ⇒ 没有候选进来，不是下单环节丢了 |
| 某几个币永远不动 | `data_quality.blocked` | 实测 `blocked_n=6`，如 `1000000BOBUSDT` 连续 476 根「零成交且四价相同」的交易所占位行 ⇒ **禁止决策** |

### 4.4 一条命令拿到全部原因

```bash
curl --noproxy '*' -s http://127.0.0.1:8787/api/v1/paper/status \
 | /Users/boos/.workbuddy-ai/binaries/python/envs/default/bin/python -c \
 "import json,sys;d=json.load(sys.stdin)['data']['item'];se=d['signal_engine'];\
print('状态',se['state_counter']);print('空转原因',se['idle_breakdown']['counts']);\
print('漏斗历史',se['funnel']['history']);print('漏斗本次',se['funnel']['since_start']);\

print('水位对齐',se['watermark_check']['aligned_1h'],se['watermark_check']['lag_1h_bars'])"
```

## 六、五个最常见的误判（都踩过）

| 误判 | 真相 |
|---|---|
| 「状态文件 cycle 42 没动，进程死了」 | 那是固定桩。真值看 `paper_runtime_3a_status.json` |
| 「`/api/health` 返回 200，系统就绪」 | 200 只证明进程在监听，不证明信号引擎在推进、不证明账本能记账 |
| 「接口返回 200，这组回测就能看」 | 44 个抽样里 10 个返回 200 但 K 线 0 根 |
| 「采集器 PID 没变，说明重启没成功」 | 采集器按防误停策略不随重启，PID 不变是**正确**的 |
| 「`paper_order.order_id` 是交易所订单号」 | 不是。是本机自增键，交易所侧查不到（7 个 token 后端 0 命中） |

## 八、出问题时的最短排查顺序

1. **接口不通** → `sh 框架/backend/start.sh status` → 看哪一行 `matched=false` → `restart`。
2. **接口通但前端白屏** → 确认访问的是 **3000** 不是 3100；再看 `curl --noproxy '*' -s -o /dev/null -w "%{http_code}" http://127.0.0.1:3000/`。
3. **引擎在跑但状态不更新** → 查 `watermark_check.aligned_1h` 与 `lag_1h_bars`（实测 `true` / `0`）。滞后就是采集断了。
4. **有候选不下单** → 查 `new_entry_gate`，再看 `orders_routed_total` 是否随候选增长。
5. **回测打不开** → 先分清 400（数组格式，D-04）/ 404（缺文件）/ 200 空图（D-09）。
6. **数据看起来不对** → 先看 `data_quality.blocked_n`，有标的被「零成交占位行」禁止决策时，那个币的所有指标都不可信。
