# 四项重点验收表（PROJECT-REVIEW-07）

判定只有三态：**通过 / 不通过 / 未验证**。未验证不计入通过。
「通过」指：有**实际运行观察或可复现实验**支撑，且判据自带「确实比到了东西」的自证（`n>0 且 0 未比到 且 0 不符`）。

## 表一：4h 跟踪止损是否使用「入场前价格」

| 项 | 内容 |
|---|---|
| **检查对象** | `策略/WyckoffMaster/event_trend_v0_1/engine_adapter.py::build_exit_channel_15m`（FT-LOW4H 分支）→ `trading_core/engine.py` 相位 A → `ExecutionPolicy.trail_level` |
| **判据（机械可复算）** | 一笔成交的 `entry_ts`；入场后第一根已收盘 4h 的收盘时刻 `f4 = floor(entry_ts/4h)*4h + 4h − 1ms`；取该笔 `stop_trace` 中第一条 `reason=trail` 的时刻 `ft`。`ft ≥ f4` ⇒ 合规；`ft < f4` ⇒ 用了入场前价格 |
| **实际运行观察** | 扫描 3,989 个 run 的 `trades.jsonl`，共 **37,404 笔**成交：32,323 笔无 `stop_trace`（freqtrade 链，不写轨迹）、5,021 笔从未上移、**60 笔有跟踪上移**。其中可判定的 **60/60 全部 `ft ≥ f4`**（合规）。按批次分：`回测日志/event_trend_v0_1/runs` 57 笔、其余 3 笔 |
| **静态代码** | 守卫条件 `if s < int(t4[k])`（只有「4h 收盘严格晚于该候选 earliest」才给通道值），注释写明「杜绝借用入场前历史 bar」 |
| **隔离验证（合成用例）** | 同一标的有两个候选（05:00 与 09:00 入场）：<br>· 只放 09:00 候选 ⇒ 09:15/09:30 通道 = `None`（正确）<br>· 同时放两个候选 ⇒ 09:15/09:30 通道 = **104.5**（= 08:00 收盘那根 4h 的 low 110 × 0.95）<br>而 09:00 才入场 ⇒ **该线来自入场前已收盘的 4h bar**，且 104.5 > 初始止损 95，相位 A 会立刻把止损抬到入场价之上 |
| **根因** | 守卫用的是「该标的全候选 `execution_earliest_ms` 集合」（`starts`），不是「当前持仓自己的 `entry_ts`」。同币第 2 笔及以后会借用第 1 笔的起点通过闸门 |
| **暴露面** | 1,663 组有成交的官方 run 中，**859 组存在同币 ≥2 笔**；第 2 笔及以后共 **3,346 笔**，其中带跟踪上移 **8 笔**（这 8 笔是唯一可能踩中的样本，实测均未踩中） |
| **结论** | **未验证 → 归入「实现有漏洞但生产未发生」**。<br>「生产是否已发生」= **不通过不了（0 例）**；「实现是否严格」= **不通过**（合成用例可复现） |
| **证据** | `out/07_4h止损入场前价格复核.json`、`out/08_同币多笔暴露面.json`、`07_4h止损入场前价格复核.py`、`engine_adapter.py:146-168` |

## 表二：跳空成交价格是否符合既定规则

| 项 | 内容 |
|---|---|
| **既定规则原文** | 冻结规则 §5：「stop bar 开盘已经低于止损，按**开盘再加不利滑点**；否则 low 触及止损，按止损再加不利滑点」；§4 入场「下一根严格更晚开始的 15m bar 开盘市价买入」 |
| **检查对象** | `trading_core/policy.py::decide_gap_exit`（`target_px = bar_open`）→ `fill.py::quote_exit`（`raw × (1−slip)` 后按 tick 向下取整） |
| **静态代码** | 跳空判定只用 `open`，不用 `low/high`；平仓价 = `target_px × (1 − slippage)` → `ROUND_FLOOR` 到 tick。**方向与顺序均符合规则** |
| **实际运行观察（模拟盘）** | `paper_3a` 共 6 笔成交，逐笔复算：<br>· 开仓 1：raw 81992.1 → 82033.1 = `81992.1×1.0005` 向上取整到 0.1 ✔<br>· 平仓 1：raw 81929.0 → **81888.0355** = `81929×0.9995`（**未取整**，按 tick 0.1 应为 81888.0）✘<br>· 平仓 2/3：同模式，均保留 4 位小数 ✘ |
| **实际运行观察（回测）** | 官方通道 5,009 笔成交中，退出原因分布：`stop_loss` 3,292、`trailing_stop_loss` 962、`max_holding_expired` 318、`intrabar_stop` 233、`force_close_eod` 133、`timeout_240h` 71。**没有一笔 `gap_open_stop`** ⇒ 回测侧**没有跳空样本**可验 |
| **口径一致性** | 回测 `slippage_bps = 3.0`；模拟盘 `slippage_each_side = 0.0005`（**5 bps**）；`SYSTEM-CONTRACT-01` 契约样张也写 0.0005。**回测与模拟盘滑点不同源** |
| **结论** | 「实现是否符合规则」= **通过**（代码路径与规则文字一致，合成/单笔复算一致）<br>「是否有真实跳空样本可验」= **未验证**（0 笔）<br>「两端口径是否一致」= **不通过**（3 bps vs 5 bps）<br>「历史平仓价是否按 tick 取整」= **不通过**（3/3 笔未取整） |
| **证据** | `paper_3a.sqlite3` 的 `paper_fill` 全 6 行、`fill.py:272-292`、`policy.py::decide_gap_exit`、`out/09_回测规则身份分布.json`（slippage 字段） |

## 表三：图表请求周期 vs 实际返回周期

| 项 | 内容 |
|---|---|
| **检查对象** | ① `/api/v1/markets/{ex}/{sym}/candles?timeframe=`（`adapter.py::v1_candles`）<br>② `/api/v1/backtests/{id}/chart`（`backtest_api.py::get_chart`）<br>③ 前端 `adapters.ts::adaptCandles` + `useMarketData.ts::ensureDetail` |
| **判据** | 用相邻 `open_time` 的**中位间隔**反推实际周期，与请求周期比对；`env.timeframe` 必须等于请求 tf；图表 `display_timeframe` 必须等于该 run 的执行周期 |
| **实际运行观察 ①** | binance BTCUSDT 8 个周期 **8/8 一致**（5m=300s、15m=900s、30m=1800s、1h=3600s、4h=14400s、8h=28800s、12h=43200s、1d=86400s），每周期 80 根。okx BTC-USDT-SWAP 全部 `out_of_scope`（不在补充集合，返回空且带原因）——这是**正确行为** |
| **实际运行观察 ②** | 组合 run `run_FT_LOW4H_DYN01_…_Vs08_Z02`（真实执行 15m）：<br>· 无参数 ⇒ K 线来自 **AVAXUSDT/1h**、`display_timeframe=1h`<br>· `?symbol=BTCUSDT` ⇒ BTCUSDT/**1h**<br>· `?timeframe=15m` ⇒ 108,193 根 15m ✔<br>而响应里 `exec_timeframe` 仍写 `15m`、`display_timeframe` 写 `1h` ⇒ **同一条响应里两个周期字段互相矛盾** |
| **实际运行观察 ③** | 前端 `adaptCandles(env, tf)` 用**请求的 tf** 去标注每根 K 线（`formatCandleTime(b.open_time, tf)`），**从不校验 `env.timeframe`**。后端一旦回退或改写周期，前端会静默按请求周期贴标签 |
| **结论** | 「单标的、8 个周期、币安」= **通过**（8/8）<br>「组合 run 的默认展示周期」= **不通过**（显示 1h，执行 15m）<br>「前端是否校验响应周期」= **不通过**（无断言） |
| **证据** | `out/02_图表周期一致性.json`、`out/04_回测重开实测.json`、`adapters.ts::adaptCandles`、`useMarketData.ts:446-458`、`backtest_api.py:1676-1679` |
