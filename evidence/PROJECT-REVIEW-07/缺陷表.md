## 二、逐条详表

### D-01｜冻结规则与实际运行规则分叉（P0）

**事实（三处，逐项对照）**

| 项 | 冻结规则文件（SHA `1f1167de…9a8ab`） | 实际运行的 `FT-LOW4H` | 差在哪 |
|---|---|---|---|
| 跟踪止损何时启用 | 首次 4h 收盘浮盈 **+2R** 才启用 | **入场即启用**（`trailing_trigger_r=0.0`） | 早启用＝更早被扫 |
| 跟踪线取几根 4h | 最近 **10 根**最低价 | 最近 **1 根**最低价 | 线更贴价格 |
| 最长持仓 | **10 个自然日**到期退出 | `max_holding_days=None`（不执行） | 一套有到期一套没有 |
| 初始止损 | `P0 = Lr − 0.1A`（结构位） | **实际成交价 × 0.95** | 完全不同的锚 |

**为什么是 P0**：`config.py` 文件头写着「严格对应冻结规则 md，SHA `1f1167de…`」，但 `make_ft_low4h_config()` 用 6 个覆盖项把规则换成了另一套，**md 没跟着更新，也没有第二份 FT-LOW4H 冻结规则文件**。任何人拿这份 md 核对当前模拟盘，都会得出「实现不符合规范」——而真相是**规范过期了**。

**叠加证据**：`out/09_回测规则身份分布.json` 显示官方通道 2,284 组里，**1,197 组跑的是旧规则（2R/10根/10天）**，只有 **22 组**是 FT-LOW4H。旧规则回测里出现过 318 笔 `max_holding_expired`（10 天强平）与 71 笔 `timeout_240h`——这些成交记录本身就是「持仓 10 天已取消」这句话的反证。

**影响**：所有「策略有效／收益多少」的历史结论，都建立在**另一套规则**上。不能用它们给当前模拟盘背书。

**最小下一步**：二选一，不要同时做——
① 写一份 `FT-LOW4H` 冻结规则文件（把上面四项写成正式规范，SHA 登记），旧 md 标 `superseded`；
② 或宣布「冻结 md 就是唯一规范」，把 `make_ft_low4h_config()` 的 6 个覆盖项改回 md（这会改变交易经济规则，须走裁决）。

### D-02｜回测与模拟盘的资金/仓位口径来自两个不同文件（P0）

**事实（逐项对照，两侧都可当场复算）**

| 参数 | 回测链（`make_ft_low4h_config()`，`backtest_runner.py:790-797`） | 模拟盘链（生效视图 → `paper_engine.py`） | 差 |
|---|---|---|---|
| 初始本金 | **2,000** USDT | **5,000** USDT | 2.5 倍 |
| 单笔风险 | 0.5% | 0.5% | 一致 |
| 最大同时持仓 | **3** | **10**（`paper_engine.py:529`） | 3.3 倍 |
| 单名名义上限 | **30%** 权益 | **10%** 权益（`:534`） | 3 倍 |
| 总名义上限 | **90%** | **80%** | — |
| 入场参与率上限 | **0.1%**（`0.001`） | **1%**（`0.01`，`:1040`） | **10 倍** |
| 组合初始止损风险 | 1.5% | 5% | 3.3 倍 |
| 滑点 | 3 bps | **5 bps** | — |
| 手续费 | 5 bps | 5 bps | 一致 |

**为什么会这样**：回测只在 `backtest_runner.py:790-797` 覆盖了 6 项（本金/止损/跟踪/风险/费率/滑点/参与率），**仓位数与名义上限没被覆盖，固定取代码默认 3/1.5%/30%/90%**；模拟盘则整份读 `10_研究参数生效视图_v2_2_user5000_shared.json`（10 仓/5%/10%/80%/1%）。

**影响（最要紧的一条）**：参与率上限差 10 倍，直接决定「这一笔能不能成交」。**回测里被判「成交量不足、不下单」的候选，在模拟盘里会成交**。所以回测的成交率系统性低于模拟盘，回测收益不能线性外推，两者也不能放在同一张表里比。仓位数 3 vs 10 则决定「同时能开几笔」，直接影响回撤形状。

**证据强度声明**：本条是**静态代码 + 两份配置文件的逐项比对**（可当场复算），不是运行观测；但 `paper_engine.py:529/534/1040` 就是实际执行点，属「代码即行为」。

**最小下一步**：先定「谁是权威」。建议以冻结契约为权威，把 `backtest_runner.py` 里没被覆盖的 4 项（仓位数、组合风险、单名上限、总名义）也从契约读；改完跑 22 组 FT-LOW4H 对比成交笔数变化。**在定下来之前，不要把回测数字与模拟盘数字并列。**

### D-03｜4h 跟踪通道闸门按「全候选」判，不按「当前持仓」判（P0）

**事实**：`engine_adapter.py:146-168` 里，`starts` 是**该标的全部候选**的入场时刻集合，循环取「最后一个小于当前 4h 收盘的入场时刻」当作跟踪通道起点。

```python
starts = sorted({_normalize_to_ms(c.execution_earliest_ms) for c in candidates})
if rule == "FT-LOW4H":
    for j in range(n15):
        k = int(np.searchsorted(t4, t, side="left")) - 1
        start = None
        for s in starts:            # ← 遍历全部候选，不是当前持仓
            if s < int(t4[k]):
                start = s
```

**后果（合成用例已复现）**：同一标的两个候选（05:00 入场、09:00 入场）。09:00 那笔在 09:15 计算跟踪线时，闸门只要求「4h 收盘晚于 05:00」，于是**09:00 之前那根 4h 被算进去**。合成用例里该通道值 104.5，高于初始止损 95、也高于入场价 100 ⇒ 这笔会被**立刻打出**。

**实际暴露面**：`out/08_同币多笔暴露面.json` — 1,663 个有成交的官方 run 中，859 组同币多笔，第 2 笔及以后共 **3,346 笔**，其中带跟踪上移的 **8 笔**。

**实际是否发生**：`out/07_4h止损入场前价格复核.json` — 全目录 4,944 个文件、37,404 笔成交，有跟踪上移 **60 笔**，首条跟踪线全部晚于「入场后第一根已收盘 4h」⇒ **60/60 合规，疑似 0**。

> 结论必须这么写：**实现有漏洞、生产未发生**。不能因为「实际没发生」就降级，也不能因为「代码有洞」就说「已经在用错价格」。

**最小下一步**：把 `starts` 换成「当前持仓的入场时刻」单值；用 `08` 里那 8 笔做定向回归，确认跟踪线不变。

### D-04｜375 个回测的 `chart.json` 是数组格式，复盘接口 400（P0）

**事实**：`out/06_图表格式冲突.json` — 对象格式 1,399 个、**数组且非空 375 个**（打开即 400）、数组但空 2,215 个。`out/04_回测重开实测.json` 复现了堆栈：`backtest_api.py:1312` 写的是 `bars[0]["t"]`，数组元素是 `list` 不是 `dict` ⇒ `TypeError` ⇒ 接口回 400。

**根因（历史事故已记录）**：官方 `backtest_chart.py` 产出对象格式 `{t,o,h,l,c,v}`；7 个批量脚本各自复制过一份 chart 生成逻辑，产出数组格式 `[t,o,h,l,c,v]`。两套契约并存。

**影响**：这 375 组**打不开**，而其中可能有当时最好的一组。同时 `out/05_回测重开抽样.json` 显示还有 10/44 个 run 返回 200 但 K 线 0 根 ⇒ 「能打开」也不等于「有东西看」。

**最小下一步**：只在**读取侧**加兼容（`bars[0]` 是 list 就按位置取值），历史文件一个不动。改完用 `out/04` 里那个 run 复测到 200。

### D-06｜登记身份校验拿退役基线比当前视图，`identity_ok` 恒 false（P1）

**事实**（`out/01_API实时抓取.json` → `/api/v1/strategies/registered`）：

```
view_sha256          82dec362c182…   ← 当前生效视图（FT-LOW4H）
expected_view_sha256 6d18d222d199…   ← 代码里写死的旧 v2.2 基线
registered_sha256    null            ← 视图里没有 registered_configs 这个键
effective_sha256     4f53cda18c2b…   ← 这是 sha256("[]")，即「读到的生效配置是空集」
identity_ok          false
problems             生效视图 SHA 不一致 / registered hash 漂移 / 18 配置身份漂移
```

**复算**：`sha256("[]") = 4f53cda18c2baa0c0354bb5f9a3ecbe5ed12ab4d8e11ba873c2f11161202b945`，与 `effective_sha256` 完全一致 ⇒ **18 条预登记配置一条都没读到**。

**真相**：`wx_config.py:64-71` 的三个固定接受值属于**已退役的 F_WX 3a–3d（5000 共享模型）**；而当前生效视图文件里装的是 FT-LOW4H 的参数，也没有 `registered_configs` 键。拿旧基线比新内容，**三项必然全 false**。

**影响**：「运行放行 = 视图 `run_frozen` ∧ 身份一致 ∧ G01–G05 全 pass」——其中「身份一致」对当前策略**结构上永不成立**。目前是靠 `run_frozen=False` 挡住，所以不影响交易；但**这条放行条件等于空的**，且问题串会把人引向「有人改了参数」的错误方向。

**最小下一步**：二选一——① 为 FT-LOW4H 登记新基线；② 让该接口明确返回「该基线适用于已退役策略，对当前策略不适用」，而不是报 3 条「漂移」。

### D-07｜前端用请求周期给 K 线贴标签（P1）

**事实**：`UI界面/web/src/api/adapters.ts::adaptCandles` 把 `tf` 参数（**请求的**周期）写进每根 K 线的标注，从不检查响应里后端声明的实际周期。后端侧 `out/02_图表周期一致性.json` 实测 binance 8 个周期 **8/8 一致**（间隔与声明完全吻合），说明**数据本身是对的**，问题在展示层不做校验。

**叠加事实**：组合 run 的 `exec_timeframe` 被改写成 `1h`，而真实执行周期是 `15m`（`out/05_回测重开抽样.json`）。

**影响**：一旦后端回退到默认周期（或某条路径给错参数），界面会**毫无提示地**把 1h 数据标成 4h。看图的人不会知道。

**最小下一步**：`adaptCandles` 里比对后端返回的周期与请求的周期，不一致就在图上挂一条告警条。**不加兜底、不静默改写**。
