# SYSTEM-CLOSELOOP-05｜最小代码变更与根因说明

## 1. 任务背景与核心目标
本阶段任务直接承接并修复 Work 在 `SYSTEM-CLOSELOOP-AUDIT-04` 中发现的 9 项阻塞根因（R1 至 R9）。目标是让隔离实例在统一入口拉起后，**无需任何测试脚本逐次驱动或手工介入**，由真实常驻执行守护进程自动完成：
$$\text{可信信号} \longrightarrow \text{挂单登记} \longrightarrow \text{合法行情自动撮合成交} \longrightarrow \text{持仓止损自动单调上移} \longrightarrow \text{触价自动平仓退出} \longrightarrow \text{账本逐项闭合}$$

## 2. AUDIT-04 发现问题与代码根因分析

| 根因编号 | 审计发现（AUDIT-04 缺陷） | 代码根因剖析 | 修复策略与修改文件 |
| :--- | :--- | :--- | :--- |
| **R1** | 挂单未固化参数，缺失必需参数时静默落单并永久卡死 | `_register_pending` 未在挂单表落盘 `stoploss_s, trail_d, model_version, config_fingerprint`，且登记前未做必需参数有效性校验，导致缺失参数仍入库为 `pending`。 | 在 `paper_pending` 增加加性迁移字段；登记前执行强校验，若缺失必需止损参数直接显式拒绝，绝不生成死单。<br>涉及：`框架/backend/live_store.py`，`框架/backend/paper_engine.py`。 |
| **R2** | 持仓记录未固化策略与规则快照，重启或配置切换时易丢失规则 | `paper_position` 表原先缺少 `stoploss_s, trail_d, config_fingerprint` 字段，建仓时不固化配置快照。 | 在 `paper_position` 表实施加性迁移，在 `open_position` 中固化写入持仓快照字段，重启或外部改动不再影响原单规则。<br>涉及：`框架/backend/live_store.py`，`框架/backend/paper_engine.py`。 |
| **R3** | 跟踪止损计算缺失参数时默默兜底（退回3×ATR或硬编码5%） | `advance_position_trailing` 在持仓无参数时回退读取配置视图或全局硬编码默认值，缺少显式失败阻断。 | 实行「持仓固化 > 显式入参」，若两者皆缺失，严禁静默兜底，显式返回 `missing_parameter_trail_d` 并保持账本不变。<br>涉及：`框架/backend/paper_engine.py`。 |
| **R4** | HTTP 接口允许外部传入假 K 线或未入库篡改行情并以此推进止损 | HTTP 接口（`paper_advance_trailing_post`）直接接受调用方传入的任意 `candle` 字典并执行，绕过了行情库真实性校验。 | 在 `live_api.py` 增加可信行情溯源防御：外部传入的 K 线必须在服务端行情库（`MARKET_DB`）真实存在且关键数值一致，未入库或篡改 K 线直接 400 拦截。<br>涉及：`框架/backend/live_api.py`。 |
| **R5** | HTTP 接口允许外部调用方在请求体中覆盖已固化的 `trail_d` 参数 | 接口对请求体中的 `trail_d` 未与持仓固化参数或实验配置进行因果校验，导致调用方可通过请求体篡改持仓跟踪规则。 | 在 `live_api.py` 与 `paper_engine.py` 中增加防覆盖校验：外部传入值与持仓/配置不一致时显式返回 `external_param_override_rejected`（400）。<br>涉及：`框架/backend/live_api.py`，`框架/backend/paper_engine.py`。 |
| **R6** | K 线几何与未来数据因果防线存在漏判 | `validate_market_candle` 中当 `now_ms is None` 时未能强行锚定真实服务端挂钟，导致未来 K 线在特定路径下漏校验。 | `now_ms` 缺省强制使用 `L.now_ms()` 服务端挂钟，未闭合未来 K 线（`close_time > now_ms`）严格判定非法。<br>涉及：`框架/backend/paper_engine.py`。 |
| **R7** | 守护进程单实例锁目录未与账本同源隔离，存在多实例竞争 | `paper_loop.py` 硬编码锁文件目录于生产路径，导致测试实例与日常实例争用同一锁。 | 支持 `PAPER_LOCK_DIR` 环境变量，缺省自动使用 `PAPER_LEDGER_DIR.parent / locks`，实现隔离实例零配置同源锁隔离。<br>涉及：`框架/backend/paper_loop.py`。 |
| **R8** | 守护进程状态仅存在于内存，API 无法跨进程获知守护真实状态与 PID | `_STATUS` 仅为模块内内存字典，`adapter` 进程与守护子进程位于不同进程空间，API 返回的均为未运行默认值。 | 在 `paper_loop.py` 增加磁盘状态落盘 `paper_daemon_{arm}_status.json`，API 跨进程读取并结合 `os.kill(pid, 0)` 探测真实存活。<br>涉及：`框架/backend/paper_loop.py`。 |
| **R9** | 轨迹查询接口在持仓不存在时返回伪造空列表，前端无法区分 404 | `get_stop_history` 未区分持仓是否存在，统一返回空列表，前端将 404 误显为「暂无上移」。 | `get_stop_history` 增加持仓存在性复核，不存在时返回 `exists=False`，API 响应标准 HTTP 404 Not Found。<br>涉及：`框架/backend/paper_engine.py`，`框架/backend/live_api.py`。 |

## 3. 最小代码变更清单（文件与修改行）

| 文件路径 | 修改性质 | 核心修改内容说明 |
| :--- | :--- | :--- |
| `框架/backend/live_store.py` | 增强 / 迁移 | 1. 扩充 `PAPER_COLUMNS`，支持 `paper_pending` 新增 `stoploss_s, trail_d, model_version, config_fingerprint`；<br>2. 补充 `paper_position` 的 `stoploss_s, trail_d, config_fingerprint` 加性迁移列；<br>3. `market_conn` 兼容可变入参容错。 |
| `框架/backend/paper_engine.py` | 增强 / 约束 | 1. `_register_pending`：挂单入库前强校验必需止损参数，并落盘 `s, d, model_version, config_fingerprint`；<br>2. `advance_pending`：推进时提取持久化快照透传给 `open_position`；<br>3. `open_position`：持仓落地时持久化 `stoploss_s, trail_d, config_fingerprint`；<br>4. `advance_position_trailing`：优先使用持仓持久化参数，参数缺失显式报错，拦截外部参数覆盖；<br>5. `validate_market_candle`：时钟缺省强制锚定挂钟，拒绝未收盘未来数据；<br>6. `get_stop_history`：持仓不存在返回 `exists=False`。 |
| `框架/backend/live_api.py` | 防线收口 | 1. `paper_advance_trailing_post`：增加外部假 K 线服务端行情库溯源拦截（400）；<br>2. 增加外部参数覆盖拦截（400）；<br>3. 持仓不存在返回标准 404；<br>4. 守护状态接口跨进程读取磁盘真实状态文件。 |
| `框架/backend/paper_loop.py` | 架构隔离 | 1. `get_lock_dir()`：支持 `PAPER_LOCK_DIR` 隔离锁路径；<br>2. 守护生命周期与轮询指标持久化落盘至 JSON；<br>3. `get_daemon_status()`：跨进程读取并执行 `os.kill(pid, 0)` 探活；<br>4. 轮询主循环加入关键事件实时无缓冲日志输出。 |
| `框架/backend/workers/paper_execution_worker.py` | 常驻守护入口 | 保持作为常驻进程的标准独立执行入口，支持 `--arm`, `--interval`。 |
