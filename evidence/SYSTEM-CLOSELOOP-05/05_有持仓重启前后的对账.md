# SYSTEM-CLOSELOOP-05｜有持仓重启前后的对账

## 1. 对账目标与核验边界
在交易系统实际运行中，进程重启、热更新或异常恢复绝不能导致以下破坏性故障：
1. **持仓状态丢失或改变**：`open` 状态被意外置空或误置为 `closed`；
2. **止损价漂移或规则遗失**：生效止损价发生变动，或丢失固化的跟踪比例 $d$ 退回旧规则；
3. **重复执行或重复成交**：重启后扫描挂单或持仓造成二次记账、重复生成成交记录（Fill）或重复记录止损上移轨迹（Stop History）；
4. **单实例锁争用**：旧进程释放不彻底导致新进程无法获取锁启动。

## 4. 重启后在途自动平仓闭环核对
在重启后，新拉起的守护进程继续自动轮询：
1. 数据库中插入触价 15m bar（价格跌穿止损）；
2. 新守护进程在下一轮推进中即时检测到跌穿条件；
3. 自动生成退出订单与平仓成交，将持仓正常标记为 `closed`，退出原因明确为 `trailing_stop_loss`；
4. 退出成交（Fill）强关联退出订单（Order），平仓手续费与实际盈亏按公式结算；
5. **账本闭合残差核验**：
   $$\text{Residual} = \text{Cash}_{\text{actual}} - \left(5000.0 + (P_{\text{exit}} - P_{\text{entry}}) \times \text{Qty} - \text{Fee}_{\text{entry}} - \text{Fee}_{\text{exit}}\right) = \mathbf{0.0}$$
   两组测试残差绝对值为 0.0，证明重启未破坏后续状态机的完整闭合。
