## 0. 先说三句话

1. **上一单把它们标成「接触历史不清楚」，这一单查清了：它们确实进过研究，但是以"计算输入"的方式进去的。**
   没有任何一条区间里跑出过候选或成交，也没有任何一条被某个运行窗口逐根处理过；但每一条的末段 4 小时 K 线，都被后面某次研究回测当成预热读进去，参与了 ATR 计算。
2. **ATR 不是无关紧要的中间量。** 它决定箱体宽度过滤（2~8 倍 ATR）、扫低深度（0.5A）、回踩区间（0.5A）、突破缓冲（0.1A）、初始止损（L−0.1A）。区间的波动率进了 ATR，就等于进了后续窗口的判定门槛。
3. **这个结论是按"该币自己的运行"查的，不是按"同一段行情别的币研究过"推的。** 每条都有该币自己的运行目录或运行记录作证。

## 3. 关键发现：ATR 预热把区间数据带进了研究

### 3.1 机制

`策略/WyckoffMaster/event_trend_v0_1/runner.py`：

- 第 215~230 行：把该币**全部年份**的 4h parquet 拼起来，先算一遍全历史 ATR(14)；
- 第 297~300 行：`warmup_start_idx = max(0, idx_start_4h - 220)` —— 从窗口起点往前回取 **220 根 4h**（≈36.7 天）；
- 于是窗口开头的 ATR，是由窗口之前这 220 根算出来的；这 220 根正好落在这些区间的末段。

### 3.2 实证（不看价格，只用运行自报的根数）

以 2026-09-01 起的窗口为例：窗口 47 天，4h 应有约 281 根，运行自报 **500 根**，多出 **219 根 ≈ 220 根预热**。

- 48 条区间找到了对应的运行目录，`多出根数` 全部落在 190~240 之间（见 `out/05_预热加载实证.csv`）；
- 1 条（ZEREBROUSDT）的后续窗口来自全扫描，不落运行目录、没有根数自报，只能给代码级证据（同一加载函数）；
- 同时核对了 1h：自报根数与窗口内应有根数一致 ⇒ **只有 4h 借了预热，1h/15m 没有**。

### 3.3 影响有多深

| 指标 | 数值 |
|---|---|
| 伸入天数 | 32 ~ 36.7 天（中位 36.7 天，即整段预热） |
| 占该区间比例 | 15% ~ 100%（中位 56%） |
| 受影响后续窗口 | 每币 1~2 个 |
| 影响的时间范围 | 集中在后续窗口开头约 1~2 周；Wilder 衰减下，窗口内跑满 42 根（7 天）后预热权重降到 4.5%，14 天后 <0.2% |

**所以不能把它说成"完全没影响"，也不能说成"整段被研究过"**：是"区间末段的波动率，决定了后续窗口开头那段行情的门槛与止损距离"。

### 3.4 为什么不能判成"仅检查过数据完整性"

如果只看到"入库 + 覆盖检查 + 没有运行窗口覆盖"，很容易判 B。但 B 的前提是"数据没进过研究计算"，而这里数据确实进了 ATR 递推。**判 B 会低估接触**，所以全部判 A2。

### 3.5 为什么也不能判成"未用于研究"

反向的错法同样存在：看到"没有窗口覆盖、没有候选、没有成交"，就写"未用于研究"。这会漏掉 ATR 这条通道。**判 C 会低估污染**，所以不判 C。

## 4. 数据条件与 OI 时点证据（分开记，不合并成一个"不合格"）

这 49 条的数据本身其实是好的——它们不能用，原因不在数据质量：

| 项目 | 结果 |
|---|---|
| 4h 根数覆盖 | 49/49 = **100%**（逐区间按 open_time 计数） |
| 1h 根数覆盖 | 49/49 = **100%** |
| 15m 根数覆盖 | 49/49 = **100%** |
| OI 5m 覆盖 | 99.96% ~ 100%（合计 1,100,128 行） |
| 200 根 4h 预热 | 49/49 满足（区间起点晚于预热完成点） |
| 真实结算 mark | 49/49 可用（区间都在 2022-01-01 之后） |
| 时长 ≥ 30 天 | 49/49 满足 |
| 时长 ≥ 12 个月 | **0/49** |

**OI 时点证据（单独列，不与数据质量混谈）**：

- 区间内 OI 来源全部是 `binance.archive.metrics`（交易所日归档，非实时轮询）；
- `fetched_at` 字段在区间内的空值率 **100%**（全库 1.2857 亿行都是空）；
- 结论：**只能声明"计算上不超前"（桶起点+5m≤决策时刻），不能声明"已证明无未来函数"**。
  归档数据的理论可得时点约为次日，但本机没有归档发布时刻的证据，因此不升级资格。
