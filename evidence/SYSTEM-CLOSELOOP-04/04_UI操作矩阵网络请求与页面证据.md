## 3. 止损轨迹 UI 404 细分状态专项审计

在 `SYSTEM-CLOSELOOP-04` 第一关第 4 点明确要求：
> “区分加载中、无记录和请求失败；404不得显示为‘暂无上移’。”

### 代码改进与状态映射
前端在 `UI界面/web/src/components/PositionPanel.tsx` 中新增独立错误状态 `stopsError: string | null`：
```tsx
const [stopsError, setStopsError] = useState<string | null>(null);

// 请求处理：
fetch(`/api/v1/paper/stops/${p.position_id}`)
  .then(async (res) => {
    if (res.status === 404) {
      setStopsError(`持仓不存在 (404 Not Found: ${p.position_id})`);
      return;
    }
    if (!res.ok) {
      setStopsError(`请求失败 (${res.status} ${res.statusText})`);
      return;
    }
    const data = await res.json();
    setStopsHistory(data.updates || []);
  })
  .catch((err) => {
    setStopsError(`网络错误: ${err.message}`);
  });
```

### 三态渲染区分实测
1. **加载中 (Loading)**：渲染骨架动画与“正在加载轨迹...”提示；
2. **无记录 (Empty Updates)**：API 返回 HTTP 200 且 `updates: []`，明确提示“已接入 FT-LOW4H 跟踪规则，当前尚未发生止损上移”；
3. **请求失败 / 404 (Failed / 404)**：API 返回 HTTP 404，界面以警告色明确渲染：
   > `⚠️ 获取跟踪轨迹失败: 持仓不存在 (404 Not Found: pos-nonexistent-for-404-audit)`
   **绝不退回或冒充为“暂无上移”**。该行为已被截图 `06_ui_404_error_state_audit.png` 严格证实。

## 4. 多时间戳止损轨迹因果呈现

在持仓详情展开面板（截图 `05_position_trailing_stops_expanded.png`）中，每一个止损变动节点均独立呈现 3 个物理时间戳，彻底消除偷跑与追溯因果缺陷：
- **引用 K 线收盘时间 (`ref_candle_close`)**：例如 `2026-10-22 12:00:00 (4h)`
- **决策触发时间 (`decision_time`)**：例如 `2026-10-22 12:00:02`
- **实际生效时间 (`effective_time`)**：例如 `2026-10-22 12:00:02`，算法约束 `effective_at = max(decision_at, ref_candle_close_ms)`，绝不允许将止损追溯至过去的旧 K 线时间生效。
