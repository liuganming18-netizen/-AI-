# SYSTEM-CLOSELOOP-04｜01 自动运行入口配置与进程身份

## 1. 自动驱动运行架构与定位

在 `SYSTEM-CLOSELOOP-04` 中，系统彻底摆脱了人工调用 `advance_trailing` 接口推进持仓的依赖，构建了**全自动常驻执行循环（Paper Execution Loop）**。

### 核心设计原则
1. **优先复用现有执行核心**：复用经过 `SYSTEM-CLOSELOOP-03` 冻结的 `paper_engine.py` 撮合核心与事件记录，绝不重新接回已退役或依赖缺失模块（如 `_warmup43`、`wx_donchian_wyckoff`）的旧核心。
2. **单实例排他执行（Single-Instance Guarantee）**：基于操作系统的 `fcntl` 独占文件锁机制（`locks/paper_exec_{arm}.lock`），证明同机同一时刻严格只启动一个推进进程，从操作系统内核级别彻底杜绝多个进程重复推进或重复撮合成交。
3. **日常执行与测试回放严格解耦**：日常执行严格从配置的数据源读取已可用行情；隔离测试只在受控独立回放入口运行，绝不将时钟注入日常下单接口。

## 2. 自动运行入口与启动方式

系统提供了两种标准启动方式，均支持 `--arm` 隔离指定：

### 方式一：独立守护进程启动（推荐常驻方式）
```bash
# 1. 常驻运行（默认每 5 秒轮询一次 3a 臂）：
/Users/boos/.workbuddy-ai/binaries/python/envs/default/bin/python 框架/backend/workers/paper_execution_worker.py --arm 3a --interval 5.0

# 2. 单次调试运行（执行单轮后退出）：
/Users/boos/.workbuddy-ai/binaries/python/envs/default/bin/python 框架/backend/workers/paper_execution_worker.py --arm 3a --once
```

### 方式二：通过 Web 适配层后台线程托管
在 `adapter.py` 启动时，可按需由适配层后台守护线程调起 `PaperExecutionDaemon.start_background()`，由同一进程空间管理。

## 3. 运行状态、健康度与可观测性 API

系统在正式路由表（`api/routes.py`）中接通了执行守护进程的状态查询端点：
- **请求路径**：`GET /api/v1/paper/execution_daemon/status?arm=3a`
- **响应示例**：
```json
{
  "mode": null,
  "quality": {
    "status": "ok",
    "note": "execution_daemon_status"
  },
  "item": {
    "arm": "3a",
    "pid": 40532,
    "status": "running",
    "running": true,
    "started_at": 1792681812822,
    "last_cycle_ms": 1792683327970,
    "cycle_count": 1420,
    "pending_matched_count": 2,
    "stops_updated_count": 2,
    "exits_triggered_count": 2,
    "last_error": null,
    "health": "healthy"
  }
}
```

### 状态字段释义
- `pid`：持有独占锁并负责当前 Arm 执行的唯一进程 PID；
- `running` / `status`：运行状态（`running` / `idle` / `failed_lock_occupied` / `stopped`）；
- `last_cycle_ms`：最近一轮推进的精确毫秒时间戳；
- `health`：健康评估（`healthy` 无异常；`degraded` 部分周期遇阻；`error` 致命阻断）；
- `last_error`：最近一次推进失败的详细原因；
- 失败与恢复行为：遇到临时网络或只读行情库锁定时，记录 `last_error` 并将状态标记为 `degraded`，下一轮自动重试恢复，不丢失持仓与挂单状态。

## 4. 单实例排他性验证证据

在自动化验收测试套件 `test_automated_closeloop.py` 中，执行了并发启动互斥性测试：
1. 进程 1 成功获取文件锁 `paper_exec_3a.lock` 并将状态置为 `running`；
2. 进程 2 尝试启动驱动同一 Arm，`acquire_lock()` 立即抛出 `BlockingIOError`，状态被置为 `failed_lock_occupied`，拒绝重复拉起；
3. 进程 1 正常退出并释放锁后，进程 2 再次尝试即可成功获取锁。
- **验证结论**：从底层彻底杜绝了多进程竞争推进、双重平仓或账本并发记账的风险。
