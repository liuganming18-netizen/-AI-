# 02 · 含义与公式字典

> 只写**本工程实际存在**的字段与**代码里实际这么算**的公式。
> 公式出处标了文件与函数名，可逐个核对。凡是"文档这么写、代码没这么做"的，单独标注。

## 一、K 线字段

| 字段 | 含义 | 单位 | 陷阱 |
|---|---|---|---|
| `open_time` | 该根 K 线**开盘**时刻（UTC 毫秒，左闭） | 毫秒 | 5m/15m/…/4h 的收盘时刻 = `open_time + 周期`；热库里 `close_time` 是 `open_time + 周期 - 1`（毫秒精度差 1） |
| `close_time` | 该根 K 线**收盘**时刻 | 毫秒 | 与 `open_time + 周期` 差 1 毫秒，比较时间必须统一口径 |
| `open/high/low/close` | 开高低收 | USDT | 冷档里是**字符串**，直接 `sum()` 会拼接 |
| `volume` | 成交量 | **标的币**（如 BTC 个数） | 不是 USDT；`1000PEPE` 这类合约的"1 个"是 1000 个 PEPE |
| `quote_volume` | 成交额 | USDT | 唯一可用于"名义金额"的量纲 |
| `trade_count` | 成交笔数 | 笔 | 0 值占 5.13%，0 与"未采集"未区分 |
| `taker_buy_volume` | 主动买入量 | 标的币 | 4.8% 是空字符串；不能当 0 |
| `taker_buy_quote_volume` | 主动买入额 | USDT | 同上 |
| `source_id` | 该行来自哪次导入 | 整数 | **同一根 K 线可以有多个 source_id = 多个版本**，不是重复采集 |
| `available_at` | 该行何时入库 | 毫秒 | 热库 49.6% 有值，冷档全空；**是本地入库时刻，不是交易所发布时刻** |
| `is_closed` | 是否已收盘 | 0/1 | 热库实测无 0 值（只存已收盘） |

### 派生量

| 名称 | 公式 | 出处 |
|---|---|---|
| 真实波幅 TR | 首根 `TR = high − low`；之后 `TR = max(high−low, |high−prev_close|, |low−prev_close|)` | `features.py:compute_wilder_atr_series` |
| ATR(14) | 前 14 个 TR 算术平均作初值，之后 `ATR_t = (ATR_{t−1}×13 + TR_t)/14` | 同上 |
| 方向效率 ER | `ER = |close_last − close_first| / Σ|close_i − close_{i−1}|`，分母 ≤1e-12 返回 None | `features.py:compute_efficiency_ratio` |
| 箱体宽度 | `(H − L) / ATR`，要求落在 2.0–8.0 | `config.py:box_min_width_atr/box_max_width_atr` |
| V20 | 突破前 20 根**完整** 1h 成交量中位数（不含突破当根） | `features.py:compute_v20_median_volume` |
| 回踩缩量 | `vol_retest ≤ 0.8 × Vs`（Vs = 扫低那根的量） | `config.py:retest_vol_multiplier` |
| 突破放量 | `vol_breakout ≥ 1.5 × V20` | `config.py:breakout_vol_multiplier` |

## 二、持仓量（OI）

| 字段 | 含义 | 单位 | 陷阱 |
|---|---|---|---|
| `open_interest` | 合约持仓**数量** | 标的币（张数按合约面值折算后） | 冻结规则明确要求用**数量**，不许用美元名义额替代 |
| `open_interest_value` | 持仓**名义额** | USDT | 等于 `open_interest × 标记价`（实测残差 1e-16） |
| `oi_ccy` / `oi_usd` | 上面两者的冗余副本 | 同上 | 与主字段同值 |
| `period` | `5m`（历史序列）或 `snapshot`（当前快照） | — | 两种口径**不能混算** |
| `ts` | 桶**起点** | 毫秒 | 5m 桶代表 [ts, ts+5m) 区间 |

### 派生量

| 名称 | 公式 | 出处 |
|---|---|---|
| 6 小时 OI 增长率 | `OI(T)/OI(T−6h) − 1`，要求 `≥ 0.02` | `config.py:oi_min_growth_pct` |
| OI 观测时点约束 | `OI(T)` 必须是"观测时间不晚于 T、且可证明 T 时刻已可得"的最近值，且距 T ≤ 15 分钟 | `config.py:oi_max_time_distance_sec` |
| 缺失处理 | 任一缺失/非正/时点不合格 ⇒ `oi_unavailable`，**拒绝入选**，不补 0 | `state_machine.py` |
| 回测对齐方式 | as-of：`ts ≤ 该根收盘时刻` 的最近一条 | `backtest_runner.py:383-394` |

**两个已知陷阱**：

1. `sum_open_interest = 0` 是**假观测**（抽样：BTC 473 行、CVC 709 行），必须当缺失，否则增长率变 inf。
2. `Δ(open_interest_value)` **不能叫"资金流入"**：它与价格收益的相关性 0.77–0.92，主要是价格乘数效应。
   `open_interest_value ≡ open_interest × mark_price`（残差 1e-16），与收盘价中位差 0.08%–0.36%（小币最大 10.4%），
   所以它**也不能当收盘价**用。

## 三、资金费

| 字段 | 含义 | 单位 |
|---|---|---|
| `funding_time` | 结算时刻 | 毫秒（保留原始精度，不截秒） |
| `funding_rate` | 该次结算费率 | 小数；`0.0001` = 1 bp |
| `mark_price` | 结算用标记价 | USDT |
| `rate_type` | `settled`（已结算） | 只有这一种进入计算 |
| `source` | `binance.archive.fundingRate` / `binance.fapi` / `okx.v5` 等 | 三个来源混存同一张表 |

### 派生量

| 名称 | 公式 | 出处 |
|---|---|---|
| 单次资金费支出 | `amount = qty × mark_T × fundingRate`（正负原样，不做缩放） | `paper_engine.py:1293-1295` |
| 现金影响 | `ΔCash = −amount` | `paper_engine.py:1469` |
| 结算判据 | `last_funding_ms < ev_ms ≤ t_ms`，缺 rate/mark ⇒ 记 `funding_gap`，**不补 0** | `trading_core/funding.py` |

## 四、多空比与大户指标（`metrics`）

| 字段 | 含义 | 单位 |
|---|---|---|
| `sum_open_interest` | 全市场持仓量 | 标的币 |
| `sum_open_interest_value` | 全市场持仓名义额 | USDT |
| `count_long_short_ratio` | 全市场**账户数**多空比 | 比值 |
| `sum_toptrader_long_short_ratio` | 大户**持仓量**多空比 | 比值 |
| `count_toptrader_long_short_ratio` | 大户**账户数**多空比 | 比值 |
| `retail_account_ls_ratio` | 散户账户多空比 | 比值 |
| `top_position_ls_ratio` | 大户持仓多空比 | 比值 |
| `sum_taker_long_short_vol_ratio` | 主动买卖**额**比（买额/卖额） | 比值 |

**两个必须知道的坑**：

1. **纯别名**：抽样 10 个币全部逐值相同 ——
   `retail_account_ls_ratio ≡ count_long_short_ratio`、`top_position_ls_ratio ≡ sum_toptrader_long_short_ratio`。
   当独立特征用会重复计数。
2. **`sum_taker_long_short_vol_ratio` 是"额"口径**，不是"币"口径：
   买入占比 = `r/(1+r)`。实测额口径误差比币口径小三个数量级。

|---|---|---|
| `details[].avgEntryPrice` | 该组交易员**持仓均价** | USDT |

## 六、策略侧口径（容易被误读的几个）

| 名称 | 定义 | 出处 |
|---|---|---|
| 每笔风险 | `risk_budget_per_trade = 0.005` = 权益的 **0.5%**（不是文档里写的 2%） | `config.py` |
| R 值 | `R_i = profit_abs_i / (开仓时权益 × 0.005)` | 冻结规则 |
| 初始止损 | FT-LOW4H 下 `stoploss_s = 0.05`（入场价 −5%）；`initial_stop_buffer_atr` 只在旧规则用 | `make_ft_low4h_config()` |
| 跟踪止损 | `trail_d = 0.05`：4h 最低价 × 0.95；`trailing_lookback_4h_bars = 1`（只看最近 1 根 4h） | 同上 |
| 参与率上限 | 订单名义 ≤ 上一根**已完成** 15m 成交额 × 0.1%（回测配置）/ 1%（实盘参数视图） | `config.py` vs `paper_engine.py:190` |
| 手续费/滑点 | 5 bps / 3 bps（回测基准）；实盘视图 5 bps / 5 bps | `config.py` / `CODEX-CLOSEOUT-01` |
| 流通市值 | `market_cap_usd = 最新价 × CMC 流通量`，分子分母同为合约标的币单位 | `adapter.py:1220-1240` |
| CVD（旧策略族） | `2 × taker_buy_volume − volume` | `strategies/common.py:59` |

**易错点**：`EventTrendConfig` 的默认 `trailing_trigger_r=2.0`、`trailing_lookback_4h_bars=10`、
`max_holding_days=10` 在 FT-LOW4H 下**全被覆盖**；直接读 dataclass 默认值会得到错误的规则。
