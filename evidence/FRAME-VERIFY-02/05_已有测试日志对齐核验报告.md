# FRAME-VERIFY-02｜05. 已有测试日志对齐核验报告

## 一、PIT 129 项通过与 OI 消融测试失败记录核实

### 1. 对应版本与问题现象
- **涉及测试用例**：[`策略/WyckoffMaster/event_trend_v0_1/tests/test_event_trend_closure.py::test_oi_ablation_and_pit_semantics`](file:///Users/boos/Desktop/威科夫因子共振趋势/策略/WyckoffMaster/event_trend_v0_1/tests/test_event_trend_closure.py#L265)
- **旧代码行为**：
  在引入 `FRAME-PIT-01` 之前，该闭环测试构造的假数据中，将 OI 增幅跳变设置在决策时刻当根 5m 桶上（`t_bo_close`）。旧规则 `open_time <= t_bo_close` 允许读取以 `t_bo_close` 为起点的 5m 桶，因而该测试原本能够通过。
- **引入 FRAME-PIT-01 后的失败记录**：
  当 `FRAME-PIT-01` 实施严格 PIT 拦截后，以 `t_bo_close` 为起点的 5m 桶覆盖的是决策时刻之后 5 分钟（`[t_bo_close, t_bo_close + 5m)`），属于未来数据，受控规则严格拒绝读取。因此，旧测试在跑新代码时，决策时刻读不到该跳变，导致 OI 增幅未达阈值，引发断言失败报错。

### 2. 先后因果关系与复测关闭证据
1. **第一阶段**：`FRAME-PIT-01` 实施严格可得性规则，拦截决策时刻正开始的未来桶；
2. **第二阶段**：导致 `test_event_trend_closure.py` 中的旧测试夹具预期落空，产生失败记录；
3. **第三阶段（同步修正）**：实现方查明该失败是由于旧测试夹具自身把“读未来桶”当成了预期，遂于 `test_event_trend_closure.py` 中将跳变构造前移一桶（`idx_bo_close = np.searchsorted(all_5m_ts, t_bo_close - 5m, side="right") - 1`），并在源码中显式添加修正说明；
4. **第四阶段（复测关闭）**：在 `evidence/FRAME-PIT-01/logs/pytest_full.log` 中，全部门禁由 103 项扩展至 **129 项，全部通过（129 passed in 9.29s）**，该失败已被正当复测关闭。
