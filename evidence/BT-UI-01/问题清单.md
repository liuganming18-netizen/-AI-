# BT-UI-01 问题清单（回测页面修复与逐笔复核）

> 工程：`/Users/boos/Desktop/威科夫因子共振趋势`
> 页面：侧栏「回测复盘」→ 回测工作台（`BacktestWorkbench`）
> 取证方式：真实接口 + 真实账本 + 浏览器探针截图；**不以 HTTP 200 或构建成功作为验收依据**。
> 全部问题都在本机真实数据上复现过（批次 `runs_sep_all_latest`，528 个 run、12 笔成交）。

---

## 一、页面读到的数据不是同一批（最严重）

| # | 现象 | 根因 | 证据 |
|---|---|---|---|
| 1.1 | 页面只能看到 `runs/`（单 run 临时目录，1198 个），**批次目录根本不出现** | 读取层只认默认运行根；批次目录（`runs_sep_all_latest` 等 8 个）与它平级，没有任何读取通道 | 批次栏未出现前的截图；`GET /api/v1/backtests` 返回里没有 `runs_sep_*` |
| 1.2 | ⑤ 逐笔明细里有「全市场成交」，读的是 `public/all_trades.json`（旧批次 70 行静态快照） | 前端直接 `fetch('/all_trades.json')`，与当前 run 完全无关 | 该文件 70 行，与任何 run 的账本都对不上 |
| 1.3 | 点⑥实验记录里的行，会用 `all_trades.json` 里的 `run_id` 去选 run ⇒ 串标的 | 同上，`viewAllTrades` 分支回退到静态快照 | 代码位置：`BacktestWorkbench` 旧 `viewAllTrades` 分支 |

**处理**：新增「批次」一等读取对象（`/api/v1/backtests/batches[...]`），列表 / 汇总 / 逐笔 / 图表全部锚定同一个 `batch_id`；删掉 `all_trades.json` 分支。

## 二、批次里的 run 打不开（图表整块消失）

| # | 现象 | 根因 | 证据 |
|---|---|---|---|
| 2.1 | 从批次选中一个 run 后，`GET /backtests/{id}` 及其 `/chart` `/trades` `/metrics` `/equity` `/quality` **全部 404**，页面上图表区直接不渲染 | `backtest_store.run_dir()` 只允许「默认根/一级目录」；批次 run 在另一个根下 ⇒ 读不到 | 复现：`run_WX_EVENT_TREND_V0_1_AIXBTUSDT_1792262009` 修前 404、修后 200（0.012s） |

**处理**：新增 `read_run_dir()`（默认根 → 同级批次目录），**只放宽读取**；`create_run` / `write_run` / 账本写入仍只认默认根（有回归测试守住）。

## 三、逐笔字段缺失，无法定位到「这一笔」

| # | 现象 | 根因 | 证据 |
|---|---|---|---|
| 3.1 | `/trades` 没有**初始止损** | 只读了 `trades.jsonl` 顶层字段，没取 `stop_trace[0].stop` | AIXBT 初始止损 0.01941926653321507 在 `stop_trace[0]` 里 |
| 3.2 | `/trades` 没有**信号时间**，只有成交时间 | `trades.jsonl` 只有 `signal_id`，没有信号时刻 | 候选信号真实时刻在 `candidates.jsonl.available_at_ms`（= 信号时间） |
| 3.3 | `/trades` 的 `trade_id` 大量为空 | 批量脚本落盘的 `trades.jsonl` 不带 `trade_id`（真实标识在 `positions.jsonl` 的 `POSITION_CLOSED`） | 12 笔里修前全部需要回填 |
| 3.4 | 退出原因是英文枚举（`max_holding_expired` / `force_close_eod`），同一列一半中文一半英文 | 三处各维护一张映射表，两张都漏了这两个枚举 | 见「四类案例对照」B/C 两例修前文字 |

**处理**：`/batches/{id}/trades` 逐笔补齐 `initial_stop`(+来源) / `signal_time_ms`(+来源) / `trade_id`(+来源)，缺失就留 `None` 并计数（`missing_initial_stop` / `unlinked_signal_time`）；退出原因统一走 `utils/runMeta.exitReasonLabel` 一张表。

## 四、K 线图与逐笔对不上（时区 + 错窗口）

| # | 现象 | 根因 | 证据 |
|---|---|---|---|
| 4.1 | 图表横轴按**浏览器本地时区**显示，表头写 UTC ⇒ 差 8 小时 | lightweight-charts 默认 `tickMarkFormatter` 用本地时区 | 修前轴标签与「信号时间 09:00」错位 8 小时 |
| 4.2 | 信号点与成交点都画成「柱上方箭头/圆点」，混在一起 | 两者都用 `aboveBar` 系列标记 | 修前同一位置两个箭头叠着 |
| 4.3 | **图表显示的是 2024-06 的 K 线，而交易发生在 2025-09** | `chart.json` 缺失时，后端用**写死的 `2024-01-01 ~ 2024-06-30`** 重建图表 | 见下表：4 个 run 的真实窗口与写死窗口**完全不相交** |
| 4.4 | 上一条还会**把错图写回 run 目录**（读接口产生写副作用） | 重建函数末尾 `S.write_chart(run_id, chart)` | 4 个 run 目录里出现了本不该存在的 `chart.json`（时间戳 = 我发请求的那一分钟） |

被写死窗口影响的 4 个 run（真实窗口取自各自 `inputs.json`）：

| run | 写死窗口 | 该 run 真实窗口 | 是否相交 |
|---|---|---|---|
| `run_WX_EVENT_TREND_V0_1_QNTUSDT_1792273818` | 2024-01-01 ~ 2024-06-30 | 2024-09-30 ~ 2025-09-30 | 不相交 |
| `run_WX_EVENT_TREND_V0_1_ONTUSDT_1792273940` | 同上 | 2021-06-20 ~ 2022-06-20 | 不相交 |
| `run_WX_EVENT_TREND_V0_1_IOTAUSDT_1792274148` | 同上 | 2022-10-17 ~ 2023-10-17 | 不相交 |
| `run_WX_EVENT_TREND_V0_1_TRXUSDT_1792274204` | 同上 | 2023-01-16 ~ 2024-01-16 | 不相交 |

**处理**：
- 轴标签显式用 `getUTC*` 格式化；图例写明「时间轴 UTC（北京 = UTC+8）」；
- 候选信号改 `inBar` 方块（`■ 候选信号`），成交用 `▲ 开仓 / ▼ 平仓` 箭头，两者分开；
- 重建图表改为**取该 run 自己的窗口**（`inputs.json(data_summary.time_range_1h)`，退路是账本权益曲线首尾），标的取 `summary.json`；取不到就报「缺 K 线，不伪造」；
- 重建结果**不再写盘**，只放内存缓存；页面上打「读时重建 · 非原始 chart.json」徽章。
- 已被写进去的 4 个错图已移出 run 目录（见 `未完成项.md` 的「现场还原」）。

## 五、0 笔被显示成「缺失」

| # | 现象 | 根因 | 证据 |
|---|---|---|---|
| 5.1 | 批次 528 个 run 里 516 个「确实 0 笔」，页面「笔数」列显示 `—` | `sa.get("trade_count") or sa.get("trades_count")`：真实值 `0` 是假值，被 `or` 吃掉变成 `None` | 修前：`trades_count: null` × 516；修后：`trades_count: 0` × 516 |

**处理**：显式判 `None`；`0` 与「缺失」严格分开（回归测试 `test_zero_trade_count_is_zero_not_none`）。

## 七、性能（首屏 30 秒空白）

| # | 现象 | 根因 | 修后 |
|---|---|---|---|
| 7.1 | `GET /backtests?limit=600` 首次 18–28 秒 | 逐个目录串行读 1198 个 `run.json`/`summary.json`，`limit` 只是最后截断 | 8 线程并发 + 120 秒缓存（预热后 0.12 秒） |
| 7.2 | 批次汇总首次 24 秒 | 预热线程与首个请求各扫一遍；`/runs` 与 `/summary` 各扫一遍 | 同 key 只构建一次 + 共用一份缓存；`/runs` 0.003 秒、`/summary` 冷 3.2 秒 / 热 0.001 秒 |
| 7.3 | 首屏图表 ~19 秒才出现 | 启动预热把 8 个批次（2130 个 run）全算一遍，把首个请求堵在后面 | 只预热「页面会默认选中」的那一个批次；首屏图表约 5 秒出现 |
