# 回测记录补登记报告（BACKFILL-01）

- 时间：2026-10-21
- 范围：`回测日志/event_trend_v0_1/` 下全部运行目录 + 全币种压测批次
- 结论：**2127 次真实回测全部在系统里有档案**，回测页可查看、可搜索、可点开

---

## 1. 问题

| 现象 | 实测 |
|---|---|
| 运行目录总数 | 2138（`runs/` 1203 + 7 个批次目录 932 + `reconstructed/` 3） |
| 有 `run.json`（正式档案） | **8**（且其中 6 个是测试目录） |
| 界面上显示「未登记」 | 2127 次真实回测 |
| 页面能看到的记录上限 | **600 条**（前端写死），后端上限 1000 |
| 全币种压测 19496 次回测 | 系统里**完全看不到**（只落在 evidence 的 jsonl） |

即：结果在盘上、档案不在系统里，界面既显示不全也搜不到。

> `reconstructed/` 下 3 个目录**没有 summary.json / inputs.json**（无任何结果产物），
> 按纪律跳过、不补造档案。

## 2. 做法（零编造）

新增 `工具_补登记历史回测.py`，对每个缺 `run.json` 的目录，**逐字段从本 run 自己的落盘文件取真实值**，取不到就留 `null`：

| 字段 | 真实出处 |
|---|---|
| 创建时刻 | `inputs.json:timestamp_created`（引擎落盘 epoch 秒） |
| 数据窗口 | `inputs.json:data_summary.time_range_1h` |
| 代码指纹 | `inputs.json:fingerprints`（逐文件 SHA256 + combined） |
| 结果指标 | `summary.json:summary_variant_a` |
| 费率 | `summary.json:reconcile.fee_model.taker_fee_rate` |
| 滑点 | `ledger.jsonl` 首行 `GENESIS_INIT.payload.slippage_bps` |
| 对账 | `summary.json:reconcile + identity`（程序自检，非独立证据） |
| 完成度 | `manifest.json` 原子提交标记 + summary 结果块 |

硬约束：

- 只走 `backtest_store.register_external_run`（run.json 唯一写入口），原子写；
- 已有 `run.json` ⇒ 跳过，**绝不覆盖**；
- `finished_at` 一律 `null` —— 产物里没有真实完成时刻，**不拿目录 mtime 冒充**；
- `risk_budget_per_trade / max_active_positions / max_notional_per_position` 产物中无记录 ⇒ `null`，**不填默认值**；
- 状态按产物证据推断，判不了给 `unknown`，不冒充 `succeeded`；
- 每份档案带 `registration.registered_by="backfill_from_artifacts"` 与 `provenance`（逐字段来源说明），
  事后审计能分清「当时登记」与「按产物补录」。

## 6. 没有做的事（边界）

- **没有**给历史产物编造完成时刻、风险预算、持仓上限（全部 `null`）；
- **没有**覆盖任何已有 `run.json`；
- **没有**为压测的 19496 次回测伪造 19496 个 run 目录（磁盘与列表双重不可行），
  只登记为一条清单型批次，明细指回 jsonl；
- **没有**把清单型批次伪装成有逐笔账本（`checks` 标「不适用」，`trades.count` 为 `null`）。
