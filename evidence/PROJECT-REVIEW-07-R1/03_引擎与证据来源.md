## 0. 为什么要单独写这一份

上一单（`PROJECT-REVIEW-07`）把三套引擎的成交放进同一张表：`37,404 笔成交`、`32,323 笔无止损轨迹（freqtrade 链，不写轨迹）`、`60/60 合规`。这三个数字本身没错，但**混了引擎**，由此得出两条不成立的推论：

1. 「没有 `stop_trace` 的都是 freqtrade」——不成立。freqtrade 只有 12,598 笔（物理 8,273），项目引擎另有 9,849 笔没有这个字段。
2. 「60/60 合规 ⇒ 4h 止损没有用入场前价格」——只能说明**这 60 笔**没问题，另外 22,447 笔没有轨迹可判，属未验证。

## 1. 五个 engine 标识，三套引擎

`run.json.engine.exec_core_version` 是每个 run 自带的引擎标识。全量 5,091 个 run 目录的分布：

| 引擎 | engine 标识 | run 数 | 成交笔数 | 逐次成交（fills） | 止损轨迹字段 | 说明 |
|---|---|---:|---:|---|---|---|
| **项目回测引擎** | `trading_core_shared_v1` | 2,139 | 707 | **有**（`/fills` 实测返回 2 笔） | 有 | 官方通道；1,197 组旧规则 + 22 组 FT-LOW4H |
| **项目回测引擎（老批次）** | 无 `engine` 字段 | 568 | 24,099 | 同左（同一执行核） | 有/无混 | `batch_tests_archive`、`_ft09_other_impl_variants`、研究批次 |
| **Freqtrade 回测引擎** | `freqtrade_backtesting` | 2,288 | 9,203 | **无** | **无该字段** | FT-ENTRY-09 研究链 + `runs_ft_replay_01` 重建产物 |
| **Freqtrade 回测引擎** | `freqtrade 2026.9` | 45 | 3,395 | **无** | **无该字段** | WORK-DYNAMIC-BT-01 组合对照 |
| **OI 共振（已退役）** | `oi_res_exec_v1.0.0` | 51 | 0（账本不可读） | — | — | 仅研究，已退役 |
| **模拟执行引擎** | — | 3 个持仓 | 6 笔成交（`paper_fill`） | **有**（独立表） | `paper_stop_history` 0 行 | 自然成交 0 笔 |

合计：2,139 + 568 + 2,288 + 45 + 51 = **5,091 个 run 目录**；成交 707 + 24,099 + 9,203 + 3,395 = **37,404 笔**。

## 2. 成交事件能力逐引擎核对（不能外推）

| 能力 | 项目回测引擎 | Freqtrade | 模拟执行引擎 |
|---|---|---|---|
| 委托单 | `orders.jsonl`（`order_id` / `status` / `fill_price` / `filled_at` / `liquidity`） | `orders.jsonl` 每笔 2 行（开/平），无状态机、无 `filled_qty`/`remaining_qty` | `paper_order` 13 行（3 成交 + 10 拒单） |
| 逐次成交 | **`/api/v1/backtests/{id}/fills`** 返回 `fill_id` / `order_id` / `trade_id` / `sequence` / `fee` / `liquidity`（实测 TAOUSDT 2 笔、WALUSDT 2 笔） | **无**：`/fills` 返回 `total=0` 且 `missing_reason=null`（不说明"本引擎不产生"） | `paper_fill` 6 行（3 开 + 3 平） |
| 部分成交 | 无样本；订单模型是一次性成交（`quantity` 即成交量） | 无字段支撑 | 无字段支撑 |
| 止损轨迹 | `trades[].stop_trace`（本项目引擎 14,957 笔有值） | 字段不存在 | `paper_stop_history` 0 行 |

**因此：**
- 「freqtrade 没有 fill 事件」不能推出「项目引擎也没有」——项目引擎的 `/fills` 是能用的；
- 「模拟盘有 `paper_fill`」也不能推出「回测也有」——freqtrade 链一笔都没有；
- 「60 笔跟踪线合规」不能替「22,447 笔无轨迹」消除疑问。

## 3. 止损轨迹的真实分布（全量 37,404 笔）

| 分类 | 项目引擎 | Freqtrade | 合计 |
|---|---:|---:|---:|
| 无 `stop_trace` 字段 | 9,849 | 12,598 | **22,447** |
| 有字段但从未上移 | 14,897 | 0 | **14,897** |
| 有字段且上移过 | 60 | 0 | **60** |
| 其中：首条跟踪线早于入场后首个 4h 收盘 | **0** | — | **0** |
| **可判定覆盖率** | 60 / 24,806 = 0.24% | 0 / 12,598 | **60 / 37,404 = 0.16%** |

上一单把「`entry_time` 是字符串」的成交也算进「无止损轨迹」，所以报出 32,323；实际无字段的是 22,447，另有 14,897 笔有字段但没上移（这些本来就不存在"借用入场前 4h"的问题）。结论应写成：

- **可判定样本 60/60 合规**；
- **22,447 笔无轨迹 = 未验证**（不是通过，也不是违规）；
- 上一单的「生产未发生」只在 60 笔上成立，不能扩写成「全库未发生」。

## 4. 三条链的口径差异（同一件事在三处名字不同）

| 项 | 项目回测引擎 | Freqtrade | 模拟执行引擎 |
|---|---|---|---|
| 本金 | 2,000（旧规则）/ 5,000（22 组 FT-LOW4H） | 2,000 | 5,000 |
| 最多持仓 | 3 | 3 | 10 |
| 参与率上限 | 0.1% / 1% | 未建模 | 1% |
| 滑点 | 3 bps / 5 bps | **0.0**（`run.json` 自述：freqtrade 默认不建模滑点） | 5 bps |
| 资金费 | 逐笔结转 | 有 `funding_fee`，但图表 `funding_events=0` | `paper_funding` 0 行 |

**Freqtrade 链滑点 0** 是上一单没写的一条：它的收益数字不能与另两条链并列比较，也不能用来验证"扣成本后是否有效"。
