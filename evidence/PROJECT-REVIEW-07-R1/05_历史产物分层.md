## 1. 软链接这件事（`08_软链接核对.json`）

```
runs_ft_replay_01/run_FT_ENTRY_09_C_Vs06_Z04_API3USDT  →  ../runs/run_FT_ENTRY_09_C_Vs06_Z04_API3USDT
```

- 1,065 个软链接，**全部**在 `event_trend_v0_1/runs_ft_replay_01/`，**全部**指向 `runs/` 下同名目录
- 断链 0，指向 `runs/` 之外 0
- 唯一目标数 1,065 ⇒ 每个目标只被链一次，不存在多链

代码里也写明了为什么这样设计（`backtest_api.py` 注释）：
研究期 run 单窗口最长 1,113 天（≈10.7 万根 15m），1,065 个目录全落盘会多出 GB 级冗余，
而 K 线本来就在市场库 ⇒ 读时按 run 自己的 symbol + window 取。

**设计本身没错。错在统计时把链接当成了 run。**
`01_产物分层.py` 用 `os.path.isdir()` 枚举，它会跟随软链接，于是同一份 run 被数了两次：
一次在 `runs/`（按盘上内容判为 B 类），一次在 `runs_ft_replay_01/`（按「没有 candidates/orders」判为缺来源）。

## 6. `candles_source` 不能当判据（`09_candles_source核对.json`）

第一版用 `candles_source` 里有「读时」二字来统计「重建率」，得出「727 重建 / 543 盘上原始」。
**这个统计作废。**

原因在 `backtest_api._finalize_chart_meta`：

```python
if not chart.get("candles_source"):
    chart["candles_source"] = (
        f"读时按本 run 自己的标的与窗口取真实 K 线（{chart.get('symbol')}/{req_tf}），"
        f"未写回 run 目录")
```

这是**默认填充**，不是事实判断。只要原 chart 没写这个字段，哪怕 K 线就是盘上那份，也会被贴「读时取」。

抽样 40 个 E 类 run（盘上 `candles` 是对象且非空），比对盘上根数与首末时间戳 vs 接口返回：

| 判定 | 条数 |
|---|---:|
| **数据来自盘上，标签却说「读时取」** | **35** |
| 数据非盘上（确为重建），标签说「读时取」 | 5 |

**87.5% 是误标。** 那 5 个真重建的，是「盘上窗口与本 run 窗口不符被拒收」那一类
（代码注释说实测有 83 个 run 的 `chart.json` 窗口被写成固定的 `2024-01-01~2024-06-30`）。

正确的判据只有一条：**看盘上 `chart.json` 的 `candles` 是否为空**。按这个口径：

| 盘上有没有 K 线 | 个数 | 占比 |
|---|---:|---:|
| 有（E 1,317 + A 375） | **1,692** | 42.0% |
| 没有（B 1,268 + D 缺 chart 920） | **2,188** | 54.3% |
| 其余（缺 inputs / 无参数 / 缺来源） | 146 | 3.6% |

## 7. 第一版错在哪（留档，不删）

| 第一版写法 | 实际 | 为什么会错 |
|---|---|---|
| 「全量 5,091 个 run 目录」 | 物理 **4,026**；5,091 是逻辑路径 | `os.path.isdir()` 跟随软链接，1,065 个链接被当成 run |
| 「上一单漏了 1,102 个 run」 | 漏的主要是 1,065 个软链接 | 同上，把链接当成了「上一单没数到的 run」 |
| 「D 缺来源 1,102 个」 | **37** 个 | 1,065 是软链接；其目标已在 B 类数过 |
| 「727 条读时重建 / 543 盘上原始」 | 不可统计 | `candles_source` 是默认填充文案，35/40 是误标 |
| 「支持-同级批次 345/345 全部重建」 | 该结论作废 | 150 个是软链接指向的盘上数据，被标签误导 |

**这次自查说明一件事**：凡是用「接口字段的文案」当事实的统计，都要回到盘上核一遍；
凡是用 `isdir()` 数目录的统计，都要先问一句「里面有没有软链接」。

## 8. 汇总一句话

**146 个能看不能算**；**480 个归档件里 321 个文案说「未知」、159 个和在册件同名**。
