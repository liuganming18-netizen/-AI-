# 04｜当前策略身份与权威依据（PROJECT-REVIEW-07-R1）

> 只核对、不改规则。任何"改参数"的建议都只写到"需要谁拍板"，不在本单执行。

## 0. 结论先行

1. **生产（模拟盘）的身份是清楚的**：生效视图 `10_研究参数生效视图_v2_2_user5000_shared.json`（SHA `82dec362…`）自我声明 `purpose=paper_isolated_execution`、`production_config=false`、`research_policy_frozen=true`；它的 `stoploss_s=0.05`、`trail_d=0.05`、入场即跟踪、5 bps 与代码 `make_ft_low4h_config()` 一致。
2. **回测的身份是"旧规则"**：冻结 md（SHA `1f1167de…`，13,315B）写的是 `2R 触发 / 最近 10 根 / 10 天到期 / P0=Lr−0.1A`，2,239 组旧规则 run 的参数与它一致。
3. **真正的问题不是"实现违反规范"**，而是三件更具体的事：
   - 没有 FT-LOW4H 的冻结规则文本，**22 组 FT-LOW4H run 却把旧 md 的 SHA 写进 `inputs.fingerprints.rules.sha256`**；
   - 这 22 组的资金参数是**混合口径**（5,000 / 3 仓 / 30% / 90% / 1%），既不是旧 md 口径，也不是模拟盘口径；
   - `config.py` 文件头仍写"严格对应冻结规则 md，SHA 1f1167de…"，而 `make_ft_low4h_config()` 用 4 个覆盖项改成了另一套。
4. **240h 不是"已取消"**：字段在视图与契约里都存在（`max_holding_hours=240`），当前执行路径不判到期，但休眠的 `live_worker` 会判 ⇒ **字段在、当前不生效、换路径就生效**。

## 4. 240h 的真实状态（最容易误判的一条）

| 路径 | 是否判 240h 到期 | 证据 |
|---|---|---|
| `unified_runtime`（当前在跑，pid 79149）→ `PE.check_position_exit_on_bar` | **不判**：只判 `low <= cur_stop` | `paper_engine.py:2251-2304` |
| `PE.advance_position_trailing` | **不判**：注释自述"入场后立即跟踪，无2R门槛、**无240小时退出**" | `paper_engine.py:2307-2317` |
| `live_worker._scan_position_exit` | **判**：`due_expiry` 分支，`ot >= due_expiry` ⇒ 本根开盘退出 | `live_worker.py:150-173` |
| `live_worker` 是否被 `unified_runtime` 引用 | **否**（`unified_runtime` 只 import `paper_engine`） | 静态核对 |

所以正确说法是：**「240h 在生效视图里、在契约里、在休眠路径里；当前主路径不执行」**。既不能说"已取消"，也不能说"正在执行"。

风险点：一旦有人把执行路径切到 `live_worker`（或复用它的出场扫描），模拟盘会开始 240h 强平，而回测 `max_holding_days=None` 不会 ⇒ 两条链立刻再分叉一次。

## 5. 「旧实验参数不同」与「生产缺陷」的界线

- **不是缺陷**：2,239 组旧规则 run 用 2R/10 根/10 天/2,000 本金/0.1% 参与率。它们是历史实验，与当前模拟盘不同属正常；只是**不能拿来证明当前策略有效**。
- **是缺陷**：22 组 FT-LOW4H run 声明 `rules.sha256=1f1167de…`（旧 md），参数却是另一套。这是**身份字段写错**，会让后来的人以为"这批 run 是按冻结 md 跑的"。
- **是缺陷**：`config.py` 文件头"严格对应冻结规则 md"与 `make_ft_low4h_config()` 的 4 个覆盖项矛盾。这是**注释与实现不一致**，不改交易规则，只改文档与身份登记即可。
- **不是缺陷但需登记**：视图里 `max_holding_hours=240` 与"无到期"并存（见 §4）。
