# DATA-LOOP-ACCEPT-01｜四项通过标准判定（主报告）

**一句话**：三个被审对象（数据路径、画布、自动闭环）**一个都没交付**，所以三项记「待审」；我用只读方式把现场量了一遍，得到四个结论——数据上游确实正常，模拟盘确实没有自然成交（不是坏了），页面显示的账和账本里的账对不上，逐笔数学本身是对的但没有一笔有效样本。**四项通过标准没有任何一项拿到完整证据。**

| 通过标准 | 判定 | 一句话理由 |
|---|---|---|
| ① 数据状态可定位 | **不通过** | 上游水位可测且新鲜，但「这批数据/参数是哪个版本」在接口里是空的，页面、接口、代码报了三个不同的策略名 |
| ② 常驻模拟自动闭环 | **未验证**（自然市场无成交，单独标注） | 独立重放 526 个标的，最近 4 小时零候选，与运行时自报逐项吻合；账本里有效成交 0 笔 |
| ③ 页面同源显示 | **不通过** | 同一时刻页面权益 5,000.00、账本 4,995.65、接口明细 3 笔亏损；测试记录被当成"已平仓"展示 |
| ④ 逐笔对账 | **部分成立** | 权益守恒与手续费复算误差为 0（数学对），但 3 笔全部是作废的合成测试，有效样本 0 |

## ① 数据状态可定位 —— 不通过

### 做对的部分（先记功）

上游是真的活着，不是"看起来活着"：

- 15m：528 个标的全部新鲜，最新已闭合 K 线 `2026-10-23 21:44:59`，滞后 7.2 分钟；
- 1h：528 个标的全部新鲜，最新闭合 `20:59:59`，滞后 52.2 分钟；
- 4h：528 个标的全部新鲜，最新闭合 `19:59:59`，滞后 112.2 分钟；
- 采集器 `realtime` 进程 42278 心跳在 7 秒前，状态 running。

（复算：`out/q01_watermark.json`。这里有个必须避开的坑：`candle_heads` 表 15m 有 210 万行、1h 有 54.6 万行，但真实标的只有 528 个——它是历史版本堆积，不是每标的一行。直接 `count(*)` 会得出"210 万个标的"，直接 `max(open_time)` 会得出"水位停在 09-12"。脚本按 `symbol` 取 `MAX(open_time)` 才是真水位。）

### 不通过的理由（三条，都可复算）

**1. 「哪个版本」在接口里是空的。**
`/api/v1/paper/accounts` 的信封里：`account_id`、`run_id`、`data_version` 三个字段**全为 null**；`strategy_version` 与 `rule_version` 都是 `F_WX_v2.2_project_closure_user_5000_shared`，`param_hash` 是 `82dec362c182`。
而这个字符串来自 `框架/backend/live_store.py:59` 的常量 `PAPER_LEDGER_SPEC`——它是**账本格式规范的代号**，不是当前策略版本。真正在跑的是 `策略/WyckoffMaster/event_trend_v0_1`（`unified_runtime.py:44-47` 导入）。
**账本规范名被当成策略版本上报**，用户无法从接口判断"这批数据、这套参数属于哪次运行"。

**2. 页面上还有第三个名字。**
浏览器实测（22:01，`screenshots/page_text_模拟盘.txt` 第 67 行）：「账户/策略身份: 模拟账户(paper) · **FT-LOW4H-EXP-V2.2**」。
于是同一套系统同时存在三个身份：接口说 `F_WX_v2.2…`、页面说 `FT-LOW4H-EXP-V2.2`、代码是 `event_trend_v0_1`。三者互不相等，**数据状态无法定位到唯一版本**。

**3. 现场存在一个假状态文件，且没有任何机制识别它。**
`框架/backend/locks/unified_runtime_status_3a.json`（11:18 落盘，610 字节）内容为：`pid: 98765`、`cycle_count: 42`、`updated_at: 2026-10-23T03:00:00Z`、`last_signal_time: 2026-10-23T02:00:00Z`、`overall_health: "ok"`、`symbol: "BTCUSDT"`。
整点时间、固定 42 次、进程号 98765，是典型的手写桩。真实运行时写的是另一个文件 `paper_runtime_3a_status.json`（PID 73353、21 次、21:59:56 起）。
两个文件并存，读错一个就会显示"健康、跑着、42 次"的假象。**状态可被伪造而系统不自知，这就不叫"可定位"。**

**4. 顺带一条：`connected` 只看有没有数据，不看数据新不新。**
`unified_runtime.py:940`：`"status": "connected" if last_15m else "waiting_for_data"`。只要库里能查到一根 15m 线，哪怕它是三天前的，也报"已连接"。判断"新鲜度"的逻辑不存在。

## ② 常驻模拟自动闭环 —— 未验证（自然市场无成交，单独标注）

这一项必须分清两件事：**"没有成交"和"链路断了"是两回事**。工单明确要求单独标注，不伪造、不混为工程失败。

### 我的独立判定方法

不信任运行时自报，我用**同一个状态机**（`EventStateMachine`，`enable_oi_filter=False`，与 `main()` 的默认构造一致）、**同一个预热窗口**（`(200×4+336+24)` 小时 = 1160 小时）、**同一个推进顺序**（4h 与 1h 按收盘时刻合并，4h 先），对全池 526 个标的重放一遍。

### 结果：无信号是自然结果，不是断链

| 指标 | 运行时自报 | 我独立复算 | 是否一致 |
|---|---|---|---|
| 箱体中 BOX | 363 | **363** | ✅ |
| 空闲 IDLE | 147 | **147** | ✅ |
| 扫低中 SWEEP | 4 | **4** | ✅ |
| 回踩中 RETEST | 12 | **12** | ✅ |
| 预热期历史候选 | 4（`history_candidates_discarded`） | **4** | ✅ |
| 最近 4 小时新候选 | 0 | **0** | ✅ |

（复算：`out/q03_signal_replay.json`，全池 526 标的、耗时 12.7 秒、跳过 0 个。这个一致性在两个运行时实例上各验过一次：18:24 起的 50390 与 21:59 起的 73353，状态分布完全相同，说明复算忠实、结论稳健。）

**读法**：状态机在正常推进（363 个箱体、4 个扫低、12 个回踩都在队列里），最近 4 小时没有任何一个标的走到"突破确认"这一步。所以**没有信号是策略条件没满足，不是下游把信号吞了**。

### 但"闭环"仍然不能算通过

- 账本里**有效**已实现记录 = **0 条**（3 条全部 `voided=1`，`void_reason=synthetic_test_isolation`）；
- 常驻运行时 50390 从 18:24 活到 21:5x（约 3.5 小时、3800+ 轮），账本**零写入**；现行 73353 从 21:59:54 起 21 轮，同样零写入；
- 因此"信号 → 挂单 → 成交 → 账本"这条端到端链路**没有任何自然样本**。按纪律：**未验证不计入通过**。

### 顺带发现：常驻进程没有可用日志

`框架/backend/logs/runtime-3a-8787.log` 只有 129 字节、三行 `[*] Stopping UnifiedRuntime gracefully...`，时间停在 18:23。
原因在代码里：`run_forever` 只在"有事发生"时才 `print`（`unified_runtime.py:1142-1143`），而 `logger.info` 的启动两行（1131、1136）没有配 handler，被直接丢弃。
后果：**无法用日志证明进程在跑、也无法用日志定位"为什么没信号"**，只能靠状态文件——而状态文件可以被伪造（见①第 3 条）。

## ③ 页面同源显示 —— 不通过

### 同一时刻，三个账

| 口径 | 权益/现金 | 已实现盈亏 | 手续费 | 已平笔数 |
|---|---|---|---|---|
| 页面（22:01 浏览器实测） | **5,000.00** | **0.00** | **0.00** | **3 笔** |
| 接口汇总（22:00:19 实测） | **5,000.00** | **0.00** | **0.00** | **3** |
| 账本 `paper_state` 表 | **4,995.65** | **−4.3455** | **1.4744** | — |

（复算：`out/q04_accounting_consistency.json`，差值字段 `api_cash_minus_state_cash = 4.34545527`。）

根因在 `paper_engine.py` 里同时存在两套算法：

- `account_view()`（434–462 行）默认口径是**重算式**：`现金 = 初始权益 + Σ(net_pnl WHERE voided=0)`。3 笔都作废 ⇒ 回到 5,000.00；
- `paper_state` 表是**累计式**：测试亏损当时就扣了，事后没回滚 ⇒ 4,995.65。

两套算法都"有道理"，但**同一个系统里并存、且没有一处声明哪个是准的**，就必然对不上。

### 更严重：作废的测试记录被当成"已平仓"展示

- 接口 `realized_history` 的查询（`paper_engine.py:1946`）是 `SELECT * FROM paper_realized WHERE account_id=? ORDER BY ts DESC`——**没有 `voided` 过滤**；
- `n_closed`（1955 行）同样没有过滤；
- 结果：页面显示"0 仓在持 / **3 笔已平**"，而账本里这 3 笔的 `void_reason` 明写 `synthetic_test_isolation`、`origin=manual`、信号号是 `sig_closeloop_btc_*` / `sig_ui_test_*`。
- 对比：`open_positions()`（465–475 行）**是**过滤 `voided=0` 的。同一模块里，持仓过滤、明细不过滤，口径不统一。

### 闸门状态自相矛盾，页面显示"无阻断"

接口原文：`allow_new_entries: true`，但同一对象里 `gate_reason: "new_entry_blocked_pending_closure_review"`、`reason: "user_ui_resumed"`。
页面据此显示「阻断原因: **无阻断 · 正常流转**」。
也就是说：闸门字段一半说"允许"，一半说"因待收尾复核被阻止"，页面取了自己想取的那一半。用户看到"正常"，看不到"曾经被拦过、拦的原因还挂在那"。

### 页面读到的实例，在审核期间被换掉了

22:01 页面显示「守护 PID: **73353**、推进周期 11 次」；我 21:49 实测的运行时是 **50390**，22:04 复查时 50390 **已死**（`NoSuchProcess`），73353 于 21:59:54 启动。
页面没骗人（它读的是新实例），但这说明：**"页面显示正常"这句话的有效期只有几分钟**，任何基于页面的验收结论都必须绑定到具体时刻和具体 PID。

### 初始权益与冻结参数不一致

接口与页面都用 **5,000**（`paper_engine.py:182` 的 `initial_equity_USDT: 5000.0`，参数视图名里也写着 `user5000`），而回测冻结参数是 **2,000**。
差 3,000（`initial_equity_vs_frozen_2000 = 3000.0`）。按 0.5%/笔的风险预算算，单笔名义规模会差 2.5 倍。**R 值口径尺度无关、不受影响**，但"模拟盘每笔下多大"与"回测每笔下多大"不可直接对比。

## ④ 逐笔对账 —— 部分成立（数学对，样本无效）

### 数学部分：成立，且精度很好

对账本 3 笔逐笔复算（`out/q02_ledger.json`）：

- **权益守恒**：每条 `equity = cash + unrealized`，最大偏差 **3.9e-09**（浮点噪声级）；
- **净盈亏**：`gross − entry_fee − exit_fee − funding` 与账本 `net_pnl` 差值 **0.0**（三笔全中）；
- **手续费**：`notional × 5bps` 与账本 `fee` 差值 **0.0**；
- **汇总对齐**：`Σnet_pnl = −4.34545527` 与 `paper_state.realized_pnl = −4.3454552739` 差值 **0.0**；`Σfee = 1.47440307` 与 `fees_paid` 差值 **0.0**；
- **现金链**：`state.cash − 最后一条 equity.cash = 0.0`。

### 样本部分：无效

3 笔的原始字段一致指向"人工合成测试"：

| 持仓 | 信号号 | 来源 | 作废 | 平仓原因 |
|---|---|---|---|---|
| 1 | `sig_closeloop_btc_1792668586` | manual | 是 | `manual_closeloop_test` |
| 2 | `sig_closeloop_btc_1792668605` | manual | 是 | `manual_closeloop_test` |
| 3 | `sig_ui_test_1792668684487` | manual | 是 | `ui_closeloop_verification` |

- 有效（`voided=0`）已实现记录：**0 条**；
- 3 笔全部在 **2026-10-22 19:29–19:31** 三分钟内完成，价格全部是 BTCUSDT 81,970 / 81,803 附近，明显是同一段人造数据；
- `paper_processed` 里这三条已被永久拉黑，说明它们确实走完了"运行时正常记账流程"。

**所以"逐笔对账"这一项：算法对、口径对、精度对，但没有一笔是策略自己产生的。作为"能力验证"可以算成立，作为"成绩"不能算数。**
