## 二、系统侧缺陷（已独立复现，7 条）

### D-1｜账本规范名被当成策略版本上报

- **文件/函数**：`框架/backend/live_store.py:59` 常量 `PAPER_LEDGER_SPEC = "F_WX_v2.2_project_closure_user_5000_shared"`，被接口用作 `strategy_version` 与 `rule_version`。
- **现象**：`/api/v1/paper/accounts` 返回 `strategy_version=F_WX_v2.2_project_closure_user_5000_shared`，而实际运行策略是 `策略/WyckoffMaster/event_trend_v0_1`（`unified_runtime.py:44-47`）。同时 `account_id`、`run_id`、`data_version` 均为 `null`。
- **复现**：

```
curl --noproxy '*' -s "http://127.0.0.1:8787/api/v1/paper/accounts" \
  | python3 -c "import json,sys;d=json.load(sys.stdin);print({k:d[k] for k in ('mode','account_id','run_id','strategy_version','rule_version','param_hash','data_version')})"
# 期望能定位到一次具体运行；实际 run_id/account_id/data_version 为 None
```

- **责任窗口**：数据路径交付窗口（接口契约层）。

### D-2｜作废的测试记录进入明细与计数

- **文件/函数**：`框架/backend/paper_engine.py:1946`（`realized_history` 查询）、`:1955`（`n_closed` 计数）——两条 SQL 都缺 `AND COALESCE(voided,0)=0`。
- **对照**：同文件 `:465-475` 的 `open_positions()` **有**该过滤。同模块内口径不统一。
- **现象**：接口返回 `n_closed=3`、`realized_history` 3 条，全部 `voided=1`、`void_reason=synthetic_test_isolation`；页面显示「0 仓在持 / 3 笔已平」。
- **复现**：见 `queries/q04_accounting_consistency.py`，输出 `api.realized_history_voided_len = 3`、`api.n_closed = 3`、`ledger_realized_live_rows = 0`。
- **责任窗口**：画布（页面数据源）交付窗口 + 账本交付窗口共同确认。

### D-3｜两套账户口径并存（重算式 vs 累计式）

- **文件/函数**：`框架/backend/paper_engine.py:434-462` `account_view()`（重算：初始权益 + Σ voided=0 净盈亏）与 `paper_state` 表（累计：测试亏损未回滚）。
- **现象**：接口现金 `5000.0`，账本 `paper_state.cash = 4995.6545`，差 `4.34545527`；已实现盈亏接口 `0.0`、账本 `−4.3454552739`；手续费接口 `0.0`、账本 `1.4744030739`。
- **复现**：`queries/q04_accounting_consistency.py` → `diffs.api_cash_minus_state_cash`。
- **责任窗口**：账本交付窗口（必须书面声明唯一口径，并让另一处服从）。

### D-4｜`market_data.status` 只看有没有数据，不看新不新

- **文件/函数**：`框架/backend/unified_runtime.py:939-945`，`"status": "connected" if last_15m else "waiting_for_data"`。
- **后果**：即便最新 15m 线停在三天前，也报「已连接」；「上游正常、下游断开」无法与「上游正常、暂无信号」区分。
- **复现**：读 `out/q07_api_runtime_status.json` 的 `item.market_data`，字段里只有 `latest_15m_close_time`，**没有任何 lag/stale 字段**；再读源码 939-945 行确认判定条件。
- **责任窗口**：数据路径交付窗口。

### D-5｜`overall_health` 不看产出

- **文件/函数**：`框架/backend/unified_runtime.py:916-924`，只要进程活着且 `last_error` 为空即 `healthy`，**不检查** `signals_generated_total`、`orders_routed_total`、账本最后写入时间。
- **后果**：本次实测 `signals_generated_total=0`、`orders_routed_total=0`、账本 26 小时未写入，状态仍为 `healthy`；接口信封 `quality.status` 也写死 `healthy`（`note: unified_runtime_status`）。
- **复现**：`out/q07_api_runtime_status.json` 中 `runtime_identity.overall_health = "healthy"` 与 `signal_engine.signals_generated_total = 0` 同时成立。
- **责任窗口**：自动闭环交付窗口。

### D-6｜闸门字段自相矛盾，页面取一半

- **文件/函数**：`框架/backend/paper_engine.py:147` `new_entry_gate()` 返回值里 `allow_new_entries: true` 与 `gate_reason: "new_entry_blocked_pending_closure_review"` 并存（`gate_reason` 保留了上一次被拦的原因，未随放行清空）。
- **现象**：接口 `allow_new_entries=true` + `gate_reason=new_entry_blocked_pending_closure_review`；页面显示「阻断原因: 无阻断 · 正常流转」。
- **复现**：

```
curl --noproxy '*' -s "http://127.0.0.1:8787/api/v1/paper/status?arm=3a" \
  | python3 -c "import json,sys;d=json.load(sys.stdin)['item']['order_processing'];print(d['status'],d['new_entry_gate']['allow_new_entries'],d['new_entry_gate']['gate_reason'])"
# 期望：ready True new_entry_blocked_pending_closure_review  ← 三者互相矛盾
```

- **责任窗口**：自动闭环交付窗口（闸门）+ 画布交付窗口（展示取舍）。

### D-7｜存在一个可被误读的假状态文件

- **文件**：`框架/backend/locks/unified_runtime_status_3a.json`（11:18 落盘，610 字节）
- **内容**：`pid: 98765`、`cycle_count: 42`、`updated_at: 2026-10-23T03:00:00Z`、`last_signal_time: 2026-10-23T02:00:00Z`、`overall_health: "ok"`、`symbol: "BTCUSDT"`。
- **性质**：整点时间 + 固定 42 次 + 进程号 98765，是手写桩；与真实运行时写的 `paper_runtime_3a_status.json`（PID 73353、21 次）并存。
- **风险**：任何读这个文件的接口/脚本都会显示「健康、跑着、42 次」，而系统无任何校验（无 PID 存活校验、无 `updated_at` 新鲜度校验）。
- **复现**：

```
cat 框架/backend/locks/unified_runtime_status_3a.json
python3 -c "import psutil;psutil.Process(98765)"   # NoSuchProcess
```

- **责任窗口**：自动闭环交付窗口（要么删除该文件，要么给它加「桩」标记并在读取侧拒用）。
