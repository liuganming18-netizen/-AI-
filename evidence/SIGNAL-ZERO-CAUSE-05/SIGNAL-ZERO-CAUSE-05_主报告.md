## 一、四个必答问题（先给结论）

### 1. 当前零信号的具体原因是什么？

**不是「策略没机会」，是实时实现比回测多了一道规范里没有的门槛，把有效事件窗口从 41.3 天压到 15 天。**

规范第 17 行只要求「ATR 至少预热 200 根完整 4h K 线」；第 32 行的建档条件只有「最近 42 根 + 宽度 2~8A + ER≤0.30 + 数据连续 + ATR 有效」，**没有任何「窗口内再等 200 根」**。回测 `runner.py:349-363` 也是「够 42 根就建档」。

实时实现 `unified_runtime.py:493`（修复前）却写成 `box_gate_bars < atr_warmup_bars` 就不建档，而 `box_gate_bars` 数的是「声明回放窗口内处理过的 4h 根数」——它的锚点是**回放窗口起点**，不是 ATR 的预热进度。

后果可以算出来：

| 项 | 数值 |
|---|---|
| 声明回放窗口 | 1,160 h（≈290 根 4h） |
| 修复前：窗口内要再等 200 根 4h 才建档 | 有效事件窗口 = **90 根 = 360 h = 15.0 天**（实测窗口 289 根 ⇒ 89 根 = 14.8 天） |
| 规范口径：ATR 已预热，够 42 根上下文即可建档 | 有效事件窗口 = **248 根 = 992 h = 41.3 天** |
| 被这道门槛吃掉 | **158 根 = 632 h = 26.3 天** |
| 一条完整事件链最长耗时（箱体 168h + 扫低 168h + 回踩 72h + 突破 168h） | **576 h = 24.0 天** |

⇒ **15 天的窗口装不下 24 天的最长事件链，数学上就不可能走完。** 这不是「刚好没机会」，是结构上被截断。

同一份行情、同一截止时刻、同一套参数、同一个窗口起点，只改这道闸门（`04_gate_isolated_ab.py`）：

⇒ 候选丢失的主因是闸门（只改闸门就恢复 17 个），跨窗口上下文只改变候选身份、不改变数量。

## 二、规范原文 ↔ 代码位置 ↔ 行为证据（工单第 1 条）

三条相关条款（原文照录，`01_规范与实现对照.json` 里带行号与文件 SHA）：

- **第 17 行**：「ATR：4h Wilder ATR(14)……**至少预热 200 根完整 4h K 线**。」
- **第 32 行**：「**每个 4h 收盘检查最近 42 根 bar**：同时满足 2 <= (H-L)/A <= 8、ER <= 0.30 时建档。数据必须连续，ATR 有效。」
- **第 106 行**：「每段允许读取之前 200 根 4h 数据预热特征，但不携带前段事件、持仓或结果标签。」

对应实现：

| 位置 | 行为 | 与规范的关系 |
|---|---|---|
| `unified_runtime.py:503-504`（修复前 480-481） | `atr_bars_seen` 与 `box_gate_bars` 同时 +1 | `atr_bars_seen` 对应第 17 行；`box_gate_bars` 是**自造的第二个计数器** |
| `unified_runtime.py:493`（修复前） | `if box_gate_bars < atr_warmup_bars: 不建档` | **规范里没有这一条** |
| `unified_runtime.py:488` | `if i+1 >= n:` 才建档 | 对应第 32 行「最近 42 根」，但 `i` 是**窗口内**下标 ⇒ 窗口前 41 根永远不检查 |
| `runner.py:298-300` | `warmup_start_idx = idx_start_4h - 220` | 回测取区间前 220 根 4h 做上下文 ⇒ **窗口第一根就能建档** |
| `runner.py:349-363` | `if len(sub_4h) >= 42: sm.check_and_form_box(...)` | 回测**没有** 200 根闸门 |

**结论（三条判定，全部 holds）**：
1. 规范第 17 行只约束 ATR 预热，未要求「建档前窗口内再累积 200 根」；
2. 实时实现把 `atr_warmup_bars` 复用成建档闸门，且计数锚在窗口起点；
3. 回测没有这个闸门 ⇒ **实时与回测不同源，回测结论不能直接搬到实时**。

**为什么当初会这样写**：`SIGNAL-HISTORY-FIX-03` 发现「改用 `atr_bars_seen` 会让 `ZEREBROUSDT` 的历史候选消失」，于是以「不改箱体窗口与 ATR 规范」为由保留了旧闸门，把问题留给裁决。本轮按工单「不能以保留旧实现为由把实现行为当成冻结规则」作出裁决：**旧闸门是实现偏差，规范只要求 ATR 预热一次。**

抽样按阶段分层（BOX / RETEST / SWEEP / IDLE 各 2 个，固定随机种子 20261025）：`PLUMEUSDT`、`MUSDT`、`FIDAUSDT`、`DYDXUSDT`、`YBUSDT`、`SCRUSDT`、`AXLUSDT`、`OPUSDT`。

复算方法（全部只用 K 线，不读引擎状态）：

- 箱体上下沿 `H`/`L` = 建档那根 4h 及其往前共 42 根的最高价 / 最低价；
- `ATR` = 从装载到的最早一根起，按 Wilder 递推一路推到那一根；
- 宽度 = `(H-L)/ATR`；`ER` = 42 根收盘的方向效率比。

结果：**44 项比对全部命中，0 项没比到，0 项不符**（`11_回溯抽样.json`）。

| 比对内容 | 覆盖 | 结果 |
|---|---|---|
| 建档那根的箱体宽度、ER | 6 个有箱体的币 × 2 项 | 全中（如 `PLUMEUSDT` 7.5331、`MUSDT` 7.7556、`YBUSDT` 7.9635） |
| 引擎最后一次 4h 评估的宽度、ER、ATR、ATR 已喂根数 | 8 个币 × 4 项 | 全中（`atr_bars_seen` 1,079 逐币一致） |

两个 IDLE 币（`AXLUSDT`、`OPUSDT`）没有箱体，只比末根 4h，同样命中。

**这里踩到一个必须写下来的坑**：第一版脚本用「当前时刻」当截止，而 02 跑在更早的时刻，中间又闭合了一根 4h ⇒ 取样段整体后移一根，8 个样本的宽度和 ER 全对不上，看起来像「复算失败」。真相是**判据的端点漂移了**，不是数据错。现已改成锚定 `02_汇总.json#upto_utc`（`2026-10-25T02:59:59Z`），并加了空转守卫：`None` 一律算「没比到」，`n_comparisons>0 且 0 未比到 且 0 不符` 才算通过 —— 因为第一版在全部 `None` 的情况下也打印了 `all_match=True`，这是典型的假通过。
