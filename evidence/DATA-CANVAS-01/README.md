# DATA-CANVAS-01 数据层可视化接线

**一句话：画布能指出数据停在哪一段、为什么停，并且四种故障各自指向不同的段。**

打开 `UI界面/web/public/system-flow.html`，首屏从上到下就四块：全局判定条 → 七段流水线芯片 → 三池分母 → 七个节点卡片。哪一段出问题，芯片上直接打「断点」并变红，往下滚就能看到该段的阻塞原因和逐条校验。

所有数字以 `REPORT.md` 为准 —— 那份文件由 `queries/make_report.py` 从产物现算生成，不手抄；本文件只讲怎么读、怎么复现、还缺什么。

---

## 一、四态验收结果

隔离环境里分别造了四种状态，每态一张全页截图、一份 DOM 事实、一份接口请求日志，三者同一次运行。

| 状态 | 全局判定 | 断点落在 | 页面给出的原因 |
|---|---|---|---|
| 正常 | 等待条件（黄） | 第 5 段 信号引擎 | 扫描正常但未触发：526 标的全量在扫、周期新鲜、水位不滞后，当前 0 条可执行信号（策略极窄，不是故障） |
| 停止采集 | 故障（红） | 第 2 段 实时采集 | 采集进程未运行或心跳过期；下游 15m 水位滞后 3.0 小时 |
| 缺数据 | 故障（红） | 第 4 段 数据质量 | 15m 滞后 4.0 小时；监控池只就绪 226/526 标的，缺 300 个（第 2 段仍是绿的 —— 采集在跑，是数据缺） |
| 接口失败 | 故障（红） | 第 6 段 模拟账本 | 接口 500；「当前正常结论已清除」，保留最后成功时间并标注过期 |

四种状态给出了**四个不同的断点**，这是验收的核心：如果画布只会「一起变红」，就说明它没在定位。

注意「正常」这一态**不是全绿**：42 条校验里 40 条通过、2 条不通过，两条都卡在接口缺字段上（见第三节 C-01、C-03）。按纪律，缺字段就判「未验证」，不拿别处的数字顶上去凑绿。

## 二、工单要求逐条对应

**1）HTTP 200／文件存在／进程存活不能单独判绿。**
每段的第一条校验确实是「接口 200 且返回 JSON」，但它只是入场券。真正决定颜色的是事实校验：心跳年龄、WS 消息年龄、水位对齐、覆盖缺口、扫描周期年龄。200 过了而事实不成立，该段照样红。

**2）0 信号必须四分类。**
按顺序判：信号接口没返回总数 → 接口失败；运行时不在跑 → 扫描未运行；周期超过 600 秒没动 → 扫描未运行（停滞）；监控池标的数少于声明值、或引擎读到的 15m 水位滞后超过 2 根 → 数据不足；有信号 → 通过；其余 → 扫描正常但未触发。
「正常」态走的正是最后一类，页面写明「不是故障」；「停止采集」和「缺数据」两态走的都是「数据不足」，但原因分别指向第 2 段和第 4 段。

**3）OKX 不支持原生 8h 记「不适用」。**
以导入计划里的 `native_skip` 和实际有没有这一路流为准，记灰色「不适用」，既不报故障，也不写成已补齐。第 4 段的校验项里单独有一条在盯这件事。

**4）三池分母分开写。**
下载池 814（全合约目录，不排除任何东西，股票/商品/外汇/指数都在里面）、展示池 549（工作台列表口径）、策略监控池 526（信号引擎实际在扫的）。三个数各自标了来源字段和排除规则，页面上并排显示，不混用。

**5）同源；读取失败清除「当前正常」。**
页面只用相对路径 `/api/v1/*`，经同源代理转发，不跨域、不直连交易所、不读本地文件。任一必需接口失败，该段强制红，标题写「当前正常结论已清除」，并把最后一次成功时间留在页面上、标明已过期 —— 不沿用上一次的「正常」。

**6）节点跳转 + 展开区。**
点顶部芯片直接滚到对应节点；每节点右侧「技术详情」折叠区放接口路径、响应字节数、逐条校验结果；首屏只留判断需要的东西。原来那 20 张接口卡片收进最底部的折叠区，而且**只有展开时才去探测**，避免首屏去拉行情和覆盖度那种大响应。

**7）截图、响应、时间、版本绑定同一次运行。**
页面把构建号写进页面（截图里可见）；Playwright 记页面加载、抓 DOM、落盘三个时刻；同源代理独立记一份请求日志。报告里逐条比过「页面收到的响应」与「代理记录的请求」的路径、状态、字节数 —— 四态全部对上，不是两次运行拼的。

## 三、接口缺口（要对方补，不补就只能一直显示「未验证」）

| 编号 | 缺什么 | 现在怎么处理 |
|---|---|---|
| C-01 | `/api/v1/data/pool-scope` 不返回快照时点 | 第 1 段固定「未验证」，页面上写明缺口编号，不伪绿 |
| C-03 | 没有「冷库全量覆盖」接口 | 第 3 段热库侧正常判，冷库侧记「未验证」，不拿热库数字冒充冷库 |
| C-05 | 账本接口不返回最近写入时点 | 第 6 段只给「本次读取成功时刻」，不当成「写入成功」 |

另外三个是查证过程中撞到的接口缺陷，不影响主链判定，但已在展开区标注：动态止损接口传非法参数返回 500 而不是 4xx；交易所名大小写不敏感、写错了也返回 200（静默回落，容易误判）；行情接口的 `limit` 参数不生效。

## 四、怎么复现

```bash
cd evidence/DATA-CANVAS-01
python queries/fault_proxy.py --port 8912   # 同源代理：页面 + 接口同一 origin，带请求日志和故障注入
bash queries/run_all_states.sh              # 四态一次跑完
python queries/make_report.py               # 重算报告与哈希清单
```

四态怎么造：正常态把心跳钉到 3 秒前、各周期水位推到当前应闭合的那根；停止采集态把心跳回拨 3 小时且不再推进；缺数据态删掉 300 个标的的 15m 覆盖、15m 水位回拨 4 小时，但心跳照常推进（这样才证明「采集在跑、数据缺」）；接口失败态数据侧全部正常，截完第一张后由代理把账本接口注入 500，再点刷新重截。

隔离纪律：后端以 `ISOLATED_MODE=1` 启动，行情库、账本、锁目录等全部显式指向 `/tmp/dc01/<态>/`，少一项就拒绝启动；端口启动前查占用、启动后校验监听进程号与本次启动的一致，不一致直接中止，防止连到上一轮的旧实例。

## 五、证据怎么读

| 文件 | 内容 |
|---|---|
| `REPORT.md` | 机械生成的完整报告：运行绑定表、四态对照、逐态七段明细、不通过的校验项、三池分母、哈希清单 |
| `screenshots/state_*.png` | 四态全页截图 |
| `out/state_*.json` | 页面 DOM 事实（判定条、七段状态、每段事实与校验、阻塞原因）+ 页面侧响应列表 + 三个时刻 |
| `out/req_*.jsonl` | 同源代理侧请求日志（每态独立清空，不跨轮混写） |
| `out/build_*.json` / `out/tick_*.json` | 隔离库怎么造的、水位推到哪 |
| `out/run_all.log` | 四态驱动全过程（端口、进程号、健康检查） |
| `out/manifest.json` | 全部产物与页面文件的 SHA-256 |
| `queries/` | 代理、截图、造库、推时间、驱动、报告六个脚本，可重跑 |
| `out/_prelim/` | 早期迭代的中间产物，**不属于四态证据**，单独存放避免与定版产物混淆 |

## 六、边界（不夸大）

- 四态是在**隔离库里用夹具造的**，不是真实交易所断流。隔离库的表结构与判定所需的数据行从生产库只读抄来，时间字段由夹具改写。这符合工单「隔离环境分别制造」的要求，但不能当成「真实断流已演练」。
- 第 1 段永远显示「未验证」，因为接口确实缺字段（C-01）。要它变绿，得先补接口，不是改页面。
- 本次只动前端页面与取证脚本，**后端一行未改**，也没有在生产实例上做故障注入。生产实例只做过一次只读实拍，因页面版本已变，未纳入四态证据。
- 画布判的是「数据通不通、停在哪」，不判策略好坏。信号引擎那一段在正常态显示「等待条件」，意思是「扫描正常但没触发」，不是「已验证可用」—— 这两件事页面分开写。
