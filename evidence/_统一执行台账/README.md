# 统一执行台账

- 建立日期：2026-10-20
- 用途：跨工单索引，避免重复核查；记录待决策、循环问题、已排除项。
- 性质：**基础设施**。只读各工单目录，不修改任何对方文件；本目录只新增自己的文件。
- 目录：`evidence/_统一执行台账/`

---

## 一、这个台账解决什么问题

今晚的规则要求"建立已通过清单，不重复核查"。106 个工单目录、几百份报告，如果不建索引，每个新窗口都要重读一遍，既慢又容易漏。

台账做三件事：

1. **索引**：每个工单目录一行，摘录报告原文里的状态声明，附来源文件。要查某个工单，先看这里，再决定要不要读全文。
2. **待决策**：把所有"需要用户拍板"的项集中在一处，标明阻塞了哪些后续工作。
3. **循环问题**：记录已经排除、不得重开的问题，以及重复问题的轮次。

## 二、口径（重要，别误用）

### 2.1 "是否可跳过复核"只有"是"才代表可跳过

- **是**：报告原文明确写了"独立验收通过/复核结论：通过"，且全文无待验收、无失败字样。
- **否**：其余全部情况，包括"仅自检通过""含通过字样但未写明独立验收""待独立验收""存在失败/退回项""未明确""无报告文件"。

**默认一律"否"。** 理由是规则自己写的："自检通过不等于 Codex 独立验收"。错判成"可跳过"的代价（漏掉未验收的缺陷）远大于多读一遍。

当前只有 1 个目录标"是"：`Work_交易台OI全历史_2026-10-17`（OI 历史接口，与策略验证无关）。

### 2.2 "状态分类"是机器初筛，不是结论

`out/01_状态摘录.csv` 的分类由关键词匹配得出，只用于快速定位，**不作为任何验收依据**。已抽查 7 个工单，分类标签有噪音（例如 `VOLUME-BE-02` 被归到"存在失败/退回项"，实际是"待 Codex 定向复验"），但**都指向"不可跳过"**，方向是安全的。

### 2.3 摘录不代替原文

摘录只取报告前 80 行的前 3 条状态行，可能漏掉正文里的关键限定。任何要用于决策的判断，必须回到原文核对。
