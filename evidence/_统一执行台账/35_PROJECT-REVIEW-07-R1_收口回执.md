## 本单新查出的 5 件事（比上一单的 12 条更该先修）

1. **144 组 FT-LOW4H 网格实验在页面上全部打不开**。它们的 `run.json` 写 `status=COMPLETED`，而读侧只认 `succeeded`，于是判成「运行未成功：None」。全库状态词表：`succeeded` 3,463 / `COMPLETED` 144 / `interrupted` 22 / `failed` 5 / `queued` 2。**当前策略最重要的那批实验，恰好是打不开的那批**——改一个状态白名单就能全解锁（T-06）。
2. **49 个 run 有成交账本却没有 `run.json`**，四个接口都返回 HTTP 200 + 空数据 + 「运行未成功：None」。样本 `run_WX_EVENT_TREND_V0_1_WALUSDT_1792826394`：17 个文件、1 笔 `intrabar_stop`、净 −25.75，页面完全打不开（T-07）。
3. **1,065 个 run 目录是软链接**（`runs_ft_replay_01/*` → `runs/*`）。按目录名数会得到 5,091，**物理 run 只有 4,026**；成交按路径 37,404、物理 33,079。**本单第一版也踩了这个坑**，已在 `05` §7 留档（T-08）。
4. **`candles_source` 这个字段不能当证据**。它是默认填充文案，抽 40 个「盘上有 K 线」的 run，**35 个数据明明来自盘上却被贴「读时取、未写回」**（87.5% 误标）。判「K 线有没有留存」只能看盘上 `candles` 是否为空：有 **1,692**、没有 **2,188**（T-03）。
5. **模拟盘平仓的成交挂不上订单**。`paper_fill` 6 行里 3 笔 `close` 的 `order_id` 全是 `NULL`；且开仓 `fill_ts` 是 K 线整点、平仓是挂钟毫秒，同表两种时间口径。用户第 4 项「逐笔订单↔逐次成交对账」在平仓侧断链（F-02）。
