## 三、程序复核与拒单防线（格式合规 $\ne$ 允许成交）

即便模型生成的 JSON 报文通过了上述 Schema 验证，程序在进入实际挂单推进（`paper_engine.py`）前，必须依次重新执行以下 5 项硬性校验：

1. **时效性与数据新鲜度校验（Timeliness Check）**：
   - 检查 `now_ms <= valid_until_ms`。若当前服务器时钟已超过有效截止时间（滞后超过 15 分钟），立即拒单：`decision_expired`。
   - 检查决策所依赖的 `kline_close_time_ms` 与当时最新的已闭合 K 线时间戳是否完全匹配，防止沿用陈旧历史决策：`stale_data_reference`。
2. **幂等性与重复指令防御（Idempotency Guard）**：
   - 使用 `decision_id` 查询 `paper_ai_decision_log` 账本。若该 ID 已被处理过，直接抛出 `duplicate_decision_id` 并忽略。
   - 查询当前标的是否已存在处于 `pending` 状态的挂单或已有开立持仓，杜绝同一信号瞬间并发打入多次：`duplicate_symbol_order_in_flight`。
3. **账户状态与熔断检查（Account State Check）**：
   - 查询账户当前权益，若账户回撤已达 20%，立刻拒单：`account_drawdown_locked_for_run`。
   - 若账户可用持仓席位已满（$\ge 10$），立刻拒单：`max_positions_reached`。
4. **策略指纹与参数未被篡改校验（Contract Fingerprint Check）**：
   - 重新核算系统加载的策略配置 SHA-256。若 `config_fingerprint` 与本地只读文件指纹不一致，立即报警并拒单：`config_fingerprint_mismatch`。
5. **数量与价格精度重新计算（Deterministic Execution Sizing）**：
   - **完全抛弃模型报文中的任何价格和仓位幻想**；
   - 由 `paper_engine` 重新读取币安交易所该标的的最新步长规范（`contract_limits`）和第一根合法开盘价；
   - 严格按照冻结公式：$\text{数量} = \min(\text{单笔风险预算} / \text{实际止损距离}, \text{资金敞口上限})$ 并对步长向下取整（`apply_order_rounding`）。
