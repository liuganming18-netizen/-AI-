# 02 成熟复用方案比较与选型建议

> **工单编号**：AI-DYNAMIC-DESIGN-01  
> **设计目标**：比较业界成熟的人工智能自主决策/智能体框架，结合量化交易高确定性、低时延、数据隐私与因果隔离要求，给出可复用架构及模型选型。

---

## 一、业界人工智能决策框架对比与复用评估

在金融决策与多智能体系统领域，目前主流的成熟方案主要有四类：

| 方案分类 | 代表实现 / 开源框架 | 核心机制 | 优势 | 针对本项目的致命缺陷 / 风险 | 适配结论 |
|---|---|---|---|---|:---:|
| **A. 纯自主智能体 (Autonomous Agents)** | AutoGPT, MetaGPT, CrewAI | 自由推理循环、自我拆解任务、自主调用任意工具或编写代码执行 | 灵活性极高，能探索未定义空间 | 幻觉率高、非确定性、可能私自修改执行代码或绕过风控、无法保证因果时钟（PIT）防御 | **坚决淘汰** |
| **B. 端到端预测模型 (End-to-End FinLLM)** | FinGPT, BloombergGPT | 模型直接输出买卖方向与目标仓位价格 | 能捕捉复杂多模态弱特征 | “黑箱”无法解释、计算价格与数量时精度漂移、严重缺乏确定性数学保障、不可审计 | **坚决淘汰** |
| **C. 状态图受控智能体 (Constrained State-Graph)** | LangGraph, Semantic Kernel | 基于预定义的状态转移有向无环图（DAG），每个节点限定输入输出类型，状态跃迁由图护栏控制 | 具备结构化状态持久化、支持人工干预审批（Human-in-the-loop）、节点边界清晰 | 若引入过多复杂依赖会导致系统过度工程化，需严格限制其只在“状态决策”节点运行 | **可部分复用其思想** |
| **D. 规则底座 + 结构化裁决智能体 (Rule-Engine + Arbiter LLM)** | 现代量化中台标准架构（本项目推荐） | **确定性程序全权负责计算与执行，AI 仅在“策略选择”与“模拟开仓准入”阶段输出结构化裁决 JSON** | 职责彻底解耦、零代码污染、程序做最终硬风控核验、完全因果隔离、百分之百可复验 | 模型推理存在几十毫秒到几秒时延，仅适用于 15m/1h/4h 等低中频决策（与本项目契合） | **首选推荐 (★★★★★)** |

## 二、候选模型深度对比：私有化本地模型 vs 商业云端 API

根据工单红线：*“未经批准不安装付费服务、不外发项目数据”*。我们在选型中必须提供**零数据外发、零额外成本的本地私有化方案**作为第一基准，并与商业云端模型进行定量对比：

| 评价维度 | 方案一：本地私有化部署 (基准方案)<br>**Qwen2.5-14B-Instruct / 7B** (Ollama/vLLM) | 方案二：本地轻量量化模型<br>**DeepSeek-R1-Distill-Qwen-8B** | 方案三：商业云端模型 (待裁决)<br>**Gemini 1.5 Flash / Pro** | 方案四：商业云端模型 (待裁决)<br>**Claude 3.5 Sonnet** |
|---|---|---|---|---|
| **数据外发范围** | **零外发 (100% 本地内存/磁盘)** | **零外发 (100% 本地内存/磁盘)** | 需将行情切片与状态数据发送至 Google 云端 | 需将行情切片与状态数据发送至 Anthropic 云端 |
| **API 订阅/调用成本** | **0 元** (利用本地 Mac/M系列芯片推理) | **0 元** (利用本地硬件推理) | 极低（Flash 约 $0.075/1M token）需绑定付费信用卡 | 中等（输入 $3 / 输出 $15 / 1M token）需商业付费 |
| **单次结构化决策时延** | 约 **800ms ~ 2.5s** (在 Apple Silicon 上) | 约 **1.2s ~ 3.5s** (含思考链推导) | 约 **500ms ~ 1.5s** (受限于外网网络延迟) | 约 **1.5s ~ 3.0s** (受外网网络延迟限制) |
| **JSON 强约束依从性** | **极高** (支持本地 GBNF 语法强制拘束) | 高 (需提示词强约束，有时思考链过长) | 极高 (支持原生 `response_schema` 严格拘束) | 极高 (支持 Tool Use / 结构化输出) |
| **离线确定性复查能力** | **完全确定** (固定 seed, temp=0，模型哈希锁定) | **完全确定** (固定 seed, temp=0，权重哈希锁定) | 差 (云端模型频繁后端静默热更新，历史不可复现) | 差 (云端版本更新后历史不可复查) |
| **是否需工单审批** | **当前即可离线试运行** | **当前即可离线试运行** | **需用户明确授权外发与付费** | **需用户明确授权外发与付费** |

### 选型落地建议

1. **第一阶段研发与模拟验证（默认推荐）**：
   - 采用 **本地 Ollama / llama.cpp 加载 Qwen2.5-7B/14B-Instruct (Q4_K_M)**。
   - **理由**：
     - 完全离线运行，**零项目数据外发**，完全遵守保密与合规红线；
     - 零 API 账单成本；
     - 结合 Ollama / llama-cpp-python 原生提供的 **GBNF (Grammar-Based Constrained Decoding)** 语法约束，能够 100% 确保输出符合 JSON Schema，绝对杜绝输出自然语言废话或非法 JSON 字段；
     - 模型权重固定（提供 SHA-256 哈希），回测与模拟复查时只要给相同的输入与 seed=0，输出结果逐字完全可复现。
2. **第二阶段商业云端扩展（严格待审）**：
   - 仅在用户明确批准“允许脱敏数据外发并开通商业账号”后，才可作为备用引擎引入云端 Gemini 1.5 Flash 作为高并发备选通道。

## 三、动态决策模式的架构适配依据

为了彻底杜绝“AI 生成毫无用处的行情点评”、“AI 随意脑补点位开仓”等常见弊病，本系统设计采纳**“规则底座 + 人工智能状态裁决（Arbiter）”模式**，其适配依据如下：

1. **确定性与模糊性的严格分野**：
   - 指标计算（Wilder ATR、唐奇安通道、成交量中位数、资金费核销）必须是 $100\%$ 精确的，绝对不能让神经网络参与浮点数乘除计算。
   - 价格精度、数量步长、名义本金取整（`apply_order_rounding`）、仓位限制（`pre_open_check`）必须由 Python 程序基于交易所规则库执行，模型无权决定数量或价格。
   - 人工智能的核心价值在于**在已批准的策略库中选择当下最适策略，并在满足突破条件时做定性决策**（例如：结合宏观/波段形态判断当前属于“真实蓄势突破”还是“假突破诱多”，决定是 `APPROVE_ENTRY` 还是 `ABSTAIN_NO_TRADE`）。
2. **三不原则（运行期硬隔离）**：
   - **不写代码**：模型在运行期无代码编辑权限，无法动态修改 Python 源码；
   - **不造规则**：模型无法无中生有创造策略，只能在经人工回测并批准的策略白名单中做离散选择；
   - **不碰资金**：模型无法接触交易所或模拟盘账户私钥/下单接口，其产出的仅是一张待审报文，必须经由 `paper_engine` 重新做 8 道因果与风控检查。
