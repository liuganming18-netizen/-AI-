# UI-PENDING-01 · 接口缺口（后端缺字段，本工单**未**越界修改）

以下两项按工单约定只提交缺口，不改后端。均已用源码定位到行，可直接裁决。

## G1 · 挂单方向 `direction`：表里有、投影丢了

- 表结构：`框架/backend/live_store.py:338`
  `direction TEXT NOT NULL DEFAULT 'long'`
- 取行函数是全列：`paper_engine.py:705-712` `SELECT * FROM paper_pending WHERE account_id=? AND status=?`
  ⇒ `pending_orders()` 返回的 dict **含** `direction`。
- 但账户视图投影**手工挑了 11 个字段，漏了 direction**：
  `paper_engine.py:1904-1910`
  ```python
  pend = [{"pending_id": ..., "symbol": ..., "origin": ...,
           "signal_uid": ..., "event_time": ..., "available_at": ...,
           "requested_at": ..., "earliest_fill_ms": ..., "created_at": ...,
           "status": ..., "reason": ..., "note": ...}
          for q in pending_orders(arm)]
  ```
- 前端契约随之没有它：`api/types.ts::RawPaperPending`、`api/liveTrading.ts::PaperPendingView`。
- **缺口申请**：在 1904-1910 的投影里加 `"direction": q["direction"]`（不新增语义，只是别丢）。
- 现状后果：页面只能显示「等待成交」，看不出这单是多还是空；本页按纪律显示「接口未提供」而非猜。

## G2 · 挂单数量 `qty` / 名义金额：表里就没有

- `paper_pending` 22 列里**没有** `qty`/`notional`（`live_store.py:333-357`）。
- 数量在成交时才按权益×单笔风险预算÷止损距离算（见 `paper_engine.py` 下单路径），
  挂单登记时只存 `atr` / `stop_price` / `stoploss_s` / `trail_d`。
- **缺口申请**：若产品要在挂单页显示「预计数量/预计名义」，需要在登记挂单时**显式落一列**
  （并定义「预计」口径：登记时按当时权益算，还是成交时重算——后者会让页面数字与成交数字不一致）。
  在没裁决前，页面显示「未提供」是对的。
- 备注：同一投影里还漏了 `atr` / `stop_price` / `stoploss_s` / `market_source` / `resolved_at` /
  `fill_position_id`，若后续要展示止损价或挂单落点，可一并补齐（同样只补投影，不加语义）。
