## 九、第 3 期追加：web 只读（2026-10-19 晚）

### 改了什么

| 文件 | 改动 |
|---|---|
| `adapter.py` | 连接池改 `mode=ro` + `PRAGMA query_only=1`；`_tail_bars` 只读时不再拉取/写库，改投 `tail_sync` 任务 |
| `infrastructure/repo/tail_fetch.py` | 新增：尾段拉取纯函数 + 网关用的最小可写存储 |
| `infrastructure/repo/tail_store.py` | 新增：尾段写入（从 `_tail_store` 原样搬出） |
| `workers/backtest_worker.py` | 新增任务类型 `tail_sync`：拉取 + 写库都在 worker 完成 |
| `start.sh` | 导出 `WEB_READONLY`（默认 1） |
| `tests/test_web_readonly.py` | 新增 4 项：只读连接、写连接独立、只读不拉不写、回退模式仍写 |

### 关键发现（比方案预期更彻底）

只让 web「不写 K 线」还不够。实测发现**统一网关本身也在写库**：
它要写 `api_calls` / `api_leases` / `api_scope_state` 做共享缓存、限频与冷却。
连接改只读后，尾段拉取直接报 `attempt to write a readonly database`。

所以第 3 期把**拉取也一起搬走**：web 请求里既不拉网络也不写库，
`tail_sync` 任务在 worker 里完成「拉取 → 写库」。

**代价（如实说）**：实时临时层（WS）陈旧时，K 线响应里的 `forming_bar`
不再由 REST 兜底补出；要等 worker 补完、或 WS 恢复。已收盘历史不受影响。

### 还没达成的

历史下载器（运行时）。请求路径已彻底退出写竞争，但后台仍有两个以上写者。
