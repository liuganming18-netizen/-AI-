## 四、几条测试为什么这么写

### T01 用「篡改 close_time」而不是造假数据
把某一根 1h bar 的 `close_time` 改成 `open + 2h`，就模拟了「这根还没收盘」。
真实回放入口必须抛错。对照组不改则正常跑完、零越界 ——
证明闸不是「一律拒绝」。

### T04c / T04d 是同一个场景的两种模式
同一组合成数据：
- `strict` ⇒ `candidates == []`，事件归档为 `OI_UNAVAILABLE`；
- `declared_assumption` ⇒ `candidates == 1`，但 `pit_proven=False`、`qualified=False`。

两种模式都必须有出口，否则要么「全拒」看不出机制，要么「全放」等于没修。

### T07 比对的是完整状态投影
不只看候选数，而是比对 `candidates` / `completed_events` / `active_event` /
`transitions` / `traces` 五组字段全等。只要有任何一处被未来数据影响，就会红。

### T08 是「截断等价」而不是「结果不变」
把 OI 截到 `available_at <= decision`、把 K 线截到 `close_time < decision`，
必须得到**逐字段相同**的候选。这同时验证了两件事：
守卫不会因为「数据变少」而改变合法结论，也不会因为「数据变多」而偷看未来。

### T10 直接用真实交接包
`evidence/ENTRY-AUDIT-04/handoff/ledger_handoff.parquet` 227 行 →
226 个唯一「标的 + 快照时刻」。断言：
- 旧规则越界 **226/226**
- 新规则越界 **0**
- 取值改变 **226/226**

数据文件缺失时该用例 `skip`，不会假绿。

### T12 把「双闸」写死
- 规格通过 + PIT 不合格 ⇒ `formal_pass_allowed = False`（T12）
- 规格通过 + PIT 合格 ⇒ `True`（T12b）
- 规格不合格 + PIT 合格 ⇒ `False`（T12c）

三条一起才说明 `formal_pass_allowed = 规格 AND PIT`，不是「或」。
