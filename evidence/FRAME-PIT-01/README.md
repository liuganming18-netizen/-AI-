# FRAME-PIT-01｜框架级防未来数据约束与测试

**结论一句话**：框架以前**没有任何强制的可得性检查**，谁都能直接读原始 parquet；
现在策略入口、回放入口、因子入口三条路都被同一套守卫管住，
**未收盘 K 线会直接抛错**，**OI 只取决策时刻已可得的桶**，
拿不到发布时点证据的运行会被明确标成「不具备正式资格」并写明原因。

> 本单**没有**宣告 `WX_EVENT_TREND_V0_1` 通过 Gate，也没有开展完整四组回测。
> 正式资格状态见 `07_正式资格状态.md`。

## 一、四条必须先知道的事实

1. **旧代码 226/226 取到未来数据。**
   真实 227 条样本里有 226 个唯一「标的 + 快照时刻」，**每一个**都被旧规则
   （`ts <= 决策时刻`）取到了「起点正好等于决策时刻」的 5 分钟桶 ——
   那个桶覆盖的是决策**之后**的 5 分钟。旧规则越界率 **100%**，新规则 **0%**。

2. **修的是取值来源，不是信号时刻。**
   决策时刻一个都没动（仍是 `1h 开盘 + 3600 秒`），阈值、撮合、费用、防拟合全部未改。
   改动只影响「这一时刻允许看到哪些数据行」。

3. **结论确实会变，但只变了一点。**
   226 个时点里，OI 6h 增幅中位差 **0.49 个百分点**、最大 **14.85 个百分点**；
   2% 门槛从 226 通过变成 **223 通过**（3 个翻转）。
   在 6 个标的、19 个标的的完整窗口回放里，候选数没变（4 → 4）——
   说明这个缺陷在多数时候**没有**改变成交结论，但确实读到了不该读的数据。

4. **仍然不是「已完全隔离」。**
   同进程代码依旧可以直接 `pd.read_parquet`。本单提供的是
   **受控入口 + 违规可检测 + 资格判定**，不是进程级隔离。
   边界如实写在 `06_未覆盖路径与防护边界.md`。
