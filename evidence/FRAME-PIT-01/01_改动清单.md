## 1 新增 `trading_core/pit_guard.py`

**为什么**：框架此前没有任何强制的可得性检查。`trading_core/pit.py` 只被
`oi_resonance_v1/core.py:253` 调用，event_trend 链完全没接；而且它在缺
`oi_observed_at` 列时会把 `close_ms` 当成观测时刻（最乐观假设），不能当闸门用。

**内容**：

| 组件 | 作用 |
|---|---|
| `DecisionClock` | 四时刻不可变容器；构造时强制 `close >= event` 且 `decision >= close + 1ms` |
| `SourceRule` | 一个数据源的可用性规则（`event_col` / `close_col` / `bucket_ms` / `declared_lag_ms` / `evidence`） |
| `AvailabilityStatus` | `exchange_close` / `declared_lag` / `settlement_event` / `unproven` |
| `PitSource` | 帧 + 规则 + 逐行 `available_at` |
| `PitStore` | `as_of()` / `value_as_of()` / 拒用与假设登记 / `audit()` / `audit_sha256()` |
| `assert_frame_available()` | 帧里只要有一行 `available_at > decision` 就抛 `PitViolation` |
| `rule_candles` / `rule_bucket_metrics` / `rule_settlement` | 三类预置规则工厂 |

**关键取舍**：`rule_bucket_metrics` 在不给 `declared_lag_ms` 时一律返回 `UNPROVEN`。
桶结束时间**不是**已证明的发布时刻，不能自动升级。

**改了会怎样**：新模块，不影响任何既有调用路径（除了下面主动接入的地方）。

## 2 新增 `event_trend_v0_1/pit_bridge.py`

**为什么**：策略侧需要两件事，且必须由框架做、不能靠策略作者自觉：
① OI 桶的可得时刻；② 每根 K 线是否已收盘。

**内容**：

| 方法 | 行为 |
|---|---|
| `register_oi(oi_ts, oi_vals)` | 登记 OI 并推导逐行 `available_at`；未证明时 `strict` 给全 NaN（等于拒用）、`declared_assumption` 给 `ts + bucket` 并置 `_oi_assumed=True` |
| `read_oi(decision, lookback, max_distance)` | 走 `extract_real_oi_growth_ex`；假设路径必须让底层自己算桶结束，**不能**把假设值伪装成已证明时刻 |
| `assert_candles_closed(close_time, decision)` | `close_time + 1 > decision` ⇒ 抛 `PitViolation` |
| `qualified` | 来源已证明 + 没走过假设 + 无 K 线越界，三者同时成立 |
| `qualification_failures()` | 把不合格原因写成可读字符串列表 |
| `audit()` / `audit_sha256()` | 整份审计记录 + 指纹（含桥接层字段，不只是 `PitStore`） |

**踩到的坑（已修）**：第一版把 `_oi_available_at`（假设值）直接传给
`extract_real_oi_growth_ex`，结果 `assumed` 判成 `False`、状态回 `ok`，
候选快照被标成 `pit_proven=True` —— 等于把假设洗成证据。
现在假设路径一律传 `oi_available_at=None`，由底层自己标记 `ok_assumed`。

## 3 改造 `features.py::extract_real_oi_growth`

**改动前**：

```python
idx_curr = np.searchsorted(oi_timestamps, target_time_ms, side="right") - 1
```

`oi_timestamps` 是 5 分钟桶的**起点**。决策时刻是整点，`searchsorted` 会选中
「起点正好等于决策时刻」的那一桶 —— 而那个桶覆盖 `[决策时刻, +5 分钟)`，是未来。

**改动后**：

```python
ok = np.isfinite(available_at) & (available_at <= target_ms)   # 判可用
idx = 满足 ok 的行里 event_time 最大的那一行
```

**新增** `extract_real_oi_growth_ex()` 返回完整判定明细
（`curr_event_ms` / `curr_available_ms` / `assumed` / `detail` 等），
`extract_real_oi_growth()` 保留 4 元组签名向后兼容。

**状态串变化**：值可用但可得时刻是假设出来的 ⇒ 返回 `ok_assumed`，**不是** `ok`。
任何只认 `"ok"` 的旧调用方会自动变成「不可用」，这是有意的 fail-closed。

**行为差异**：见 `05_新旧行为对照.md`（226/226 取值改变，3 个 2% 门槛翻转）。

## 4 改造 `state_machine.py`

| 位置 | 改动 | 原因 |
|---|---|---|
| `__init__` | 新增 `pit_mode` / `oi_bucket_ms` / `oi_declared_lag_ms`；创建 `self.pit` | 策略侧拿到守卫 |
| `process_1h_bar` | 用 `DecisionClock.for_bar(open, HOUR_MS)` 推导四时刻 | 四个时刻显式分开 |
| `process_1h_bar` | `self.pit.assert_candles_closed(clock.close_time_ms, decision_ms)` | 未收盘即抛错 |
| OI 决策段 | `extract_real_oi_growth(...)` → `self.pit.read_oi(...)` | 走受控读取 |
| OI 决策段 | `strict` 下 `ok_assumed` 改写为 `oi_pit_unproven` ⇒ `OI_UNAVAILABLE` | 拒用不填默认值 |
| `CandidateSnapshot` | `pit_proven = (oi_status == "ok")`；说明改中文 | 不再一律写死 `False`，也不再一律写死英文串 |
| `export_state` / `restore_state` | 带上 `pit_mode` / `pit_oi_bucket_ms` / `pit_oi_declared_lag_ms` | 热重启不得悄悄换回更宽松的口径 |

**决策时刻没变**：`decision_ms` 数值上等于旧的 `close_time_ms = open + 3600s`。
这是刻意的 —— 修 PIT 不许顺手挪信号时点，否则等于换了个策略再比结果。

**一处数字巧合要说清**：1h bar 的真实最后一毫秒是 `open + 3599999`，
而 `decision_ms = open + 3600000`。所以 `available_at_ms`（写成 `decision_ms`）
本来就晚于真实收盘 1 毫秒，不存在「收盘前就能看到」的问题。
