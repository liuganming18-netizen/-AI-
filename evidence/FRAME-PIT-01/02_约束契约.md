# 02 约束契约

## 一、四个时刻，不许互相冒充

| 名称 | 含义 | 谁定义 | 本项目的实际取值 |
|---|---|---|---|
| `event_time` | 数据点所属区间的**起点** | 交易所 | K 线 `open_time`；OI/metrics 的 `ts`（5m 桶起点） |
| `close_time` | 区间的**最后一毫秒** | 交易所 | K 线 `close_time`（= `open + 周期 − 1ms`） |
| `available_at` | 这个值**最早能被读到**的时刻 | 本框架按来源规则推导，必须有证据 | 见下方三类规则 |
| `decision_time` | 策略做决定的时刻 | 调用方 | `1h 开盘 + 3600s`（与旧口径逐毫秒一致） |

**三条禁止**：

1. **禁止**用 `open_time <= decision_time` 判可用。那只说明区间开始了，不说明区间结束了。
2. **禁止**把「桶结束时间」或「机械平移 5 分钟」当成**已证明**的发布时间。
   桶结束只能作为假设；一旦采用，本次运行必须判为不具备正式资格。
3. **禁止**在取不到可得时刻时填默认值继续跑。只有两条路：显式拒用，或照用但判不合格，
   且两条路都必须把原因写进审计记录。

**时钟自校验**（`DecisionClock.__post_init__`）：

- `close_time >= event_time`
- `decision_time >= close_time + 1ms` —— 区间没结束不许决策

## 二、三类来源规则

| 状态 | 用于 | `available_at` 计算 | 证据要求 |
|---|---|---|---|
| `exchange_close` | K 线（4h / 1h / 15m） | `close_time + 1ms`（无 `close_time` 列时退 `open + 周期`） | 落盘 `close_time` 存在且 `is_closed = 1` |
| `declared_lag` | 官方 metrics / OI 统计桶 | `ts + bucket_ms + declared_lag_ms` | **必须**有显式声明的延迟数值；没声明就是 `unproven` |
| `settlement_event` | 资金费结算 | `funding_time` | 只用于结算**之后**的记账，不得用于入场决策 |
| `unproven` | 其它一切 | 整列 NaN，不猜 | —— |

**K 线为什么算 `exchange_close`**：
parquet 有 `available_at` 列但 **100% 为空**，`is_closed` 全为 1。
这只能证明「K 线在 `close_time + 1ms` 已闭合」，**不能**证明我们那一刻就收到了它。
所以 note 里如实写「本地摄取延迟未证」。这是本框架目前能做到的最强表述。

**OI 为什么算 `unproven`**：
OI parquet 只有 `ts`（5m 桶起点）、`open_interest` 等列，`fetched_at` **全为空**。
官方接口文档没有发布延迟归档，本地也没有历史抓取时刻。
⇒ 没有任何证据能证明「桶结束后多久能读到」，因此 `unproven`。

## 三、两条处理路径

| 模式 | 未证明来源的处理 | 后果 |
|---|---|---|
| `strict` | **显式拒用**：`available_at` 全 NaN，任何取用落空；策略侧把事件归档为 `OI_UNAVAILABLE` | 不出候选，`trading_summary.trade_count = 0` |
| `declared_assumption`（默认） | **照用**：把「桶结束」当可得时刻；状态记为 `ok_assumed` | 出候选，但 `pit_qualified = False`、`formal_pass_allowed = False`，原因写进 `formal_pass_block_reasons` |

**默认选 `declared_assumption` 的理由**：它不隐藏问题 ——
跑得出结果，但每个产物都带着「不合格 + 原因」。
`strict` 会让所有含 OI 门槛的变体直接 0 成交，反而看不出机制是否修对。
两种模式都有测试覆盖（T04c / T04d）。

## 四、硬约束清单

| 编号 | 约束 | 执行点 | 违反时 |
|---|---|---|---|
| C1 | 1h bar 必须已收盘才能决策 | `PitBridge.assert_candles_closed` ← `state_machine.process_1h_bar`、`runner.run_state_machine_simulation` | 抛 `PitViolation` |
| C2 | 4h bar 必须已收盘才能建箱 | 同上（`label="4h"`） | 抛 `PitViolation` |
| C3 | OI 只能取 `available_at <= decision` 的观测 | `extract_real_oi_growth_ex` | 该观测不入选 |
| C4 | 距决策超过 15 分钟的旧观测不得凑数 | 同上（`max_distance_ms`） | 返回 `oi_curr_too_far_*` |
| C5 | 6h 回看点同理受 C3/C4 约束 | 同上 | 返回 `oi_past_*` |
| C6 | 帧里出现 `available_at > decision` 的行即视为违规 | `assert_frame_available` | 抛 `PitViolation` |
| C7 | 帧里出现 `available_at` 为空的行即视为违规 | 同上 | 抛 `PitViolation` |
| C8 | 未证明来源不得进入正式资格 | `PitBridge.qualified` → `runner._build_run_files` | `formal_pass_allowed = False` |
| C9 | 无状态机可查时不得默认合格 | `_build_run_files(sm_inst=None)` | `qualified = False` + 原因 |
| C10 | 热重启不得换回更宽松口径 | `export_state` / `restore_state` 带 `pit_mode` | —— |

## 五、审计记录字段（写进每个 run 的 `inputs.json`）

| 字段 | 含义 |
|---|---|
| `pit_guard_version` | 守卫版本（当前 `pit_guard_v1.0.0`） |
| `mode` | `strict` 或 `declared_assumption` |
| `qualified` | 正式资格（来源已证明 + 无假设 + 无越界） |
| `unproven_sources` | 哪些源没有可得时点证据 |
| `assumptions` | 登记过的假设（源名 + 状态 + 模式 + 说明） |
| `refusal_count` / `refusal_reason_counts` | 拒用次数与原因分布 |
| `sources.<name>` | 每个源的规则、行数、`event_time` 范围、`available_at` 范围 |
| `oi_available_at_rows` / `oi_available_at_assumed` | 实际生效的可得时刻行数、它是不是假设值 |
| `oi_reads` / `oi_assumed_reads` / `oi_refused_reads` | OI 读取次数、其中假设路径次数、取不到次数 |
| `candles_checked` / `candle_violations` | 校验过的 K 线根数、越界根数 |
| `qualification_failures` | 不合格原因（可读字符串列表） |
| `audit_sha256` | 整份审计记录的指纹 |

`summary.json` 侧：

| 字段 | 含义 |
|---|---|
| `formal_pass_allowed` | **规格可证 AND PIT 可证** |
| `formal_pass_allowed_components` | `{"instrument_spec": bool, "pit": bool}` |
| `formal_pass_block_reasons` | 具体卡在哪（如 `instrument_spec_unproven`、`oi_available_at_unproven:…`） |
| `pit_audit_sha256` | 与 `inputs.json` 的 `pit_audit.audit_sha256` 一致 |
| `pit_qualified` | 与 `pit_audit.qualified` 一致 |
