## 二、谁被约束了（逐个核对）

| 入口 | 路径 | 是否受约束 | 说明 |
|---|---|---|---|
| `run_variant_abc`（runner.py:594） | → `run_state_machine_simulation` | ✅ | 主入口 |
| `run_state_machine_simulation`（runner.py:305） | 自带 K 线闸 + 注册 OI | ✅ | 直接调用也受约束 |
| `execute_reconciliation_suite`（runner.py:387 起 4 处） | → `run_state_machine_simulation` | ✅ | 对账套件 |
| `execute_reconciliation_suite` 分段还原（runner.py:421 / 444） | 直接 `process_1h_bar` | ✅ | `process_1h_bar` 内部自带闸 + 懒注册 |
| `框架/backend/backtest_runner.py:793` | → `run_variant_abc` | ✅ | 后端建单入口 |
| `run_batch_2025q4_100.py` 等 11 个批量脚本 | → `run_variant_abc` | ✅ | 传递受约束 |
| `run_full_sweep_200x100.py:175` | → `run_state_machine_simulation` | ✅ | |
| `diagnose_signal_funnel.py:89` | → `run_state_machine_simulation` | ✅ | |
| `audit_reconciliation.py:120` | → `run_state_machine_simulation` | ✅ | |
| `scan_signal_density.py:123` | **直接** `process_1h_bar`（复刻驱动） | ✅ | 懒注册 + 内部闸兜住 |
| `evidence/**` 下 9 个审计脚本 | → 上述两个入口 | ✅ | 传递受约束 |
| `oi_resonance_v1/core.py:253` | → `trading_core/pit.py`（另一套） | ⚠ 不在本单范围 | 见 `06` |

**结论**：本单范围内**没有**「未接入守卫的生产入口」。
唯一直接调用 `process_1h_bar` 的实验脚本也被函数内部闸兜住，
因为它必须经过 `assert_candles_closed` 和 `self.pit.read_oi`。

## 三、守卫没盖住的地方（关键）

守卫只约束**经过它**的读取。以下路径绕得过去：

1. `EventTrendRunner.load_symbol_data` 里的 `pd.read_parquet(...)`
   —— 它读的是整段历史，**不按决策时刻裁剪**。守卫是在「用」的时候拦，
   不是在「读」的时候拦。所以「文件被读进内存」这件事本身不受约束。
2. 任何新写的脚本直接 `pd.read_parquet` 然后自己算特征。
3. `state_machine` 收到的 `oi_timestamps` / `oi_values` 数组
   如果被外部篡改（例如把 `available_at` 全设成桶起点），守卫会照它算 ——
   这正是 `compare_old_new.py` 复现旧规则用的手法，也说明**数组本身不是可信边界**。

⇒ 所以本单提供的是「受控入口 + 违规可检测 + 资格判定」，
**不是**进程级隔离。不得宣称已完全隔离。
