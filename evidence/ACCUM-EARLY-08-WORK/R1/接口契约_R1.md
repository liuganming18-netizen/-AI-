# 接口契约 · 研究信号接入（R1 修订版）

> 对象：反重力隔离回测（`ACCUM-EARLY-08-ANTIGRAVITY`）产出的**研究信号** → 现有
> `live_signal` 存储 → 现有 `/api/v1/signals` → 现有信号页面。
> 版本：`accum08-research-signal/v1`（= 模块常量 `MANIFEST_VERSION`）
> 本版取代 `../接口契约.md`（草案 v1）；草案保留不动，差异见 §9。
> 所有数字都是**实测值**，出处见 `README.md` 的证据表。

---

## 1. 一句话边界

研究信号**只展示、恒不可执行、不进入当前交易区、不产生订单**。
本契约不定义「可执行研究信号」，因为这种信号在本项目里**还不存在**（`approved=false` 是硬事实，不是占位）。

## 3. 四时刻与 K 线时刻（互不替代）

| 字段 | 本单取值 | 语义 |
|---|---|---|
| `event_time` | `confirm_close_ms` | 事件时刻（1h 确认 bar 收盘） |

| `available_at` | **`NULL`** | 可得时刻。反重力未记录 OI/交易所发布延迟 ⇒ **无证据就留空**，禁止用 `confirmed_at` 顶替 |

`available_at=NULL` 的副作用（实测，不是推测）：当前区排除明细里 `missing_time` 会 +289。
这是**如实结果**，不是缺陷 —— 它同时说明「这条信号连可得时刻都还没有证据」。

## 4. 幂等

- 键：`signal_uid`（= 反重力 `candidate_id`，形如 `accum05_4a_ACTUSDT_1784116799999`），**原样使用、不加前缀、不改写**。
- 冲突策略：`ON CONFLICT(signal_uid) DO UPDATE` **只**更新 `payload_json` / `executable_reason` / `executable_state` / `updated_at`。
- **永不改写**：`first_seen_at`、四个时刻、价格事实、身份列。
- 实测：第二次导入 `new=0 / updated=289`，`first_seen` 逐条不变，`updated_at` 全部推进。
- `signal_uid` **不含 `run_id`** ⇒ 两臂（arm_a / arm_b）候选 uid 完全相同（289 = 289，集合逐位一致），**只能导入一个臂**。本单选 `arm_b`（`run_status=OK`）；`arm_a` 是 `FAILED`（`invalid_reasons=['EXIT_CLOSE_REJECTED']`，20 条 run_problems），且导入器带 `--require-ok` 会直接拒绝它。

## 5. 可执行性判定链（五层，实测）

`unified_runtime.py:2169 _scan_actionable` 的限定条件，缺一不可：

| 层 | 条件 | 研究行实际值 |
|---|---|---|
| L1 | `executable_state='enterable'` | `historical_not_executable` ✗ |
| L2 | `payload.role='enterable_arm_entry'` | `research_only` ✗ |
| L3 | `payload.arm=<本臂>`（生产臂 `3a`） | `4a/4b/4c` ✗ |
| L4 | `confirmed_at IS NOT NULL AND available_at IS NOT NULL` | `available_at=NULL` ✗ |
| L5 | 调用方传入的 `origin` 过滤（生产自然路径传 `live`） | `historical_research` ✗ |

**实测矩阵**（在副本上逐层改坏，`out/60_闸门正反例.json`）：

| 状态 | `scan(None)` | `scan('live')` |
|---|---|---|
| 原样 | 0 | 0 |
| 只改坏 L1 | 0 | 0 |
| L1+L2 | 0 | 0 |
| L1+L2+L3 | 0 | 0 |
| L1–L4 全坏 | **289** | 0 |
| 单条五层全坏 | 1 | 0 |

**必须说清的两件事**：

1. 四层各自独立有效，任意一层在就扫不到 —— 所以「不可执行」不是靠单一开关。
2. **一旦五层全被破坏，`route_pending_orders(origin='historical_research')` 会真的登记挂单**（副本账本 `paper_pending=1`）。也就是说 `paper_engine.open_position` **没有** `approved=false` 的硬拒。当前开仓闸门 `allow_new_entries=true`（`set_by=user_ui_control`，`since_ms=1792753532432`）。⇒ 见 §8 待裁决 3。

## 6. 查询契约（真实 HTTP）

| 用途 | 请求 | 实测结果 |
|---|---|---|
| 研究范围 | `GET /api/v1/signals?scope=all&origin=historical_research&limit=1000` | 200，289 条，`has_more=false` |
| 当前交易区 | `GET /api/v1/signals?scope=current&limit=500` | 200，0 条，`quality.excluded_n=289` |
| 负向对照 | `GET /api/v1/signals?scope=all&origin=live&limit=1000` | 200，0 条（证明 `origin` 过滤真的生效） |

**`total` 的坑（实测，务必注意）**：审计通道 `total = len(merged)`，即**本页条数**，不是库内总数。
`limit=1 → total=1 且 has_more=true`；`limit=1000 → total=289 且 has_more=false`。
要判「读全了没有」只能看 `has_more`，不能看 `total`。

**顶层身份 vs 条目身份**：响应顶层的 `strategy_version/rule_version/param_hash`
是**运行时身份**（`FT-LOW4H-EXP-V2.2` / `FT-LOW4H` / `82dec362c182`），与条目自带的
`ACCUM-RESEARCH-v0::4x` 不是同一套东西。只读顶层的消费方会把研究信号误标成 FT-LOW4H。
本单**未改**接口结构（属契约扩张），条目级身份逐条正确。

## 9. 与草案 v1 的差异

| 项 | 草案 v1 | R1 修订 |
