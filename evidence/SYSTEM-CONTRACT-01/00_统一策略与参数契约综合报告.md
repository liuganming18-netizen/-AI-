## 一、目标与执行背景

在先前的闭环审计与日常运行中，系统存在以下关键隐患与混淆：
1. **参数缺失仍静默开仓**：当生效配置视图缺失或解析失败时，模拟盘引擎静默使用硬编码的 `FALLBACK` 兜底（`stoploss_s=0.05, trail_d=0.05`），且无守护启动自检（阻塞 `B-04`）；
2. **多通道身份混淆**：144 组 Freqtrade 网格研究、UI 新建回测与模拟盘演练混称为“同一核心”，但实际上这三者的执行器、参数来源、时间步进推进机制与费用结算完全不同；
3. **订单无配置身份追溯**：`paper_order` 与 `paper_fill` 过去缺少 `stoploss_s`、`trail_d` 与 `config_fingerprint` 列，生产数据库存在新旧两套 schema（阻塞 `B-05`）；
4. **请求体可篡改正式配置**：调用方可在日常 `POST /paper/orders` 请求体字面量中随意携带并覆盖正式绑定的核心止损参数。

本工单旨在**彻底建立统一策略与参数契约**，冻结配置接口，消除任何静默兜底，为挂单、订单、持仓提供不可篡改的配置身份与全链路可追溯性，并在严禁新单开仓的同时保障既有持仓的正常跟踪止损与安全退出。

## 二、实施内容六项逐项落实

### 1. 明确列出三条实际执行路径

系统已在 `框架/backend/strategy_contracts.py` 中建立不可变注册表 `EXECUTION_PATHS`，严格区分三条路径，明确标识**不可统一**：

| 执行路径 | 业务名称 | 实际入口 | 策略定义 | 执行器（Executor） | 参数来源 | 数据源 | 费用口径与结算 | 差异与边界标识 |
|---|---|---|---|---|---|---|---|---|
| **路径 1** | **144组 Freqtrade 网格研究** | `evidence/FT-LOW4H-GRID-01/code/01_run_all_grid_backtests.py` | `WyckoffLow4hGridBase` 派生类 (144 组) | **Freqtrade CLI** (`dry_run=True`) | 策略派生类静态类变量 + `user_data/config.json` | `user_data/data/binance/` + `数据/raw/` | 单边手续费 0.0005，无滑点，事后复现逐笔资金费率结算 | 离线全周期网格回测，无常驻挂单与撮合循环，事件调度由 Freqtrade 全权托管。 |
| **路径 2** | **UI 新建研究回测** | `POST /api/v1/backtests` (`backtest_api.py:create_run`) | `WX_EVENT_TREND_V0_1` (`EventTrendRunner`) | **BacktestRunner** (`backtest_runner.py`) | `event_trend_bridge.py:PARAMETER_WHITELIST` + 请求体 params | `MarketDataRepository` (`数据/raw/` 多周期与 `数据/raw_oi_metrics/`) | `taker_fee_bps` (5.0 = 0.0005) + `slippage_bps` (3.0 = 0.0003) + 真实资金费事件 | Web 异步任务队列 (`jobs.sqlite3`)，向量化初筛 + 15m 事件精确撮合，产物落独立 run 目录。 |
| **路径 3** | **模拟盘演练与守护执行** | `POST /paper/orders` (`live_api.py`) / `paper_loop.py` | `FT-LOW4H` (低频唐奇安/威科夫跟踪) | **PaperEngine** (`paper_engine.py` / `paper_loop.py`) | 正式生效视图 JSON (`EFFECTIVE_VIEW` 环境变量或指定冻结文件) | `live_store.py` (`paper_*.sqlite3`) + `market.sqlite3` 真实闭合 K 线 | 单边 `fee_each_side` (0.0005) + `slippage_each_side` (0.0005) + 实时资金费核算 | 常驻守护进程异步轮询，真实首次请求锚点，因果时钟防御，挂单到点真实成交。 |

> **核心纪律**：绝不将这三套执行器改名为“同一核心”；各通道生命周期与撮合逻辑各自独立。

### 2. 为 FT-LOW4H 建立明确、可验证的配置身份

在 `框架/backend/strategy_contracts.py` 中建立强类型配置数据类 `FtLow4hConfigIdentity`，结构如下：
- `strategy_id`: 固定为 `"FT-LOW4H"`；
- `strategy_version`: 策略版本（例如 `"FT-LOW4H-EXP-V2.2"`）；
- `rule`: 跟踪规则（固定为 `"FT-LOW4H"`）；
- `stoploss_s`: 初始止损比例（必须在 `[0.001, 0.50]` 区间，例如 `0.05`）；
- `trail_d`: 跟踪止损比例（必须在 `[0.001, 0.50]` 区间，例如 `0.05` 或 `0.12`）；
- `risk_per_trade_equity_fraction`: 单笔风险预算比例（必须在 `[0.0001, 0.10]` 区间）；
- `portfolio_initial_stop_risk_cap`: 组合初始止损风险上限（必须在 `[0.001, 0.50]` 区间）；
- `fee_each_side`: 单边手续费（必须在 `[0.0, 0.01]` 区间）；
- `slippage_each_side`: 单边滑点（必须在 `[0.0, 0.01]` 区间）；
- `detail_timeframe`: 撮合执行周期（`15m`）；
- `tracking_timeframe`: 跟踪参考周期（`4h`）；
- `max_holding_hours`: 最大持仓小时数（正整数，例如 `240`）；
- `config_fingerprint`: 规范化配置字节的 SHA-256 前 12 位（或 64 位）唯一指纹；
- `config_path`: 配置文件绝对路径。

内置 `validate()` 方法对每个字段做强校验，非法或越界配置立刻拒绝。

### 3. 取消静默 5% 兜底与硬阻断

1. **取消默认兜底**：`paper_engine.py` 的 `FALLBACK` 字典彻底移除硬编码的 `stoploss_s` 和 `trail_d`。当视图文件缺失或解析失败时，`approved_params()` 返回 `_config_valid: False`，`stoploss_s: None`，`trail_d: None`，`config_fingerprint: None`。
2. **开仓闸门前置**：在 `open_position()` 最前置增加 `SC.validate_entry_contract(params, ...)`，只要配置无效、必需参数缺失、或指纹不匹配，**100% 拒绝新单并报告具体原因**（`rejected_by_config_contract: ...`），账本写入 0 行！
3. **守护启动自检（闭环 B-04）**：在 `paper_loop.py` 的 `PaperExecutionDaemon.run_forever()` 开始时执行启动配置自检。若配置无效，抛出 `RuntimeError: startup_config_check_failed`，状态落盘为 `failed_config_check`，拒绝静默启动。

### 4. 挂单、订单、持仓保留配置身份；重试与重启不换规则

1. **Schema 统一迁移（闭环 B-05）**：
   - 升级 `live_store.PAPER_COLUMNS`，在 `paper_order` 与 `paper_fill` 中新增 `stoploss_s`、`trail_d`、`config_fingerprint`、`config_source` 列；
   - 对生产四库（`paper_3a.sqlite3` ~ `paper_3d.sqlite3`）执行加性迁移，验证生产四库 100% 具备上述列，消除了双重 Schema 隐患。
2. **挂单持久化与转化**：
   - 挂单登记（`_register_pending`）时，将有效配置的 `stoploss_s`、`trail_d`、`model_version`、`config_fingerprint` 写入 `paper_pending`；
   - 进程重启后，直接从 SQLite 读取挂单持久化字段；
   - 到点推进成交时，`open_position` **严格沿用挂单时已锁定的身份**，原样写入 `paper_order`、`paper_fill`、`paper_position`，绝不因当前环境的配置改动或删除而改变已有交易的规则。

### 5. 请求体不得覆盖已绑定的正式参数

在 `live_api.py` 的 `paper_order_post` 中：
- 读取当前生效配置 `approved_params()`；若配置无效，直接阻断（返回 400）；
- 校验请求体中的 `stoploss_s` 或 `trail_d`：若请求体传参且与配置不符，明确返回拒绝：
  `"配置已绑定 stoploss_s=0.05，请求体不得覆盖正式参数 (0.2)"`；
- 统一使用正式配置参数；隔离实验若需不同参数，必须通过指定独立的配置文件（例如指定 `EFFECTIVE_VIEW`）加载，绝不允许从 HTTP 请求体随手篡改。

### 6. 维护既有持仓管理（新单禁止不影响退出）

工单特别强调：“维护既有持仓管理，不能因禁止新单而停止已有持仓退出”。
- `advance_position_trailing` 与 `close_position` 推进 4h 最低价跟踪止损与触发退出时，直接读取该持仓在 `paper_position` 中固化的 `trail_d` 与止损参数；
- 即使此时全局配置文件被误删或置空（新单开仓完全被阻断），已有持仓继续正常进行 4h K 线跟踪止损推进，若击穿止损则正常平仓并生成带有配置身份的平仓订单，实现完全闭环！
