## 2. 但「零接触」这个说法不准确：有两处读共享

B 的探针注释写「生产进程与生产账本**零接触**」。逐字核对：

1. **行情库是共享的（只读）**。`MARKET_DB` 指向生产 `market_v2.sqlite3`。铺信号的脚本用 `sqlite3.connect("file:…?mode=ro", uri=True)` 只读打开，引擎取 15m/4h 已闭合 bar 做成交价与止损基准时也走这个库。
   - 这不是缺陷——隔离测试要用真实行情算 ATR 与成交价，不共享就得造假数据。但它意味着「隔离」是**写隔离**，不是「什么都独立」。
2. **生效参数视图是共享的（只读）**。`EFFECTIVE_VIEW` 没设，`paper_engine.py:174` 会回落到工程内正式位置。也就是说隔离实例用的是**生产在用的那套参数**，这正是「同参数比较」需要的，但同样属于共享读。

⇒ 准确表述应当是：**写路径 4 条全部隔离，读路径 2 条共享生产（行情库、参数视图），均为只读**。交付方若继续写「零接触」，属于表述过头。

## 3. 隔离环境的闸门是「不存在」⇒ 当前拒绝新开仓

`/tmp/ui-link-01/live/paper_new_entry_gate.json` **不存在**。而闸门读取是 fail-closed 的（`paper_engine.py:147-166`）：

```
raw = json.loads(gfile.read_text())   # 读不到 ⇒ raw = None
ok = isinstance(raw, dict)            # ⇒ False
allow = bool(ok and raw.get("allow_new_entries") is True)   # ⇒ False
reason = "gate_file_missing_or_unreadable"
```

所以**现在这个隔离实例是不允许新开仓的**。B 如果后面要证明「隔离闭环能成交」，必须在隔离环境里自己把闸门打开（`POST 127.0.0.1:8799/api/v1/paper/toggle_gate`），并且证明写的是 `/tmp` 那个文件。

**这里有一个必须盯的操作风险**：生产闸门和隔离闸门靠端口区分，没有别的护栏。打错端口（例如沿用 8787）就会把日常实例的开仓状态改掉——而日常实例当前是 `allow_new_entries=true`（19:05:32 由界面恢复）。这不是代码缺陷，是测试操作纪律，必须在交付里写明「只打 8799」。
