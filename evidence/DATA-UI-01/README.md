| 场景 | 界面表现 | 证据 |

## 7. 本次修掉的三个真实缺陷（都在实测中发现，不是推测）

1. **「取齐」虚报**：原来只要处理过就计 `12/12`。实测 BTC 的大户账户多空比其实是被推迟的。
   改为逐块判「真有值」后，同一轮如实报 `10/12` 并列出未齐标的。
   —— 直接对应工单「不能把下载成功当入库完成」。

2. **核心块被推迟会把好值冲成空**：实测 BTC 的 `top_position` 从 `1.7772` 变 `null`。
   改为核心块也参与继承（保留原 `fetched_at`、标 `carried_over`）。
   修复后覆盖表里该块从 59/60 变 **60/60**。

3. **OI 块写成「有值但为空」**：出现 `available:true` 但 `amount`/`usd` 全 `null` 的空壳块，
   界面从有值变「—」。现在构造时判为不可用，读取端也会回退库表拿上一份好值（层级如实标 `db_snapshot`）。
