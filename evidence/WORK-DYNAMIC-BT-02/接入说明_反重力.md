## 1. 三个层级的入口

| 层级 | 文件 | 粒度 | 用途 |
|---|---|---|---|
| run 级 | `out/09_run级索引.csv` | 每 run 1 行 × 45 | run → 标的集合 / 笔数 / 时间范围 / 复盘包 SHA |

## 2. 字段表（`10_逐笔复盘索引.csv`，74 列）

### 2.1 身份与连接键

| 字段 | 类型 | 单位/取值 | 语义与来源 |
|---|---|---|---|
| `run_id` | str | `run_FT_LOW4H_DYN01_<策略>` | 与 `回测日志/event_trend_v0_1/runs_work_dynamic_bt_01/<run_id>/` 同名 |
| `strategy` | str | 45 个策略类名 | 组别 + 入场参数编码，如 `Wyckoff_C1_S05_DYN_Vs08_Z06` |
| `group` | str | `A`/`B`/`C`/`P1`/`P2` | A=固定 d5%、B=固定 d20%、C=动态 8→20→5%、P1/P2=一致性对照 |
| `param_group` | str | `Vs04_Z02`…`Vs08_Z06` | 入场参数（`c_vs` × `c_z`） |
| `symbol` | str | 如 `BCH` | 标的，**不是**交易对；对 = `pair` |
| `pair` | str | 如 `BCH/USDT:USDT` | 合约交易对 |
| `trade_id` | int | 1..n | **派生**：引擎导出无此字段，按 `(open_timestamp, 白名单索引)` 升序还原 1..n |
| `trade_id_status` | str | `derived` | 提示不要当交易所 ID 用 |
| `symbol_trade_seq` | int | 1..n | 该标的**跨 run** 的第几笔（按入场时刻排序），供逐币翻阅 |
| `entry_order_key` / `exit_order_key` | str | `run_id\|symbol\|trade_id\|0/1` | **替代连接键**（派生，唯一稳定），因为回测无 `order_id` |
| `candidate_id` | str | `cand_C1_ev_...` | 候选 ID，可回查 `out/15_入场审计_*` |

### 2.2 时间轴（**全部 UTC**，两种表示同存）

| 字段 | 类型 | 单位 | 语义 |
|---|---|---|---|
| `signal_ts_ms` / `signal_utc` | int / str | epoch **毫秒** / `YYYY-MM-DDTHH:MM:SSZ` | 信号 1h K 线**收盘**时刻 |
| `confirm_ts_ms` / `confirm_utc` | 同上 | 同上 | 紧接下一根 1h 收盘（确认 K 线） |
| `entry_ts_ms` / `entry_utc` | 同上 | 同上 | 真实成交（= 确认后首个 15m 开盘时刻） |
| `exit_ts_ms` / `exit_utc` | 同上 | 同上 | 真实退出成交时刻 |
| `holding_hours` | float | 小时 | `(exit-entry)/3600000`，4 位小数 |

> 时区纪律：毫秒时间戳一律 UTC epoch；`*_utc` 字符串一律带 `Z`。
> **没有任何本地时区字段**，前端若要按本地时区展示请自行转换，不要反推。

### 2.3 订单/成交（每笔恰好 2 条：1 入 1 出）

| 字段 | 类型 | 单位 | 语义 |
|---|---|---|---|
| `entry_order_seq` / `exit_order_seq` | int | 0 / 1 | 引擎 `trade.orders` 的下标 |
| `entry_order_price` / `exit_order_price` | float | 报价币/USDT 每 1 单位标的 | 成交价（引擎 `safe_price`） |
| `entry_order_qty` / `exit_order_qty` | float | 引擎 `amount`（合约张数） | 实测 `price × qty = USDT 名义价值`（contract size 已隐含为 1） |
| `entry_order_cost` / `exit_order_cost` | float | **USDT，含手续费** | 引擎 `cost`；实测 `cost = qty × price × (1 + fee_side)`，6,790/6,790 成立 |
| `entry_order_fee` / `exit_order_fee` | float | USDT | **派生** `= cost − qty×price`（引擎未单独导出每笔手续费） |
| `entry_order_tag` / `exit_order_tag` | str | — | 入 = 候选 ID；出 = 退出原因（如 `trailing_stop_loss`） |
| `order_id` | str | **恒为 `MISSING`** | 见 §5 |
| `fill_id` | str | **恒为 `MISSING`** | 见 §5 |

### 2.4 止损与切档（**这是本单最容易被误读的部分**）

| 字段 | 类型 | 单位 | 语义 |
|---|---|---|---|
| `initial_stop_effective` | float | 价格 | **真正的初始止损** = 成交价 × 0.95（按价格步进向下取整），取 `stage_trace` 首行 |
| `initial_stop_basis` | str | — | 固定文案，写明来源，防止被当成引擎字段 |
| `engine_initial_stop_loss_abs` | float | 价格 | 引擎导出的同名字段，**恒等于 开仓价×0.01**（3,395/3,395，比值 ∈ [0.0100, 0.0122]） |
| `engine_initial_stop_is_artifact` | bool | — | 3,395/3,395 = `True` ⇒ **禁止使用该字段当初始止损** |
| `effective_stop_final` | float | 价格 | 退出时的生效止损 |
| `effective_stop_max` | float | 价格 | 全持仓期生效止损的最高值 |
| `stop_updates` | int | 次 | 生效止损被重算的次数（合计 16,921 次） |
| `stage_final` | int | 1/2/3 | 退出时所处分档 |
| `n_stage_events` | int | 次 | 切档事件数（193 笔有切档） |
| `stage_path` | str | — | 如 `1→2@2021-12-15T04:00:00Z->2→3@2021-12-17T16:00:00Z`；无切档写 `none` |

> ⚠️ **必须警告下游**：`engine_initial_stop_loss_abs` 是 `stoploss=-0.99` 的配置产物

## 5. 缺失语义（**必须原样展示，不许补零**）

| 字段 | 状态 | 为什么缺 | 补证方法 |
|---|---|---|---|
| `order_id` | `MISSING·导出裁剪` | 引擎在内存里**有** `order_id = str(自增计数器)`（`backtesting.py:940/955`），但导出走 `Trade.to_json(minified=True)`（`bt_fileutils.py:527,535`）把它裁掉 | ① 在回测进程内让策略自行落盘 `trade.orders` 的完整 JSON（需改**隔离策略**，非公共代码）；② 或对 `trade_list_to_dataframe(..., minified=False)` 做一次性离线重导出（需在回测进程内执行，事后无法补） |
| `status` / `filled` / `remaining` / `order_type` / `price` / `order_timestamp` | `MISSING·导出裁剪` | 同上 | 同上 |
| `fill_id` | `MISSING·环境不存在` | 回测没有交易所，不存在成交回报 ID 这个概念 | 只有 dry-run / 实盘才有；回测永远补不出来，**不要用任何自造 ID 冒充** |
| `engine_initial_stop_loss_abs` | 有值但**语义无效** | = 开仓价×0.01，配置产物 | 用 `initial_stop_effective` |
| 逐笔手续费 | 派生 | 引擎未单独导出每笔 fee | 已用 `cost − qty×price` 派生，与 trade 层 `fee_open/fee_close` 对账最大差 6.8e-14 |

### 7.3 必须遵守的三条（否则会画出假图）

1. **`candles_scope` 必须判断**：`trade_windows_union` 是「各笔成交回看窗口的并集」，含断档（实测 AVAX 1h 断档 12,261 根 ≈ 1.4 年），**不能当主图做形态判断**，只能当兜底并提示。
2. **周期源必须取 `display_timeframe`**：现在页面不传 `timeframe`，后端返回 1h，而前端 `bucketCandles(..., sourceSec=900)` 把载荷当 15m ⇒ 15m/30m 两个视图把 1h 的图贴错标签（实测 15m 显示 2548 根，后端原生 10,192 根）。修法二选一见 `out/15_入口核查.json` 的 `4_已知缺陷`。
3. **不要用 `window` 当 K 线轴**：组合 run 的 `window` 是「首笔入场 ~ 末笔出场」或研究期，而单标的 K 线只覆盖该标的自己的成交区间，两者不相等属正常；轴以 `candles_window_shown` 为准。
