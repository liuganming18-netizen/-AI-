# 公共源码改动记录｜`框架/backend/backtest_api.py`

> 本单（WORK-DYNAMIC-BT-02）**唯一**改动的公共源码文件。改动原因、范围、验证、回滚全部在此留痕。
> 前端一律未改（属反重力公共前端），只出接入说明与缺陷定位。

## 0. 为什么必须改（不改就是「假通过」）

首轮实测到的三处**自相矛盾**，任何一处都能让审核与前端得出错误结论：

| # | 现象（实测） | 危害 |
|---|---|---|
| 1 | `/chart` 返回 `candles` 1334 根真实 K 线，同响应里 `what_works` 仍写「candles 为空（结构性限制）」、`chart_partial=true` | 有图却被标成无图；审核无法据此判真假 |
| 2 | 补 K 线的分支把 `exec_timeframe` 改写成**当前显示周期**，与 `spec.exec_timeframe=15m` 冲突 | 执行周期语义被污染（复盘里「按 15m 开盘价撮合」这句话失去依据） |
| 3 | `timeframe=1d` 静默回退成 1h，却把 `display` 标成用户要的周期 | 用错的图冒充对的图 |
| 4 | `symbol=ZZZ`（不在 run 内）仍返回上一轮的「74 标的组合装不进契约」文案 | 原因指向错的对象，误导排查 |

以及本轮新发现的**两处会画出假数据**的路径：

| # | 现象 | 危害 |
|---|---|---|
| 5 | replay 分支 `bars = tfs.get(req_tf) or tfs.get("1h")` | 某笔缺 4h 时把 1h 混进来再标成 4h |
| 6 | 主图直接拿 replay 的 K 线：那是「每笔成交各自回看窗口」的**并集** | AVAX 1h 实测 3 笔成交跨 2021-12/2023-05/2023-09，**断档 12,261 根 ≈ 1.4 年**，是断轴图，不能当主图 |
| 7 | 读取上界 = 末笔成交 + 2 天留白 | 实时市场库比冻结 feather 新 ⇒ 图上出现**回测当时还不存在**的行情（BEAMX 多出 24 根 1h / 6 根 4h / 96 根 15m，全在 2025-01-01） |

## 1. 改动清单（13 个 hunk，+250 / −10 行）

文件：`框架/backend/backtest_api.py`

| 位置 | 改动 | 目的 |
|---|---|---|
| `_run_data_range()`（新增，`lru_cache`） | 读 `inputs.json` 的 `data_summary.time_range_1h` 得本 run 实际消费的数据区间 | 给「不画未来行情」提供裁剪依据 |
| `cm_utc()`（新增） | UTC 毫秒 → 文案 | 只用于说明文本 |
| `_CHART_TF_ALLOWED` + 白名单校验 | `timeframe` 不在 `4h/1h/15m` ⇒ `400` | 拒绝而不是静默回退 |
| `focus_ms` 解析（`get_chart`） | 支持 `?focus_ms=` 按笔聚焦 | 与既有 `_fill_candles_from_market` 口径一致 |
| replay 分支取 K 线 | 只取**请求的那个周期**，缺的记 `candles_skipped_tf` | 不混周期 |
| replay 分支主图 | 改为**市场库连续行情**（`_market_candles_window`），replay 只供逐笔标注；取不到才退回并集并写 `candles_scope=trade_windows_union` + `candles_gaps` | 主图必须连续 |
| replay 分支读取区间 | 按 `_run_data_range` 裁剪，写 `candles_clipped_to_run_data` | 不画回测数据之外的行情 |
| parquet 兜底 | 删掉「缺该周期就拿 15m 顶」；无 `window` 直接报错而不是用 2022~2025 默认值 | 同 5、7 |
| `except Exception: pass` | 改写 `chart["candles_error"]` | 不再吞异常 |
| `_finalize_chart_meta()`（新增） | 有 K 线就 `chart_partial=false` / `blocked_reason=null` / 重写 `what_works`；恢复 `exec_timeframe` 为 spec 真值、另给 `display_timeframe`；给 `candles_bars / candles_scope / candles_gaps / candles_window_matches_run_window / symbol_in_run / requested_symbol` | 响应内部自洽 |
| `_finalize_chart_meta()` 无图分支 | `blocked_reason` 按**本次请求**重写（区分「标的不在 run 内」与「本周期无数据」） | 原因指向对的对象 |
| `_fill_candles_from_market` | 同样按 `_run_data_range` 裁剪，写 `candles_clipped_to_run_data` | 同 7 |

## 6. 追加改动｜`?context_days=N` 上下文行情（BT-KLINE-CONTEXT-01，2026-10-24）

用户指出「只有 7 根 K 线」，选定「扩 ±7 天」。后端**只加不改**：

| 新增 | 作用 |
|---|---|
| `_CONTEXT_DAYS_MAX = 90`、`_TF_STEP_MS` | 参数上限与周期步长（15m/1h/4h 白名单） |
| `_parse_context_days(params)` | 缺省 / 非法 ⇒ **0**（不改变既有行为）；上限 90 |
| `_infer_tf_from_bars(bars)` | 从相邻 `t` 的中位间隔反推周期；认不出就 `None`（**不猜**） |
| `_apply_candle_context(run_id, doc, chart, days)` | 在 run 消费区间**之外**前后各补 `days` 天真实行情 |

关键纪律：

- **run 区间一根不动**：新增两段单独计数（`candles_context_before` / `candles_context_after`），
  并显式给 `candles_window_matches_run_window=false` + `candles_context_note` 说明「这不是本 run 消费过的数据」。
- **预算**：`FT_REPLAY_CANDLE_CAP = 20000`，超了**从离 run 最远的开始砍**（`pre = pre[1:]` / `post = post[:-1]`），
  run 区间不参与裁剪。
- **失败不静默**：补上下文抛异常 ⇒ 只在 `candles_context_note` 写明原因，**保留 run 区间**，不假装成功。
