## 四、04-D 指出的三项退出差异：核查结论

**核查方法**：`scripts/01_退出差异影响核查.py` 纯算术复算两条退出臂，不写账本、不改代码。先用现行语义（A 臂）复算 6 笔真实持仓的 `exit_ts` / `exit_price`，必须与账本**逐位相同**（复现不了就直接判核查无效），再用已定语义（B 臂）复算同一批样本，比较两条臂的差异。

| 差异项 | 04-D 的说法 | 本单核查结果 |
|---|---|---|
| ① 用 4h 最低价判退出 | `paper_engine` 会拿 4h 低点判退出，比 15m 粗 | **样本内未触发**。样本入场都在 4h 中间，且引擎的因果守卫（`ref_close_ms <= entry_ts` 跳过）会屏蔽同一根 4h，实测「4h 路径退出」笔数 = 0 |
| ② 退出时刻落在 15m | 退出时刻应为 15m 收盘 | **两臂一致**。全部样本退出时刻差 0 分钟 |
| ③ 跟踪止损生效顺序 | 4h 收盘后应该下一根 15m 才生效 | **差异真实存在，本样本未走到**。`legacy` 臂把生效时刻放在 4h 收盘本身，`fixed` 臂放在下一根 15m，两者差一根 15m；本样本两臂逐笔相同（时刻、成交价、止损价全同） |

**结论**：`needs_fix=false`（不改 `paper_engine`），但**这不是「没有缺陷」**，只是「缺陷在本样本没被触发」。为免把「没触发」误读成「不存在」，另做了一个路径探针：**入场前同一根 4h 的低点已经 ≤ 初始止损的情形有 17/50 例** —— 说明这条路径真实可达，只是本单的真实入场样本恰好没走到。

**同时保留原行为对照**：研究入口里留了 `legacy_4h_exit=True` 开关，走「4h 低点判退出 + 4h 收盘即生效」，与修正臂在同一份作业上逐笔比对。实测两臂 2 笔全部相同（时刻/成交价/止损价），与 01 号脚本结论一致。

## 五、已确定语义的接线（9 项，逐项对撞引擎生效视图）

| 项 | 生效值 | 来源 |
|---|---|---|
| 确认周期 | 1h 收盘 | 本模块固定 |
| 执行周期 | 15m | 本模块固定 |
| 入场延迟 | 15 分钟 | 引擎 `signal_execution_delay_minutes` |
| 初始止损 | 成交价 × 0.95 | 引擎 `stoploss_s` |
| 跟踪止损幅度 | 5% | 引擎 `trail_d` |
| 跟踪触发 | 入场即跟踪（`R=0`） | 本模块固定，不读配置 |
| 最长持仓 | 不设（退出驱动不调用到期强平） | 本模块固定 |
| 吃单手续费 | 5 bps | 引擎 `fee_each_side` |
| 跟踪止损生效时刻 | 4h 收盘后**下一根 15m** | 本模块固定，`next_15m_after_4h_close` |

这 9 项由 `check_fixed_rules()` 与 `paper_engine.approved_params()` 逐项对撞，任一项不符 ⇒ 配置校验置 `fixed_rules_mismatch` ⇒ 开仓阻塞。**实测把引擎 `stoploss_s` 临时改成 0.04，闸门立刻报 `fixed_rules_mismatch` 并拒绝开仓**（用例 N9）。

**时序细节**：生效时刻 = `(4h收盘毫秒 // 900000 + 1) × 900000`。不能写成「4h 收盘 + 15 分钟」—— 4h 收盘是 `...:59.999`，加 15 分钟会得到 `...:14:59.999`，与 15m 开盘时刻差 1 毫秒，跨口径比对会恒假失败。

## 八、全链验证结果（冷热两条数据链）

三个独立作业，各自独立目录、独立账本，互不污染：

| 作业 | 币种 / 窗口 | 为什么选它 | 结果 |
|---|---|---|---|
| `run_cold` | SOLUSDT 2026-08-01→09-05 | 成交 bar 只能来自**冷档**（热库 15m 从 2026-09-12 才开始） | 2 笔持仓、2 笔平仓、4 笔委托、4 笔成交、2 个候选 |
| `run_hot` | AVAXUSDT 2026-09-12→10-25 | 成交 bar 来自**热库** ⇒ 两条来源都要通 | 3 笔持仓、3 笔平仓、3 个候选 |
| `run_legacy` | 同 `run_cold`，但走旧行为 | 原策略行为对照臂 | 2 笔持仓、2 笔平仓 |
| `run_resume` | 同 `run_cold` 目录、**新进程**再跑一遍 | 恢复能力 | 委托数、成交数前后不变 |

**断言 A–K 全部通过**（逐笔回原始字段，不看自报）：

- **C 入场时序**：`entry_ts` == 成交 bar 开盘；≥ 确认时刻 + 15 分钟；< 确认时刻 + 30 分钟；成交原价 == 候选预测价（逐位相同）。冷档与热库两种来源都出现过。
- **D 初始止损**：== 向下取整（成交价 × 0.95），且只向上移动。
- **E 退出时序**：退出时刻全部落在 15m 收盘；跟踪止损生效时刻按该笔**声明的模式**用各自公式校验（修正臂 19/19 符合「4h 收盘向上取整到 15m」；对照臂 19/19 符合「4h 收盘即生效」）；并断言臂与模式必须对上 —— 修正臂不许落旧模式，对照臂不许落新模式。
- **F 重复**：同一 `signal_uid` 再下一次被挡（`duplicate_signal_uid`）；重复扫描前后委托 4→4、成交 4→4、候选 2→2、**缺口 2→2**，去重事件 2 条。
- **G 重启**：新进程跑同一目录，委托/成交数不变；身份从账本 `paper_position.signal_uid` 恢复（内存里没有候选，只能靠账本）。
- **J 隔离**：生产四本账本与实时信号库 sha 前后不变；研究账本全部在 `runs/` 下；生产账本目录里研究账本 0 个；早前工单自己的研究账本 sha 未变。

- **本轮修掉一个会让这个指标失真的缺陷**：缺口表原来不幂等，重复扫描/重启会把同一条缺口再插一遍。实测冷窗口 2 条缺口被写了 3 遍（表里 6 行），于是「缺口数」会随重跑次数增长，读的人会误以为缺口变多了。现改为按 `(事件, 字段, 起, 止)` 先查后写，并把「重扫前后缺口数相等」加进了断言。

## 十二、剩余阻塞与未验证（不许当成「通过」）

### 12.1 阻塞开仓的三件事（都不是工程问题，需要裁决）

1. **49 项规则参数全部待批**。fixture 里的取值来自 04-A 的推荐值，**推荐不等于批准**。用户批准前，正式配置拿不到，开仓一律阻塞。
2. **两套经济口径未裁决**。策略包（3bps / 2000U / 3仓 / 30% / 0.1%）与生效视图（5bps / 5000U / 10仓 / 10% / 1%）必须择一。本单的处理是「声明哪套就必须全链路严格匹配哪套，不匹配就阻塞」，**没有替用户选**。
3. **13 项待决规则未定**（局部压制位定义、承接基准、扫低回收根数、观察期限、回抽期限、盘中破位取消、入场距离上限、持仓量必要性、重复候选限制等）。这些不定，候选的疏密与真假都无从判断。

### 12.2 未验证的事（明确不计入通过）

- **真实挂钟下的自动成交**：本单全部是回放时钟，没有在真实时间轴上验证过「等一根 15m 收出来再成交」。
- **甲乙丙三组方案的绩效**：本单只证明管道行为，**没有任何绩效结论**。冷窗口 2 笔、热窗口 3 笔，样本量根本不构成统计意义。
- **冷档 15m 的可得时间**：填充率 0%，只能声称「计算不超前」，不能证明「当时可得」。凡涉及严格有效性的成绩，冷档样本都不能计入。
- **4h 低点判退出这条路径的实盘影响**：本样本没触发（17/50 的路径探针说明它可达）。真正要判断影响，需要一批「入场点靠近 4h 边界」的样本。
- **`max_holding_hours=240` 仍在生效视图里并参与视图哈希**，但实际不执行（`max_holding_days=None`）。改它会让人整个实验身份漂移，所以留着没动。

### 12.3 已知未修的相邻问题（不在本单范围，登记备查）

- HTTP 与前端还不认 `4a/4b/4c` 三个研究臂（下单接口会返回 400）。
- 15m 冷档仍无 `available_at`；热库 15m 只从 2026-09-12 起。
- 03-B 登记的三处自写 SQL 仍只读热库。
- `repeat_candidate_limit` 未批准 ⇒ 冷却为 0，候选会比正式规则更密。
