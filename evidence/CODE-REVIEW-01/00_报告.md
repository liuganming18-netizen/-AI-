## 0 结论

你报的两件事**不是同一个问题**，而且第一件比"没留底"更严重：

| 症状 | 真实原因 | 严重度 |
|---|---|---|
| UI 回测"没有留底" | 2135 个运行里 **2127 个没有 `run.json`**；UI 看到的那份"记录"是**读取时用默认值现场合成的**，不是落盘的 | **P0** |
| 日志里"不逐笔订单" | 后端日志 85 行全是 `[adapter]` 预热，**0 条** run/trade 级日志；且 51.6% 的运行本来就 0 笔 | **P1** |

关键区别：
- 逐笔数据**没有丢**。`trades.jsonl` 在，`GET /trades` 能返回（实测 `OPUSDT` 2 笔，带 `order_id` / `signal_id`）。
- 丢的是**"这次运行发生过"这件事本身**——没有 `run.json`，就没有时间、没有参数、没有状态、没有哈希。等于**结果在，档案不在**。

## 1 症状 A：所谓"留底"，是打开页面时现编的

### 1.1 事实

```
回测日志/event_trend_v0_1/runs/     1203 个目录
  ├─ 有 run.json                        8 个
  └─ 无 run.json（读时合成）          1195 个

全工程 回测日志/ 下（含 runs_sep_* 等）：
  扫描 2135 个运行目录 → 有 run.json 8 个 / 无 2127 个
```

### 1.2 机制

`框架/backend/backtest_store.py:327`

```python
def read_run(run_id: str) -> Dict[str, Any]:
    d = read_run_dir(run_id)
    f = d / "run.json"
    if f.exists():
        return json.loads(f.read_text(encoding="utf-8"))
    return _summary_to_run_doc(d, run_id)      # ← 没有 run.json 就现场合成一份
```

`_summary_to_run_doc`（同文件 262–324 行）里：

```python
"status": STATUS_SUCCEEDED,                                          # 266 行：状态写死
"created_at": sm.get("created_at") or sm.get("executed_at") or utc_now_iso(),  # 267 行：时间兜底
"finished_at": sm.get("finished_at") or utc_now_iso(),               # 268 行
"risk_budget_per_trade": 0.005,                                      # 281 行：参数硬编码
"fee_rate": 0.0005,                                                  # 282 行
"slippage_bps": 3.0,                                                 # 283 行
```

### 1.3 实测后果

直接请求 UI 用的那个接口：

```
GET http://127.0.0.1:8787/api/v1/backtests?limit=5
→ 5 条记录的 created_at 全部等于 2026-10-20T15:04:01Z
```

也就是说：**列表里每一条的"运行时间"都是你打开页面的那一刻。**
这解释了为什么看起来"没有留底"——它确实没留，每次刷新重新生成一遍。

更麻烦的是 `config` 里的 `risk_budget_per_trade=0.005 / fee_rate=0.0005 / slippage_bps=3.0` 是**写死的**。如果某个 run 当时用的是别的参数，界面显示的仍是这三个数——**显示的不是实际跑的配置**。

> 补充：这不是新问题。`backtest_api.py:1074` 的注释已经记过一次同类事故：
> "实测后果：2,125 个回测产物目录、登记库 0 条业务记录。"

## 2 症状 B：逐笔没丢，但"日志"里确实一条都没有

### 2.1 后端日志根本没有业务行

```
框架/backend/logs/backend.log
  85 行，全部以 [adapter] 开头（预热耗时）
  含 backtest / trade / run_id 的行数：0
```

所以你说"日志里看不到逐笔订单"是**准确的事实描述**：日志里不但没有逐笔，连"有一次回测"都没有。

### 2.2 逐笔数据其实在，而且能查

```
GET /api/v1/backtests/run_WX_EVENT_TREND_V0_1_OPUSDT_1792273646/trades
→ total 2
  trade_id=trd_c913e33d…  order_id=ord_98c1b468…  net_pnl=+10.27  exit=max_holding_expired
  trade_id=trd_a0181475…  order_id=ord_e1bef4d9…  net_pnl=-9.33   exit=max_holding_expired
```

目录里对应 `trades.jsonl` 2 行、`orders.jsonl` 4 行、`ledger.jsonl` 83 行——**完整**。

### 2.3 一半的运行本来就是 0 笔

`event_trend_v0_1` 是事件驱动（4h 箱体 → 破底扫低 → 缩量回踩 → 突破），信号极稀：

| trades_count | 运行数 |
|---:|---:|
| 0 | **618（51.6%）** |
| 1 | 498 |
| 2 | 78 |
| 3 | 4 |

所以"点开一个回测，逐笔是空的"——**大概率是这次真的没有成交**，不是记录丢了。
两者必须能区分，而现在区分不了，因为没有 `run.json` 里的漏斗（`boxes/sweeps/retests/breakouts/executed_trades`）可看。

### 2.4 还有一处会让人误以为"没有逐笔"

`框架/backend/backtest_api.py:592-598`（图表兜底重建）：

```python
"price": float(t.get("entry_price") or 0.0),
"qty":   float(t.get("qty") or 0.0),
"net_pnl": float(t.get("net_pnl") or 0.0),
"initial_stop": float(t.get("initial_stop") or 0.0),
```

缺字段被填成 **0.0**。一旦走到这条兜底路径，K 线图上会画出**价格为 0 的买卖点**——视觉上就是"没有逐笔"或者"逐笔乱飞"。

## 3 三个根因

| # | 根因 | 位置 | 后果 |
|---|---|---|---|
| 1 | 批量脚本不写 `run.json`，只写产物 | 根目录 `run_batch_*.py`、`run_full_sweep_200x100.py` | 2127 个运行没有档案 |
| 2 | 读接口用默认值补空 | `backtest_store.py:262-324` | 假时间、假参数、假状态 |
| 3 | 没有运行级日志 | 全后端 | 出问题只能靠翻目录 |

根因 1 和 2 是**互相掩护**的：因为没写 `run.json`，读接口就合成；因为能合成，所以没人觉得必须写。这就是"看起来一直有记录"的假象能维持这么久的原因。

## 4 修复清单

### P0（必须先修，否则"留底"永远是假的）

| # | 动作 | 位置 | 验收标准 |
|---|---|---|---|
| 1 | `_summary_to_run_doc` 删掉 `utc_now_iso()` 兜底，缺时间就返回 `null` | `backtest_store.py:267-268` | 列表里不同 run 的 `created_at` 不再相同；缺失显示"未记录" |
| 2 | 删掉硬编码参数，改为从 `summary.json` 实读或 `null` | `backtest_store.py:281-283` | 界面参数 == 落盘参数，逐字段可比 |
| 3 | `status` 不再写死 `SUCCEEDED`，按 `summary.json` 的真实漏斗/退出码判定；判不了给 `unknown` | `backtest_store.py:266` | 失败运行不再显示成功 |

> 第 5 条很重要：**不要给历史目录批量补 `run.json`**。补出来的时间是编的、参数是猜的，等于把假档案洗成真档案。

## 5 标准与门禁怎么防住这一类问题

| 本次事故 | 对应规则 | 门禁编号 | 现在会不会被拦住 |
|---|---|---|---|
| 读时合成假时间 | R2 禁止读时兜底 | `FAB-01` | 会（P0） |
| 硬编码参数冒充实际配置 | R2 | `FAB-02` | 会（P0） |
| 状态写死 succeeded | R10 状态不得冒充 | `FAB-03` | 会（P0） |
| 2127 个运行无档案 | R9 产物必登记 | `REG-01` | 会（P0） |
| 图表缺失值填 0 | R7 缺失即 null | `NULL-01` | 会（P1） |
| 吞异常丢行 | R7 | `ERR-01` | 会（P1） |

**本次门禁实跑结果：P0 = 7 项、P1 = 14 项、P2 = 18 项，退出码 1（阻断）。**
