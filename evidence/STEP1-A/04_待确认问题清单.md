> 这些问题的共同点：**不是我能靠再查一遍数据解决的**，必须由 Codex 拍板，或者必须补一份现在不存在的东西。

## 一、必须先定的三件事（不定就没法往下走）

### Q1｜冻结哪一个代码代际？

- **问题**：现在有 6 个代际（`1e419902` / `4c5a5c58` / `0d300ece` / `f0b18131` / `f24313aa` / `734c505d`）。
  当前工作树只等于 `734c505d`，但这一代**没有提交**。
- **为什么必须定**：不同代际的 `engine.py`、`fill.py`、`engine_adapter.py` 不同，
  旧代际已证实有 41.7% 成交价越界（`BACKTEST-LOSS-03`）。跨代际合并统计没有意义。
- **定了影响什么**：决定 544 个 run 可用、还是 2125 个 run 全部作废重跑。
- **拿什么能定**：
  ① 一句明确指令（「以工作树为准，先提交再冻结」或「退回某个已提交代际」）；
  ② 若选工作树：需要一次提交，把这 5 个文件固化，并记录新的 `code_combined_sha256`。

### Q2｜主对象用「混装池」还是「单一窗口批次」？

- **问题**：`runs` 池有 394 种窗口、438 个标的、6 个代际；而 `runs_sep_all_latest`（528 标的 × 1 窗口）、
  `runs_aug100`（102 × 1）、`runs_2025aug100`（100 × 1）都是干净的单窗口批次。
- **为什么必须定**：混装池无法回答「这是哪一段行情的成绩」；单窗口批次样本又太少（12 / 2 / 6 笔成交）。
- **定了影响什么**：决定验收结论的时间范围与样本量；也决定要不要补跑。
- **拿什么能定**：明确「正式验收以哪个时间窗口为准」，并接受该窗口的成交笔数
  （目前单窗口批次最多 12 笔，远低于冻结规则要求的 100 笔）。

### Q3｜是否要求「统一日历边界 + 60/20/20 时间切分」？

- **问题**：冻结规则 §6 要求全币共用统一日历边界、按 60%/20%/20% 切开发/验证/锁定测试。
  现有 2125 个 run **没有一个**按此切分；`runs_sep50` 甚至是逐币自适应窗口（最早 2020-01-24）。
- **为什么必须定**：没有时间切分就没有「样本外」概念，锁定测试区间也无从谈起。
- **定了影响什么**：决定是否必须重跑（大概率要）；决定能不能声称「样本外」。
- **拿什么能定**：给出三段具体 UTC 起止日期（冻结规则要求「运行前写出具体日期」）。

## 二、参数与口径（改一个字就改结果）

### Q4｜初始资金到底记 2000 还是 10000？

- **冲突**：`config.py` 字段是 2000，全部 run 也是 2000；但同文件注释写「10000 USDT 是本轮研究口径」。
- **为什么必须定**：所有百分比收益、单笔风险金额都随本金变。
- **定了影响什么**：只影响对外表述与报告口径，不影响已有 run 的成交价与 R 倍数。
- **拿什么能定**：一句确认 + 顺手删掉或改正那条注释（本轮不动代码）。

### Q5｜正式口径是「单标的独立账户」还是「组合账户」？

- **问题**：现在全是单标的独立账户（每个 run 2000 本金），而规则里写着组合最多 3 仓、总风险 1.5%、总名义 90%。
  这三条在单标的账户里**从未被检验过**。
- **为什么必须定**：独立账户不能算组合回撤、组合夏普、组合资金费；也不能回答「同时多信号时先做哪个」。
- **定了影响什么**：若要求组合口径，必须新增跨标的撮合层，现有 2125 个 run 全部不能直接用作组合成绩。
- **拿什么能定**：明确「本轮验收只做事件级/单币级」还是「必须做组合级」。

### Q6｜币池用静态名单还是重算前 50？

- **问题**：实际全用静态 JSON（20/50/100/528 个）；规则要求每日 UTC 00:00 按前 30 天成交额重算前 50。
- **为什么必须定**：静态名单有幸存者偏差；`AUDIT-375-V3` 已把「缺流动性筛选凭据」列为红线。
- **定了影响什么**：决定是否要重建历史时点币池（工作量大），也决定现有结论能不能对外说。
- **拿什么能定**：明确「本轮接受静态名单并披露偏差」或「必须重建」。

## 三、对照实验（三套并存，必须选一套）

### Q7｜「四组对照」以哪一套为准？

- **三套现状**：
  - 冻结规则：A（含 OI）/ B（关 OI）/ C（成本压力）——**三组**，B/C 无独立 run 目录。
  - `FLOW-OI-01`：基线 → 流量 → OI → 大户，**阶梯叠加**；结果 +101.53 → +14.72（下降）。
  - `FACTOR-ENTRY-01`：基线 / 流量 / 拥挤度 / 合并，**平行过滤**；结果 +101.53 → +272.55（上升），
    但已被 `FACTOR-ENTRY-02` 判「不成立」（97.5% 改善来自 2022 年指标缺失剔除）。
- **为什么必须定**：三套的分组逻辑不同，同一批 227 候选能得出相反结论。
- **定了影响什么**：决定「因子是否有增益」这个核心结论的方向。
- **拿什么能定**：指定唯一一套，并明确「共同可用样本」的定义（是否剔除 2022 年指标缺失段）。

### Q8｜B / C 变体要不要独立 run 目录？

- **问题**：代码支持 `create_variant_runs`，但所有批次都没开；B/C 的汇总只嵌在 A 的 `summary.json` 里。
- **为什么必须定**：没有独立目录就无法逐笔对账 B/C，也无法单独重跑或审计。
- **定了影响什么**：要开的话需要重跑；不开就只能接受「只有汇总、没有逐笔」。
- **拿什么能定**：明确 B/C 是否需要逐笔证据。

## 四、证据缺口（现在补不出来，只能承认或补做）

### Q9｜合约规格 0 条 verified，正式验收门槛怎么定？

- **现状**：`unverified_historical` 1682、`contradicted` 60、`not_listed` 8、`verified` **0**。
  全部 `formal_pass_allowed = False`。但取整确实用了规格（`spec_status = spec_applied`）。
- **为什么必须定**：这是「成交价是否真实可成交」的根，不是文档问题。
- **定了影响什么**：决定现有 700 笔成交能不能作为正式结果，还是只能当「研究参考」。
- **拿什么能定**：要么补出窗口起点前的规格快照 + 区间内每份变更证据，要么明确「接受 unverified 并降级表述」。

### Q10｜资格审计要不要覆盖其余 1750 个 run？

- **现状**：`AUDIT-375-V3` 只审了 375 个（最老两代、2024H1 窗口），结论 211 违反 / 164 证据不足 / 0 合规。
  其余 1750 个 run（4 个代际、多种窗口）**没有任何资格审计结论**。
- **为什么必须定**：「0 合规」这个结论目前只对 17.6% 的样本成立，容易被误读成全量结论。
- **定了影响什么**：决定要不要再出一份覆盖 2125 个 run 的审计。
- **拿什么能定**：明确「只认 375 个」还是「必须全覆盖」。

### Q11｜83 个被后写的图 + 469 个缺图，是否影响冻结？

- **现状**：`runs` 池 83 个 `chart.json` 比同目录其他文件晚约 7 小时（例：12:44 vs 05:53）；
  469 个目录没有 `chart.json`。
- **为什么必须定**：图是「成交落在 K 线区间内」这类核对的唯一可视化证据。
- **定了影响什么**：决定这 83 个能否作为原始证据，469 个要不要重建。
- **拿什么能定**：确认「图不作为验收证据，只以账本与 K 线原件为准」，或要求重建。

### Q12｜0 成交批次怎么判定？

- **现状**：`runs_sep50_full`（50 个 run）与 `runs_sep50_strict`（50 个 run）**全部 0 成交**，
  报告层没写是「无候选」还是「候选被拒」。
- **为什么必须定**：0 成交可能是策略正常（没信号），也可能是链路故障（全被拒）。
- **定了影响什么**：决定这 100 个 run 是「有效空样本」还是「无效运行」。
- **拿什么能定**：读 `funnel` 与 `rejects.jsonl` 分类统计（本轮未做，属可补的证据）。

### Q13｜`FLOW-OI-01` 是否按 `close_time` 重跑？

- **现状**：227/227 用了未收盘 1h K 线（信号时刻正好是开盘那一秒，当根还有 60 分钟没走完），
  metrics 也 227/227 用了未结束的 5 分钟桶。四组结果建立在含未来信息的特征上。
- **为什么必须定**：这是前视偏差，不是口径争议。
- **定了影响什么**：重跑会改变四组的每一笔过滤判定，结论可能完全反转。
- **拿什么能定**：一句「重跑」即可；具体改法已登记在 `evidence/FLOW-DATA-01/04_独立抽查与差异.md`。
