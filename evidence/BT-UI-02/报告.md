### ② 全池 2,125 个 Run 缺图深度归因与最小修复
* **全池结构统计**：
  - 8 个批次共 2,125 个 run 目录。
  - 7 个专属批次（共 932 个 run）静态 `chart.json` 覆盖率 100%。
  - 默认目录 `runs/`（1,193 个 run）中，729 个存在静态 `chart.json`，464 个缺失。
* **464 个缺图归因与验证**：
  - 归因原因：100% 为回测脚本离线导出时未生成静态 `chart.json` 文件。
  - 底层数据完整性：464 个标的底层 parquet 15m K 线与时间窗口完整率 100%，真实缺 K 线的 run 为 0。
  - 解决方案：后端通过 `_fallback_chart_cached` 命中 parquet 底表，120ms 内读时动态重建 15m 蜡烛线与打点，完全自愈，不修改磁盘也不伪造 K 线。
* **83 个历史写死错图被拦截**：
  - 发现历史遗留的 83 个 run 被写死了 `2024-01-01 ~ 2024-06-30` 的假窗口。
  - 最小修复：增加 `_chart_window_reject_reason` 进行安全拒收，强制按该 run 自身的真实 `inputs.json` 动态补画，杜绝时间错位。
* **交付证据**：`evidence/BT-UI-02/缺图原因统计.json` 与 `缺图原因统计.md`。
