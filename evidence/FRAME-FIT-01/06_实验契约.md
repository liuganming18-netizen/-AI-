# 实验契约（FRAME-FIT-01）

本文件定义「一个实验」在框架里到底是什么。任何绕过这里的做法都不被承认。

---

## 一、两层身份

### 设计身份（design_identity）

由六项派生，任一项变化 ⇒ **新身份** ⇒ 不能继承旧结果：

| 组成 | 来源（复用现有机制，不另算一套） |
|---|---|
| 策略标识 / 版本 | `EventTrendConfig.strategy_name / strategy_version` |
| 代码版本 | `EventTrendRunner.code_fingerprint()["combined_sha256"]`（18 个文件） |
| 参数 | `EventTrendRunner.config_fingerprint(cfg)["sha256"]`（49 个字段） |
| 冻结规则 | `EventTrendRunner.rules_fingerprint()["sha256"]` |
| 样本范围 | 标的清单（去重升序）+ 窗口起止 |
| 分组规则 | `SplitPolicy.sha()`（三段区间 + 隔离长度 + 划分方式） |
| 评价指标 | 指标定义字典（主指标 / 次指标 / 成本口径） |

算法：`sha256(canonical_json({六项}))`。缺项**不补默认值**，记 `None` 进哈希，
并单独列出缺项供闸门拒绝 —— 「没给」与「给了空」必须能区分。

### 运行身份（run_identity）

`sha256({design_identity, data_sha256})`。

数据指纹跑完才知道（要读 K 线），所以**不进冻结**。冻结锁的是设计身份，
运行身份把「这一次实际用了哪份数据」钉在结果上。

---

## 二、事件流（append-only）

文件：`<登记库根>/events.jsonl`，一行一个事件，带哈希链：

```json
{"seq": 0, "prev": "000…0", "event": {...}, "hash": "sha256(seq+prev+event)"}
```

`head.json` 记 `{count, last_hash}`。删改中间行断链，截断末尾与 head 不符。
`verify()` 重算全链；`state()` 先 `verify()`，不通过就抛 `RegistryTampered`。

事件类型（只增不改）：

| 类型 | 记什么 |
|---|---|
| `register` | 实验 ID、父实验、设计、设计身份、样本范围、分组规则、指标、分组标记、模式 |
| `freeze` | 冻结时刻 + 被冻结的设计身份 |
| `invalidate` | 冻结失效（实测身份 ≠ 冻结身份）+ 原因 |
| `run` | 绑定一次运行：run_id、数据指纹、运行身份、实际样本范围 |
| `trial` | 试验结论：成功/失败/放弃/无效 + 指标 + 分组角色 |
| `abandon` | 明确放弃 + 原因 |
| `observe` | 某批样本「已被查看/比较/用于调参」+ 样本键清单 |
| `unseal` | 解封最终留出的时刻 + 当时的身份 |

**没有 `update` / `delete`**。改配置的唯一合法路径是登记新实验 + 写 `parent_experiment_id`。

## 三、分组规则（SplitPolicy）

三段：`train` / `valid` / `holdout`，各为 `(起, 止)`，闭区间，**时间顺序**。

`validate()` 检查五件事，任一不满足 ⇒ `configured = False`：

1. 三段都给了（缺一段不算配置）；
2. 日期可解析且起 ≤ 止；
3. 划分方式必须是 `chronological`（本框架不接受随机切分 —— 时序数据随机切会直接泄漏）；
4. 相邻段不重叠、不相接；
5. 相邻段间隔 ≥ 隔离长度。

`isolation_hours` 不给 ⇒ 直接判未配置。**不填默认天数。**

### 隔离长度怎么定

```python
required_isolation_hours(spans) -> max(spans) 向上取整到整小时
```

`spans` 来自真实成交的 `exit_time_ms - entry_time_ms`。无有效跨度 ⇒ `None`（UNKNOWN），
不猜。向上取整而不是四舍五入：隔离少 1 小时就是泄漏。

本单实测 = 240 小时（详见 `04_拟议划分及依据.md`）。

### 泄漏检查

`check_leakage(rows, policy, observed_keys)` 查三类：

1. **标签跨界**：某样本出场时刻越过**后一段的起点** ⇒ 阻断。
   落在隔离带内不算跨界 —— 隔离带的作用就是吸收这段尾巴。
2. **重复样本**：同 `(symbol, entry_ms)` 出现多次 ⇒ 阻断（同一次机会只能算一条）。
3. **已观察样本进了留出段** ⇒ 阻断。

未配置的划分**不做检查**，直接报「无法进行泄漏检查」，不假装查过。

## 四、闸门语义

### 创建入口 `guard_create(spec)`

| 模式 | 行为 |
|---|---|
| `research`（缺省） | 允许创建；自动登记一条实验；`formal_eligible` 恒 `False`，原因逐条透出 |
| `formal` | 必须有已登记实验 ID、已冻结、身份一致、分组已配置、留出未污染；否则 **409** |

研究模式放行是刻意的：不让跑就等于让所有研究停摆。但它**永远拿不到正式资格**，
这一条写死在返回值里，调用方改不了。

### 执行入口 `guard_execute(run_id, doc)`

跑之前查两件事：

1. 该 run 是否绑定到**已登记且已冻结**的实验（未绑定 / 未冻结 / 已放弃 ⇒ 拒绝）；
2. 登记身份与**当前**代码/参数/样本是否一致（防「登记后改代码再跑」）。

不一致 ⇒ 写一条 `invalidate` 事件（冻结失效）+ 拒绝执行。
拒绝时 run 直接标 `failed`，**不产出任何结果文件**。

## 五、正式资格 `formal_eligible`

同时满足才给，缺一条都不给：

- 模式是 `formal`；
- 六项设计成分齐全（无缺项）；
- 分组已配置且自洽；
- 已冻结；
- 未放弃；
- 至少一次已登记运行；
- 有试验结论记录（失败也要记 —— 「只留赢家」不算合格）。

返回 `(bool, reasons)`，`reasons` 必须原样透出，不许只报一句「不通过」。

---

## 六、几个刻意的「不给」

| 情形 | 处理 | 为什么不给 |
|---|---|---|
| 同一设计身份再登记一次（换个 ID） | 拒绝 | 否则等于用新名字继承旧结果 |
| 冻结两次 | 拒绝 | 第二次会掩盖冻结后的改动 |
| 解封两次 | 拒绝 | 留出只能看一次 |
| 运行前填数据指纹 | 不支持 | 跑前算不出来，填了就是编 |
| 未配置划分就解封 | 拒绝 | 没有划分就没有「留出」这回事 |
| 历史 run 补登记 | 不做 | 工单第 6 条：缺历史标 UNKNOWN，不补造 |

---

## 七、这框架**不**保证什么

- 不保证不过拟合。反复试错仍然可能过拟合，框架只让试错留痕。
- 不保证身份不可伪造。有人手工改 `events.jsonl` 并重算全链，链是自洽的 ——
  这属于主动伪造，不是「静默改写」。静默改写（改一行、删一行）会被发现。
- 不保证策略代码一定走受控入口。同进程代码仍可直接 `pd.read_parquet`；
  本框架约束的是**经过闸门的启动**。
