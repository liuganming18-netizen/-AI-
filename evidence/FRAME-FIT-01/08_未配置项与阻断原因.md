## 二、结构性未配置项（不是这次忘了填，是确实还没有）

| 项目 | 状态 | 说明 |
|---|---|---|
| 正式划分日期 | **UNCONFIGURED** | 框架只给候选（60/20/20 与 70/15/15），切哪天由人定。未定 ⇒ 没有「留出」这回事 ⇒ 不给正式资格。 |
| 解封方案 | **UNCONFIGURED** | 谁有权解封、解封后多久必须登记结果、解封后能否再改参数 —— 这三条没有契约。机制已实现（一次性解封 + 冻结前置），方案本身待定。 |
| 执行链样本范围 | **缺陷** | `_run_event_trend` 写死 2024-01-01~2024-06-30，请求窗口不生效。登记范围与实际范围脱节 ⇒ 身份再准也绑不上真实样本。本单不修，只阻断。 |
| 参数注入 | **缺陷** | 同一函数只把 `initial_equity` 传给配置，其余 48 个参数在事件趋势链上不生效。「改参数换身份」机制成立，但改参数不会改变结果 ⇒ 试验册会记下大量「不同身份、相同结果」的条目。这一条要在修好注入后才能解读。 |
| 227 条样本的干净留出 | **不可得** | 样本横跨 2021-12 ~ 2026-10。任何覆盖全区的划分，留出段都会命中已观察样本（60/20/20 命中 57 条，70/15/15 命中 43 条）。要干净留出只能等新行情或换标的池。 |
| 历史 2130 个 run 的设计身份 | **UNKNOWN** | 它们发生在登记库存在之前。工单第 6 条：缺历史标 UNKNOWN，不补造。它们只作为「已发生的事实」保留，不得被追认为某次正式实验的结果。 |
| 四组实验计划的正式文件 | **不存在** | 冻结规则 A/B/C、FLOW-OI-01 阶梯四组、FACTOR-ENTRY-01 平行四组 —— 三套都只存在于代码变体与证据目录里，没有一份带分组规则/指标/试验次数的计划书。本框架用 `group` 字段预留位置，历史三套一律标 UNKNOWN。 |
| 数据版本（运行前） | **不可得** | 数据指纹要读 K 线才能算。跑前只能冻结设计身份，跑后再绑运行身份。这不是缺陷，是时序决定的。 |
| 规格历史资格 | **0 条 verified** | STEP1-A 已实测：全池 `verified` = 0（缺 spec_changes 覆盖证据）。规格不合格 ⇒ 即使实验身份齐全，成交价的可信度仍另说。 |
| PIT 接入 | **并行窗口进行中** | 本单边界内不动 PIT 代码。`trading_core/pit.py` 与新增的 `pit_bridge.py` 一个字没改。 |

## 三、结论

按现在的状态，**任何一个正式实验都拿不到资格**，最短的阻断链是：

1. 没有批准的划分日期 ⇒ 分组未配置；
2. 就算配了划分，执行链写死窗口 ⇒ 登记范围 ≠ 实际范围；
3. 就算窗口对上了，留出段仍含已观察样本 ⇒ 该段不能声称未见；
4. 就算以上都解决，历史 run 无身份、规格 0 条 verified ⇒ 结果仍不能对外。

这不是框架太严，是这四件事本来就没做完。框架的作用是把它们**摆出来**，
而不是让人在文档里含糊过去。
