## 二、怎么装

把 `data/freqtrade/` 整体作为 Freqtrade 的数据目录使用（`--datadir` 指向它），或用软链把 `futures/` 挂到 `user_data/data/{交易所}/futures/`。
文件名已按现行规则生成：`{配对名，"/" 与 ":" 换成 "_"}-{周期}-{类型}.feather`。

关键配置：

| 配置项 | 值 | 说明 |
|---|---|---|
| `trading_mode` | `futures` | 数据在 `futures/` 子目录，现货模式找不到 |
| `margin_mode` | `isolated` | 杠杆 1.0，逐仓与全仓在 1 倍下无差别；若你用全仓请写明 |
| `stake_currency` | `USDT` | |
| `timeframe` | `15m` | 执行周期 |
| informative | `1h`、`4h` | 箱体用 4h，扫低/突破用 1h |
| 蜡烛类型 | `futures`、`funding_rate`、`open_interest`、`mark` | 四类都已导出。OI 是 5m，mark 是 1h |
| `startup_candle_count` | `3520` | 15m 根数，等于 220 根 4h × 16。导出区间实际提供 3,552 根，够用 |
| `max_open_trades` | `3` | |
| `tradable_balance_ratio` | `1.0` | |
| `dry_run_wallet` | `2000` | 初始资金 |
| 回测区间 | `--timerange 20250801-20251231` | |
| 配对 | `AR/USDT:USDT`、`BANANA/USDT:USDT`、`BAT/USDT:USDT`、`CTSI/USDT:USDT`、`PUMPBTC/USDT:USDT` | |

**必须实现的一件事**：仓位不能用 FT 默认的 `stake_amount`。要用 `custom_stake_amount` 实现

```
qty = 当时权益 × 0.005 ÷ (入场价 − 初始止损价)
```

再按单仓 30%、总名义 90%、参与率 0.1%（读 sidecar 的 15m 成交额）截断。
不实现这一条，数量对不上，后面全部对不上。

## 三、请交回什么

| 项 | 要求 |
|---|---|
| 逐笔交易 | 每个标的的入场时间、入场价、出场时间、出场价、数量、出场原因 |
| 成本五项 | 入场费、出场费、滑点损失、取整损失、资金费，分开列 |
| 权益曲线 | 逐 bar 或逐 15m 的账户权益，用于算真实回撤 |
| 运行配置 | 完整 config 与策略文件 |
| 版本 | Freqtrade 版本号、策略文件 sha256 |
| 原始输出 | 回测导出的 trades 与 stats 原文件，不要只给汇总数字 |

**不要只给总收益。** 没有逐笔就无法定位差异，也无法判断差异是引擎实现不同还是口径不同。

## 四、收到之后我做什么

按 `01_冻结比较规则.md` 第七节的顺序：
① 先核对是不是同一批交易（笔数、入场时间）→ ② 价格与数量 → ③ 成本五项 → ④ 汇总指标 → ⑤ 差异分类。

**不强求两套总收益一致。** 能归因到已知口径差异（mark 粒度、历史合约规格假设、资金费结算间隔混合）就记录并说明，不为对上而改口径。

## 五、四个必须提前知道的限制

1. **本窗口只有 5 笔可比对成交**（5 个标的各 1 笔）。回撤、胜率、PF 在这个样本量下没有判别力，本轮只核对「算的是不是同一件事」。
2. **所有数据都没有发布时点证据**（`available_at` 全 None、`fetched_at` 全空）。只能按收盘/桶结束假设，结果不具备 PIT 正式资格。
3. **OI 在 2025-08-29 06:20–06:30 UTC 全池缺 3 桶**，已按原样保留未补齐。若 FT 侧对缺数据做填充，会造成差异，请勿填充。
4. **mark 蜡烛是「一个价格填四列」**：源只有每小时一个 `mark_open`，导出时写进 open/high/low/close、volume=0。不要把它当成真实的四个价格去做波动类计算。
