**用途**：在收到 FT 结果之前先把口径钉死，避免事后按结果调口径。
**状态**：已冻结，等待 FT 基线。收到结果后只按本文件重算，不新增指标、不改公式。

所有数值取自 `策略/WyckoffMaster/event_trend_v0_1/config.py`（冻结规则 `sha256:1f1167de…9a8ab`），不是本轮新设。

| 项 | 值 | 来源 |
|---|---|---|
| 初始资金 | **2,000 USDT** | `initial_equity = 2000.0` |
| 杠杆 | **1.0 倍** | `max_leverage_per_symbol = 1.0`（引擎默认值） |
| 每笔风险预算 | **权益的 0.5%** | `risk_budget_per_trade = 0.005` |
| 最大同时持仓 | **3 仓** | `max_active_positions = 3` |
| 同币最大持仓 | **1 仓** | `max_symbol_positions = 1` |
| 总风险预算上限 | **1.5%** | `max_total_risk_budget = 0.015` |
| 总名义金额上限 | **权益的 90%** | `max_total_notional = 0.90` × 杠杆 1.0 |
| 单仓名义上限 | **权益的 30%** | `max_notional_per_position = 0.30` |
| 参与率上限 | **前一根已完成 15m 成交额的 0.1%** | `max_participation_of_prev_15m_quote = 0.001` |

### 1.1 仓位公式（必须照这个算，否则不可比）

```
单位风险 unit_risk = 入场成交价 − 初始止损价
下单数量 qty       = 当时账户权益 × 0.005 ÷ unit_risk
```

再用上面三条上限截断：单仓名义 ≤ 30% 权益、总名义 ≤ 90% 权益、订单名义 ≤ 前一根 15m 成交额的 0.1%。
最后按价格步长取整（见第四节）。

**这一条是本次比对最容易出错的地方**：Freqtrade 默认的 `stake_amount` 是固定金额或按可用余额分配，**不等于**「权益 × 0.5% ÷ 风险距离」。
必须在策略里用 `custom_stake_amount` 实现上式，否则成交数量对不上，后面所有金额都对不上。

### 1.2 未知项（标待定，不自行补默认值）

| 项 | 状态 | 处理 |
|---|---|---|
| 历史合约规格（价格步长、最小下单量） | **待定** | 只能用当前规格假设；PRECISION-04 显示 576 次运行 0 个 verified，所以这是假设不是事实 |
| 资金费的实际计价方式（FT 侧） | **待定** | 见第三节，允许差异 |
| 部分成交与排队 | **不建模** | 两套引擎都按「全量成交」处理，属共同简化 |

## 二、成本口径（四类必须拆开报，不许合并成一个数）

| 成本 | 值 | 说明 |
|---|---|---|
| 手续费 | **taker 5 bps**（0.0005） | `taker_fee_bps = 5.0`。本策略全部市价进出，不用 maker |
| 滑点 | **3 bps**（0.0003） | `slippage_bps = 3.0`，买加价、卖减价 |
| 取整损失 | 按价格步长 | 买 `ROUND_CEILING`、卖 `ROUND_FLOOR`；与滑点分开记，不并入滑点 |
| 资金费 | 真实结算事件 × mark 价格 | 缺 rate 或 mark 时记缺口，**不补 0** |

压力档（仅方案 C 用，本次不用）：手续费 10 bps、滑点 6 bps。

**比对要求**：逐笔给出「入场费、出场费、滑点损失、取整损失、资金费」五项，不能只给一个「总成本」。
旧引擎的对应字段在 `out/05_旧引擎基准成交.csv` 里已经拆好，可直接对照。

## 三、资金费（允许差异，但要能解释）

- 结算时刻用**真实结算事件**，不用固定周期近似。
- 计价用**结算时点的 mark 价格**。
- 包里同时给了 `-1h-mark` 蜡烛（每小时一个值）与 sidecar 里的结算时点 mark。前者供 Freqtrade 装载，后者是精确值（含毫秒偏移），核对时以 sidecar 为准。
- **资金费金额不要求逐笔完全一致**；要求一致的是：结算次数、每次结算的费率、结算方向（多付还是空收）。若金额差异超过一个数量级，先查是不是按固定周期重采样了——那是转换错误，不是策略差异。

## 四、撮合与价格

| 项 | 规则 |
|---|---|
| 入场时点 | 1h 突破收盘确认后，**下一根 15m 开盘**（严格更晚，不是同一根） |
| 入场取消 | 开盘价 > 突破收盘价 + 0.5 × ATR 则取消 |
| 初始止损 | `P0 = 回踩低点 Lr − 0.1 × ATR` |
| 跟踪止损 | 浮盈达 2R 后，用最近 10 根 4h 的最低价作新止损，**下一根 15m 生效** |
| 最长持仓 | 10 个自然日（240 小时），到点按市价平 |
| 结束时处理 | 窗口末尾未平仓位按市价强平，计入成交 |
| 价格取整 | 买向上取整、卖向下取整，按价格步长 |
| 跳空保护 | 出场只用开盘价判断跳空，不在跳空时用理论止损价成交 |

## 五、共享账户 与 独立固定仓位配对（必须分开写，不能混）

这是两个完全不同的口径，**任何情况下都不能相加**。

### 5.1 共享账户回测（本包基线口径）

- 所有标的共用一个 2,000 USDT 账户。
- 权益随已实现盈亏和浮盈浮亏变化，**后开的仓位按当时的权益算数量**。
- 仓位之间有耦合：一笔亏损会缩小后面所有仓位的规模。
- **Freqtrade 回测天然是共享账户**，所以本包与 FT 可以直接比。
- 组合回撤必须基于**逐 bar 盯市的真实权益曲线**算，不能用逐笔累计盈亏算。

### 5.2 独立固定仓位配对（不是组合）

- 每个信号**单独回放一次**，账户初始权益固定为 1,000,000（只影响风控放行，不影响净额）。
- 数量锁定为 A 组的 `fixed_qty`，所有对比组用同一个数量。
- 目的是比较「规则变体的差别」，**不是**衡量组合表现。
- **禁止**把这些独立交易的收益相加后称为「组合收益」或「组合回撤」。
- 这套实现位于 `evidence/BREAKEVEN-02/code/be_core.py` 与 `02_run_fixed.py`，**不在策略包内，也不参与代码指纹**，所以引用时必须单独声明版本。

**本轮给 FT 的是 5.1，不是 5.2。**

## 六、指标定义（收到结果后按这几个式子重算，不采用对方自报口径）

| 指标 | 定义 | 常见错误 |
|---|---|---|
| 净收益 | 逐笔 `net_pnl` 之和；单笔 = 出场净额 − 入场成本 − 手续费 − 滑点 − 取整 − 资金费 | 用毛收益代替净收益 |
| 回撤 | 逐 bar 真实权益的峰值回撤（含浮亏） | 用逐笔累计曲线算，会低估 |
| 胜率 | `net_pnl > 0` 的笔数 ÷ 总笔数 | 用毛收益判胜负 |
| 盈亏比（payoff） | 平均盈利 ÷ 平均亏损绝对值 | 与利润因子混称 |
| 利润因子（PF） | 总盈利 ÷ 总亏损绝对值 | 与盈亏比混称 |

**PF 与盈亏比不是一回事，报告里必须分别写、分别命名。**

## 七、核对顺序（收到 FT 结果后照这个顺序做，不跳步）

1. **先核对是不是同一批交易**：交易笔数、每个标的的入场时间。入场时间对不上，后面全部不用比。
2. **再核对价格与数量**：入场价、出场价、数量。数量对不上先查仓位公式（1.1 节）。
3. **再核对成本五项**：入场费、出场费、滑点、取整、资金费。
4. **最后才核对汇总指标**：净收益、回撤、胜率、盈亏比、PF。
5. **差异分类**：属于「引擎实现差异」还是「口径差异」。口径差异（资金费计价、历史规格）不算错误，但要写明。

**不强求两套总收益一致。** 若差异能归因到已知口径差异（第三节、1.2 节），就记录差异并说明原因，不为了对上而改口径。
