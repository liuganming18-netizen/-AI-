# SYSTEM-CLOSELOOP-03｜01 执行身份映射与变更说明

## 1. 任务背景与核心目标

在本次闭环审计及修复中，针对此前 `AUDIT-02` 报告指出的「执行身份混乱、前端展示与后端执行脱节、模拟盘声明固定止损而回测执行跟踪止损」等系统性缺陷，确立了以下统一准则：
- **禁止混用规则**：确立唯一的真实执行身份映射链路，坚决杜绝“展示一套、执行另一套”。
- **规则明确落地**：隔离接入用户确认的 **FT-LOW4H** 跟踪退出规则。
- **保护生产账本**：对生产环境各 Arm 账本实行 100% 隔离，不改变日常默认开仓闸门，不启动真实交易。

## 3. FT-LOW4H 跟踪退出规则规范

本轮隔离验收接入用户已经确认的 **FT-LOW4H** 规则：

$$\text{Initial Stop} = \text{Fill Price} \times (1 - s)$$
$$\text{Candidate Stop} = \text{Low}_{4h} \times (1 - d)$$
$$\text{Effective Stop} = \max(\text{Initial Stop},\, \text{Previous Stop},\, \text{Candidate Stop})$$

### 规则执行细则：
1. **入场即跟踪**：买入成交并建立持仓后立即生效初始止损，**无 2R 盈利门槛**，**无 240 小时超时强平退出**。
2. **只上不下单调性**：新 4 小时 K 线收盘后，若候选价格低于当前已生效止损，保持当前止损不变，不记录下移、不修改持仓。
3. **真实引擎推进**：严禁通过外部绕过撮合核心手工 `INSERT` 止损记录。所有止损上移必须通过 `PaperEngine.advance_position_trailing()` 计算并驱动。
4. **强关联平仓订单**：当价格击穿止损线退出时，撮合核心必须先创建平仓 `paper_order`（方向为 `sell`），再生成 `paper_fill` 并将 `order_id` 强关联，彻底杜绝平仓成交订单号为 NULL 的漏洞。

## 4. 关键代码变更说明

### 4.1 核心修复清单
1. **`框架/backend/paper_engine.py`**：
   - **挂单推迟根因修复**：修正 `open_position` 中 `order_request_ms` 错误计入 `attempt_ms` 的逻辑，防止挂单每次推进时被向后顺延 15 分钟导致无法撮合。
   - **FT-LOW4H 计算接入**：支持基于 $s$ 计算初始止损，基于 $d$ 与 4h K 线计算跟踪止损。
   - **平仓订单强关联**：重构 `close_at_price()`，平仓时先行生成 `paper_order`，获取其 `order_id` 并存入 `paper_fill.order_id`。
   - **全生命周期推进**：新增 `advance_position_trailing()`，负责读取最新收盘 4h K 线、计算候选止损、落盘 `paper_stop_history`、更新持仓，并在击穿时自动平仓。

2. **`框架/backend/live_api.py`**：
   - **因果与安全防线**：增加 `signal_uid` 必须存在于数据库的可信防线；校验标的一致性；拦截客户端请求时间小于 `available_at` 的未来时钟穿梭请求。
   - **移除陈旧口径**：全面清理代码中“固定止损、trailing关闭”的历史陈旧注释与硬编码分支。
   - **暴露统一执行端点**：提供 `GET /api/v1/paper/identity` 查询当前执行策略版本；挂载 `POST /api/v1/paper/advance_trailing` 支持显式推进与回放触发。

3. **`框架/backend/live_store.py`**：
   - 加性扩展字段 `voided INTEGER DEFAULT 0` 和 `void_reason TEXT` 至 `paper_realized`、`paper_order`、`paper_fill`、`paper_pending`。
   - 过滤查询确保作废记录不参与账户权益核算，旧测试脏数据得到证据保留与正式绩效排除。

4. **`UI界面/web/src/components/PositionPanel.tsx`**：
   - 新增「FT-LOW4H 止损轨迹」可折叠面板及实时查询组件，展示初始止损、最新止损、上移历史（时间戳、引用 K 线价格、候选值、生效值）。
