### 2.3 时间戳语义与单位（02.A / 02.B 全文结论）

**时间戳**：`ts` 是 5 分钟桶的**起点**，桶收盘 = ts + 300000ms。依据三条：①99.99% 的行 ts 能被 300000 整除；②相邻 ts 差恒为 300000；③采集器写入 5m 口径时用的判据就是 `ts + 5min <= now`。少量非对齐行来自 `snapshot` 类抓取（同一序列的另一条落库口径），决策只读 `period='5m'`，不受影响。

原始来源：GET https://fapi.binance.com/futures/data/openInterestHist?symbol=<SYM>&period=5m&limit=N；落库判据：`if ts + OI_5M_MS > now: continue` —— 桶没结束就不写 '5m' 口径；这条判据本身就说明 ts 是**区间起点**（ts+5min 才是收盘）。

**单位**：比值/价格 全部接近 1 ⇒ `open_interest` 是**币本位数量**、`open_interest_value` 是 **USDT 名义额**；状态机 `oi_min_growth_pct` 用的是数量增长，与读取器 `OI_VALUE_COLUMN` 一致，不存在「拿张数当币数」「拿数量当金额」的混用。

两件都不是「看字段名猜」得出的，是从原始表反证出来的：
时间戳靠「能否被桶宽整除 + 相邻差是否恒定」；单位靠「`open_interest_value / open_interest`
是否等于同期价格」。前者错会把 5 分钟桶的收盘价当成观测值，后者错会让 OI 增幅差几个数量级。

01.C 那个决策点（BTCUSDT，2026-10-11T20:00:00Z）的窗口实测：353 行 `late`、9 行 `future`
（与 §2 第 6 行 02.C 的四态不是同一个窗口，不可直接相加）。

## 8 报告数字双向对撞

见 `out/07_报告数字对撞.json`。两条规则：

1. **正向**：正文里每个登记过的数字，必须与产物字段格式化后的字面量**完全相同**；
2. **反向**：正文里任何 3 位以上的数字（时间戳除外），必须能在某个产物字段里找到来源，
   否则说明「报告写了一个产物里没有的数」——上一批工单靠这条抓出 4 处抄错。

对撞规则已在上文 §8 说明，机器结果写在 `out/07_报告数字对撞.json`：
正向（登记事实必须出现在正文）与反向（正文 3 位以上数字必须能追到产物）各若干条，
