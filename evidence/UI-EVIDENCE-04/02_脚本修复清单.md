## P1｜manifest 缺失显式化（对应 `01` C2）

**原代码（问题）**

```python
manifest_data = json.load(open(manifest_path)) if manifest_path.exists() else {}
```

manifest 不存在时静默变成空对象，后续流程完全不知道它缺了，于是 CSV 照写「manifest.json / …」。

**修复后**

```python
if manifest_path.exists():
    manifest_data = json.load(open(manifest_path))
    manifest_status = "present"
else:
    manifest_data = {}
    manifest_status = "missing"
    print(f"  [WARN] manifest.json 缺失：{manifest_path}（源侧无官方哈希，只能记未验证）")

manifest_summary_sha = None
if manifest_status == "present":
    manifest_summary_sha = (((manifest_data.get("files") or {})
                             .get("summary.json") or {}).get("sha256"))
run_hashes = (run_data.get("hashes") or {}) if isinstance(run_data, dict) else {}
official_summary_sha = manifest_summary_sha or run_hashes.get("summary.json") or None
```

并区分两种哈希：

| 字段 | 含义 |
|---|---|
| `summary_sha256` + `summary_sha256_source = "computed_by_test_script"` | 脚本对本地文件实算 |
| `official_summary_sha256` + `official_sha_source` | 官方来源（`manifest.json` / `run.json.hashes` / `missing`） |

**manifest 缺失时一律写 `missing`，不造文件、不补哈希。**

```python
_pngs = sorted(EVID_DIR.glob("*.png"))
_png_hash_map = {}
for _x in _pngs:
    _png_hash_map.setdefault(file_sha256(_x), []).append(_x.name)

png_dup_groups = {k: v for k, v in _png_hash_map.items() if len(v) > 1}
```

正文：

## P7｜新增源码 / 构建产物版本绑定（对应 `01` C5）

新增 `collect_version_binding()`，产出 `09_源码与构建产物版本绑定.json`：

| 绑定项 | 内容 |
|---|---|
| `frontend_src` | `UI界面/web/src/**` 逐文件 SHA-256 + 目录树 SHA-256 + 文件数 |
| `frontend_dist` | `UI界面/web/dist/**` 同上，另记 `newest_mtime` |
| `backend` | `adapter.py` / `live_api.py` / `live_store.py` / `unified_runtime.py` / `service_manager.py` / `paper_engine.py` / `strategy_contracts.py` 的 SHA-256、大小、mtime |
| `test_script` | 测试脚本自身的 SHA-256 |

目录树哈希算法：`按相对路径字符串 + 该文件 SHA-256 依次 update 进同一个 sha256()`，保证目录内容一变、树哈希就变。

缺失项显式列在 `out["缺失项"]`，不静默跳过。
