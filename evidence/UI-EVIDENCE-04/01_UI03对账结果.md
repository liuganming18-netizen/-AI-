## C2｜manifest 不存在，哈希来源是编的

| 项 | 值 |
|---|---|
| 审计 JSON 自记 `manifest_present` | **false** |
| 磁盘 `manifest.json` | **不存在** |
| `run.json.hashes` | **`{}`（空）** |
| CSV04 声称来源 | `manifest.json / files.summary.json.sha256` |
| CSV04 判定 | 「一致」 |

**源侧没有任何官方哈希可比对**：manifest 没有，run.json.hashes 也是空的。

CSV 里那个 `5f42d255…` 是**测试脚本自己算的**（`file_sha256(summary_path)`），却被标注成来自 manifest。

正确写法只有一种：

```
产物哈希（脚本自算）  | 5f42d255… | SHA-256(本地文件实算) | 仅供参考·非官方比对
产物哈希（官方来源）  | —         | missing               | 无法比对·未验证
```

**不得另造 manifest**。本轮修复版即按此处理（见 `02` P1）。

## C3｜清单第 9 行：清单把自己写成了空文件

`08_文件清单与哈希.csv` 第 9 行：

```
交付证据文件,evidence/SYSTEM-UI-03/08_文件清单与哈希.csv,0,e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
```

- `size = 0`
- `SHA = e3b0c442…b855` —— 这是 **`sha256("")`**，空文件哈希

成因（脚本第 1227-1234 行）：

```python
with open(csv_08, "w", ...) as f:          # ← 文件已被创建，size=0
    for p in sorted(EVID_DIR.glob("*")):   # ← 遍历目录，包含自己
        if p.is_file():
            w.writerow([..., p.stat().st_size, file_sha256(p)])
```

打开写入时文件已存在且为空 ⇒ 读到 0 字节 ⇒ 算出空文件哈希 ⇒ 写进清单。

**还有一处连带错误**：清单在 `audit_ui_verification.json`（4,504 B）和 `00_*.md` 之前生成，导致清单里记的是 JSON 的**旧值 4,499 B**，与实际 4,504 B 不符。顺序错了，后写的文件永远统计不到正确大小。
