## 二、复用 VERIFY-03 排除混杂的夹具设计

在前序 `FRAME-VERIFY-03` 中，验证团队成功建立了排他性夹具，彻底排除了 4 大混杂干扰，精准定位了零运行死锁缺陷。本套件完整继承并复用该夹具设计：

### 1. 窗口混杂消除（Scope Alignment）
- **混杂成因**：请求如果使用非默认窗口（如 2024-02-01 ~ 2024-05-31），会触发底层执行链写死窗口校验，报 `请求窗口...但执行链写死为...`，掩盖死锁真实原因。
- **夹具设计**：严格将请求窗口对齐为底层写死窗口 `('2024-01-01', '2024-06-30')`，确保 `scope_mismatch` 绝对为 `None`。

### 2. 分组混杂消除（Split Policy Validation）
- **混杂成因**：随意配置训练/验证/留出集会触发样本重叠、隔离带不足（需 $\ge 240$ 小时）或污染已观察样本。
- **夹具设计**：
  - `train`: `2024-01-01 ~ 2024-03-31`
  - `valid`: `2024-04-15 ~ 2024-06-30`（隔离带 15 天 = 360 小时 $> 240$ 小时）
  - `holdout`: `2026-10-25 ~ 2026-11-25`（完全避开已观察样本的 2021-12 ~ 2026-10 观测区间）
  - 确保 `policy.validate()` 严格返回空列表。

### 3. 身份混杂消除（Identity Parity）
- **混杂成因**：硬编码配置或代码哈希计算偏差，导致请求身份与登记身份不符，触发 `当前代码/参数/规则/样本/分组/指标与登记身份不一致`。
- **夹具设计**：直接调用系统真实的 `current_design_parts(scope, policy, DEFAULT_METRICS_SPEC)` 提取当前运行环境的代码与配置哈希，确保登记身份与请求身份逐字符 100% 绝对一致。

### 4. 冻结前置满足（Pre-freeze Requirement）
- **混杂成因**：未冻结状态会触发 `配置未冻结` 拦截。
- **夹具设计**：登记后显式调用 `reg.freeze(eid)`，确保其实验状态处于合法已冻结状态，仅保持 `runs = []` 初始零历史状态。

## 三、调用层次明确界定：控制器函数测试 vs HTTP 端口测试

按照工单要求：“**区分控制器函数测试与HTTP端口测试，不扩大结论**”。

在本验证体系中，测试严格界定如下：

```
┌────────────────────────────────────────────────────────────────────────┐
│                          调用层次与结论边界划分                         │
├───────────────────┬────────────────────────────────────────────────────┤
│ 层次              │ 真实调用路径与测试范围                             │
├───────────────────┼────────────────────────────────────────────────────┤
│ **函数级守卫**    │ `experiment_registry.py::guard_create`             │
│                   │ 直接校验入参字典与 Registry 状态机                 │
├───────────────────┼────────────────────────────────────────────────────┤
│ **控制器函数级**  │ `backtest_api.py::create_run(payload)`              │
│                   │ Python 进程内控制器接口函数直接调用，包含入参解析、│
│                   │ 模式分流、HTTP 状态码组装（如 202 / 409 等）       │
├───────────────────┼────────────────────────────────────────────────────┤
│ **HTTP 网络端口** │ 外部独立 Web 服务器（如 Flask/FastAPI 8000 端口）   │
│                   │ **[说明] 本套件未起独立网络服务进程，不测 HTTP**   │
│                   │ **网络端口监听与反向代理，结论仅限于控制器代码层** │
└───────────────────┴────────────────────────────────────────────────────┘
```

本验证的所有结论均严格限定于**进程内函数守卫与 API 控制器函数级**，绝不泛化或声称已完成生产环境独立 Web 服务的网络接口端到端验收。
