## 0 一句话结论

R1 的 `proven_regular_*` 不只是命名问题：它在**真实数据上把 188 个「缺失」判了出来，而这 188 个时刻在 ±1,000 ms 内全都有真实事件**（最大偏移 11 ms，188/188 命中）。根因是预期时刻按整点生成、实际记录带 1~47 ms 尾数，R1 用**精确毫秒相等**比对 ⇒ 抖动被当成缺失。改用官方周期证据 + 观测相位 + 1,000 ms 容差后，本单在 51 笔持仓里**没有发现任何缺失**（0 条），R1 会标记的 38 笔降到 0 笔。金额层面两套口径的差额与 05-C / R1 完全一致（口径 A Δ 0.659199640、口径 B Δ 0.049099877），**变的是完整性的定性与证据等级，不是钱**。

## 2 周期证据分级：官方 / 观测推断 / 不可判定

R1 把观测间隔推算直接叫 `proven_regular_4h/8h/1h`，并用它判断完整性。本单改为 6 个互不替代的等级：

| 等级 | 含义 | 候选数 |
|---|---|---|
| `official_snapshot` | 官方快照 interval 自 `updateTime` 起生效，覆盖整个持仓区间 | 46 |
| `official_partial` | 官方快照存在，但 `updateTime` 晚于入场 ⇒ 前段无官方证据 | 0 |
| `inferred_uniform` | 观测间隔恒定，**仅能推断** | 5 |
| `inferred_with_multiples` | 观测间隔是同一基数的整数倍（缺事件痕迹） | 0 |
| `switch_detected` | 观测到周期切换 | 0 |
| `undetermined` | 不可判定 | 0 |

**完整性五态**（说「网格上有没有缺」）与**主张四态**（说「能不能声称已证明」）是两个维度，不互相替代：

| 完整性 | 含义 | 候选数 |
|---|---|---|
| `NO_GAP_DETECTED` | 网格上未发现缺失——**不等于已证明完整** | 51 |
| `MISSING_DEMONSTRATED` | 官方周期下确有缺失 | 0 |
| `INCONSISTENT_INFERRED` | 仅在推断周期下不符 | 0 |
| `UNDETERMINED` | 不可判定 | 0 |
| `NOT_APPLICABLE` | 不适用（持仓内无预期时刻） | 0 |

| 主张 | 含义 | 候选数 |
|---|---|---|
| `PROVEN` | 官方覆盖 + 相位一致 + 网格无缺失 | 44 |
| `NOT_PROVEN` | 未证明（**不等于已推翻**） | 7 |
| `REFUTED` | 已推翻（官方周期下确有缺失） | 0 |
| `UNKNOWN` | 不可判定 | 0 |

另有 4 个候选在 `(entry, exit]` 内**没有任何预期结算时刻**（持仓短于一个周期，含 0 时长笔），这类不参与缺口判断，也不给 `PROVEN`。

官方覆盖持仓的候选 **46 / 51**。剩下 5 个（`BNBUSDT`、`DOTUSDT`、`XLMUSDT` 的 `updateTime` 为空；`IRYSUSDT`、`SKRUSDT` 的 `updateTime` 晚于持仓）**没有官方证据**，因此它们的完整性最高只能到「未发现缺失」，**不能声称已证明**。

**为什么历史间隔不能证明原生周期**（三条，都能在本数据上指到具体标的）：

1. **缺失记录本身会改写观察到的间隔**。`WUSDT` 全史 5,573 条事件里只有 1 个 8h 间隔，那是漏了一条结算，不是 8h 周期（官方 4h、`updateTime` 2024-04-03）。反过来，若某个 4h 标的连续漏掉一半结算，观测到的间隔会全部变成 8h——见 §7 的 S1 反例：同一份数据，R1 判 `proven_regular_8h` 且「完整」，而官方证据说它是 4h，实际缺一半。
2. **周期会真的变**。本单实测 **15 个标的**存在周期切换（39 个标的出现过多种间隔）。`AXSUSDT` 是 `8h → 1h（2026-01-17）→ 4h（2026-01-26）`；`SKRUSDT` 在窗口内来回切了 4 次。一个标的只有一个周期，是错的。
3. **历史规律不包含规则文本**。观测只能说明「过去这样结算」，不能说明交易所当时的规则。

## 3 预期结算时刻：周期长度 ≠ 相位

R1 用 `first_t = (entry_ms // step_ms + 1) * step_ms` 生成预期时刻，这等于**强制相位为 0**（UTC 整点）。工单要求核对这一点，本单的做法是：

1. 先按 `step` 在**局部邻域（持仓 ±7 天；样本不足时退回 ±30 天上下文）**统计 `t mod step` 的残差；
2. 要求主导残差支撑 ≥ 10 条且占比 ≥ 98.00%，才承认相位可用；
3. 用 `grid_instants(phase, step, entry, exit)` 生成，而不是 `(entry//step+1)*step`。

**实测结果**：51 个候选的相位都是 0，0 个非 0，相位改变网格的候选 0 个。也就是说，在这个数据集里「相位=0」事后看是对的——但这是**验证结果，不是默认假设**。反例 S4 证明差别有多大：4h 周期、结算在 01/05/09 点的合成序列，R1 按相位 0 生成 3 个预期时刻**全部落空**（判 3 次缺失）；本单按观测相位 1h 生成，3 个全部匹配。

**周期切换的处理**：局部邻域若出现 ≥2 段不同间隔（每段 ≥3 连），判 `switch_detected`，完整性直接 `UNDETERMINED`——切换时刻没有官方记录，任何单一网格都会算错（S3 反例：8h→4h 落在持仓内，R1 仍按 4h 铺满，判「缺 1 次」；本单拒绝下结论）。

## 4 判据缺陷实证：R1 的 188 个「缺失」全是毫秒抖动

| 项 | 值 |
|---|---|
| R1 口径（相位 0 + 严格窗口 + 精确毫秒相等）算出的缺失 | 188 条，涉及 38 个候选 |
| 其中在 ±1,000 ms 内能找到真实事件 | 188 / 188 |
| 最大偏移 | 11 ms |
| 本单口径（相位观测 + 1,000 ms 容差）算出的缺失 | 0 条，涉及 0 个候选 |
| 全池事件毫秒尾数非 0 的比例 | 95,144 / 211,604（44.96%） |

这不是数据问题，是**判据问题**：预期时刻是整点，实际 `funding_time` 带 1~47 ms 尾数（全池最大；其中 R1 那 188 个缺失点的偏移不超过 11 ms），精确相等必然落空。R1 报告里的 `GAP_PARTIAL_MISSING` 由此而来。

**R1 分类的实际含义**：它标 `NO_GAP_COMPLETE` 的笔，恰好是那些事件的毫秒尾数碰巧为 0 的笔；标 `GAP_PARTIAL_MISSING` 的笔，是尾数非 0 的笔。分类结果与「有没有漏结算」无关——**这两个类名的字面意思都被误用了**。

## 5 真实记录核对（只用生产数据）

### 5.1 周期切换与官方 `updateTime` 对得上

15 个标的观测到切换；其中 **14 个**的「官方 interval」与「观测到的最后一段周期」一致。这 14 个里有 **13 个**的 `updateTime` 落在最后一次切换的 ±48h 内，另 1 个晚于该窗口（`YGGUSDT` Δ168.175h：`updateTime` 也可能是费率上下限变更，不必然是周期变更）。举三个对齐的：

| 标的 | 观测切换 | 官方 | `updateTime` 与最后切换的差 |
|---|---|---|---|
| `AXSUSDT` | 8h → 1h → 4h | 4h | -0.983h |
| `BABYUSDT` | 4h → 1h → 4h | 4h | 0.017h |
| `BLURUSDT` | 8h → 1h → 4h | 4h | -2.983h |

唯一**不一致**的是 `IRYSUSDT`：官方 1h、`updateTime` 2026-10-23，而观测到的最后一段是 4h（2026-05-19）。这恰好说明**官方值只对 `updateTime` 之后有效**，用它去判 9 月的持仓会判错——本单对 `IRYSUSDT` 用的是观测推断（4h），并把这一点写进了 `interval_evidence_note`。

### 5.2 端点抖动：退出同刻的那次结算会凭空消失

`entry < t <= exit` 是毫秒级严格比较。实测 2 个候选、2 个事件卡在端点上（口径 × 候选共 4 条记录）：它们的名义结算时刻正好等于退出时刻，但记录晚 3~4 ms，于是被严格判据排除。金额不小：

| 标的 | 退出时刻 | 若纳入的资金费 | 说明 |
|---|---|---|---|
| `AIGENSYNUSDT` | `2026-09-23T16:00:00Z` | 0.017469676 | 退出同刻（严格判据不纳入） |
| `WALUSDT` | `2026-10-10T12:00:00Z` | -0.362186164 | 退出同刻（严格判据不纳入） |

`WALUSDT` 那笔是**收取** -0.362186164——严格判据把它漏掉，等于把成本算高了。本单的处理是：容差匹配 + 标 `boundary_dependent`，**并且不给 `PROVEN`**（2 个候选因此降级），因为「退出成交发生在结算前还是后」在毫秒级上本来就不可判定。

### 5.3 「非零结算」不等于完整（真实案例）

`AXSUSDT` 那笔持仓，热库已有 30 次结算，合并后是 33 次——**有 30 次照样漏了 3 次**。这类「有结算就判完整」的推理在旧 8h 零事件判据下完全看不见（S2 反例即此）。真实数据里这类「次数变多」的笔共 1 笔。

### 5.4 冷档补入的事件没有「网格外野事件」

51 笔持仓内共补入 44 条冷档事件，落在预期网格外的 **0 条**（涉及 0 个候选）。补进来的是同一条结算，不是新造的时刻。字段缺陷（`rate` / `mark_price` 缺失）候选 0 个。

## 10 未验证与不能声称

1. **「当时可得」仍未证明**。适配器对全部事件写 `availability=unproven`，本单没有改变这一点；官方快照是本单当天抓的，不能反推历史可得性。
2. **官方证据只覆盖 `updateTime` 之后**。5 个候选（`BNBUSDT`、`DOTUSDT`、`XLMUSDT`、`IRYSUSDT`、`SKRUSDT`）的历史段没有官方证据，它们的完整性只能算「未发现缺失」。
3. **相位是观测一致，不是官方文件**。本单没有拿到交易所的结算时刻规则文本，只能说「观测残差一致」。
4. **`PROVEN` 的含义有限**：官方周期覆盖 + 相位观测一致 + 网格内无缺失。它**不**包含「当时可得」「未来不会变」「策略层已接受」。
5. **`IRYSUSDT` 的官方 1h 与观测 4h 不一致**，本单按观测推断处理；如果交易所实际在 9 月就是 1h，那这笔会少记若干次结算——本单无法排除这种可能，已如实标 `NOT_PROVEN`。
6. **端点抖动无法从数据上判定先后**。`WALUSDT` 的 -0.362186164 是否该计入，取决于退出成交与结算的毫秒级先后，本单只给区间不给结论。
7. **结论只在 48 标的 / 51 笔 / 窗口 1925.00 小时内成立**，不能推广到全池。
8. **同键冲突（两侧 `rate`/`mark` 不等）在真实数据里是 0 条**。冲突分支只有合成用例覆盖，**不得声称已用真实数据验证**；本单真实走到的只有「网格内无缺失」与「端点抖动」两条路径。
9. **未做**：正式实时读取链改造（`paper_engine.funding_events` 仍只读热库）、策略层参数、经济口径选择。
