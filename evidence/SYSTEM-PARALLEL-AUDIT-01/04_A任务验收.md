## 三、A1 本金与风险参数真实生效

### 3.1 实测

固定：`atr=1.0`、`stoploss_s=0.05`、`risk_per_trade=0.005`、`slippage=3bps`，只改视图 `initial_equity_USDT`。

| 视图本金 | `account_view().initial_equity` | `equity().equity` | 落库 qty | 期望 qty（预算÷stop_dist） | 一致 |
|---|---|---|---|---|---|
| 2000 | 2000.0 | 2000.0 | **1.96** | 1.960784 | ✓ |
| 5000 | 5000.0 | 5000.0 | **4.901** | 4.901961 | ✓ |
| 20000 | 20000.0 | 20000.0 | **19.607** | 19.607843 | ✓ |

预算分别为 10 / 25 / 100 USDT，`stop_dist = entry − stop = 100.10 − 95.0 = 5.10`。
qty 取整到 0.001 步长 ⇒ 1.96 / 4.901 / 19.607，误差 < 1 个数量步长。

### 3.2 修复路径（代码级）

`paper_engine.open_position` 成交段：

```
eq = equity(con, arm, con_mkt, params)
...
rr = _apply_order_rounding(..., equity=e, ...)      # e = eq["equity"]
```

`equity()` → `account_view()` → `db_init_equity`，其取值顺序是：

1. `paper_account.initial_equity`（已有账本，优先）
2. `L.get_configured_initial_equity()`
3. `INIT_EQUITY = 5000.0`（兜底）

`get_configured_initial_equity()` 的取值顺序：

1. 环境变量 `PAPER_INITIAL_EQUITY`
2. `strategy_contracts.load_ft_low4h_config()` 的 `initial_equity_USDT`（且 `_config_valid` 为真）
3. `INIT_EQUITY = 5000.0`

**这条链现在是通的**。11:49 时断在第 2 步（`equity()` 全文用 `L.INIT_EQUITY` 常量），现已接上。

## 四、A2 已有账户不重置

### 4.1 实测两步

| 步骤 | 结果 |
|---|---|
| ① 视图 5000 建账并开仓 | `open_ok=true`、`filled`、持仓 1、`account_view.initial_equity=5000.0`、cash=5000.0 |
| ② 视图切 20000，**同一账本** | `approved_initial_equity_USDT=20000.0`、`get_configured_initial_equity=20000.0`，但 `account_view.initial_equity` **仍 5000.0**、cash **仍 5000.0**、`equity()` **仍 5000.0** |

三条断言：

- **账户未被改写**：`account_view().initial_equity == 5000` ✓
- **未注资**：cash 仍 5000，没有跳成 20000 ✓
- **身份核对拒绝**：带 `expected_initial_equity=20000` 打开账本 ⇒ 抛 `LedgerIdentityMismatch`，消息为「配置与已有账本身份冲突：当前配置初始本金为 20000.0 USDT，但已有账本记录为 5000.0 USDT。已有账户不得被重新注资或重置余额，已严格拦截，等待迁移方案。」✓

### 4.2 这条行为的含义

「配置改了但已有账户不跟着变」是**正确**的——否则等于给运行中的账户偷偷注资。但要注意它的另一面：

> 已有账本是 5000 建的，即使把视图改成 2000，这个账户**仍按 5000 跑**。
> 想让 2000 生效，必须**换一个新账本目录**，不能改配置。

这不是缺陷，是设计约束。但必须写清，否则会有人以为「改了配置就生效了」。

## 五、A3 缺配置拒新单且不阻断退出

### 5.1 缺配置的构造方式（关键）

**不能用 `unset EFFECTIVE_VIEW` 模拟缺配置。** unset 会回落到工程内默认视图（存在且有效），实测会「静默接受」——这正是我在 FINAL-01 首跑犯过的错（已记入 `MEMORY-OPS.md`）。

本轮做法：把 `EFFECTIVE_VIEW` 指向 `/tmp/wx_a_task/a3/view_absent.json`，该文件确实不存在。

### 5.2 实测

| 检查 | 结果 |
|---|---|
| `approved_params()` | `_config_valid=False`、`_config_error=config_file_not_found`、`_source=missing`、`stoploss_s=None`、`trail_d=None` |
| 开新单 | `ok=False`，reason = `rejected_by_config_contract: config_file_not_found: 配置文件不存在于指定路径: …/view_absent.json` |
| 已有持仓平仓 | `ok=True`、`reason=closed`、`exit_price=109.945`、`qty=4.901`、`gross_pnl=48.25`、`entry_fee=0.2453` |
| 平仓后剩余持仓 | 0 |

**拒新单不静默兜底、不阻断退出，两条都成立。**

### 5.3 一个残留观察

`approved_params()` 在缺配置时返回的 `initial_equity_USDT` 是 **5000.0**（来自 `FALLBACK`）。这是兜底值，但因为 `_config_valid=False` 已让开仓被拒，所以这个 5000 不会被用于下单。**属可接受，但要留意**：任何不检查 `_config_valid` 就直接读 `initial_equity_USDT` 的调用方，会拿到 5000。

## 六、我这一轮自己犯的错（必须记录）

### 6.1 环境隔离失效：差点写生产账本

**现象**：第一次跑 `03_A任务验收.py`（12:07）时，报错路径是 `数据/paper/paper_3a.sqlite3` —— **生产账本目录**。

**根因**：`live_store.py:54` 有 `LEDGER_DIR = get_ledger_dir()`，是**模块级常量**，在 `import` 那一刻就固定。我的脚本先 `import live_store` 再设 `PAPER_LEDGER_DIR`，所以 `paper_conn()` 仍用 import 时的路径。

更隐蔽的是**两个函数不一致**：`ensure_live_schema()` 每次读环境变量（写到 /tmp），而 `paper_conn()` 用模块常量（读到生产）。两者指向不同目录，脚本看起来「在隔离环境跑」，实际不是。

**已做的核查**：`out/03_污染自查.json` 扫了 `数据/paper/` 下全部 4 个 sqlite3，按 `sig_a1_/sig_a2_/sig_a3_` 三个前缀逐表逐列检索，**结果 0 命中** ⇒ 未污染。目录里现有的是之前的 `sig_ui_test_*` / `sig_closeloop_*`，不是我的。

**修复**：改为**每个场景一个独立子进程**，环境变量在进程启动前注入，模块常量自然正确。修复后实测 `LEDGER_DIR=/private/tmp/wx_a_task/...`，隔离生效。

### 6.2 测试数据把流动性帽先触发了

**现象**：修复隔离后首跑，三档视图 qty 全是 **0.999**，期望是 1.96/4.901/19.607。

**根因**：我造的 15m `quote_volume=100000`，参与率帽 `0.001 × 100000 = 100 USDT` 名义 ⇒ qty = 100/100.1 ≈ 0.999。**流动性帽先于风险预算触发**，把本金差异完全掩盖了。

**修复**：`quote_volume` 提到 5e9/根（帽 = 5e6，远大于最大测试预算 100 USDT）。修复后三档 qty 正确分化。

**教训**：验证「A 参数是否生效」时，必须先确认**没有别的约束先把它截断**。否则会得出「A 不生效」的假结论——这次是假阴性，但同样的错法也能造出假阳性。

### 6.3 时钟参数

`open_position` 默认只创建挂单（`pending_future_fill`），不立即成交，读不到 qty。要让挂单真实成交，必须满足：

```
order_request + delay <= bar_open <= attempt,  且 attempt - bar_open <= 1h
```

取 `requested_at = first_request_ms = b-4·M15`、`now_ms = b-2·M15` ⇒ `earliest_fill = b-3·M15`，市场里恰有该 bar，lag = 1 根 15m。

**这不改变产品代码，只是喂给它一个自洽的时钟。**
