## 一、基线冻结了什么

`FINAL-01` 的 B 关（风险关）在 11:49 已通过：固定 `raw_open=100` 与 `stoploss_s`，只改 ATR 0.5/1/2/5 ⇒ 止损恒 95.0、数量恒 4.901、风险比预算 0.9998。「先按 ATR 定量再换百分比止损」的分叉已消除。

但 A 任务（本金与风险参数真实生效）会改 `live_store` / `paper_engine` / `wx_execution`。**B 关的通过结论只对当时的 SHA 有效**。所以先把「已通过的定量行为」冻成可机械复跑的基准。

基线内容（`out/00_基线.json`）：

| 部分 | 内容 |
|---|---|
| 文件 SHA | 8 个后端文件 |
| 关键常量 | `L.INIT_EQUITY`、`FALLBACK` 的 4 个字段 |
| 定量矩阵 | 4 档 s × 4 档 ATR × 2 档 equity = **32 组** |
| 分叉判据 | 8 组（4 档 s × 2 档 equity），每组判「四档 ATR 下止损是否唯一、数量是否唯一」 |
| 冻结视图 | `exp1` / `exp2` 下 `approved_params()` 的 12 个字段 |

### 1.1 基线首跑结果（B 关有效性的核心证据）

| s | equity | 止损（四档 ATR 恒定） | 数量（四档 ATR 恒定） |
|---|---|---|---|
| 0.03 | 2000 | 97.0 | 1.998 |
| 0.03 | 5000 | 97.0 | 4.995 |
| 0.05 | 2000 | 95.0 | 1.96 |
| 0.05 | 5000 | 95.0 | 4.901 |
| 0.08 | 2000 | 92.0 | 1.234 |
| 0.08 | 5000 | 92.0 | 3.086 |
| 0.20 | 2000 | 80.0 | 0.497 |
| 0.20 | 5000 | 80.0 | 1.243 |

8 组全部「止损唯一=True、数量唯一=True」⇒ 定量层无分叉。

### 1.2 一个必须记清的事实

`apply_order_rounding` 的 `equity` **入参本身工作正常**：

- `s=0.05, equity=2000` ⇒ qty **1.96**（预算 10 USDT ÷ 5.1）
- `s=0.05, equity=5000` ⇒ qty **4.901**（预算 25 USDT ÷ 5.1）

所以 A-1 缺陷的性质**不是**「定量层不支持不同本金」，而是「引擎调用时恒传 `INIT_EQUITY`，视图值根本没进去」。这两句话的责任方完全不同，不能混说。

## 二、受影响回归怎么用

`01_regress.py` 拿基线当基准，重跑同一组输入，逐字段比对，然后按「哪些文件变了」把结论精确映射到「哪些项作废」。

### 2.1 判定分层（关键：不许一有变化就全盘作废）

| 情形 | 判定 |
|---|---|
| SHA 全同 | 全部项有效 |
| SHA 变但定量矩阵全同 | **定量项仍有效**（行为未变），但身份已变，需重新绑定版本 |
| SHA 变且某组定量变了 | 只作废涉及该字段的项 |
| `wx_execution.py` 变 | 作废 B 关全部定量结论 |
| `live_store.INIT_EQUITY` 变 | 作废 A-1 结论与所有「绝对预算」数字 |
| `paper_engine` 的 `equity()` 变 | 作废 A-1 结论 |

### 2.2 文件 → 受影响项映射表

| 文件 | 变化时作废的项 |
|---|---|
| `strategies/wx_execution.py` | B关_止损唯一性、B关_数量唯一性、B关_风险比预算、B关_全链路风险重算 |
| `live_store.py` | A-1_权益基准、A-1_绝对预算10vs25、C关_账本闭合 |
| `paper_engine.py` | A-1_权益基准、A-1_绝对预算10vs25、A-2_stop_price污染、A关_参数身份贯穿、C关_账本闭合、C关_上移与退出 |
| `strategy_contracts.py` | A关_缺配置拒单、A关_参数身份贯穿 |
| `unified_runtime.py` | B任务_统一入口启动整链、B任务_进程状态、B任务_隔离与停止范围 |
| `live_api.py` | A-2_stop_price污染、A关_客户端不能覆盖冻结参数、C任务_UI数据同源 |
| `paper_loop.py` | C关_自动成交、B任务_统一入口启动整链 |
| `api/routes.py` | C任务_UI数据同源、B任务_进程状态 |

## 四、怎么复跑

```bash
PY=/Users/boos/.workbuddy-ai/binaries/python/envs/default/bin/python
$PY evidence/SYSTEM-PARALLEL-AUDIT-01/queries/01_regress.py
```

输出三块：文件 SHA 变化、定量矩阵差异、受影响项。若 `差异条数 = 0` 且 `常量漂移 = 0`，则判定为「定量有效但身份已变」，只需更新版本绑定。

**不要重跑 `00_baseline.py`**——那会覆盖基准，让回归失去参照。只有确认要立新基准时才重跑。

## 五、边界

- 基线只覆盖**定量纯函数 + 关键常量**，不覆盖引擎的调用路径。引擎是否把视图值传进去，属 A 任务验收范围。
- 本文件不做「A 任务是否通过」的判定，只提供回归工具与首次结果。
- 不改任何业务代码。
