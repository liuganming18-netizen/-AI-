## 五、声称的 run 是否真实存在（结构性否定）

这一步比「在库里没搜到」更强。`框架/backend/backtest_store.py` 用 `RUN_ID_RE` 校验 run_id，不匹配直接拒绝登记：

```
^(bt_[0-9]{8}T[0-9]{6}Z_[0-9a-f]{8}
 |run_WX_EVENT_TREND_V0_1_.*
 |run_FT_ENTRY_09_.* |run_FT_STOP20_.* |run_FT_EXIT01_.*
 |run_FT_STOPGRID01_.* |run_FT_STOPGRID02_.* |run_FT_LOW4H_.*)$
```

| run_id | 匹配 `RUN_ID_RE` | 真实 run 目录命中 | 文本出现处 |
|---|---|---|---|
| `run_sep50_001` | **False** | **0 / 2,268** | 仅 `SYSTEM-UI-01/04_…csv` 与 `test_system_ui_01.py` |
| `f89a2bc1` | **False** | **0 / 2,268** | 仅 `SYSTEM-UI-01/04_…csv` 与 `test_system_ui_01.py` |

`RUNS_ROOT` = `回测日志/event_trend_v0_1/runs`，实有 **2,268** 个 run 目录，无一命中。

**判定**：这两个 ID 在结构上就不可能被登记进回测库，且只出现在对方自己的对账表与测试脚本里。这不是「找不到」，是**对账对象本身不存在**。
