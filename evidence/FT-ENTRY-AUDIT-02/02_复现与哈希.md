## 六、只读证明（上游未被改动）

本轮**没有写入** `evidence/FT-ENTRY-01/` 与 `evidence/FT-ENTRY-02/` 下的任何文件，理由与验证方式：

1. **脚本层**：11 个脚本只使用 `pandas.read_csv` / `zipfile.ZipFile(..., 'r')` / `Path.open('rb')`，全部 `open` 模式为读；写入目标一律为 `FT-ENTRY-AUDIT-02/out|logs/`。
2. **哈希层**：`out/39_复现哈希清单_v1.csv` 同时记录上游文件的 `sha256` 与 `mtime_utc`。第三方可用同一条命令重算后逐行比对：

```bash
$PY - <<'EOF'
import hashlib, pandas as pd
d = pd.read_csv('out/39_复现哈希清单_v1.csv')
d = d[d['scope'].str.startswith('UPSTREAM')]
bad = []
for _, r in d.iterrows():
    p = '../../' + r['path'] if r['path'].startswith('FT-ENTRY') else r['path']
    h = hashlib.sha256(open(p, 'rb').read()).hexdigest()
    if h != r['sha256']:
        bad.append((r['path'], r['sha256'], h))
print('不一致数 =', len(bad))
for b in bad: print(b)
EOF
```

3. **时间层**：`mtime_utc` 全部早于本轮审计开始时刻；若被改动，`mtime` 与 `sha256` 会同时变化。
4. **范围层**：本轮新增文件只出现在 `evidence/FT-ENTRY-AUDIT-02/`（`queries/`、`out/`、`logs/`、两份 md）。

## 七、重跑时可能出现的差异（已知不确定性）

| 项 | 是否确定性 | 说明 |
|---|---|---|
| 逐笔 CSV 读取与指标重算 | **完全确定** | 纯算术，无随机数 |
| 归因四栏分解 | **完全确定** | 残差为 0，可逐笔对账 |
| 时间块 Bootstrap / 置换 | **确定（固定种子）** | 配对重采样 `SEED+1`、置换 `SEED+2`、标的聚类 `SEED+3`，`SEED=20261020`，1000 次 |
| 时间块划分 | 确定 | 30 天日历块、从研究期起点对齐，38 块 |
| FT-ENTRY-02 快照 | **不确定** | 依赖对方批次是否跑完；本轮已在 19/19 后重跑，若对方后续重跑会变 |
| 哈希清单 | 随报告修订而变 | 报告定稿后需重跑 `11_hash_manifest.py` |

**种子常量**（`queries/06_stats.py`）：`SEED = 20261020`、`BLOCK_DAYS = 30`、`N_BOOT = 1000`。改动其中任一项，置信区间数值会变，但**结论方向（是否含 0、Holm 后是否显著）在本轮样本上不会翻转**——因为原始 p 值离 0.05 都很远（A1 0.736、A2 0.986、C1 0.152、C2 0.356）。
