### 3. 修复冷档资金费读取路径

#### (1) 缺陷定位
在 `框架/backend/market_repository.py:127-129` 中：
```python
def _flat_shards(self, exchange, market, symbol, metric):
    d = self.archive_root / metric / exchange / market / symbol
    return sorted(d.glob("*.parquet")) if d.is_dir() else []
```
- **根因**：盘上实际物理结构为平铺文件：`数据/archive/parquet/funding/binance/um/<SYMBOL>.parquet`（路径深度为 3）；而代码假定 `<SYMBOL>` 是一个子目录（路径深度为 4），导致 `d.is_dir()` 恒为 `False`，返回空列表 `[]`，生产冷读接口返回 526/526 全部 0 行（事实 F22-F24）。

#### (2) 修复补丁实现
修改 `_flat_shards` 方法，使其同时兼容**单文件平铺**与**子目录分片**两种布局：
```python
def _flat_shards(self, exchange, market, symbol, metric):
    # 兼容平铺文件结构：.../metric/exchange/market/<symbol>.parquet
    flat_file = self.archive_root / metric / exchange / market / f"{symbol}.parquet"
    if flat_file.is_file():
        return [flat_file]
    # 兼容目录分片结构：.../metric/exchange/market/<symbol>/*.parquet
    d = self.archive_root / metric / exchange / market / symbol
    return sorted(d.glob("*.parquet")) if d.is_dir() else []
```

## 二、索引精度与执行缺陷排查

### 1. 方向效率 (ER) 索引精度排查（排查“差一根 Bug”）

#### (1) 数学与规则定义
根据 `WX_EVENT_TREND_V0_1_策略与回测冻结规则.md` §2：
- 选取最近 42 根完整 4h K 线（$C_1, C_2, \dots, C_{42}$）。
- 分子为总位移：$|C_{42} - C_1|$。
- 分母为总路径：$\sum_{i=1}^{41} |C_{i+1} - C_i|$（其间恰好为 **41 次**相邻收盘价变化的绝对值之和）。
- 严防写成切片取了 43 根 K 线导致分子变成当前价格减去第 42 根之前的价格。

#### (2) 代码实测与切片核对
核查代码实现：
1. **计算函数**（`策略/WyckoffMaster/event_trend_v0_1/features.py:52-66`）：
   ```python
   def compute_efficiency_ratio(closes: np.ndarray) -> Optional[float]:
       if len(closes) < 2:
           return None
       net_change = abs(closes[-1] - closes[0])
       diffs = np.abs(np.diff(closes))
       total_path = np.sum(diffs)
       if total_path <= 1e-12:
           return None
       return float(net_change / total_path)
   ```
   - 若传入数组长度 $N = 42$：
     - `closes[-1]` 为第 42 根，`closes[0]` 为第 1 根，分子严格为 $|C_{42} - C_1|$；
     - `np.diff(closes)` 产出长度为 $42 - 1 = 41$ 的差值数组，分母严格为 41 次相邻变化之和。
2. **切片传入点核对**：
   - `unified_runtime.py:530`：`seg = bars_4h[i + 1 - n : i + 1]`。当 $n=42$ 时，切片长度 $(i + 1) - (i + 1 - 42) = 42$ 根。
   - `unified_runtime.py:1468`：`SELECT ... LIMIT 42`，获取 42 行。
   - `runner.py:352`：`last_42 = sub_4h.tail(42)`，严格为 42 行。
- **排查结论**：**代码索引完全精确，未发生“差一根（43 根）”缺陷**。
