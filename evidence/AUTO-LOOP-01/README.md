# AUTO-LOOP-01｜常驻模拟闭环与回测对账

**一句话结论：进程确实会自己把一笔交易从头走到尾（信号→挂单→成交→止损上移→退出→费用与权益落账），
但只在「回放时钟」下被证明；真实挂钟下当前没有新信号，所以「真实自动成交」仍是**未验证**。
另外本轮发现并修掉了一个会让所有持仓在入场后 15 分钟就被错误平掉的因果缺陷。**

判定口径只有三态：**通过 / 不通过 / 未验证**。未验证不计入通过。

## 二、隔离环境怎么做的

目录：`iso/<标的>/`

| 项 | 位置 | 说明 |
|---|---|---|
| 行情库 | `iso/<标的>/market.sqlite3` | 只含目标标的的 15m/1h/4h 全量历史，先写进 `candle_dataset`（未激活），由统一运行入口每步 `sync_dataset_bars_upto(now)` 按回放时钟逐根激活 ⇒ 进程永远看不到未来 bar |
| 账本 | `iso/<标的>/paper/` | 独立四臂账本，`PAPER_LEDGER_ALLOW_INIT=1` 受控建档 |
| 信号库 | `iso/<标的>/live/` | 独立 `live_signals.sqlite3` |
| 锁与状态 | `iso/<标的>/locks/` | 独立文件锁与 `paper_runtime_3a_status.json` |
| 新开仓闸门 | `iso/<标的>/gate.json` | 隔离闸门，与生产闸门互不影响 |
| 参数视图 | `iso/<标的>/params_view.json` | 从生产视图逐字节复制，运行期只读 |

价格与成交量**按原始文本精度复制**，没有经过 `seed_dataset` 的两位小数格式化
（那条路径会把 0.010308 写成 0.01，低价币会被毁掉）。

## 四、重启接管与暂停新开仓

把同一段回放拆成两个**独立进程**：

- **段 A**（10-01 00:00 → 10-03 00:30）：195 轮，信号 1、成交 1、止损上移 1、退出 0。进程正常退出并释放文件锁。
- **段 B**（10-03 00:30 → 10-06 00:00）：新进程（不同 PID）接管，**先把隔离闸门改成 `allow_new_entries=false`**，287 轮，退出 1。

接管后账本状态：持仓 1 条、成交 2 条（开+平）、止损历史 2 条、已实现 1 条、订单 2 条 ⇒ **没有重复建仓、没有重复成交、没有重复上移**。

闸门确实挡新开仓（另一组证据，BBUSDT 10-10~10-12，闸门关闭）：
信号 1 个、`routed=0`、`matched=0`、`waiting_gate` 每轮累加 69。
（`waiting_gate` 是「每轮各计一次」的累加值，不是 69 个不同信号 —— 这一点容易误读，特此写明。）

## 五、与回测逐笔对账

同一输入：回测读 `数据/市场数据/parquet`，隔离库读 `数据/市场数据/db/market_v2.sqlite3` 的副本。
四个标的三周期逐 bar 逐字段比对，**0 处数值差异**（`out/input_parity.json`，`all_parity=true`）。

同一参数与执行成本：把回测配置覆盖成 paper 生效视图的值 —— 初始权益 5000、费率 5bps、滑点 5bps、参与率上限 0.01。

| 入场时刻 | 2026-10-02 15:15Z | 同 | **一致** |

| 数量 | 7462 | 1963.26 | 不一致 |

| 入场手续费 | 0.24968 | 0.06569 | 不一致 |
| 初始止损 | 0.06357 | 0.05427 | 不一致 |
| 止损上移次数 | 1 | 11 | 不一致 |
| 跟踪止损终值 | 0.06974 | 0.06799 | 不一致 |
| 退出时刻 | 2026-10-03 05:30Z | 2026-10-05 06:30Z | 不一致 |
| 退出价 | 0.06971 | 0.06795 | 不一致 |

| 退出手续费 | 0.26007 | 0.06670 | 不一致 |
| 资金费 | 0.50164 | 0.27909 | 不一致 |
| 净盈亏 | +19.7713 | +1.6107 | 不一致 |
| 期末权益 | 5019.7713 | 5001.6107 | 不一致 |
| 收益率 | 0.3954% | 0.0322% | 不一致 |

**入场三件套完全对齐，出场全面分歧。** 这不是抄错数，是两套规则本身不同：

1. **初始止损**：模拟盘 = 成交价 × (1−0.05)；回测 = 箱体低点 − 0.1×ATR。
   同一个信号，模拟盘止损距离 5%，回测 18.9% ⇒ 同样 0.5% 风险预算下，回测的仓位只有模拟盘的 1/3.8，
   后面所有金额（手续费、资金费、净盈亏）都被这个比例放大或缩小。
2. **跟踪触发**：模拟盘没有门槛（4h 低点 × 0.95 只要更高就上移）；回测要先到 2R 才启动跟踪。
3. **退出粒度**：模拟盘按 15m 逐根判「最低价是否触及止损」；回测是「明细周期穿越即成交」。

⇒ 要让两边逐笔一致，必须先裁决「到底用哪套止损规则」。在那之前，逐笔金额对不上是**预期结果**，
不是对账失败。对账的价值在于：把分歧定位到了这三条，而不是笼统地说「有差异」。

明细：`out/reconcile_VELVETUSDT.csv`、`out/reconcile_VELVETUSDT.json`。

## 六、本轮发现的缺陷（重要）

### 缺陷 D-1：4h 止损判定用了「入场前已收盘」的 K 线（已修）

**症状**：修复前跑 BBUSDT、WALUSDT、VELVETUSDT 三个真实信号，全部在**入场后第一根 15 分钟**就被判
`trailing_stop_loss` 平掉，止损上移次数恒为 0 —— 闭环永远走不到「上移」那一步。

**根因**：`paper_engine.advance_position_trailing` 用 `last_closed_4h(upto=now)` 取「最近一根已收盘 4h」。
入场后不满一根 4h 时，拿到的是**入场前就已收盘**的那根，却直接拿它的最低价判「是否击穿止损」。

**铁证**（WALUSDT，`out/rootcause_4h_causality.json`）：

| 项 | 值 |
|---|---|
| 入场 | 2026-10-10 11:15Z，止损 0.03666 |
| 实际用于判退出的 4h K 线 | 04:00–**07:59:59**（比入场早 3 小时 15 分），最低价 0.03506 ≤ 止损 |
| 同一时刻 15m K 线 | 11:15–11:29，最低价 **0.03801 > 止损**，根本没碰到 |

即：用入场前的价格事件，把入场后的仓位平掉了。同一模块的 15m 路径本来有 `bar_before_entry_time` 守卫，
4h 路径漏了，两条路径口径不一致。

**修复**：加一条守卫 —— `4h 收盘时刻 <= 入场时刻` 时整根不参与跟踪与退出判断。
改动 34 行 diff，`out/paper_engine_autoloop01.diff`。

**回归**：后端测试修复前 18 failed / 361 passed / 79 skipped，修复后**完全相同的 18 failed / 361 passed / 79 skipped**，
失败集合逐条相同 ⇒ 没有引入新失败。这 18 项是既有失败（集中在系统隔离、启动、回测 UI 读取路径），
与本改动无关，也没有因为本改动变好。

**修复后同一段回放**：止损上移 1 次、正常退出、净 +19.77。

### 未修的观察

- `advance_pending` 会遍历四个臂，每个臂都建一份账本；隔离环境下会顺手创建 3b/3c/3d 的空账本。不影响判定，但会让「空账本」看起来像真实账户。
- 回放时 `waiting_gate` 是每轮累加值，容易被误读成信号条数（本轮已在证据里标注）。
- 生产行情库文件时间会被**其它长期进程**（实测 PID 55012）推进，与本轮无关；本轮脚本对行情库全部只读。

## 七、哪些**没有**被证明

1. **真实挂钟自动成交：未验证。** 回放跑的是 10-02 的历史信号；真实挂钟窗口（45 秒）内隔离库没有新 bar，0 信号 0 成交。
   本轮只证明「轮询在跑」，不证明「真实挂钟下会自动成交」。
2. **生产启用下限之前的历史信号没有被补开。** 生产 `paper_epoch_ms` 仍钉在 2026-10-14T01:00Z。
   全池 526 标的全量扫描（09-07 至 10-23）只有 4 个候选，**全部早于该下限**，10-14 之后 **0 个**
   （`out/scan_candidates.json`）。所以本次回放要在隔离进程里把「本进程的启用下限」前移到数据起点才能跑 ——
   这是**隔离回放的时钟参数**，只在本进程内 monkeypatch `live_store.get_paper_epoch_ms`，
   不写库、不改生产文件、不影响任何生产实例；进程身份里记了 `epoch_floor_override_ms` 与作用域。
   这一条是本次交付里最需要复核的让步，特此显式披露。
3. **策略有效性：未验证。** 单笔样本（1 笔，+19.77，占权益 0.395%）不构成任何统计结论。
4. **两套止损规则该用哪套：未裁决。** 这是逐笔对账 13 项不一致的根因，需要人来定。
5. **多标的并发、资金费逐笔累计口径、部分成交**：本轮只跑单标的单笔，未覆盖。
