# 02 币安「聪明钱」与多空均价：官方来源核实

核实方式：**实调官方接口 + 读本机已落地的官方响应**，不以第三方教程为依据。
所有时间 UTC。原始响应留档在 `raw/`。

> 说明：币安开发者文档站（developers.binance.com）在本机抓取返回 HTTP 202 空正文，未能取到文档页原文。
> 因此本节的结论全部建立在**可复现的实调结果**上，而不是文档转述。凡实测不到的，本节直接写"不可获取/未验证"。

## 二、问题 1：是否存在独立的「聪明钱」数据，而不只是大户聚合比率？

**存在，且与大户聚合比率是两套完全不同的东西。**

| | 聪明钱（Smart Signal） | 大户聚合比率（`/futures/data/*`） |
|---|---|---|
| 端点 | `www.binance.bh/bapi/futures/v1/public/future/smart-money/signal/*` | `fapi.binance.com/futures/data/topLongShortPositionRatio` 等 |
| 粒度 | 一个"队列"的持仓（人数/数量/均价/鲸鱼子集） | 只有比率，没有量、没有价、没有人数绝对值 |
| 有金额 | 有（`*Positions` 按标记价折算的 USDT 市值） | 无 |
| 有均价 | 有（4 个均价字段） | 无 |
| 有身份 | 有**伪匿名**身份（`topTraderId` + `traderName`） | 无 |
| 覆盖 | 只是币安自定义队列，**不是全市场** | 全市场 / 大户两个口径 |

**队列口径是币安未公开的**。已有接入把它标成 `cohort_definition: undisclosed`，这个标注是对的，本轮核对后维持。
BTCUSDT 实测：队列 1,723 人、持仓市值 32.65 亿 USDT，而同期全市场 OI 约 9.47 万 BTC（≈ 76 亿 USDT）⇒ **队列只占全市场的一部分，不能当全市场持仓**。

## 三、问题 2：能返回哪些真实字段？有时间戳吗？有账户范围吗？有历史吗？

### 3.1 `overview`（实调 ETHUSDT，2026-10-18T11:09:41Z，HTTP 200）

21 个键，全部有值：

```
symbol, totalPositions, totalTraders, longShortRatio,
longTraders, longTradersQty, longTradersAvgEntryPrice,
longWhales,  longWhalesQty,  longWhalesAvgEntryPrice,
shortTraders, shortTradersQty, shortTradersAvgEntryPrice,
shortWhales,  shortWhalesQty,  shortWhalesAvgEntryPrice,
longProfitTraders, shortProfitTraders, longProfitWhales, shortProfitWhales,
updateTime
```

实测值（ETHUSDT）：多 586 人 / 129,331.319 ETH / 均价 2,569.00213906；空 1,013 人 / 608,193.178 ETH / 均价 2,384.31970173。

### 3.2 `details/stats`（12 个键）

```
longTraders, longWhales, longPositions, longQty, longWhalePositions, longWhaleQty,
shortTraders, shortWhales, shortPositions, shortQty, shortWhalePositions, shortWhaleQty
```

`*Positions` 是**按标记价折算的持仓市值（USDT）**，不是开仓成本额。

### 3.3 `details/list`（每行 11 个键）

```
timeRange, traderName, topTraderId, side, netPositions,
lastTradeTime, userType, traders, currentPositions, currentQty, avgEntryPrice
```

实测一行具名交易员（ETHUSDT，2026-10-18）：

```json
{"traderName":"CRYPTOBTN","topTraderId":"5211687911097327617","side":"BUY",
 "userType":0,"traders":1,"currentQty":28.973,"currentPositions":70046.24,
 "avgEntryPrice":2419.62004328,"lastTradeTime":1792320659676}
```

- `userType=2` = 该侧队列汇总行；`userType=0/1` = 单个交易员行。
- `netPositions` **实测恒为 null**，不可用。
- 本地 523 个快照里，**431 个标的能拿到具名行**，每标的 1~8 行。

### 3.4 时间戳：有三种，必须分开

| 时间 | 字段 | 含义 | 能否当快照时点 |
|---|---|---|---|
| 交易活动时间 | `details/list[].lastTradeTime` | 该队列最近一次成交/持仓变动 | **不能**。活跃度低不等于数据陈旧 |
| 日级队列标记 | `overview.updateTime` | 全标的共享、按天推进 | **不能** |
| 上游数据快照时点 | 无此字段 | 币安未公开 | **不存在**，只能留 null |

⇒ 唯一可用于判新鲜度的是**本机取回时点**（`finished_at` / `local_fetched_at`）。已有接入就是这么做的，正确。

### 3.5 账户范围

**是伪匿名个体，不是账户身份。** `topTraderId` 是 19 位数字 ID，`traderName` 是用户昵称（如 `doge2neiro`、`User-54e0e`、`大老虎Joe`）。
币安**不公开**这些 ID 对应的真实账户、保证金余额、成交明细。
`details/list` 在默认 `rows=10` 时每标的返回 **2 条汇总 + 最多 8 条具名**（`details_total` 可到 109）⇒ 拿到的是"榜单前几名"，**不构成账户全貌**。

### 3.6 历史

**没有历史时序。** 三层证据：

1. `timeRange` 参数（`ALL`/`90D`/`30D`/`3D`/`7D`）改变的是**聚合回溯窗口**，不是返回时间序列；返回体永远是"当前一条"。
2. 本地快照是**覆盖式**的：523 个标的各 1 份文件，没有历史目录。
3. 官方归档（`data.binance.vision` 的 `futures/um/monthly/metrics` 与 `daily`）里**没有** smart-money 目录；本机 `数据/raw_oi_metrics` 逐日档案也只有 8 列聚合指标。
4. 本机唯一接近历史的是 `api_calls` 里的调用日志：11 天、94,898 条 overview 正文、106 个标的 ⇒ **样本残缺、且时间是本机取回时点**，不能当历史序列做回测。

**结论：聪明钱只能实时观察，不能进历史回测。**

## 四、问题 3：是否真实提供多头/空头平均持仓价？适用范围是什么？

**真实提供，但有三个限定。**

### 4.1 提供的字段（`overview`，4 个）

| 字段 | 实测（BTCUSDT，2026-10-18T11:05:59Z） |
|---|---|
| `longTradersAvgEntryPrice` | 84,694.62965224 |
| `longWhalesAvgEntryPrice` | 84,854.43918685 |
| `shortTradersAvgEntryPrice` | 78,420.03389355 |
| `shortWhalesAvgEntryPrice` | 78,333.04144232 |

另有 `details/list[].avgEntryPrice`：**单个具名交易员**的开仓均价（如 PENDLEUSDT 的 `doge2neiro` = 1.2672）。

### 4.2 三个限定

1. **范围限定**：只覆盖"聪明钱队列"，**不是全市场、不是全部大户**。想拿"全市场多空均价"——**不可获取**。
2. **加权方式未公开**：币安没说这是简单平均还是按数量加权 ⇒ 只能原样引用，不能自己换算成"总成本"。
3. **只有当前值**：没有历史序列，也没有上游快照时点 ⇒ 只能标注为"本机取回时刻的值"。

### 4.3 与"大户聚合比率"的关系

`/futures/data/topLongShortPositionRatio` 等 4 个端点**只返回比率**，实调确认字段为
`longAccount` / `shortAccount` / `longShortRatio` / `timestamp`（或 `buyVol` / `sellVol` / `buySellRatio`），
**没有均价、没有金额、没有身份**。

⇒ 因此：

- **不能**把 `top_position_ls_ratio` 改名为"聪明钱持仓"或"资金金额"；
- **不能**把 `taker_buy_share` 或 VWAP 冒充"多空平均持仓价"；
- **能**说的是：币安对"聪明钱队列"提供 4 个均价字段（仅当前值），对"大户/全市场"只提供比率。

## 五、历史可得性：官方聚合指标的时间边界（实调）

| 端点 | 实调结果 |
|---|---|
| `/futures/data/topLongShortPositionRatio` | 200，字段 `longAccount/shortAccount/longShortRatio/timestamp` |
| `/futures/data/globalLongShortAccountRatio` | 200，同上结构 |
| `/futures/data/takerlongshortRatio` | 200，字段 `buyVol/sellVol/buySellRatio/timestamp`，`buyVol` 是**币数** |
| `/futures/data/openInterestHist` | 200，`sumOpenInterest/sumOpenInterestValue/timestamp`，`limit=500` 时 1h 只能回溯约 20.8 天 |
| `/fapi/v1/openInterest` | 200，只有**当前**一个点 |

**30 天边界实测**：

- `startTime` = 35 天前 → 返回 `{"code":-1130,"msg":"parameter 'startTime' is invalid."}`
- `startTime` = 25 天前 → 200，但**返回的是最新几条**，不是 startTime 附近的点
  ⇒ 超窗时不报错、静默给最新值，这是个容易骗过自己的坑。

**结论**：REST 只能覆盖近 30 天；要长历史只能靠官方日档案（本机已有 2020-09 起），日档案有约 **4 天发布滞后**。

## 七、与反重力契约文档的核对（只登记，不代改）

`evidence/FLOW-OI-01/02_field_contract.md` §4 写：

> 实测确认：币安官方公开历史指标中不存在全市场或大户的多空平均持仓价字段。

这句**对大户/全市场是成立的**，但容易被读成"币安没有多空均价"。实际是：
币安**对聪明钱队列**提供了 4 个均价字段（`longTradersAvgEntryPrice` / `longWhalesAvgEntryPrice` /
`shortTradersAvgEntryPrice` / `shortWhalesAvgEntryPrice`），只是**只有当前值、没有历史**。

建议改成："大户/全市场多空均价不可获取；聪明钱队列有 4 个均价字段但仅当前快照、无历史，不得用于回测。"
这样既保住了"不许用 VWAP 冒充"的原意，又不会让下游误以为币安完全没有这个数据。

另外该契约 §1~§3 未覆盖：断档与陈旧上限、时间对齐（PIT）、主动方向与真实资金流水的区分、
`sum_taker_long_short_vol_ratio` 的口径说明。这四项已在 `03_机器可读契约.md` 补齐。

## 八、不可获取清单（明确写死，不用别的指标顶替）

| 想要的 | 状态 | 原因 |
|---|---|---|
| 全市场多空平均持仓价 | **不可获取** | 官方只对聪明钱队列给均价 |
| 大户（top 20%）多空平均持仓价 | **不可获取** | `/futures/data/*` 只给比率 |
| 聪明钱历史序列（逐时点） | **不可获取** | 只有当前快照；归档无此目录 |
| 账户级持仓明细 / 真实账户身份 | **不可获取** | 只有伪匿名 ID + 昵称，且每标的 ≤8 行 |
| 合约账户充值/提现（外部净流入） | **不可获取** | 币安不公开；OI/CVD 都不能替代 |
| 聪明钱队列成员判定规则 | **未公开** | 币安未说明谁算"聪明钱" |
| 鲸鱼门槛（保证金余额 Top 20%？） | **未验证** | 社区说法，币安未确认 ⇒ 标 `community_claim_unverified` |
| 上游数据快照时点 | **不存在** | 只能留 null |
