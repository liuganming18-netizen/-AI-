## 四、跨源单位核对：`sum_taker_long_short_vol_ratio` 到底是币还是额？

做法：同一 5 分钟桶，用 K 线算 `买量/卖量`（币口径）与 `买额/卖额`（额口径），跟官方比值比。

| 标的 | 日期 | 桶数 | 相对误差中位（币口径） | 相对误差中位（**额口径**） |
|---|---|---|---|---|
| BTCUSDT | 2026-09-15 | 288 | 1.8e-4 | **5.5e-5** |
| BTCUSDT | 2026-09-20 | 288 | 1.4e-4 | **2.9e-5** |
| ETHUSDT | 2026-09-15 | 288 | 2.0e-4 | **6.1e-5** |
| ETHUSDT | 2026-09-20 | 288 | 2.4e-4 | **1.2e-4** |
| UNIUSDT | 2026-09-15 | 288 | 5.5e-4 | **6.2e-7** |
| UNIUSDT | 2026-09-20 | 288 | 3.6e-4 | **8.3e-7** |
| LPTUSDT | 2026-09-15 | 288 | 4.6e-4 | **2.5e-7** |
| LPTUSDT | 2026-09-20 | 288 | 4.3e-4 | **2.7e-7** |

**结论：官方比值是"主动买额 / 主动卖额"，额口径。** 在 UNI/LPT 上额口径误差比币口径小 3 个数量级，排除巧合。
等价买入占比 = `r / (1 + r)`。

残留的 1e-5~1e-4 级误差来自币安按逐笔算、K 线按桶聚合的边界差异，**不是单位错误**（相对误差量级 1e-4，不是 10 或 0.001）。
另有每天 2~6 个桶的差异 >1%（最大 10.9%，ETHUSDT 2026-09-15）——属边界/快照错位，单列不修。

## 五、OI 变化有没有混入价格效应

| 标的 | `oi_quote/oi_base` 与收盘价相对差（中位 / p99 / 最大） | 恒等式残差中位 | corr(Δ额, Δ量) | corr(Δ额, 收益率) |
|---|---|---|---|---|
| BTCUSDT | 0.083% / 0.97% / 2.56% | 7.6e-17 | 0.834 | 0.770 |
| ETHUSDT | 0.114% / 1.28% / 5.08% | 7.6e-17 | 0.769 | 0.918 |
| UNIUSDT | 0.364% / 3.44% / 10.36% | 7.6e-17 | 0.839 | 0.909 |
| LPTUSDT | 0.248% / 2.32% / 6.32% | 6.9e-17 | **0.953** | 0.831 |

- 恒等式 `1+Δ额 = (1+Δ量)(1+Δ价)` 残差 ~1e-16 ⇒ **名义额严格等于"数量 × 价格"**，没有第三种成分。
- 名义额变化与价格收益率的相关系数 0.77~0.92 ⇒ **名义额变化主要由价格驱动**。
  ⇒ 用 `delta_oi_quote` 当"资金流入"会系统性误判；判真实加仓只能用 `delta_oi_base`。
- `oi_quote/oi_base` 是**标记价**，与收盘价中位差 0.08%~0.36%，小币最大 10.4% ⇒ 不能当收盘价。
- LPTUSDT 的相关系数必须先剔掉那个 `OI = 0` 的桶才算得出来（剔 2 对后 = 0.9528 / 0.8312）——这本身就是"零值必须当缺失"的证据。

### 6.1 但"覆盖率"标记不对

## 七、PIT 时间审计（本次最严重的发现）

对 227 笔候选逐笔检查：取到的那根 1h K 线 / 那个 metrics 桶，在信号时刻**是否已经收盘**。

| 检查项 | 结果 |
|---|---|
| 信号时刻取到的 1h K 线已收盘 | **0 / 227**（全部未收盘） |
| 未收盘 K 线的未来跨度 | **227/227 = 3,599,999 ms（≈60 分钟）**（K 线 close_time 比信号时刻晚整整 1 个周期减 1 毫秒） |
| 信号时刻在 K 线内的位置 | **227/227 = 0 分钟**（信号时刻正好等于该 K 线 open_time） |
| metrics 桶已结束 | **0 / 227**（全部未结束，未来 5 分钟） |
| 未来数据合计 | 13,620 K 线·分钟 + 1,135 桶·分钟 |

### 7.1 发生了什么

反重力的取数规则是 `df_c[df_c["open_time"] <= ts].iloc[-1]`。
227 笔候选的 `snapshot_time_ms` **全部正好落在整点**（`min_into_bar = 0`），
于是这条规则取到的就是**从该整点开始、还要走 60 分钟才收盘的那根 K 线**。

用这根 K 线算出来的 `bar_volume`、`bar_taker_buy_quote`、`bar_taker_buy_ratio`、
`bar_upper_shadow_ratio`、`bar_body_ratio`、`bar_return`、`bar_taker_buy_net_quote`
**全部含有信号之后的 60 分钟信息**。

**一个具体例子**（UNIUSDT，`cand_ev_..._UNIUSDT_1639627200000_1640278800000`）：

| 项 | 值 |
|---|---|
| 信号时刻 `snapshot_time_ms` | 2021-12-23T17:00:00Z |
| 取到的 K 线 `open_time` | 2021-12-23T17:00:00Z（**同一秒**） |
| 该 K 线 `close_time` | 2021-12-23T17:59:59.999Z（比信号晚 59.99998 分钟） |
| 特征里记的 `bar_volume` | 922,120 UNI —— 这是 17:00→18:00 一整小时的成交量 |
| 特征里记的 `bar_return` | −0.2694% —— 这是 17:00→18:00 的涨跌 |
| 特征里记的 `bar_taker_buy_ratio` | 0.4578 —— 这是 17:00→18:00 的主动买占比 |

在 17:00:00 这一秒，这三样东西**一个都还不存在**。

### 7.2 影响面（只讲能证的）

- 受影响字段：上列 7 个「当根」字段 + 依赖它们的 4 个假设判定（`is_hyp_a/b/c/d`）。
- **不受影响**：`quote_cvd_24h` / `base_cvd_24h` / `norm_cvd_24h` / `taker_buy_ratio_24h` / `delta_oi_*` / 4 个官方比率 —— 它们是 24h 窗口或官方快照，虽然窗口右端也含这根未收盘 K 线（约 1/24 权重），但主导项是已收盘部分。
- 方向不确定：本审计**不推断**"用了未来数据所以结论偏乐观"，因为不知道突破后 60 分钟是涨是跌。只能确定"这 7 个字段的取值在信号时刻是不可知的"。

### 7.3 还有一处口径错位

227 笔里有 **42 笔** `snapshot_time_ms` 比 `datetime_utc` **早 15 分钟**（另 185 笔相等）。
即这 42 笔用来算特征的时点，比它自己标注的信号时间还早 15 分钟 —— 同一个"信号时刻"在两张表里不是同一个数。

### 7.4 怎么改（给反重力的建议，本轮不动它的代码）

```python
# 现在
bar = df_c[df_c["open_time"] <= ts].iloc[-1]
# 应为：只取已收盘的
bar = df_c[df_c["close_time"] < ts].iloc[-1]
# metrics 同理：桶 [T, T+5min) 结束才可用
m_pit = df_m[df_m["ts"] + 300_000 <= ts]
```

改完后 227 笔的特征值会**全部变化**（每笔少 60 分钟信息），所以这是**必须重跑**的整改，不能只改文档。
