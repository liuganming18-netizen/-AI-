## 三、用户验收要求对照与证据闭环

### 1. 批次统计与收益边界
- **要求**：区分 27 个策略实验和逐币子记录，禁止重复累计；本批真实成交应与源账本 4,325 笔一致；分组收益不得冒充单一账户收益。
- **落实证据**：
  - 清理历史拆分的 210 个逐币子目录，批次目录下仅存 27 组策略运行；
  - `summary` 接口返回：`runs_total: 27`，`trades_total: 4325`，`trades_rows: 4325`，自洽性检查 `trades_total_matches_rows: True`；
  - 批次元数据与 API 声明透传：`"27 组均为独立策略研究实验，每组为独立模拟运行；分组净收益不可横向累加，累加值仅为统计总和，不得冒充单一账户收益"`。

### 2. 补齐交易明细字段与组级详情查询
- **要求**：补齐 API 到页面的成交时间、出场时间、价格和关联标识，确保组级运行详情可查询。
- **落实证据**：
  - 修复 `trades.jsonl` 与 `ledger_links.py`，完整输出：
    `entry_time_ms`（进场毫秒）、`entry_time`（ISO）、`exit_time_ms`（出场毫秒）、`exit_time`（ISO）、`entry_price`（开仓价）、`exit_price`（出场价）、`qty`（持仓数量）、`initial_stop`（P0止损）、`net_pnl`（净盈亏）、`exit_reason`（退出原因）、`trade_id`、`signal_id`；
  - 页面表格中的空白横杠 `—` 全部替换为精确的真实数值。

### 3. 时间物理分离、下单标记与源账本定位
- **要求**：信号、确认、下单、成交、出场分别展示。源数据没有真实下单时间就标“未记录”，禁止用成交时间替代；导入生成的 ID 须标明性质，并保留源记录定位。
- **落实证据**：
  - **信号时间**：`signal_time_ms` 记录原 1h 突破收盘时间；
  - **确认时间**：`confirm_time_ms` 记录 C1/C2 确认 K 线收盘时间（对于 C0 与信号时间一致）；
  - **下单时间**：`order_time_ms: null`，`order_time: "未记录"`，严格遵守禁止用成交时间替代的铁律；
  - **成交时间**：`entry_time_ms` 记录 15m K 线实际执行撮合时刻（严格晚于信号时间与确认时间）；
  - **出场时间**：`exit_time_ms` 记录实际平仓时间戳；
  - **ID 性质与溯源**：每笔带有 `trade_id_nature: "imported_reconstructed"`，同时标注 `source_file: "evidence/FT-ENTRY-09/out/00_all_27_trades_consolidated.csv"` 与 `source_row`（源底表物理行号），追溯精度 100%。

### 4. K 线与交易标记时区、单位与周期核对
- **要求**：核对 K 线与交易标记使用相同时间单位、时区和币种周期。以实际时间戳验证，不靠文件名推测。
- **落实证据**：
  - **周期**：真实行情统一为执行周期的 **15 分钟（15m）**；
  - **时间单位**：后端输出全部统一为 **13 位毫秒级整数时间戳（ms）**，前端图表库统一除以 1000 转换为秒级（UTC）渲染；
  - **时区**：全部以 UTC 物理基准对齐，界面展示标明 UTC，彻底杜绝时区错位偏移。

### 5. 缺失数据诚实性原则
- **要求**：有交易但缺 K 线的币明确显示缺失，不能用空图或替代数据冒充已支持；拒单和确认失败不得显示为成交。
- **落实证据**：
  - 4,325 笔真实成交严格对应平仓闭环交易；45 笔执行拒单与 4,758 笔确认放弃严格隔离在 `rejects.jsonl` / `unexecuted.jsonl` 中，绝不混入 `trades.jsonl`；
  - 标的缺失 K 线时，API 与页面明确返回 `missing_reason: "标的 {symbol} 缺少真实 15m K 线归档数据，未绘制任何合成图表"`，绝无假数据或空图冒充。
