## 二、四个源头

### 2.1 163 条的手续费与资金费为何为 0 —— **字段读取错误**

**结论：不是真实计算结果，不是导出遗漏，不是未计费。是取错了键名。**

三个方向各自排除了一个可能：

| 可能性 | 排除证据 |
| :--- | :--- |
| **真实计算结果就是 0** | 不成立。同一批 163 条在共享内核重放里，`fee_paid` 非零 **163/163**，`funding_cost` 非零 **163/163**；费用合计 **10.308546**、资金费合计 **5.209154**（122 笔支出、41 笔收入） |
| **导出遗漏（字段没落盘）** | 不成立。引擎成交记录的键里 `fees` 与 `funding_fee` **都存在**（`engine.py:1038`），`total_fees` / `total_funding` **都不存在** |
| **未计费（引擎没扣）** | 不成立。引擎在平仓时扣 `entry_fee + exit_fee` 并累计 `cum_funding_fee`；账本 `FEE_CHARGED` / `FUNDING_FEE` 事件合计与逐笔记录逐项相等（见 4.2） |

**现场**：`evidence/FACTOR-ENTRY-01/stage2_candidate_feature_pipeline.py:255-256`

```python
trade_fees    = float(matched_trade.get("total_fees", 0.0))
trade_funding = float(matched_trade.get("total_funding", 0.0))
```

引擎写的是 `"fees": pos.entry_fee + exit_fee` 与 `"funding_fee": pos.cum_funding_fee`。键名不匹配 ⇒ `.get(..., 0.0)` 静默返回 0，不报错、不告警。

**对照**：42 条旧记录走的是另一条路（`enrich_unified_candidate_dataset.py:347-348` 读 `trades_rich.jsonl` 的 `fees`/`funding`），所以 42/42 有真实值。**同一张表里两代际的成本口径一个有一个没有**，这就是「同一版本」最直接的破口。

逐条证据：`01_cost_zero_evidence.csv`（163 行：表中 0 vs 重放真实值 vs 差额）。

### 2.3 COTI 同一快照的取消/成交冲突 —— **订正上一轮的机理**

`01_coti_conflict.csv` / `01_coti_conflict.json`

同一快照 `2021-12-23 03:00`，同一个 15m 开盘价 `0.40545`，一次判取消、一次判成交。

| 项 | 连续回放（2021-12-01 起） | 窗口回放（group 39，2021-12-16 起） |
| :--- | :--- | :--- |
| 事件起点 | 1639900800000（12-19） | 1639627200000（12-16） |
| 箱体上沿 H | 0.36434 | 0.36434（**相同**） |
| 箱体下沿 L | 0.28777 | 0.28777（**相同**） |
| 方向效率 ER | 0.002230 | 0.073559 |
| **建档时刻 ATR** | **0.0124230** | **0.0163849（+31.9%）** |
| 突破收盘 | 0.3985 | 0.3985（相同） |
| **允许最高入场价** | **0.4047115** | **0.4066924** |
| 执行 bar 开盘 | 0.40545 | 0.40545（同一根 bar） |
| 结论 | 0.40545 > 0.4047115 ⇒ **取消** | 0.40545 < 0.4066924 ⇒ 成交于 0.405572 |

**机理**：两侧的箱体上下沿**完全一样**（价格在两个不同时段都触及 0.28777~0.36434），但**箱体形成时刻不同**，而 ATR 取的是「建档那一刻」的 4h ATR(14)，所以 ATR 不同；`允许最高入场价 = 突破收盘 + 0.5 × ATR`，于是同一个开盘价在一侧越线、另一侧不越线。

**订正 ENTRY-AUDIT-02**：上一轮写「箱体下沿 0.28777 vs 0.2879015，说明两次运行形成的箱体并不相同」。本轮重放证明 **箱体上下沿完全相同**，`0.2879015` 其实是**初始止损价**（`= 回踩低点 0.28954 − 0.1 × ATR`）—— 上游把止损价硬写进了 `box_low`（`enrich_unified_candidate_dataset.py:318`），才让它看起来像箱体下沿。结论方向不变（同一信号两种结论），但**机理从「箱体不同」订正为「ATR 不同」**。

**不主张**哪一侧「绝对正确」：两侧各自在其切分下都自洽。要主张的是**它们不是同一个样本**。

**十段链路**（每条记录都能走完）：

```
候选ID → 执行决策(executed/cancel_reason) → 成交或取消
      → 退出(exit_time/exit_price/exit_reason) → 手续费(fee_paid)
      → 资金费(funding_cost) → 净盈亏(net_pnl)
```

**范围边界（必须说明）**：本轮覆盖的是「表里出现过的 152 个标的」。若某些标的在连续回放里有候选但从未进入上游表，本轮不会发现——那属于「扩大研究范围」，不在工单授权内。

### 3.4 符号约定（工单要求「统一费用正负号」）

| 层 | 字段 | 符号 |
| :--- | :--- | :--- |
| 逐笔记录 | `fees` | 正号 = 支出 |
| 逐笔记录 | `funding_fee` / `cum_funding_fee` | 正号 = 支出，负号 = 收入 |
| 账本 | `FEE_CHARGED.payload.fee` | 正号 = 支出（与逐笔同号） |
| 账本 | `FUNDING_FEE.payload.delta` | **现金变动**：支出为负、收入为正 |

**这就是最容易出错的地方**：账本资金费的 `delta` 与逐笔的 `funding_fee` **差一个负号**。不统一就会得出「资金费对不上」的假结论——本轮第一次跑探针时就撞上了这个（`all_funding_match=false`），取负后 5/5 相等。
