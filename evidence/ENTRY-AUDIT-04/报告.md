### 1.5 费用符号与净盈亏公式

```
net_pnl = gross_pnl - fees - funding_fee
fees    = entry_fee + exit_fee
```

| 字段 | 符号约定 |
| :--- | :--- |
| `gross_pnl` | 多空统一为「平仓现金流 − 开仓现金流」的净额，正 = 赚 |
| `fees` / `entry_fee` / `exit_fee` | 正 = 支出（手续费只可能是支出） |
| `funding_fee` | **正 = 支出（付出资金费），负 = 收入（收到资金费）** |
| `net_pnl` | 胜负一律按这个判，不用 `gross_pnl` |

**跨层符号差异（必须知道，否则会误判「资金费对不上」）**：
账本事件 `FUNDING_FEE.payload.delta` 是**现金变动口径**（支出为负、收入为正），与 `funding_fee` **符号相反**，关系是 `cum_funding_fee = −Σdelta`。

**滑点不重复扣减**：滑点与取整已经写进 `entry_price` / `exit_price`（= `price_audit.post_round_price`），所以 `net_pnl` 只再减 `fees` 与 `funding_fee`，不再单独减 `slippage_loss`。再减一次即重复扣减（全样本会额外少 9.519034 USDT）。

### 1.8 本轮新发现：`order_id` 跨代际撞号

这是做交接包时踩到的坑，必须写进契约，否则 FE07 一定会串账。

**现象**：同一个候选在连续回放与窗口回放里会生成**完全相同的 `signal_id` 与 `order_id`**。原因是这两个 ID 都由「标的 + 箱体起止时刻」派生，与回放窗口无关。

**实测**：引擎输出层 **213 条成交记录里有 6 组 `signal_id` 重复，共 13 行**。映射到 205 个候选后重复行数为 **0** —— 不是因为撞号消失，而是因为候选映射按 `(group, symbol, snapshot)` 选中的是同一 run 里的**另一笔**成交；撞号仍存在于引擎输出层。

| 候选 | 连续回放 qty / 净盈亏 | 窗口回放 qty / 净盈亏 |
| :--- | :--- | :--- |
| ETHUSDT `ord_bcfc4c…` | 0.040 / −3.506058 | 0.041 / −3.593710 |
| ETCUSDT `ord_b1ea88…` | 3.32 / +22.112697 | 3.33 / +22.179302（另一窗口也是 3.33） |
| IOTXUSDT `ord_59d856…` | 6484 / +4.380534 | 6474 / +4.373778 |
| ONEUSDT `ord_8246d3…` | 2735 / −6.501020 | 2722 / −6.470119 |
| XRPUSDT `ord_0c2e83…` | 124.7 / −9.989269 | 124.3 / −9.957226 |
| BANANAUSDT `ord_b7a29b…` | 3.4 / −9.945499 | 3.4 / −9.945499（同值） |

**后果**：按 `order_id` 单键关联会静默取到**另一代际**的那一笔，手数与金额都不同（因为两代际起始权益与前序交易不同 ⇒ 手数不同）。本轮脚本第一版就是这么错的，导致 5 条金额看起来「对不上」，改成 `(run_id, order_id)` 复合键后 227/227 与 ENTRY-AUDIT-03 逐位一致。

## 三、结论：数据一致性与策略有效性必须分开报

### 3.1 数据一致性

**第一阶段：通过（自证层面）**

- 18 项自检全通过：227 行 / 205 成交 / 22 未成交 / 226 唯一信号 / 两代际 185+42 分账 / 净值恒等式 205/205 / `fees = entry_fee + exit_fee` 205/205 / 22 条未成交全部有原因且与原始拒单事件逐字相同 / `formal_pass_allowed` 全 false / PIT 全 UNPROVEN。
- 与 ENTRY-AUDIT-03 逐位对齐：净盈亏、手续费、资金费三项合计**完全相等**。
- 与 FE06 逐笔对齐：净盈亏 205/205 相同；三套标签 227/227 相同。
- 零改动自检：51 个上游/代码/合约文件 **零改动**；16 个反重力自冻结产物 **零改动**。

**第二阶段：未执行**（FE07 未交付）。

### 3.2 策略有效性

**未证明。** 理由与数据一致性无关：

1. **历史合约规格全池无 `verified`**（0/227），13 条 `contradicted`、2 条 `not_listed` ⇒ 连「当时的下单精度对不对」都不可证。
2. **PIT 未证** ⇒ 无法证明决策时刻就能拿到这些数据。
3. **两代际净盈亏方向相反**（+144.11 对 −42.57）⇒ 连续回放赚的钱在窗口回放里是亏的，说明结论高度依赖回放切分方式。
4. 主样本胜率 43.56%、B 侧 30.95%，样本量 163 / 42 都不足以支撑稳健性结论。

因此：**「数据一致性通过」≠「策略有效」**。前者只说明账本、费用、分类三者对得上，是后者的**必要非充分条件**。
