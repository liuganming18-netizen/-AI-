### 5.1 版本绑定问题的说明（R-14）

报告 §2 写「隔离后端代码 Git 版本：`2a13325f189e`」。我核实：

```
git rev-parse HEAD  →  2a13325f189e13de7ed06a836ba3d9db4ee63ce3   ✓ 与报告一致
git status --porcelain -- 框架/backend
  M 框架/backend/adapter.py
  M 框架/backend/live_api.py
  M 框架/backend/live_store.py
  M 框架/backend/paper_engine.py
  M 框架/backend/strategies/wx_execution.py
  ...（另有 backtest_*.py 等多项）
```

**commit 号对，但工作区是脏的。** `git rev-parse HEAD` 只标识最后一次提交，不标识实际运行的代码。按项目既有纪律，版本应绑定**文件 SHA-256**，而不是 commit。

正面的一点：前端 `dist` 构建时刻 **12:08:04**，晚于最后一次 `src` 修改 **12:07:58**（`src/api/liveTrading.ts`），且构建产物里确实含有报告声称的修复文案（`执行守护未运行`、`进程离线`、`仓在持`、`笔已平`、`总资金(盯市MTM)`、`可用现金`、`持仓接口读取异常`）⇒ **截图反映的是最新前端代码，这一点成立。**
