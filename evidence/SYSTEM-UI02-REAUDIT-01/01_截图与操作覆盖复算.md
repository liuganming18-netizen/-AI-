**16 个 `view_*.png` 确实是 16 个互不相同的 SHA-256。** 这是我自己重算的，没有引用对方 `08_文件清单与哈希.csv`。


**但工单说得对：哈希不同不能代替操作覆盖通过。** 而且这里还有更糟的情况——**这次的重复不在 view 上，在 state 上**。

### 2.1 为什么脚本的哈希自检没发现

`test_system_ui_02.py` 第 830–836 行：

```python
for i in range(1, 17):
    fn = f"view_{i:02d}_"
    match = next(EVID_DIR.glob(f"{fn}*.png"), None)
```

**自检循环只遍历 `view_01` ~ `view_16`，天生不含 `state_*` 文件。** 所以它必然打印「唯一哈希 16/16」——这个自检的范围恰好是「一定会通过的那部分」。

`queries/01_脚本审计.py` 的 D4 项机械确认：`覆盖视图数=16`、`是否覆盖 state_* 状态截图 = False`。

## 三、像素差异量化：画面到底变了没有

哈希只能回答「变没变」，不能回答「变了多少」。为了区分「真的切了页签」和「只是守护周期计数跳了一下」，对每组图做了顶部 900px 区域的像素差异量化（阈值 16/255）。

| 图组 | 最小差异占比 | 判读 |
|---|---|---|
| 数据中心三页签（08/09/10） | **13.22%** | **页签切换真实**（三张两两 13.22%–14.32%） |
| 策略管理四页签（11/12/13/14） | **8.95%** | **页签切换真实**（六对 8.95%–16.10%） |
| 交易工作台同面板三视图（05/06/07） | **0.073%** | 05↔06 **几乎没变**；05↔07 1.18%、06↔07 1.16% |
| 信号三态 | **0.000%** | 空态↔失败态**完全没变** |
| 持仓三态 | **0.081%** | 正常↔空态**几乎没变**；正常↔失败 23.52%（失败态真实） |
| 止损轨迹三态 | **0.000%** | **三张全部没变** |

### 3.1 这些数字的含义

**成立的部分（有像素证据）**

- View 08 / 09 / 10：差异 13%+ ⇒ 三个页签内容确实不同，**「真实点击页签」这一条通过**。
- View 11 / 12 / 13 / 14：差异 9%–16% ⇒ 四个页签内容确实不同，**通过**。
- 持仓失败态：23.52% ⇒ 500 注入确实改变了画面，**失败态真实存在**。

**不成立的部分**

- **止损轨迹三态差异 0.000%**：`state_stop_trail_normal` / `state_stop_trail_failed` / `view_06` 是同一份字节。报告声称的三种互斥呈现**最多只有一种是真的**。
- **信号失败态差异 0.000%**：`state_signal_failed` 与 `state_signal_empty` 同一份字节 ⇒ 截图里显示的是**空态**，不是「网络错误/离线重试」。
- **View 05 ↔ View 06 差异 0.073%**：点了「止损轨迹」按钮后画面几乎没变。这不是「轨迹展开了」，而是**展开区没有任何内容可渲染**（原因见 `03_隔离失效与生产污染.md`：生产账本 `paper_stop_history` 0 行）。
- **持仓正常↔空态差异 0.081%**：两次截图几乎相同。原因不是「空态做对了」，而是**两次都是生产账本的 0 仓在持**——所谓「把隔离库持仓改成 closed」对页面毫无影响。

## 四、写入时序：注入到截图之间有没有留时间

| 时刻 | 同秒写入的文件 | 含义 |
|---|---|---|
| 12:11:52 | `state_signal_empty.png` | — |
| 12:11:53 | `state_signal_failed.png` | 隔 1 秒，但字节与上一张完全相同 |
| **12:12:18** | `state_stop_trail_failed.png`<br>`state_stop_trail_normal.png`<br>`view_06_stop_trail.png` | **三张同秒写出，字节全同** |

`queries/01_脚本审计.py` 的 D1 项逐注入点核对结果：

| 行 | 注入路径 | 判定 |
|---|---|---|
| 479 | `/api/v1/signals` | 注入后先等待（`wait_for_timeout(1000)`）— 形式正常，但画面无变化 |
| 591 | `/api/v1/paper/accounts` | 注入后先等待（`wait_for_timeout(5500)`）— **有效**（差异 23.52%） |
| **629** | `/api/v1/paper/stops` | **注入后未等待，直接截图** |

源码第 628–631 行：

```python
proxy_state.injected_error_path = "/api/v1/paper/stops"
trail_area.screenshot(path=str(EVID_DIR / "state_stop_trail_failed.png"))   # ← 中间没有任何 wait
proxy_state.injected_error_path = None
```

**注入与截图之间没有 `wait_for_timeout`、没有 `wait_for_response`、也没有重新触发请求。** DOM 不可能在这三行之间重渲染，所以这张「失败态」必然等于上一张「正常态」。像素差异 0.000% 与这个读法完全吻合。

## 八、DOM 与 API：抓了，但一次都没比

`queries/01_脚本审计.py` 的 D2 项严格判定（只有同一行里同时引用 API 变量与 DOM 变量并做比较才算「比对」）：

```
同时抓了 DOM+API 的视图: 2 ／ 其中做了机械比较: 0
  View 01: 只抓不比
  View 03: 只抓不比
```

- **View 01**：抓了 `tickers_api` 与 `topbar_text`，然后断言的是 `"UTC" in topbar_text` 和 `"只读" in topbar_text` —— **跟 API 无关**。

⇒ **16 个视图里，DOM 与 API 的机械比对次数为 0。** 报告 §5 那 18 行「完全一致」、§6 那 14 行「完全一致」，**全部是人手写的**。这一点在 `04_证据表来源.md` 里有独立证据（机器侧对账数组为空 + shell 展开残骸）。
