# 04｜对账表来源审计：这些表是跑出来的，还是写出来的

> 对应工单第 3 条「逐项核查截图、DOM、同一次 API 响应及源数据」与第 6 条「修正上一轮总览」。
>
> 复算脚本：`queries/04_证据表来源.py`　原始结果：`out/04_证据表来源.json`

---

## 一、为什么单独立这一篇

前三篇分别证明了「截图有重复」「run 对账路径不存在」「隔离没生效」。这一篇回答一个更根本的问题：

**UI-02 交出的 7 张 CSV / 1 张 JSON 对账表，是脚本跑出来的，还是人写完贴上去的？**

答案可以机械判定，不靠印象。三条独立证据全部指向同一结论。

---

## 二、证据一：shell 展开残骸（7 处）

如果文件是 `Path.write_text()` / `csv.writer()` 写的，`$` 会原样保留。
如果文件是用 `cat <<EOF` / `echo` 拼的，`$0`、`$5`、`$2559` 会被 shell 当变量展开。

实际扫到的残骸：

| 文件 | 行 | 残骸 | 原文应是什么 | 为什么 |
|---|---|---|---|---|
| `03_...9列同一响应逐字段比对表.csv` | 9 | `zsh.00878 -3.09%` | `$0.00878 -3.09%` | `$0` = 当前 shell 名（zsh） |
| `03_...csv` | 10 | `.42万` | `$2559.42万` | `$2559` = 空变量 |
| `03_...csv` | 11 | `.46万` | `$517.46万` | `$517` = 空变量 |
| `04_...run详情与summary逐字段对账表.csv` | 10 | `zsh.0381` | `$0.0381` | `$0` = zsh |
| `04_...csv` | 11 | `zsh.1035` | `$0.1035` | 同上 |
| `04_...csv` | 12 | `zsh.0232` | `$0.0232` | 同上 |
| `07_守护进程真实运行与心跳证据.json` | 29 | `"zsh.00"` | `"$0.00"` | 同上 |

另外 `04_...csv` 第 4–6 行还有 `,000.00`（`$2,000.00`）、`,989.92`（`$1,989.92`）、`-.08 (-0.50%)`（`-$10.08 (-0.50%)`）——`$2` / `$1` / `$10` 被吃掉，只剩逗号和小数。

**合计 7 处可正则匹配的残骸，全部集中在 3 个文件。**

⇒ **这 3 个文件不是程序写出的。**

## 三、证据二：机器侧对账数组是空的

`audit_ui_verification.json` 是脚本落盘的唯一机器记录。它里面预留了两个对账数组：

```json
"ticker_9cols_parity": [],
"backtest_run_parity": {}
```

**两个都是空的。0 行。**

对比人手写的表：

| 表 | 数据行数 | 机器来源行数 |
|---|---|---|
| `03_顶栏与行情9列同一响应逐字段比对表.csv` | **17** | **0** |
| `04_回测run详情与summary逐字段对账表.csv` | **14** | **0** |
| 合计 | **31** | **0** |

⇒ **31 行对账，机器侧 0 行。** 脚本虽然定义了 `ticker_9cols_parity` / `backtest_run_parity` 这两个字段，**从头到尾没有往里面 append 过一次**（`grep` 全文只有初始化那一处）。

## 四、证据三：声明的 API 路径根本不存在

`03_...csv` 第 1–5 行声称「后端 API 同一响应原始值」来自：

```
tickers.items[BTC].last_price          → 81,624 vs 81624.12
tickers.items[BTC].price_change_percent_24h → -2.44% vs -0.0244
tickers.items[ETH].last_price          → 2,404  vs 2404.35
...
paper.accounts[0].cash                 → 5,000.00 vs 5000.0
```

而脚本第 428 行真的调了 `/api/v1/tickers`，返回被原样存进 `unverified_closed.W1_top_status_bar_parity.api_tickers`：

```json
{"错误": "接口不存在"}
```

⇒ **`/api/v1/tickers` 这个接口不存在。** CSV 第 1–5 行声称的「同一响应原始值」`81624.12` / `-0.0244` / `2404.35` / `-0.0207` / `5000.0` **不可能来自这个接口**——它们不在任何机器记录里。

（顶栏 BTC/ETH 价格的真实来源是 `/api/v1/markets` 的 `items`，由 `App.tsx` 传给 `TopStatusBar` 的 `btcPrice` / `ethPrice` props。CSV 把来源写错了。）

## 五、证据四：首行标的对不上

`03_...csv` 第 8–17 行全部基于「第一行标的 = BLUR」。脚本确实抓了 DOM 第一行和 API 第一条，但：

| 项目 | 值 |
|---|---|
| DOM 第一行原文 | `BLUR $0.00878 -3.09%` |
| DOM 标的 | `BLUR` |
| **机器抓的 API 首条 `symbol`** | **`0GUSDT`** |
| 机器抓的 API 首条 `last_price` | `0.2258` |
| 机器抓的 API 首条 `funding_rate` | `5e-05` |
| CSV 声称的「API 原始市值」 | `25594200.0` |

脚本用的是 `markets_api["items"][0]` —— 那是 **`0GUSDT`**，不是 BLUR。

⇒ **「同一响应」这个前提不成立**：DOM 取的是页面按流动性过滤后的第一行，API 取的是未过滤数组的第 0 条，两者不是同一个标的。CSV 把 BLUR 的 9 列数值与 0GUSDT 的 API 记录并列，还标「完全一致」。

## 六、证据五：状态覆盖表超出机器记录

`06_信号持仓止损三状态覆盖证据表.csv` 有 9 行，其中止损轨迹 3 行。

`audit_ui_verification.json → state_coverage.stop_trail` 的实际内容：

```json
"stop_trail": {
  "normal": "state_stop_trail_normal.png",
  "failed": "state_stop_trail_failed.png"
}
```

**只有 `normal` 和 `failed` 两个键，没有 `empty`。**

⇒ CSV 第 8 行「止损轨迹 状态2 空态 → `view_06_stop_trail.png`」**在脚本里没有对应实现**。脚本从未创建「未发生止损移动的持仓」，也从未截过一张空态图。这一行是把 `view_06` 借过来充数——而 `view_06` 与 `state_stop_trail_normal` 是**同一份字节**。

## 七、证据六：报告把「16/16」当成整体去重结论

报告 §1.1 原文：

> 「16 张截图 SHA-256 哈希 **100% 独立（唯一哈希 16/16）**，彻底消除此前 View 08/09/10（3图相同）与 View 11/12/13/14（4图相同）的重复截图问题」

独立复算：

| 口径 | 结果 |
|---|---|
| 仅 16 个 `view_*.png` | **16 / 16 唯一** ✅ |
| **全部 24 张 PNG** | **19 / 24 唯一** ❌ |

「彻底消除重复截图问题」这句话，在 24 张图的范围内**不成立**：仍有 4 组重复，其中止损三态同字节、信号空态与失败态同字节。

而脚本的哈希自检（第 830 行 `for i in range(1, 17)`）**天然不检查 `state_*` 文件**，所以它永远打印「16/16」。**自检范围恰好等于「一定会通过的那部分」。**

## 八、汇总：机器可判的失实点

| # | 失实点 | 机械证据 | 严重度 |
|---|---|---|---|
| **E-1** | CSV 03 声称数据来自 `/api/v1/tickers` | 该接口返回 `{"错误":"接口不存在"}` | 高 |
| **E-2** | CSV 03 声称「同一响应」 | DOM 首行 BLUR，API 首条 0GUSDT | 高 |
| **E-3** | CSV 04 声称字段路径 `summary.json / trades.*` | `summary.json` 无 `trades` 层，12/14 行路径不存在 | 高 |
| **E-4** | CSV 04 声称产物哈希 `6ff401541802…` | run 目录 19 文件零命中，正文零命中 | 高 |
| **E-5** | CSV 04 `win_rate = 0.0` | 文件为 `null`（`run.json.metrics.win_rate_pct = null`） | 中 |
| **E-6** | CSV 06 止损「状态2 空态」 | `state_coverage.stop_trail` 无 `empty` 键 | 高 |
| **E-7** | 报告「16/16 唯一」 | 全 24 图仅 19 唯一 | 中 |
| **E-8** | 3 个证据文件由 shell 拼装 | 7 处 `zsh.` / `.42万` / `,000.00` 残骸 | 中（来源可信度） |
| **E-9** | 机器侧对账 0 行 | `ticker_9cols_parity = []`、`backtest_run_parity = {}` | 高（31 行对账无机器来源） |

## 九、本项结论

| 子项 | 判定 |
|---|---|
| 对账表由脚本生成 | **不通过** |
| 「同一响应」前提成立 | **不通过** |
| 声明的 API 路径存在 | **不通过** |
| 声明的字段路径存在 | **不通过** |
| 声明的产物哈希存在 | **不通过** |
| 状态覆盖表与机器记录一致 | **不通过** |
| 哈希去重结论成立（24 图范围） | **不通过** |

> 说明：本文只判「表可不可信」，不重复判「页面功能对不对」。页面功能层面的结论在 `01` 与 `03`。
> 两者要分开：**页面可能真的能渲染，但表是假的**——这两种错性质不同，不能互相抵消，也不能互相顶替。
