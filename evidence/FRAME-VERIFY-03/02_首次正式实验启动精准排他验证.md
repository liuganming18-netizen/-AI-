# FRAME-VERIFY-03｜02. 首次正式实验启动精准排他验证

## 一、问题背景与混杂消除设计

在 `FRAME-VERIFY-02` 的死锁复现中，测试输出同时出现了两个阻断项：
1. `尚无已登记运行（试验次数为 0，不能宣称有结果）`
2. `当前代码/参数/规则/样本/分组/指标与登记身份不一致...`

实现方可能会对此提出合理质疑：“实验被拒是否并非由于 runs=0，而是由于调用方构造测试时传入了不匹配的参数、未对齐窗口或错误的身份哈希等混杂因素导致的？”

为了彻底消除这一混杂，本工单设计了**零混杂纯净测试方案（Pure Exclusion Test）**：
1. **消除窗口混杂**：明确绑定底层写死窗口 `('2024-01-01', '2024-06-30')`，使 `execution_scope_mismatch` 严格返回 `None`；
2. **消除分组混杂**：构建满足严苛要求的 `SplitPolicy`（`train: 2024-01-01~2024-03-31`, `valid: 2024-04-15~2024-06-30` 隔离 15 天=360h > 240h，`holdout: 2026-10-25~2026-11-25` 远离已观察样本），`policy.validate()` 严格返回 `[]`；
3. **消除身份混杂**：直接调用系统真实的 `current_design_parts` 提取当前系统代码与规则指纹，使登记时派生的 `design_identity` 与 `guard_create` 运行时计算的 `design_identity` **100% 逐字符全等**；
4. **满足全部启动前置条件**：显式执行 `reg.freeze(eid)`，确保配置已冻结、模式为 `formal`、未被放弃（`abandoned=False`）；
5. **保持零运行记录**：`exp["runs"] == []`。

在此完美无瑕的静态配置下，调用真实生产入口，排他性检验 `blockers` 是否**唯一且必然仅包含** `尚无已登记运行（试验次数为 0，不能宣称有结果）`。

## 四、给 FRAME-FIT-01 团队的最小复现与最小整改方案

### 1. 最小复现脚本（可直接复制执行）

```python
import tempfile
from experiment_registry import (
    ExperimentRegistry, SplitPolicy, DEFAULT_METRICS_SPEC,
    current_design_parts, guard_create, MODE_FORMAL
)

tmp = tempfile.mkdtemp()
reg = ExperimentRegistry(tmp)
scope = {"symbols": ["BTCUSDT"], "window_start": "2024-01-01", "window_end": "2024-06-30", "source": "request"}
policy = SplitPolicy(train=("2024-01-01", "2024-03-31"), valid=("2024-04-15", "2024-06-30"),
                     holdout=("2026-10-25", "2026-11-25"), isolation_hours=240, label_span_source="240h")
parts = current_design_parts(sample_scope=scope, split_policy=policy, metrics_spec=DEFAULT_METRICS_SPEC)
parts.update({"strategy_version": "v0.1.0", "strategy_name": "event_trend", "entry_filter_rules": "box", "exit_rules": "atr"})

eid = reg.register(design=parts, sample_scope=scope, split_policy=policy, metrics_spec=DEFAULT_METRICS_SPEC, mode=MODE_FORMAL)["experiment_id"]
reg.freeze(eid)

# 尝试创建首个运行
spec = {"symbols": ["BTCUSDT"], "window_start": "2024-01-01", "window_end": "2024-06-30",
        "experiment": {"mode": "formal", "experiment_id": eid}}
res = guard_create(spec, registry=reg)

print("是否允许启动:", res["ok"])       # 打印: False
print("阻断原因:", res["blockers"])     # 打印: ['尚无已登记运行（试验次数为 0，不能宣称有结果）']
```

### 2. 最小整改建议（无需重构架构）
在 [`框架/backend/experiment_registry.py`](file:///Users/boos/Desktop/威科夫因子共振趋势/框架/backend/experiment_registry.py#L1119)：
```python
# 修改前 (行 1119):
ok, why = reg.formal_eligible(eid)

# 修改后：
# 启动门禁只检查静态资格与冻结状态，不检查 runs 是否已产生：
ok, why = reg.formal_launchable(eid)
```
其中 `formal_launchable` 只检查：模式为 formal、无设计缺项、分组完整自洽、已冻结、未放弃。
将 `if not exp["runs"]` 与 `if not exp["trials"]` 仅保留在 `formal_eligible`（供解封留出 `unseal_holdout` 与交付验收报告调用）。
