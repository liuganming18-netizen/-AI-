## 三、为什么不改 `backtest_api.py`

`create_run` 里的调用是：

```python
exp_gate = EXP.guard_create(clean)
if not exp_gate.get("ok"):
    return _envelope(missing_reason="实验资格校验未通过（FRAME-FIT-01）", ...), 409
```

`guard_create` 的签名没变，`ok` 的语义（能不能创建）没变，返回里只是**多了**字段。
所以控制器一行都不用动 —— 这也说明修复点在登记模块内部，不在调用方。

## 四、并发修改（不是本单做的，但交付物是合并后的状态）

本单执行期间有另一个进程/窗口在改同一批文件。独立复验必须知道这件事，
否则会把别人的改动算到本单头上，或者把「合并后才通过」误当成「本单改完就通过」。

| 时点 | 文件 | 内容 |
|---|---|---|
| 02:41（本单开始读代码时） | `backtest_api.py` | `create_run` 在 L978 开始，**没有** `_freeze_design` |
| 02:56:18 | `backtest_api.py` | 出现 `_freeze_design`（创建时冻结）+ 留出段守卫 `infrastructure.guard.holdout` |
| 02:58:30 | `tests/test_frame_fit_02.py` | 研究模式用例被改写为 `test_research_run_is_frozen_and_writes_trial` |
| 03:00:47 ~ 03:01:47 | 生产登记库 | 写入 8 条事件（见 `06` 第五节） |

处理方式：

1. **不覆盖别人的改动**：发现 `backtest_api.py` 变了之后，本单没有回滚它，而是让本单的
   「启动 / 交付」拆分与它共存，并重跑全量确认两边都过；
2. **留确定基准**：`snapshot/` 存合并后 4 个文件，`reproduce.sh` 逐字节比对；
3. **如实记录**：并发写入若在交付后继续，本文件的行号与哈希会漂移 —— 那时以
   `snapshot/` 为准，不以行号为准。
