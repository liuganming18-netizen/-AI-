# FRAME-FIT-02｜02. 启动许可与结果交付资格契约

## 一、为什么必须分开

一句话：**「能开跑」和「能交付」是两个时点的事，用同一个判断就会死锁。**

- 运行记录（`runs`）只能在启动之后、由执行器写入；
- 如果启动时要求「已有运行记录」，那么第一次永远不满足，永远启动不了；
- 反过来，如果为了能启动就把「有运行记录」这条删掉，那跑完没跑完都能宣称有结果 —— 一样糟。

所以拆成两个阶段，各自有各自的条件集合，**交付资格包含启动许可的全部条件**（单调）。

---

## 二、两个阶段的条件（逐条）

### 启动许可 `STAGE_LAUNCH` — `_launch_blockers()`

| # | 条件 | 不满足时的原话 | 来源 |
|---|---|---|---|
| 1 | 登记模式必须是 `formal` | `登记模式为 'research'（研究运行不具正式资格）` | 原有 |
| 2 | 设计七项齐全 | `设计缺项：…` | 原有 |
| 3 | 分组已配置且自洽（时间顺序、段间隔 ≥ 隔离长度） | `分组未配置/不自洽：…` | 原有 |
| 4 | 已冻结 | `配置未冻结` | 原有 |
| 5 | 冻结身份 == 当前登记身份 | `冻结身份与当前登记身份不一致…` | 原有 |
| 6 | 未放弃 | `实验已放弃` | 原有 |
| 7 | 留出段内没有已观察样本 | `留出段内含有已观察样本（登记集：…）` | 原有判据（与解封共用） |

**明确不含**：`runs` 是否为空、`trials` 是否为空。

### 结果交付资格 `STAGE_DELIVERY` — `formal_eligible()`

| # | 条件 | 不满足时的原话 |
|---|---|---|
| 1-7 | 启动许可的全部条件 | 同上 |
| 8 | 至少一次运行 | `尚无已登记运行（试验次数为 0，不能宣称有结果）` |
| 9 | 至少一条试验结论 | `有 N 次运行但无任何试验结论记录（失败/放弃也须入册，只留赢家不算合格）` |
| 10 | **每次**运行都有对应结论 | `N 次运行没有对应的试验结论（如 …）⇒ 结果记录不完整，不能宣称正式交付` |
| 11 | 至少一条结论带量化结果 | `所有试验结论都没有量化结果（metrics 全空）⇒ 没有可交付的结果，不能宣称正式交付通过` |

第 11 条是**故意**的：失败的运行没有 metrics，所以「只跑失败」的实验永远不具交付资格 ——
它只能如实报失败，不能对外说「正式交付通过」。

## 三、判定顺序（不可调换）

```
guard_create(spec)
  ├─ 研究模式 → 自动登记（不冻结）→ 允许跑，formal_eligible 恒 False
  └─ 正式模式
       ├─ 无 experiment_id            → 拒绝（不得临时起意）
       ├─ formal_launchable(eid)      → 启动许可（7 条）
       ├─ 登记身份 == 当前身份？       → 不一致 ⇒ 拒绝（身份漂移）
       └─ 窗口与执行链写死窗口一致？   → 不一致 ⇒ 拒绝（scope mismatch）
       ↓ 通过
create_run 落 run 文档（202）

execute_run(run_id)
  ├─ guard_execute：实验已登记 / 未放弃 / 已冻结 / 身份未漂移
  │    └─ 漂移 ⇒ 写 invalidate 事件并拒绝（冻结失效）
  ↓ 通过
_run(...)  ← 昂贵策略计算（测试里替换这一层）
  ↓
成功 → record_execution(outcome="success", metrics=…)
失败 → record_execution(outcome="failure", note=异常)
闸门拒绝 → **不写任何记录**
```

---

## 四、不变式（测试逐条锁住）

1. **启动不写事件**：`guard_create` 通过后，登记库里事件条数不变，`runs` / `trials` 仍为 0。
2. **交付单调**：`formal_eligible` 为真 ⇒ `formal_launchable` 必为真（反之不成立）。
3. **不写记录就没有资格**：没有任何路径能在「没真跑」的情况下让 `runs` 非空。
4. **幂等**：同一 `run_id` 重复 `record_execution` 只产生一条 run、一条 trial。
5. **越权不写**：未登记 / 未冻结 / 已放弃 / 未知结论 → 一律不写，并返回原因。
6. **拒绝不写**：`execute_run` 在闸门处被拒时，run.json 里不会出现 `experiment_record`。
7. **既有拦截不减**：未冻结、身份漂移、窗口不符、已放弃、样本污染、分组未配置，六条全部仍拒绝（T06 覆盖）。

## 五、字段口径（返回值）

`guard_create()` 正式模式返回：

| 字段 | 含义 |
|---|---|
| `ok` | **能不能启动**（只看启动许可 + 身份 + 窗口） |
| `stage` | 固定 `"launch"`，提醒调用方这是启动阶段的结论 |
| `blockers` | 启动阻断原因（空 = 放行） |
| `design_identity` | 本次请求算出的设计身份 |
| `delivery_eligible` | 此刻是否已具备交付资格（首次实验必然是 `false`） |
| `delivery_blockers` | 交付还差什么（首次实验通常是「尚无已登记运行」） |

`list_experiments()` 每项同时给 `launchable` / `launch_blockers` 与 `formal_eligible` / `blockers`，
**不再把两件事混在一列里**。
