# FRAME-FIT-02｜03. 真实入口调用链

## 一、谁调谁（不是示意，是本单探针实际走的路）

```
evidence/FRAME-FIT-02/scripts/probe_launch_before_after.py
├── ExperimentRegistry.register(mode=formal) + freeze()
│      └── 零运行、零试验（这就是「首个」）
├── ① 旧逻辑等价复现
│      └── reg.formal_eligible(eid)                ← 旧 guard_create 正式分支就这一句
├── ② 新逻辑
│      └── experiment_registry.guard_create(spec)
│             ├── _requested_mode(spec)            → formal
│             ├── execution_scope_mismatch(scope)  → None（窗口对齐）
│             ├── current_design_parts(...)        → 当前代码/参数/规则/样本/分组/指标
│             └── formal_launchable(eid)           ← 本单新增：只看静态条件
├── ③ 控制器
│      └── backtest_api.create_run(payload)        → 202 + run_id
│             ├── _runnable_gate()                 → 放行
│             ├── BR.validate_run_spec(payload)    → 保留白名单字段
│             ├── EXP.guard_create(clean)          → ok=True（同一个函数）
│             ├── infrastructure.guard.holdout     → no_holdout ⇒ 放行
│             ├── _freeze_design(eid)              → 已冻结 ⇒ 跳过（并发改动引入）
│             └── S.create_run(run_id, doc)        → 落 run.json
└── ④ 执行入口
       └── backtest_runner.execute_run(run_id)
              ├── EXP.guard_execute(run_id, doc)   → None（冻结 + 身份一致）
              ├── _run(run_id, doc)                ← **测试/探针替换的就是这一层**
              ├── S.set_status(SUCCEEDED, ...)
              └── _record_experiment_outcome(...)
                     └── EXP.record_execution(...) → attach_run + record_trial
```

**关键点**：闸门（`guard_create` / `guard_execute`）和登记（`record_execution`）都在真实链路上，
测试里只把 `_run` 换成桩 —— 昂贵策略计算可以替，被测逻辑没替。

## 三、读这段记录能看出什么

**1. 同一个实验、同一个身份，修复前后结论相反。**
`design_identity` 一字未变（`a76070e6…`），唯一变化是**判断用哪一阶段的条件**。
所以这不是「放宽了某个阈值」，而是「问对了问题」。

**2. 启动那一刻就已经把「还不能交付」写清楚了。**
`ok=true` 与 `delivery_eligible=false` 同时出现在一个返回里，
`delivery_blockers` 原话就是「尚无已登记运行」。调用方没有机会把「能启动」误读成「有结果」。

**3. 跑完才真的产生记录。**
`runs=1`、`trials=1`、`trial_outcome=success`，且 `experiment_record.recorded=true`
（写进了 run.json，可事后核对）。此时 `delivery_eligible` 才变 `true`。

**4. 闸门全程没写记录。**
`before` / `after_guard` 两步都在 `runs=0` 状态下完成；
`runs` 变 1 只发生在 `execute_run` 之后 —— 即「记录来自执行，不来自过闸」。

## 四、失败路径的记录长什么样

`execute_run` 里 `_run` 抛异常时：

```python
S.set_status(run_id, S.STATUS_FAILED, failure_reason=..., traceback=...)
_record_experiment_outcome(run_id, doc, outcome="failure", note="RuntimeError: …")
```

run.json 里会有：

```json
"experiment_record": {"outcome": "failure", "recorded": true, "error": null}
```

登记库里对应一条 `trial(outcome="failure", metrics=null)`。
此时 `formal_eligible` 仍为 False，原因多一条「所有试验结论都没有量化结果」。

闸门拒绝（`gate_err`）时**不调用** `_record_experiment_outcome`，run.json 里没有
`experiment_record` 字段 —— 用例 `test_gate_rejection_writes_no_record` 锁住这一点。
