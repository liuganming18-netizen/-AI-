## 四、OI 门槛是否恢复（改动④的运行时取证）

**能做到什么、做不到什么，如实写清**：

- **做不到**：从运行中进程的内存里直接读 `signal_engine.enable_oi_filter`（没有 pyrasite 之类的注入工具，
  且 `MultiSymbolSignalEngine` 不把该值导出到状态文件，`signal_engine.oi_diag` 恒为 null，
  因为 `oi_diag` 是 `RealSignalEngine`（单标的）的属性，不在多标的聚合层）。

- **做到的是完整参数链 + 同版本代码实测**：

| 环节 | 事实 | 来源 |
|---|---|---|
| ① 命令行 | 新 Runtime 的 cmdline = `unified_runtime.py --arm 3a --symbol all --interval 2.0`，**没有** `--enable-oi-filter` | psutil 实测 pid 14879 |
| ② 参数解析 | `parser` 只定义 `--arm/--symbol/--interval/--once/--status`，**根本不存在** `--enable-oi-filter` | `unified_runtime.py:3156-3161` |
| ③ 构造调用 | `UnifiedRuntime(arm=..., symbols=..., poll_interval_sec=...)`，**不传** `enable_oi_filter` | `unified_runtime.py:3177` |
| ④ 默认值 | `enable_oi_filter: Optional[bool] = None` ⇒ `enable_oi = None` | `unified_runtime.py:2453, 2472-2473` |
| ⑤ 回落 | `None ⇒ getattr(config,"enable_oi_filter",True)` | `unified_runtime.py:786-787` |
| ⑥ 配置值 | `EventTrendConfig().enable_oi_filter = True` | 实测 |

- **隔离实测（同版本代码）**：

```
EventTrendConfig.enable_oi_filter = True   (bool)
  MultiSymbolSignalEngine(默认不传) .enable_oi_filter = True
  MultiSymbolSignalEngine(显式 None) .enable_oi_filter = True
  MultiSymbolSignalEngine(显式 False) .enable_oi_filter = False
  MultiSymbolSignalEngine(显式 True ) .enable_oi_filter = True
```

**结论**：运行中的 OI 门槛 = **True（开着）**。
证据等级：**参数链 + 同版本代码 + 配置实测**，**不是**运行时内存取证。
这一条要按「间接证明」记，不能按「运行时直读」记。
