## 一、唯一活跃路径（生产）

```
unified_runtime.py:2943  run_forever()
  └─ while: step_once()                                    :2943-2998
       ├─ 1. 信号引擎扫描 / 候选落库
       ├─ 2. router.route_pending_orders(now, origin)       :2879
       ├─ 3. （同上）
       └─ 4. self.execution.execute_cycle(now,
                process_start_ms=self.started_at_ms)        :2892
             └─ UnifiedExecutionDaemon.execute_cycle        :2334
                  ├─ PE.advance_pending(T=now_ms,
                  │     process_start_ms=process_start_ms)  :2347
                  │    └─ 遍历 L.ARMS → pending_orders(arm)  :898-953
                  │         └─ PE.open_position(..., pending_id=…)   :966
                  ├─ 4h 跟踪止损推进（advance_position_trailing）
                  └─ 15m 明细周期退出（check_position_exit_on_bar）
```

**结论：生产环境里挂单推进只有一个入口** —— `Runtime.step_once` → `execute_cycle` → `advance_pending`。

## 三·补、既有的一道「不补开历史」护栏（不是本单加的，需知道）

`unified_runtime.py:2853-2855`（`step_once` 第 1 步之后）：

```python
if origin == "live":
    # 启动之前确认的历史事件一律不补开（水位线纪律）
    new_cands = [c for c in new_cands if c.available_at_ms >= self.started_at_ms]
```

含义：**自然路径本来就已经拒绝「确认时刻早于本进程启动」的候选**，且是静默丢弃（不进 `new_signals`、
不进 `funnel`）。它与我加的 C3 是**互补的两段**：

| 段 | 位置 | 管什么 |
|---|---|---|
| 信号 → 挂单 | `step_once:2855`（**既有**） | 候选的 `available_at_ms` 早于进程启动 ⇒ 不落库、不挂单 |
| 挂单 → 成交 | `open_position` C3（**本单新增**） | 应成交 bar 在进程启动前已收盘 ⇒ 拒单，不追补 |

⇒ 这条护栏解释了为什么「重启后不会冒出历史候选」，但**它不能替代 C3**：已有挂单（在进程启动前就已登记）
不受它管，仍会走到 `open_position`。`test_probe_succ` 正是这种「已登记挂单」——它 15:46 就落库，
走的不是候选筛选那条路，所以这条护栏管不到它，只能靠 C3 拦。

## 五、明确未修（规则层缺口，需裁决，不自选）

1. **执行动作从未在 bar 开盘时刻真实发生**：`bar_at_or_after` 强制 `is_closed=1`，
   所以成交必然是「闭 bar 后回读该 bar 的 `open`」，`entry_ts` 恒早于实际处理 15~30 分钟。
   要做到「现实执行点成交」需要 bar 开盘瞬间的实时报价（ticker/aggTrade）—— 那是**新成交模型**，
   本单不自选（工单：「若现有实现无法在现实执行点取到既定成交依据，报告具体缺口」）。
2. **撮合不检查 bar 的 `available_at`**：`test_probe_succ` 实测 `fill_ts=16:30:14.728Z`
   早于该 bar 的 `available_at=16:30:16.461Z` **1.733 秒**（见 `out/02`）。属于证据链上的
   PIT 疑点，是否加判据需裁决（`available_at` 语义尚未定案：是交易所可得还是入库时刻）。
3. **`MAX_FILL_LAG_MS` 仍以 `bar.open_time` 为基准**（1 小时）：因为 bar 必须闭合，
   最小 lag 恒为 15 分钟 ⇒ 实际「真迟到」容忍是 45 分钟。本单**没有**改这个数，
   而是另加一条不依赖数值阈值的判据（C3）。是否把基准改为 `bar.close_time` 需裁决。
4. **`live_worker.advance_paper` 仍无调用者**（休眠），本单不接线。
