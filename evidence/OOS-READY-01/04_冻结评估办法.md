# OOS-READY-01｜冻结评估办法

- 性质：**事前写定的判定规则**。一旦批准，累积期内不得修改；任何修改都触发版本重置。
- 适用对象：`WX_EVENT_TREND_V0_1`（策略版本以冻结文件 SHA-256 为准，不认 Git HEAD）。
- 本文件不产生任何收益数字，只规定"怎么判"。

---

## 一、冻结对象

批准当天必须落盘以下五项，缺一项不得起算：

| 项 | 内容 | 落盘形式 |
|---|---|---|
| 策略规则 | `evidence/WX_EVENT_TREND_V0_1_策略与回测冻结规则.md` | SHA-256 |
| 代码 | 策略、撮合、风控、账本相关文件 | 逐文件 SHA-256 清单 |
| 参数 | 阈值、仓位、成本假设 | 参数表 + SHA-256 |
| 币池规则 | 前 50 按 30 天成交额、上市满 90 天、排除指数 | 规则文本 + 实现文件 SHA-256 |
| 数据范围 | 起算日、可用数据截止 | 覆盖清单 + 快照 SHA-256 |

哈希由脚本计算并落盘，不手写。

---

## 二、候选样本选择规则

### 2.1 币池

- 每日 UTC 00:00，按此前完整 30 天平均日成交额排序，取前 50。
- 要求上市满 90 天。
- 排除 `INDEX`／`crypto_index` 类合约（如 `BTCDOMUSDT`）。
- 入池只控制新建事件；出池不强制结束已有事件或仓位。
- **完整保留退市币与退市结果**，不得用"今天仍存活的名单"筛历史。

### 2.2 事件

A 状态机原样执行，**不新增阈值、不新增因子、不做参数搜索**：

- 箱体：42 根完整 4h，`2 <= (H-L)/A <= 8`，`ER <= 0.30`，ATR 预热 ≥200 根。
- 扫低：`L-0.5A <= low < L`，`close >= L+0.1A` 且 `<= H`，7 天内首根。
- 回踩：`L <= low <= L+0.5A`，`low > S`，`close >= L+0.1A` 且 `>= open`，`volume <= 0.8*Vs`，72 小时内。
- 突破：首次上穿 `H+0.1A` 的 1h 收盘，`volume >= 1.5*V20`，`OI(T)/OI(T-6h)-1 >= 0.02`。
- 冷却 24 小时；单币最多一个观察事件；最长观察 14 天。

### 2.3 配对口径

沿用 `BREAKEVEN-02` 的固定仓位配对：**同一入场时刻、同一入场价、同一数量、同一初始止损**，只比退出分支。这样排除"前一笔提前退出导致后一笔仓位漂移"的串行资金耦合。

### 2.4 剔除

- 切分边界前 24 天停止新建事件；跨界未完整结束的样本单列，不计入独立评分。
- 允许读取边界前 200 根 4h 做预热，但不携带前段事件、持仓或结果标签。
- 亏损样本一律保留，不得静默删除。

## 三、数据可用时钟

| 环节 | 规则 | 违反后果 |
|---|---|---|
| 决策时刻 | 1h 开盘 + 3600 秒 | — |
| OI 可用 | `桶起点 + 5m <= 决策时刻` | 未收盘桶参与即抛 `PitViolation`，该事件作废 |
| 未收盘 K 线 | 物理剔除（`is_closed == 1`） | 同上 |
| 入场 | 确认后下一根严格更晚开始的 15m 开盘 | 提前成交即作废 |
| 跳空 | 开盘 > 突破收盘 + 0.5A，或开盘 < H，或止损不低于入场价 → 取消 | 不得等待更优价格 |
| 止损抬升 | 触发根之后下一根 15m 起生效 | 当根生效即作废 |
| 资金费 | 真实结算事件 + 结算 mark；正费率多头付 | 用收盘价冒充 mark 即作废 |
| 历史发布时点 | **无证据，只能声明"计算上不超前"** | 不得声明"已证明无未来函数" |

## 四、主要比较指标

不新增指标，全部沿用冻结规则 §6：

- **漏斗**：箱体数、扫低数、回踩数、首次突破数、量能拒绝数、OI 拒绝/缺失数、候选数、风险拒绝数、真实成交数。
- **收益**：净收益、每笔净 R、每事件净 R（未交易记 0）、PF、胜率、平均盈亏比、MFE/MAE、持仓时长。
- **风险**：组合最大回撤（**只在真实组合模拟下报**）、资金暴露。
- **成本分项**：手续费、滑点、资金费分别列出。
- **切片**：按币种、季度、入场时期。
- **集中度**：单币贡献、最大五笔贡献。
- **区间**：28 天时间块重采样，固定种子，2000 次，报净期望 95% 区间。**不对每笔独立 bootstrap**。

## 五、成本口径

| 项 | 基准 | 压力 |
|---|---|---|
| 手续费 | 5 bps/边 | 10 bps/边 |
| 滑点 | 3 bps/边 | 6 bps/边 |
| 价格处理 | 买 ×1.0003，卖 ×0.9997 | 同左 |
| 资金费 | 真实结算事件与 mark | 同左（不放大） |
| 取整 | `trading_core/fill.py`，Decimal，买 ceil／卖 floor | 同左 |
| 订单上限 | 不超过前一根 15m 成交额的 0.1% | 同左 |

两套结果**分别报告**，不得只报基准。

## 六、失败条件

任一成立即判 **FAIL**：

1. 样本外净收益 ≤ 0；
2. PF < 1.20；
3. 组合最大回撤 > 10%；
4. 28 天时间块重采样净期望 95% 区间下界 ≤ 0；
5. 压力成本下净收益 ≤ 0；
6. 样本不足：<12 个月，或 <100 笔已结束交易，或 <10 个实际交易币种 → 判**证据不足**。

第 6 条要单独说清：**"证据不足"不等于"策略无效"，但同样不得进入前向模拟，更不得进入 Live。**

## 七、停止规则

| 编号 | 条件 | 动作 |
|---|---|---|
| P1 | 工程 Gate 未过（同输入两次运行结果不逐项一致） | 停止，不得进入评估 |
| P2 | G1／G2／G4 未闭环 | 停止，攒出的样本不得用于判定 |
| P3 | 累积期内提前查看收益指标 | 违规，该段样本作废 |
| P4 | 评估后二次使用同一段样本 | 禁止；需新版本号并声明原测试集已被看过 |
| P5 | 因结果修改阈值／币池／因子 | 版本重置，样本重新累积 |
| P6 | 出现数据覆盖异常（如某币 OI 缺失率突增） | 暂停该币入池，记录原因，不得静默剔除 |

## 八、前置缺口与闭环要求

以下 7 项来自本单检查，**在起算前必须有明确处置**。不能用统计结果替代。

| 编号 | 缺口 | 起算前要求 |
|---|---|---|
| G1 | 历史 OI 发布时点无证据 | 写成明文边界：能声明"计算上不超前"，不能声明"已证明无未来函数" |
| G2 | 历史合约规格 0 条 verified（576 次运行全 unverified/contradicted） | 要么找到当时快照，要么固定写"按当前规格回填"并量化对取整/最小单的影响 |
| G3 | 资金费 mark 只有 2022-01-01 起 | 2021 段结论标注"资金费口径不完整"，或不纳入评分 |
| G4 | 既有运行用随机 100 标的，非冻结规则前 50 | 按前 50 实现并出具运行清单（新工单） |
| G5 | 组合级回撤从未计算 | 补真实组合模拟层，否则失败条件第 3 项无法判定 |
| G6 | 最细价格路径 15m | 如实披露触发滞后最多 15 分钟，方向不确定 |
| G7 | 研究 Gate 已 FAIL，样本只够识别 ±2.51 U/笔 | 这是本方案要解决的问题本身；不得在结论里回避 |

## 九、交付要求（评估完成时）

1. 冻结清单与全部 SHA-256；
2. 事件漏斗逐级计数；
3. 全部事件与候选快照（不只成交的）；
4. 逐笔成本账本（手续费／滑点／资金费分列）；
5. 两次确定性对账结果；
6. 工程 Gate 与研究 Gate 各自的 PASS/FAIL 与原因；
7. 失败时的归因（是样本不足、执行不可信，还是策略无效——三者分开写）。

---

## 十、变更控制

- 任何规则改动 → 新版本号 + 新冻结清单 + 样本重新累积。
- 不得在旧测试集上"再跑一次看看"。
- 不得把"样本内表现好"当作"验证通过"。
- 本文件一旦批准，修改需书面记录修改人、时间、原因，并同步更新 SHA-256。
