## 一、新增：`策略/WyckoffMaster/flow_oi/pit_features.py`

### 为什么放在这里
`evidence/` 是产物目录，不该放生产实现。受控取数必须是被多个入口共用的一份代码，
否则迟早又长出第二条路径。放在 `策略/WyckoffMaster/flow_oi/` 下：
① 能被 `evidence/` 下的实验脚本 import；② 不进入事件趋势策略的代码指纹清单。

### 结构

| 成员 | 作用 |
|---|---|
| `FlowPitFeatureExtractor` | 一次决策 = 一个实例 = 一个独立 `PitStore` |
| `SourceRead` | 单个数据源本次读取的结果（状态 / 是否有证据 / 可用时刻 / 原因） |
| `summarize_pit()` | 把逐候选字段汇总成实验入口要的一份资格报告 |
| `FLOW_PIT_VERSION = "flow_oi_pit_v2.0.0"` | 本层口径版本 |
| `FEATURE_CONTRACT_VERSION = "flow_oi_features_v2"` | 特征契约版本，写进每一行 |

### 关键实现（不是另写一套 PIT）

```python
from ..trading_core.pit_guard import (PIT_GUARD_VERSION, AvailabilityStatus,
                                      DecisionClock, PitMode, PitStore,
                                      PitUnavailable, PitViolation,
                                      rule_bucket_metrics, rule_candles)
```

- 规则全部来自 FRAME-PIT-01 的 `rule_candles` / `rule_bucket_metrics`；
- 取数一律走 `PitStore.as_of(name, decision_time)`；
- 未证明源在 `strict` 下由 `PitStore` 抛 `PitUnavailable`，本层捕获后记成 `refused`。

### 三处必须讲清的口径

**① 三类数据源的可用性规则**

| 源 | 规则 | 证据 | 结论 |
|---|---|---|---|
| 1h K 线 | `close_time + 1ms` | parquet 有 `close_time`，`is_closed` 全为 1 | `exchange_close`（可证） |
| metrics 5m | `ts`（桶起点） | 无 `create_time` / `available_at` | `unproven` |
| OI 5m | `ts`（桶起点） | `fetched_at` 全空 | `unproven` |

**② 声明延迟只推迟取数，不提升资格**

`metrics_declared_lag_ms` / `oi_declared_lag_ms` 会让 `available_at = ts + 5m + lag`，
但本层资格口径是 `proven = (rule.status is EXCHANGE_CLOSE)`。
`declared_lag` **不算可证** —— 否则随手填个 `lag=1` 就能把未证明的源洗白。
另外 `lag=0` 直接 `ValueError`（0 不是证据，等价于把桶结束当发布时间）。

**③ 覆盖与资格分开**

- `coverage_status`：`COMPLETE` / `MISSING_CANDLES` / `MISSING_METRICS` / `MISSING_OI` / `PARTIAL`
- `pit_status`：`PROVEN` / `ASSUMED` / `REFUSED` / `INCOMPLETE`
- `pit_qualified = (pit_status == "PROVEN")`
- `formal_eligible = pit_qualified`（数据有洞会先变成 `INCOMPLETE`，所以自然为 False）

## 五、阈值 / 公式 / 撮合 / 费用：一个都没改

四组准入规则原样保留（逐条对照）：

| 规则 | 阈值 |
|---|---|
| Hyp A 承接 | `taker_buy_ratio_24h < 0.48` 且 `delta_oi_base_24h > 0` |
| Hyp B 健康推进 | `bar_taker_buy_ratio > 0.52` 且 `delta_oi_base_24h > 0.02` 且 `body_ratio > 0.4` |
| Hyp C 滞涨派发 | `bar_taker_buy_ratio > 0.50` 且 `vol_ratio >= 2.0` 且 `upper_shadow >= 0.45` 且 `body_ratio < 0.35` |
| Hyp D 减仓轧空 | `delta_oi_base_24h <= -0.05` |
| G2 拦截 | `taker_buy_ratio < 0.45` 或（`vol_ratio >= 2.0` 且 `upper_shadow >= 0.50` 且 `body_ratio < 0.30`） |
| G3 拦截 | 在 G2 基础上 `delta_oi_base_24h <= -0.05` |
| G4 拦截 | 在 G3 基础上 `global_account_ls_ratio > 1.8` 且 `top_position_ls_ratio < 0.9` |
| 陈旧容差 | K 线 2h、metrics 2h（原值） |

**但取数窗口确实变了，必须说清**：

| 项目 | 旧 | 新 |
|---|---|---|
| 突破当根 | `open_time == ts`（决策刚开始，全是未来） | `open_time == ts - 1h`（刚收盘） |
| 24h 窗口 | `ts-24h < open_time <= ts`（24 根，含未收盘那根） | `open_time >= ts-24h` 且已收盘（24 根，到 `ts-1h` 为止） |
| 当刻 metrics/OI | `ts <= ts`（含未结束桶） | `ts + 5m <= ts`（即 `ts-5m` 桶） |
| 24h 前对照点 | `ts <= ts-24h` | `available_at <= ts-24h`（即 `ts-24h-5m` 桶） |

这是**取数口径**的修正，不是阈值调整；对结果的影响见 `05_新旧行为对照.md`。
