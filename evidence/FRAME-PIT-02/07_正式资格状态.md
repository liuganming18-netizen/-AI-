# FRAME-PIT-02｜07. 正式资格状态

## 一、当前状态（一句话）

**FLOW-OI 四组实验：`formal_eligible` 恒为 False，227 笔无一例外。**

这不是"修得不够"，是数据本身证不出来。

---

## 二、为什么

### 1. Metrics / OI 没有发布时点证据

| 源 | 有没有发布时点 | 能不能证 |
|---|---|---|
| 1h K 线 | 有 `close_time` + `is_closed=1` | 能证"交易所闭合"（但摄取延迟仍未证） |
| Metrics 5m | **没有** `create_time` / `available_at` | **不能证** |
| OI 5m | `fetched_at` **100% 为空** | **不能证** |

抽样实测：

```
oi      : syms=8 files=30 rows=1779127  fetched_null=1779127   (100%)
metrics : syms=8 files=30 rows=2343888  (无 fetched_at / create_time 列)
candles : syms=8 files=30 rows=148342   avail_null=148342      (100%)
```

### 2. 声明延迟不升级资格

本层 `proven = (rule.status is EXCHANGE_CLOSE)`。
`declared_lag` 只推迟取数时刻，不算可证 ——
否则随手填 `lag=1` 就能把任何未证明源洗成已证明。

### 3. 结果就是：只要用了 Metrics/OI，就不可能 PROVEN

四组实验的 G3 / G4 必须用 OI 和大户指标，
G2 也要用 `taker_buy_ratio`（这个来自 K 线，可证）。
所以：

- G1 / G2 的特征向量本身可能"可证"（K 线可证）；
- 但 **G3 / G4 必然不可证**；
- 而四组共用同一张特征表，整张表的 `formal_eligible` 只能取"全部为真"，即 False。

这是设计使然，不是缺陷。

---

## 三、三层资格，别混

| 层 | 字段 | 本单取值 | 含义 |
|---|---|---|---|
| 策略层 | `WX_EVENT_TREND_V0_1.summary.formal_pass_allowed` | 仍为 False | 规格 `verified` 0 条（FRAME-PIT-01 结论） |
| 数据层 | `pit_qualified` / `formal_eligible` | 227 笔全 False | 本单新增 |
| 实验层 | `flow_oi_four_groups_v2` 的 `formal_statement` | "研究结论，不具备正式资格" | 本单新增 |

三层各自独立，任何一层为 False 都不能出正式结论。**本单只补了数据层和实验层。**

---

## 四、就算 PIT 可证，这 227 笔也不能当正式样本

FRAME-FIT-01 已确认：227 笔横跨 2021-12 ~ 2026-10，是**反复观测过**的样本。
任何全区划分的留出段都会包含已观察样本（60/20/20 → 57 条；70/15/15 → 43 条）。
干净留出只能等新行情或换标的池。

**这条与本单无关，但汇报时必须一起说**，否则容易被理解成"PIT 修好了就能上正式回测"。

## 六、要变成"可正式"需要什么

按依赖顺序：

1. **拿到 Metrics / OI 的真实发布时点证据**（交易所文档 + 落盘 `fetched_at` 或
   可复核的发布时刻档案），并在 `rule_bucket_metrics` 里新增一条带证据的规则；
2. 用新证据重算 227 笔特征，确认 `pit_qualified=True`；
3. 换一批**未被观测过**的样本（新行情 / 新标的池），否则留出段不干净；
4. 通过 FRAME-FIT-01 的正式实验闸门（设计身份 + 运行身份 + 已冻结 + 有试验结论）。

这四步一步都不能省。本单只完成了"把入口堵住"，没有也**不能**替后面三步下结论。
