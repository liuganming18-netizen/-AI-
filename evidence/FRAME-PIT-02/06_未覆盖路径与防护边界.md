# FRAME-PIT-02｜06. 未覆盖路径与防护边界

**先说结论**：本单把 FLOW-OI 四组实验的**因子入口**接进了守卫，
但**没有**做进程级隔离，也**没有**把仓库里所有读 Metrics/OI 的脚本都改一遍。
下面是挡不住的地方，一条都不藏。

---

## 一、挡不住的（机制性）

### 1. 同进程代码仍可直接 `pd.read_parquet`

守卫只约束"经过它"的读取。任何代码写

```python
df = pd.read_parquet("数据/市场数据/parquet/oi/binance/um/BTCUSDT/xxx.parquet")
```

就完全绕过。本层提供的是**受控入口 + 违规可检测**，不是沙箱。

**怎么发现**：只要不走 `extract_features_for_candidate`，产物里就没有
`feature_contract_version` / `pit_status` 这些字段。四组入口的
`assert_controlled()` 会直接抛 `UncontrolledFeatureError`。

### 2. `load_symbol_data` 读的是**整段历史**，不是决策时刻前的切片

实测（COTIUSDT 2021-12-23 03:00 UTC 那笔）：

| 源 | 读入行数 | 实际使用行数 |
|---|---|---|
| `candles_1h` | 49,157 | 6,908 |
| `metrics_5m` | 512,212 | 6,368 |
| `oi_5m` | 513,164 | 6,368 |

守卫在**取用**时筛（`available_at <= decision`），不是在**读取**时裁剪。
也就是说：未来数据确实被读进了内存，只是没被用进特征。
真正做"读取时裁剪"需要改数据访问层（换成分区裁剪 + 列裁剪），本单没做。

### 3. `_CACHE_*` 是模块级字典，可被任意覆盖

`generate_flow_oi_01.py` 的 `_CACHE_CANDLES_1H` / `_CACHE_METRICS` / `_CACHE_OI`
是普通 dict。测试正是靠注入它们来造反例的（`test_t01`~`test_t05`）。
这也意味着：**任何代码都能替换掉输入**。守卫能保证"给我什么就按什么筛"，
不能保证"给我的就是真的"。

### 4. 旧实现的字节码仍可执行

`legacy/generate_flow_oi_01.pre_pit.cpython-313.pyc` 保留下来是为了做新旧对照
（`test_t11` 用它证明旧实现确实泄露）。它**不是**生产路径，但技术上仍可被调用。
删掉它就失去了"旧行为到底长什么样"的可复现证据，所以选择保留并在此声明。

### 5. 仓库里还有别的脚本直接读 Metrics / OI

这些脚本**不属于 FLOW-OI 四组实验路径**，本单未改：

| 脚本 | 用途 |
|---|---|
| `evidence/FACTOR-ENTRY-01/enrich_unified_candidate_dataset.py` | 历史因子富化 |
| `evidence/FACTOR-ENTRY-01/stage1_feature_contract_and_coverage.py` | 历史字段覆盖统计 |
| `evidence/FACTOR-ENTRY-03/attribution_analysis.py` | 历史归因分析 |
| `evidence/ENTRY-AUDIT-02/00_freeze_manifest.py` | 历史冻结清单 |
| `evidence/ENTRY-AUDIT-03/00_freeze_baseline.py` | 历史基线冻结 |
| `evidence/DATA-UI-01/tools/audit_field_coverage.py` | 字段覆盖审计 |

它们要么是已冻结的历史审计产物，要么只做统计不产特征。
**它们产出的东西同样不能当正式合格结果用** —— 但它们不产 `pass_g1..g4`，
所以进不了四组实验。

### 6. 1h K 线只能证"交易所闭合"，不能证"我们何时收到"

candles parquet 有 `available_at` 列，但抽样 148,342 行**全部为空**。
所以 `exchange_close` 的含义严格来说是：
"交易所定义这根 K 线在 `close_time+1ms` 闭合"，**不是**"我们那一刻就拿到了"。
本地摄取延迟（下载 / 入库 / 落盘）没有任何证据。

这与 FRAME-PIT-01 的口径一致，但必须写明：**它比"已证明可读"弱一档**。

### 7. 未纳入的数据源

- `15m` K 线（FLOW-OI 只用 1h / metrics / oi，撮合在别处）；
- `funding`（结算事件，不参与入场决策）；
- 任何 live / 实时流。

### 8. 上游补上发布时点后，本层不会自动受益

规则是写死的：metrics / OI 一律 `unproven`。
即使将来 parquet 里真的填上了 `fetched_at`，本层也不会自动改判 ——
需要显式新增一条"有证据的发布时点"规则（并说明证据来源）。
这是**待扩展点**，不是"已经支持"。

## 二、防护边界（一句话）

> 本层能保证：**凡是经过 `extract_features_for_candidate` 的特征，
> 每一个取值都满足 `available_at <= decision_time`，且来源证据等级被如实记录。**
>
> 本层不能保证：**进程内没有别的路径读到未来数据。**

所以：**不得宣称已完全隔离。**

---

## 三、如果被绕过，怎么发现

| 绕过方式 | 可发现的痕迹 |
|---|---|
| 不调入口，自己算特征 | 产物缺 `feature_contract_version` / `pit_status`，`assert_controlled` 直接抛 |
| 调入口但替换 `_CACHE_*` | `pit_sources[*].rows_total` 与真实数据行数不符；`pit_audit_sha256` 与同参数重跑不一致 |
| 把 `decision_time` 改大 | `decision_clock.decision_time_ms` 与候选 `snapshot_time_ms` 不一致 |
| 把 `declared_lag` 调小 | `pit_sources[*].available_at_ms` 会前移；`reason` 里带 `declared_lag_not_qualifying` |
| 直接改阈值 | `pass_g2..g4` 与 `g2/g3/g4_reject_reason` 对不上；阈值不在本层，需改 `_classify`（会留下 diff） |

## 四、本单明确没做的事

- 没改 `trading_core/`（含 `pit_guard.py`）；
- 没改 `event_trend_v0_1/` 任何文件；
- 没改 `框架/backend/`；
- 没改决策时刻、过滤阈值、费用、撮合、账本、交易闸门；
- 没下载、没迁移、没动生产数据与采集器；
- 没重跑 227 笔四组回测（只做了 3 笔入口冒烟）。
