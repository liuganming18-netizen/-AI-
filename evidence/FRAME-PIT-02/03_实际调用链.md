## 二、数据源登记与筛选（一次决策）

| 步骤 | 代码 | 结果 |
|---|---|---|
| 1 | `_prepare_candles` | 剔除 `is_closed != 1` 的行（不靠时间戳"碰巧"排除），按 `open_time` 去重排序 |
| 2 | `_prepare_buckets` | 按 `ts` 去重排序 |
| 3 | `PitStore.add` | 按规则算每行 `available_at`；`unproven` 源记入 `assumptions` |
| 4 | `PitStore.as_of(name, d)` | 只保留 `available_at <= d` 的行；`strict` 下未证明源直接抛 `PitUnavailable` |
| 5 | 选中最后一行 | 再断言 `available_at <= d`（兜底，防逻辑写错） |
| 6 | 24h 前对照点 | 同样走 `as_of(d - 24h)`，不外推、不回填 |

## 四、读这张审计记录能看出什么

**1. 决策时刻没动。**
`decision_time_ms = 1640228400000` 与候选的 `snapshot_time_ms` 完全一致（整点）。
本单没有为了让旧结果不变而挪动信号时刻。

**2. 用的 bar 是"刚收盘那根"。**
`bar_open_time_ms = 1640224800000` = 决策时刻 − 1h，
`bar_available_at_ms = 1640228400000` = 决策时刻。
旧实现取的是 `open_time == 1640228400000`（决策时刻才开始的那根）。

**3. 用的桶是 `ts-5m`。**
`metrics_event_time_ms = 1640228100000` = 决策时刻 − 5m，
`available_at = 1640228400000` = 决策时刻（按"桶结束"假设）。
旧实现取的是 `ts == 1640228400000`（覆盖之后 5 分钟的未结束桶）。

**4. 读取范围远大于使用范围 —— 这是必须说清的边界。**
`candles_1h` 读了 49,157 行，只用 6,908 行；`oi_5m` 读了 513,164 行，只用 6,368 行。
守卫是在**取用**时筛，不是在**读取**时裁剪。同进程代码仍可直接 `read_parquet`。

**5. 两个 qualified 不相等时，看 `qualified`。**
本例两者都是 false；若将来给了带证据的发布延迟，`guard_level_qualified` 会先变 true，
而 `qualified` 仍是 false —— 因为 `declared_lag` 不升级资格。

## 五、四组实验怎么消费

```
flow_oi_four_groups_v2.extract_all(df_cand)
  → assert_controlled(df)          # 缺 PIT 字段直接抛 UncontrolledFeatureError
  → run_four_groups(df)
      G1 = df[is_filled & pass_g1]
      G2 = df[is_filled & pass_g2]
      G3 = df[is_filled & pass_g3]
      G4 = df[is_filled & pass_g4]
  → 返回 formal_eligible / formal_statement / groups_consumed_from
```

四组用的是**同一张表、同一批列**，`pass_g1..g4` 由受控入口算好写进表里。
任何一组想换数据源，都得改 `extract_all`，而那里只有一个出口。
