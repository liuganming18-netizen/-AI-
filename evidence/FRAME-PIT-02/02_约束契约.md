# FRAME-PIT-02｜02. 约束契约

本文件定义 FLOW-OI 因子入口对"什么时候的数据可以读"的硬约束。
所有约束由代码强制，不依赖作者自觉。

---

## 一、四个时刻（不得互相冒充）

| 名称 | 含义 | 谁定义 | FLOW-OI 里的取值 |
|---|---|---|---|
| `event_time` | 数据点所属区间的**起点** | 交易所 | K 线 `open_time`；统计桶 `ts` |
| `close_time` | 区间的**最后一毫秒** | 交易所 | `open_time + 3600000 - 1` |
| `available_at` | 这个值**最早能被读到**的时刻 | 按来源规则推导，必须有证据 | 见下表 |
| `decision_time` | 策略做决定的时刻 | 候选快照 | `snapshot_time_ms`（整点） |

**三条禁止**：

1. 禁止用 `open_time <= decision_time` 判可用 —— 那只说明区间**开始**了。
2. 禁止把"桶结束"当成已证明的发布时间 —— 桶结束只说明区间结束，不说明发布。
3. 禁止把"桶时间 + 5 分钟"当成证明 —— 那是机械平移，不是证据。

**旧实现的错误正是第 1 条**：`ts` 是整点，`open_time <= ts` 必然选中从决策时刻才开始的那根。

## 二、三类数据源的可用性规则

| 源 | 规则 | `available_at` | 状态 | 证据 |
|---|---|---|---|---|
| `candles_1h` | `rule_candles("1h", 3_600_000)` | `close_time + 1ms` | `exchange_close` | parquet 有 `close_time`，`is_closed` 全为 1 |
| `metrics_5m` | `rule_bucket_metrics(...)` | 未证明时按 `ts + 300_000` **假设** | `unproven` | 无 `create_time` / `available_at` 列 |
| `oi_5m` | `rule_bucket_metrics(...)` | 未证明时按 `ts + 300_000` **假设** | `unproven` | `fetched_at` 100% 为空 |

抽样实测（`scripts` 见 `04_测试与日志.md`）：

```
oi      : syms=8 files=30 rows=1779127  fetched_null=1779127   (100%)
metrics : syms=8 files=30 rows=2343888  (无 fetched_at / create_time 列)
candles : syms=8 files=30 rows=148342   avail_null=148342      (100%)  is_closed!=1 = 0
```

**结论**：K 线可以证"交易所何时闭合"；Metrics / OI 证不了"我们何时收到"。
K 线的 `available_at` 列也全空，所以只能证闭合、不能证摄取延迟 —— 这一点在
`06_未覆盖路径与防护边界.md` 里单独写明。

## 三、未证明源的两条路（只有两条）

| 模式 | 行为 | 结果字段 |
|---|---|---|
| `strict` | `PitStore.as_of` 抛 `PitUnavailable` ⇒ 本层捕获，该源**拒用** | `pit_status=REFUSED`，该源的值全部 `None`，原因写进 `formal_block_reasons` |
| `declared_assumption`（缺省） | 按"桶结束"假设照用 | `pit_status=ASSUMED`，值算得出来，但 `pit_qualified=False` |

**两条路都不许填默认值后继续。** `strict` 下 K 线照常处理 ——
不是"一有未证明源就整体拒用"，那会掩盖真正能算的部分。

## 四、声明延迟的边界

- `declared_lag_ms` 必须是**正整数**，`0` 或负数直接 `ValueError`；
- 声明延迟会让 `available_at = ts + bucket + lag`，**只影响取数时刻**；
- **不提升资格等级**：本层 `proven = (rule.status is EXCHANGE_CLOSE)`，
  `declared_lag` 永远不算可证。

理由：如果声明延迟能升级资格，那么"随手填 `lag=1`"就能把任何未证明源洗成已证明，
约束等于没有。

## 五、覆盖状态与 PIT 资格：两个字段，两件事

```
coverage_status  ← 数据齐不齐（取到了没有）
pit_status       ← 时点有没有证据（那时能不能取到）
```

| 字段 | 取值 | 含义 |
|---|---|---|
| `coverage_status` | `COMPLETE` | 三源都有可用行 |
| | `MISSING_CANDLES` | 1h K 线取不到 |
| | `MISSING_METRICS` | metrics 取不到（含过期） |
| | `MISSING_OI` | OI 取不到 |
| | `PARTIAL` | 其它不齐 |
| `pit_status` | `PROVEN` | 所有存在的源都有证据，且数据齐全 |
| | `ASSUMED` | 有源无证据，按假设照用 |
| | `REFUSED` | `strict` 下拒用 |
| | `INCOMPLETE` | 数据有洞，无法判定完整性 |

派生字段：

```
pit_qualified    = (pit_status == "PROVEN")
formal_eligible  = pit_qualified      # INCOMPLETE 已经先把洞算进去了
formal_block_reasons = [具体到源、具体到原因]
```

**为什么 `INCOMPLETE` 单独一档**：数据有洞时，说"可证"是空话（没东西可证），
说"未证明"又不准确（不是证据问题）。单列一档，避免两种错。

## 六、每一次决策必须留下的审计记录

`extract()` 的返回值里固定包含：

| 字段 | 内容 |
|---|---|
| `feature_contract_version` | `flow_oi_features_v2` |
| `flow_pit_version` | `flow_oi_pit_v2.0.0` |
| `pit_guard_version` | `pit_guard_v1.0.0` |
| `pit_mode` | `strict` / `declared_assumption` |
| `decision_time_ms` | 本次决策时刻 |
| `decision_clock` | `event_time_ms` / `close_time_ms` / `decision_time_ms` / `source` |
| `decision_clock_rule` | 口径原文 |
| `pit_sources` | 每个源：`state` / `proven` / `guard_proven` / `rule_status` / `assumed` / `rows_total` / `rows_used` / `event_time_ms` / `available_at_ms` / `age_ms` / `reason` |
| `pit_audit` | `PitStore` 原始审计 + `guard_level_qualified`（守卫原判）+ `qualified`（本次生效）+ `consumer_rules` |
| `pit_audit_sha256` | 上述审计的指纹 |
| `formal_block_reasons` | 逐条阻断原因 |

`pit_audit` 里有两个 qualified，含义不同，已在字段名上分开：

- `guard_level_qualified`：只看来源规则的证据等级（`pit_guard` 原判）；
- `qualified`：本次实际生效的资格（再叠加"声明延迟不升级"这条消费端收紧）。

## 七、四组实验侧的约束

`evidence/FRAME-PIT-02/flow_oi_four_groups_v2.py`：

1. `assert_controlled(df)`：缺 `pit_status` / `pit_qualified` / `formal_eligible` /
   `coverage_status` / `formal_block_reasons` / `feature_contract_version`
   任一列 ⇒ 抛 `UncontrolledFeatureError`。旧路径产物进不来。
2. 四组（G1/G2/G3/G4）全部从**同一张受控特征表**切片，不允许任何一组另取数据。
3. 汇总里 `groups_consumed_from` 固定写 `controlled_entry_only`。
4. `formal_statement` 按 `formal_eligible` 二选一，非黑即白，没有"大概算正式"。

## 八、明确不做的事

- 不改决策时刻（仍是候选快照时刻，整点）；
- 不改过滤阈值、假设判定阈值、陈旧容差；
- 不改费用、滑点、撮合、账本；
- 不下载、不迁移、不动生产数据与采集器；
- 不重跑 227 笔四组回测。
