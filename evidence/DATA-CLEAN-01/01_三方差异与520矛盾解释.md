## 2 矛盾结论：旧报告两句话不能同时成立

旧报告同时写过：
- (A)「两份 `_backup` 快照均与当前正式目录逐字节相同」
- (B)「两份之间有 520 个资金费文件不同」

**A 是错的。** 复核结果：

| 比较对 | 完全一致 | 存在差异 |
|---|---|---|
| live vs s2 | **3,155 / 3,155** | 0 |
| live vs s1 | 2,634 / 3,155 | **521** |
| s1 vs s2 | 2,634 / 3,155 | **521** |

差异模式**全部一致**：`live = s2`、`live ≠ s1`、`s1 ≠ s2`（521 条无一例外）。

### A 为什么错

当时的验证命令只比了 **s2**：

```
for d in oi_metrics ohlcv funding mark1h; do diff -rq $d _backup/20261014T192054Z/$d; done
```

结果全为 0 差异，随后把「s2 与 live 相同」外推成「两份都与 live 相同」，**s1 从未被单独核对**。这是外推错误，不是数据变化。

### 521 个差异是什么

| 类别 | 数量 | 差异字段 | 数值列 |
|---|---|---|---|
| `funding/*.parquet` | **520** | 仅 `source` 列 | **全部相同** |
| `manifest.json` | 1 | `generated_utc`、`funding.bytes` | — |

520 个资金费文件的实际差异（逐文件用 pandas 读取比对，非字节 diff）：

| 项 | live（= s2） | s1 |
|---|---|---|
| 行数 | 与 s1 相同 | 与 live 相同 |
| `funding_time` | 一致 | 一致 |
| `funding_rate` | 一致 | 一致 |
| `mark_price` | 一致 | 一致 |
| `rate_type` | 一致 | 一致 |
| **`source`** | `binance.archive.fundingRate+mark1h` / `binance.fapi` | `binance.archive.fundingRate+mark1h+fapi` / `binance.fapi+mark1h` |

- **520 / 520 个文件：除 `source` 外全部字段完全相等**（`DataFrame.equals` 结果 `live_eq_s1 = 0/520`，逐列比较仅 `source` 不同）。
- 文件体积差 22~35 字节，正是 `+fapi` / `+mark1h` 后缀在压缩后的大小差。
- `manifest.json` 印证：`generated_utc` s1 = `2026-10-14T18:58:36Z`、live/s2 = `2026-10-14T19:20:13Z`；`funding.bytes` s1 = 40,146,135、live/s2 = 40,134,797，**差 11,338 字节**；两者 `funding.rows` 均为 2,189,855，`ohlcv`/`oi_metrics`/`mark1h` 的 `bytes` 与 `rows` 完全一致。

### 结论

- **s2 与 live 在 3,155 个文件上逐字节相同**（sha256 全量比对，非抽样）⇒ s2 是 live 的完整物理副本。
- **s1 不是 live 的副本**：它比 live 多出 `source` 列里的合并来源标记（`+fapi`、`+mark1h`）。数值无差，但**溯源信息有独有内容**。
- 因此 s1 **不能**按「完全重复」处理。
