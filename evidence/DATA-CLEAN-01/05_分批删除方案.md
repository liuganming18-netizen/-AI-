## 第一批：删除 `_backup/20261014T192054Z`

**为什么它排第一**：这是唯一一个「全量哈希逐字节相同」的对象，不需要推理、不需要重建、不需要判断业务价值。

| 项 | 值 |
|---|---|
| 绝对路径 | `/Users/boos/Desktop/威科夫因子共振趋势/数据/研究输入/WyckoffMaster/_backup/20261014T192054Z` |
| 文件数 | 3,155 |
| 独有文件 | 0 |
| 与 live 关系 | 3,155 个文件 sha256 **全部相同**（含 `manifest.json`） |
| 保留副本 | live 本体（同路径去掉 `_backup/...`） |
| 运行依赖 | 无（lsof 0 条、代码 0 处、crontab 0 条） |
| 删除后丢失什么 | **只丢失一份物理副本。数据内容 0 丢失。** |
| 释放 | 9,031.6 MB |

**风险**：删完后只剩一份 live + 一份 s1。如果 live 被误删，s1 仍在（数值等价，`source` 更详细）。**不会出现零副本状态。**

2. **9,758 行独有数据未逐条核完**。仓储层对应时段有数据且更完整，但没做「逐行确认能补上」的演练。执行前应先做这一步，或接受「这 9,758 行可能是尾部已修正的数据」的判断。

## 待核：`_backup/20261014T190050Z`

**不建议现在删。** 理由：它的 520 个 funding 文件在 `source` 列上有 live 没有的溯源后缀（`+fapi`、`+mark1h`）。

- 如果用户认为「数值一致就够了，溯源标记不重要」⇒ 可加入第一批一起删，多释放 9,031.6 MB。
- 如果用户认为「数据血缘要留」⇒ 保留，只删 s2。

**这个判断必须由用户做，不能替用户决定。**

## 4 每批执行前的强制核对

执行前逐项跑，任何一项不一致就**停止该批**并报告：

| 检查 | 通过标准 |
|---|---|
| 路径存在性 | 目标路径存在，且是目录 |
| 文件数 | 与 `scan_*.json` 记录一致（s2 = 3,155；ohlcv = 1,578；oi_metrics = 526） |
| 总字节 | 与 `scan_*.json` 累加值一致 |
| 保留副本可读 | 保留副本路径存在，且能成功读出首尾各 1 个文件 |
| 无进程占用 | `lsof` 对该路径 0 条 |
| 无新增写入 | 目标目录内 mtime 最近 10 分钟内无变化 |
| 磁盘余量 | 执行后可用空间 ≥ 12 GiB（删除只会增加，天然满足） |

## 5 执行方式（不在本阶段执行）

- **禁止** `rm -rf`、通配符、`find -delete`。
- 逐批用显式绝对路径，Python `shutil.rmtree` 或 `os.remove` 逐文件删除，**逐条记录成功/失败**。
- 每批记录：删除前可用空间、删除后可用空间、实际删除文件数、失败文件数与原因。
- **不可逆**：删除后无法从本项目恢复。不声称「删了还能恢复」。
