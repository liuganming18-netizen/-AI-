## 三件必须让你知道的事

### 1 旧报告那句话是错的，原因已定位

旧报告写过「两份快照都与正式目录逐字节相同」。实际验证命令只比了**第二份**（`20261014T192054Z`），然后把结论外推成「两份都相同」。第一份从未被单独核对。

实测：`live = s2`（3,155/3,155 相同）、`live ≠ s1`（521 个不同）。差异模式 521 条无一例外。

### 2 那 520 个文件差在哪

**只差一列 `source`**。数值（`funding_rate`、`mark_price`、`funding_time`、`rate_type`）逐行完全相同。

- 当前目录：`binance.archive.fundingRate+mark1h`
- 第一份快照：`binance.archive.fundingRate+mark1h+fapi`

第一份快照的溯源信息**更详细**。所以它不能按「完全重复」删掉——这要你决定：数据血缘要不要留。

### 3 发现一个数据质量问题（不是清理问题）

研究输入的持仓量数据，在 **2026-09 ~ 2026-10** 这段时间：

- 持仓量数值**整体滞后一格**（T+1 的值 = 仓储 T 的值）
- 4 个多空比字段**整段为 NaN**，仓储有值
- 受影响行数中位标的约 5.8%，最高 29%

**这意味着：如果 9 月之后跑过用这份数据做输入的回测，结论可能建立在错位数据上。** 建议在清理之前，先查这批回测有哪些。这件事已写进 `04_待核清单.md` 第 3 项。
