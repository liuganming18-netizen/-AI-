## 二、第一条：价格校验覆盖——已达成（有全仓静态证据）

### 2.1 写账本的位置只有一处文件

语法树扫描结果：`框架/backend` 与 `策略` 下所有含 `INTO/UPDATE paper_*` 的字符串常量，**全部落在 `框架/backend/paper_engine.py` 一个文件**（28 处 SQL），分布在 8 个函数：

| 函数 | 写入的表 | 是否有价格门禁 |
|---|---|---|
| `open_position` | 持仓、订单、成交、初始止损轨迹 | **有**（写任何表之前，第 1229–1254 行） |
| `close_at_price` | 持仓状态、已实现、订单、成交 | **有**（开连接之前判高低价；算完成交价再判越界，第 1812–1857 行） |
| `close_position` | 无（委托给 `close_at_price`） | 委托链，已覆盖 |
| `check_position_exit_on_bar` | 无（委托给 `close_at_price`） | 委托链，已覆盖 |
| `enforce_drawdown` | 无（委托给 `close_at_price`） | 委托链，已覆盖 |
| `record_stop_update` | 止损价、止损轨迹 | 不涉及成交价（止损不是成交） |
| `accrue_funding` / `backfill_closed_funding` | 资金费累计、迟到补记修正 | 不涉及成交价 |

⇒ 补丁说明第七节第 2 条自己承认的"未做全仓静态证明，若另有代码直接写已实现表则管不到"——**现在补上了：没有第二条写成交的路径。**

### 2.2 撮合调用点逐个核

| 调用点 | 函数 | 传了高低价 |
|---|---|---|
| `paper_engine.py:1778`（手工平仓） | `close_at_price` | 是 |
| `paper_engine.py:2084`（回撤强平） | `close_at_price` | 是 |
| `paper_engine.py:2539`（逐根判退出） | `close_at_price` | 是 |
| `accum_early_entry.py:1860`（持仓退出推进） | `close_at_price` | 是 |
| `live_worker.py:440`（实时退出扫描） | `close_at_price` | 是 |
| `replay_calc.py:684`（单事件回放入场） | `plan_entry` | 是（该参数已无默认值，漏传直接报错） |

`open_position` 的 8 个调用点都不传高低价，是因为它**内部**从成交 K 线自己读——门禁在函数体内，不在调用点（其中 5 个走模拟盘账本：`unified_runtime.py:2247`、`live_worker.py:354`、`accum_early_entry.py:1667`、`paper_engine.py:925`、`live_api.py:1124`；另外 3 个是旧策略引擎与探针脚本，不写模拟盘账本）。这一点已在 2.1 表中核实。

### 2.3 两个必须写明的放宽点（不是缺陷，但会漏）

1. **0.1% 容差**：`validate_execution_price_in_bar`、`close_at_price`、`scan_exit` 三处的 `tol` 默认都是 `0.001`，即允许成交价超出 K 线区间 0.1%。在振幅小于 0.2% 的窄幅 K 线上，这个容差能放过一个"该 K 线从未到过"的价格。属于设计选择，但复核成绩时必须知道它存在。
2. **缺 low 时单事件回放不判退出**：见第四节 D 组。

## 三、第二条：强制熔断——未达成（硬证据）

### 3.1 实测：异常后开仓入口仍被调用 6 次，6 次都在"已判无效"之后

隔离沙盒里造 1 笔持仓 + 6 个不同时间戳的候选，注入"退出推进抛异常"，探针记录每次进入开仓入口时的运行状态：

| 项 | 实测值 |
|---|---|
| 运行状态 | `FAILED` |
| 失效原因码 | `EXIT_DRIVE_ERROR` |
| 退出推进被调用次数 | 6 |
| 开仓入口被调用次数 | **6** |
| 其中发生在"已判无效"之后的次数 | **6（全部）** |

逐条明细：

```
S0USDT  状态=FAILED  ← 异常就发生在这一轮之前
S1USDT  状态=FAILED
S2USDT  状态=FAILED
S3USDT  状态=FAILED
S4USDT  状态=FAILED
S5USDT  状态=FAILED
```

**读法**：状态机在第一轮就被打成"无效"，但后续 5 个时间戳仍被送进开仓入口。开仓入口 `try_open` 内部唯一的开仓动作就是调 `paper_engine.open_position`，而后者第 1269/1284/1299 行直接写持仓表——它**根本不接收运行状态**，无从判断"这次运行已经废了"。

### 3.2 代码级：三个位置都没有"停止"这个动作

| 位置 | 现在的行为 | 缺什么 |
|---|---|---|
| `accum_early_entry.py:2314` 统一时间轴主循环 | 每个时间戳先推退出、再无条件开仓 | 循环里没有"状态已失效就跳出"的判断 |
| `accum_early_entry.py:2244` 逐笔推退出 | 异常 → 标记 → `continue` 下一笔 | `continue` 是"跳过这一笔"，不是"停止整轮" |
| `accum_early_entry.py:1953` 收尾推进全部持仓 | 逐笔 try/except → 标记 → 继续 | 即使时间轴阶段已废，收尾照样把全部持仓推到窗口末并写账本 |

### 3.3 后果：账本里混着"废运行"的成交，只有结论被拦住

现状的防线全部在"出口"：跑分器抹掉胜率、收益率，生产指标入口读到 `run_status.json` 就把指标置空。但**入口没拦**——账本照写、挂单照登、止损照改。这带来两个具体问题：

1. **账本不可信**：一次废运行留下的持仓/成交与正常运行无法区分，只能靠外部文件判断；
2. **状态文件可能根本不存在**：`run_status.json` 只在 `evidence/ACCUM-EARLY-07-W5/scripts/run_abc_pool.py` 里落盘。换任何别的入口跑回测，`backtest_metrics.compute_metrics` 读不到文件就**不阻断**（补丁说明第七节第 5 条自认）。⇒ 换入口 = 防线归零。

## 四、顺带核出的一条同类问题（D 组）

单事件回放里，某根 15 分钟 K 线**缺最低价**且开盘没穿止损时，无法判断盘中是否触及止损。实测：

| 项 | 结果 |
|---|---|
| 是否判为"未触及" | **是**（`hit=False`） |
| 是否给出拒单码 | 否（`reject_code=None`） |
| 是否计数 | 是（`n_bars_no_low=1`） |
| 这个计数有谁在读 | **没有任何调用方**（全文件只出现在 `scan_exit` 内部） |

⇒ 缺数据的回放会静默地"没止损"，运行仍判正常，成绩照出。性质与第二条相同：**发现了异常，但不阻断**。

## 五、精化工单 W-002（可直接转发施工）

### 施工范围

| 编号 | 内容 | 对应工单原文 |
|---|---|---|
| **W2-01** | 熔断开关：运行判为无效后，停止一切推进与写入 | 第二条 |
| **W2-02** | 熔断位置落盘：状态写进账本目录，不再依赖跑分脚本 | 第二条 |
| **W2-03** | 缺最低价的退出判定升级为"本次回放无效" | 第二条（同类） |
| **W2-04** | 0.1% 容差只出报告，不改值 | 第一条（只报告） |

### W2-01 具体改法（三处，缺一不可）

1. **时间轴主循环**（`accum_early_entry.py` 的 `_replay_timeline`）
   每轮开头判 `run_state["status"] != "OK"` ⇒ 记录 `halted_at_ms` / `halted_stage` 后 `break`，**该时间戳的开仓也不再执行**。
2. **逐笔推退出**（`_advance_open_positions`）
   异常后的 `continue` 改为"标记后 `break` 本方案循环"；已在无效状态时直接返回，不再进第二笔。
3. **收尾阶段**（`drive_all_exits`）
   入口先判状态：已无效 ⇒ 直接返回 `{"halted": True}`，**不推进任何持仓、不写任何表**。

**双保险**：`try_open` 入口增加状态判断，无效时返回 `halted_by_run_invalid` 且不调 `paper_engine`。这样即使将来有人新增第四条调用链，也进不去。

### W2-02 具体改法

- `research_run` 结束时把运行状态写到**账本目录**（与 `ledger_identity.json` 同级），字段：状态、原因码、熔断时刻、熔断阶段、已处理事件数 / 总事件数、前 50 条问题明细。
- `backtest_metrics.compute_metrics` 除了读现有 `run_status.json`，**再读账本目录这份**；任一为无效即阻断。
- 账本目录这份由引擎自己写，**不依赖任何 evidence 下的脚本**。

### W2-03 具体改法

`scan_exit` 在"开盘没穿止损 + 缺最低价"时，不再返回"未触及"，改为返回 `price_valid=False` + 拒单码 `MISSING_BAR_RANGE`；`replay_one` 据此把整条回放判为无效（与现有"退出价越界"同一处理方式）。

### W2-04（只报告，不改）

在交付说明里给出：本窗口内 15 分钟 K 线振幅小于 0.2% 的占比、以及这些 K 线上容差相当于多少倍振幅。**不改 `tol` 的值**（改它等于改判定口径，需用户裁决）。
