# DATA-UI-02｜采集补齐与 UI 端到端复验（验收报告）

> **状态：待 Codex 验收。**
> 本报告不以「HTTP 200 / 构建通过 / 截图有数字」作为完成依据；每条结论都指向可复跑的脚本与落盘证据。

## 一句话结论

原来 60 个标的里 48 个是字母表最前面的冷门币，三类新增比率只有 **24/60** 有值、33 个被判过期。
查下来是两件事叠加：**① 选标的的依据不对**（按字母序，不是按流动性）；
**② 那 33 个「过期」里绝大多数是假警报** —— 阈值（900s）比轮转周期（实测 38 分钟）还短，
数据一直在采，只是被判成过期。修完后轮转真正铺满，四个比率块**全部 62/62**，未轮到 0、过期 0。

**必须说清楚的一点**：24 → 62 的跳变**不是数据变多了，是判据变了**。
同一把 900s 尺子下，改后还是 **24**，与改前的 24 **一模一样**（见 `覆盖对照表.md` 的两列）。
也就是说原来那 33 个「过期」几乎全是「轮转周期 38 分钟 > 阈值 15 分钟」的数学必然结果，
数据一直在采。真正的改进是「未轮到 3 → 0」和下面这条修出来的覆盖漏洞。

**审计还抓出两个我自己改出来的坑，都已修**：

1. 目标集合在进程启动时算一次就固定 ⇒ 后进入前 60 的 `LITUSDT` 永远采不到；
2. 改成每轮重算后，直接换成最新排名列表 ⇒ 排名漂移让轮转窗口在轮次间错位，
   `PENGUUSDT`、`APRUSDT` 在整整 6 轮（一个完整周期）里一次都没轮到，
   最后成功时间停在上一代进程（05:09:27 / 04:09:05）。
   改为「保留既有顺序、新增追加末尾」，游标语义稳定，`ceil(62/12)=6` 轮必定覆盖全部。

端到端一侧：用「原始存储 → 同源 API → 界面」逐字段比对（4 次采样跨 7 分 44 秒）
+ 界面文字核验（5 案例 × 14 项），**0 项不一致、0 个异常静止字段、0 次接口降级**。

## 一、工单四个问题的回答

### 1. 60 个标的是怎么选的？与完整池什么关系？

| 项 | 数值 | 说明 |
|---|---|---|
| 币安加密池 | **526** | `underlyingType=COIN`，官方分类口径 |
| 指数（排除） | 2 | `underlyingType=INDEX`，按工单要求排除，不并入分母 |
| 欧易加密 | 286 | 其中 23 个是补币安没有的 |
| 公开扩展应采 | **62** | 24h 成交额前 60 ∪ 主流 12 ∪ 固定观测 2（去重后） |

- **改前**：`sorted(coins)[:48]` 取 ASCII 升序前 48，全是 `0GUSDT`/`1000000BOBUSDT`/`1000CATUSDT` 这类
  0-9/A 开头的冷门币；BTCUSDT 字母序第 107 位，只能靠主流清单额外补进来。
- **改后**：读本机 `realtime_quotes.quote_volume_24h` 降序取前 60（**不产生上游请求**），
  再并入主流清单与固定观测。
- **固定观测**（`1000CATUSDT`、`ACHUSDT`）：成交额只有几十万美元，按流动性排不进去，
  但它们是验收标的和界面快捷按钮，必须长期可观测。
- **排除停更标的**：成交额是滚动 24 小时值，下市后停在旧数字。实测 `PUMPBTCUSDT`、
  `1000000BOBUSDT`、`PROMPTUSDT` 价格流停在 2026-10-05（13 天前）却仍带 1 亿以上旧成交额，
  会被稳定排进前 60，而它们根本没有 K 线。已按逐字段 `price_event_time` 过滤。

### 2. 三个比率块：应采 / 有值 / 有效 / 缺失原因

| 比率块 | 应采 | 改前·有值 | 改后·有值 | 改后·过期 | 改后·未轮到 |
|---|---|---|---|---|---|
| 主动买卖量比 | 62 | 24（过期 33） | **62** | 0 | 0 |
| 大户账户多空比 | 62 | 24（过期 33） | **62** | 0 | 0 |
| 全市场账户多空比 | 62 | 24（过期 33） | **62** | 0 | 0 |
| 大户持仓多空比（核心对照） | 62 | 60 | 62 | 0 | 0 |

> 「改前·有值」按**统一 900s** 判过期（当时的读端口径），与工单里的 24/60 一致；
> 「改后」按订正后的轮转阈值（2880s）。两者对照见 `覆盖对照表.md`。

**缺失原因分类**（互斥，优先级从高到低：上游不支持 → 未轮到 → 限频 → 错误 → 过期 → 无记录）：

- **未轮到**：轮转窗口还没轮到该标的（每轮 12 个、单轮 456s、6 轮铺满）。这类不是失败，下一轮就会补。
- **限频**：被网关预算推迟（`DeferredRequest`），下一轮优先重试。
- **上游不支持**：欧易没有 `/futures/data/*` 这类公开多空比端点，恒为不支持，界面如实标注。
- **过期**：有值但距取数时刻超过阈值。

### 3. 24/60 之后有没有继续推进？OI 是否挤占预算？

**继续推进了**，日志实测连续 9 个完成轮次（`logs/轮转推进.txt`）：

```
03:12:25 12/12   03:21:41 10/12（重试 2）   03:29:43 8/12（重试 4）
03:33:11 12/12   03:40:03 10/12（重试 2）   03:47:59 9/12（重试 3）
03:54:58 12/12   04:02:28 12/12   04:09:30 12/12   04:12:34 12/12 …
```

中途 8/12、10/12 的轮次不是失败：被预算推迟的标的下一轮优先重试，后面回到 12/12。

**OI 确实挤占预算**：528 个请求一轮、单轮约 545 秒，占满一个 600 秒周期，每轮有 56~202 次请求被判
「本地请求预算已用尽」。

**试过的修复已回退**：把一轮摊到 `interval × 0.65`（390 秒）内 —— 目标比实际耗时还短，
节流分支**从未触发**；而把周期改成按本轮开始计时，会让 OI 占空比从 48% 抬到约 91%，方向相反。
回退后单轮快照耗时与改前无可分辨差异（105.67 / 156.65 / 175.0 秒 vs 改前中位约 145 秒）。
详见 `未完成项.md` 第三节。

## 二、端到端复验结果

| 项 | 结果 | 证据 |
|---|---|---|
| 源 vs 接口逐字段（值/单位/统计周期/源时间） | **0 项不一致** | `端到端复验.md` |

| 接口降级（200 + 空字段集） | **0 次**（本次） | 同上「一之二、采样健康」 |
| 界面文字 vs 接口（5 案例 × 14 项 = 70 项） | **0 项不一致** | `界面文字核验.md` |
| 截图（5 案例 × 3 张：干净视图 / 展开证据 / 历史覆盖） | 15 张 | `screenshots/` |

**判据要点**（这几条不写清就会得出假结论）：

- **时间推进看 `fetched_at` 与 `event_time`，不看页面刷新时间**。值不变但 `fetched_at` 推进 = 正常。
- **未收盘 K 线不能要求逐位相等**：`realtime_klines` 每个 (交易所,标的,周期) 只有一行且原地覆盖，
  两次读必是不同版本。判据是「同一根 bar + 同一写入版本逐位相等」，否则「界面读数不晚于接口读数」。
- **「窗口内不变」不等于故障**：已结算资金费 8 小时一次、轮转块约 40 分钟一轮、
  OI 全池轮询 10~20 分钟一次，8 分钟窗口内本来就不会变。只有**没有合理原因的静止**才算异常。
  这条判据是被实测打出来的：第一次复验恰好跨过 OI 刷新，报 0；第二次没跨过，
  欧易 OKB 的 `oi_qty` 被判「异常静止」。查库确认它在 05:31/05:51/05:53/06:00 每次都写了新值
  （值确实在变，只是间隔比窗口长），才补上这一类。
- **界面源时间显示为 `MM-DD HH:mm:ss`（省略年份）**，是显示口径不是数据差异，比对要按显示口径比。
- **接口降级要单列**：`build_metrics` 抛异常时返回 200 + 空字段集，若当成数据去比会误报「全字段不一致」。

## 三、展示口径（工单明确要求的几组「分开」）

- **当前/预测资金费 vs 已结算资金费**：分两行。前者来自 `premiumIndex.lastFundingRate`（未结算、下次结算生效），
  后者来自 `fundingRate(rate_type=settled)`。界面上分别是「资金费率（当前/预测）」与「资金费率（已结算）」。
- **历史覆盖 vs 当前实时状态**：`coverage[]` 里 `archive`（历史已存/行数/UTC 起止/缺根）与
  `realtime`（在采/未收盘）是两组独立字段；界面上一块是「当前值」，另一块是
  「历史覆盖（按周期分列，与上方当前值互不填充）」。
- **缺失/过期/失败/不支持**：界面显示「—」+ 具体原因，**不补 0、不用旧值伪装新数据**。
  例：欧易的三类多空比显示「上游不支持：欧易无 `/futures/data/*` 同类多空比公开端点；本系统不跨所拼接」。
- **页面保持简洁**：详细证据折叠在「数据完整度与口径标准结论」里，默认收起。

## 九、仍未完成的部分

见 `未完成项.md`，共 11 条，每条都有准确原因。最需要知道的四条：

1. **轮转铺满要 38 分钟**（62 标的 / 每轮 12 / 单轮 456s），任一时刻的「有值数」是时间的函数。
2. **OI 挤占预算没解决**：试过的节流无效已回退；真正的杠杆是降低 OI 频率或缩小标的数，属产品决策。
3. **行情表 `event_time`/`received_at`/`fetched_at` 停在 2026-10-05**（逐字段时间列是新的），
   任何用这三列判新鲜度的读端都会误判，属独立工单。
4. **整点切换后实时 K 线层会短暂为空**，接口回退到归档最后一根已收盘 K 线（源时间会早 1~2 小时）；
   界面如实显示源时间与层级，但没有隐藏。上一轮复验撞到过（`counts.stale = 8`），
   最终这轮没落在整点、未复现，所以它仍然是个**没被修掉**的已知现象。
