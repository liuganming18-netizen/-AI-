# 02 三组实验对照协议：固定策略 vs 规则动态 vs 人工智能动态

> **协议版本**：EXP-PARITY-V1.0  
> **核心目标**：建立绝对公平成信的对照基准，防止利用“带病的执行缺陷”、“刻意做弱的对照组”或“LLM 历史结局记忆泄露”伪造人工智能动态策略的有效性。  
> **执行纪律**：本协议参数与规则在验收实验启动前**全面冻结**，严禁在查看对照结果后反向微调规则或模型提示词。

---

## 一、三组对照架构定义

对照实验由三个严格平行的独立账户单元（Arms）组成，共享同一套修复执行缺陷后的底层引擎，杜绝代码路径分叉：

```
                      ┌──────────────────────────────────────────────┐
                      │    统一执行与撮合底层 (修复缺陷后的严密环境)     │
                      │  · 严格跳空按 open 结算   · 15m 逐根连续遍历  │
                      │  · 统一 5000U 初始资金    · 5bps 费率/5bps 滑点│
                      │  · 8h 资金费刚性入账     · 20% 账户回撤刚性熔断 │
                      └──────────────────────┬───────────────────────┘
                                             │ 相同候选事件池 (526标的)
                     ┌───────────────────────┼───────────────────────┐
                     ▼                       ▼                       ▼
            【对照组 A】                    【对照组 B】             【实验组 C】
         修复后的固定基准策略             简单规则驱动动态策略        人工智能 (AI/LLM) 动态策略
        (Fixed Baseline Arm)            (Rule Dynamic Arm)       (AI Dynamic Arm)
         · 参数永久冻结                   · 确定性显式量化规则       · LLM 结构化推理决策
         · 固定 s=0.05, d=0.03            · 动态调整 s, d, 仓位     · 与 B 组相同动作权限/预算
         · 不做任何动态干预                · 可解释、无过拟合         · 严格因果提示词无未来信息
```

### 1. 对照组 A：修复后的固定策略 (Arm A: Fixed Baseline)
- **策略内核**：`FT-LOW4H` 事件趋势策略。
- **参数规格**：永久固化。
  - 初始止损比例：$s = 0.05$（入场价下方 5%）
  - 跟踪止损比例：$d = 0.03$（4h 最低价下方 3%）
  - 单笔名义风险：$0.5\%$（账户权益的 0.5%）
  - 最大持仓数：$10$ 仓
  - 退出规则：4h 跟踪抬线，15m 触及止损即出场，无动态干预。

### 2. 对照组 B：简单规则驱动的动态策略 (Arm B: Rule Dynamic)
- **设计原则**：**充分可解释、有坚实统计依据，严禁故意做弱以衬托 AI！**
- **驱动因子**：基于市场公认的宏观波动率与微观动量指标（已在特征库中经过因果闭合验证）：
  1. **波动率自适应因子 ($\sigma_{ATR}$)**：当前标的 14 周期 ATR 与历史 100 周期中位数比值 $R_{ATR} = ATR_{14} / Median(ATR_{100})$。
  2. **趋势效率因子 ($ER$)**：Kaufman 效率比率 $ER = |\Delta Price| / \sum |Step|$。
  3. **宏观市场压力因子 ($BTC_{Trend}$)**：BTCUSDT 4h 处于 EMA20 之上或之下。
- **规则矩阵 (Rule Matrix)**（严格预设，在验收前完全固化）：
  - **高波动震荡市 ($R_{ATR} > 1.3$)**：扩大止损距离，降低仓位暴露。
    - 初始止损 $s$ 调整为 $0.06$（原 $0.05$ 放大 1.2 倍）；
    - 跟踪止损 $d$ 调整为 $0.04$（防被毛刺震荡扫出）；
    - 单笔风险下调至 $0.35\%$（防守模式）。
  - **高动量顺风市 ($R_{ATR} \le 1.1 \land ER > 0.6 \land BTC_{Trend} = \text{Bull}$)**：收紧止损，适当放大获利暴露。
    - 初始止损 $s$ 保持 $0.05$；
    - 跟踪止损 $d$ 收紧至 $0.025$（加速锁利）；
    - 单笔风险上浮至 $0.6\%$。
  - **默认基准态**：回退至基准参数 ($s=0.05, d=0.03, \text{risk}=0.5\%$)。
- **调整预算约束**：与 C 组执行完全一致的离散档位与预算上限。

### 3. 实验组 C：人工智能动态策略 (Arm C: AI / LLM Dynamic)
- **模型定位**：在收到候选信号（`CANDIDATE`）或持仓 4h 周期刷新时，由大语言模型（如 DeepSeek-R1 / Claude 3.5 Sonnet / GPT-4o 等固定版本）基于**完全相同的数据上下文**进行结构化推理。
- **动作权限**：与对照组 B **完全同构**，输出严格限定在离散参数空间中，严禁越权。
- **推理输出格式**：强制 JSON Schema 结构化响应，包含推理链（COT）与结构化动作：
  ```json
  {
    "candidate_id": "cand_btc_1792666800000",
    "action": "ACCEPT_WITH_PARAM_ADJUST",
    "params": {
      "stoploss_s": 0.05,
      "trail_d": 0.025,
      "risk_fraction": 0.005
    },
    "reasoning_summary": "ER处于0.65高位且BTC强势，收紧跟踪距离以锁定潜在利润",
    "risk_rationale": "波动率处于历史50分位，无需缩减基础风险头寸"
  }
  ```

## 二、五大绝对统一底座 (The Parity Contract)

为彻底消灭“因执行环境差异造成伪 Alpha”，三组必须在以下五大维度保持物理级一致：

| 维度 | 统一标准 | 违规判定红线 |
|---|---|---|
| **1. 数据可见性 (Visibility)** | 仅允许访问 `t <= now` 的已闭合 K 线 (15m/1h/4h)、已结算资金费、已归档链上 OI 及账户现有持仓状态。三组特征输入向量完全相同。 | AI 访问包含未来收盘价、未闭合 K 线或通过外部网络抓取未知信息即判作弊。 |
| **2. 初始资金与风控 (Account)** | 统一 $5,000.00$ USDT 初始现金，单标的最大持仓上限 $10\%$，最大持仓数 $10$ 仓，账户最大回撤熔断线 $20\%$。 | 回测与模拟盘、或各组间使用不同本金或不同名义敞口上限。 |
| **3. 交易成本与摩擦 (Friction)** | 统一单边手续费 $5\text{ bps} (0.0005)$，单边滑点 $5\text{ bps} (0.0005)$，资金费按 8h 真实事件全额计提（缺 mark 记 gap）。 | 任何一组减免滑点、享受 0 手续费或忽略资金费。 |
| **4. 成交与撮合模型 (Fill Model)** | 统一使用 15m 逐根遍历撮合；开盘跳空按 `open` 结算；跌破止损按真实滑点扣减；无亚 tick 精度；严禁完美止损假设。 | 任何一组使用 `LIMIT 1` 漏线撮合或强行按理想止损价成交。 |
| **5. 策略候选池与权限 (Cadence)** | 统一由底层状态机输出候选事件（526 个标的），两种动态方案拥有完全相同的决策频率（4h 推进决策一次）及相同的候选池。 | AI 拥有高频刷新权限，或 AI 可跳过状态机直接在全市场任意开仓。 |

### 动态方案动作空间与预算硬约束 (Budget Constraints)
B 组与 C 组的动态动作被锁定在严格的**有限离散网格**内：
- 初始止损 $s$ 可选档位：$\{0.04, 0.05, 0.06\}$（基准为 0.05，上下浮动不超过 20%）；
- 跟踪止损 $d$ 可选档位：$\{0.025, 0.03, 0.04\}$（基准为 0.03）；
- 单笔风险 $\text{risk}$ 可选档位：$\{0.35\%, 0.5\%, 0.6\%\}$（基准为 0.5%）；
- **单日调整预算**：单标的在存续期间每天最多调整参数 1 次；全账户单日调整参数总次数不得超过 5 次。严禁高频变动导致隐性过拟合。

## 三、时间区间切分与大模型历史结局泄露证明边界

### 1. 大模型历史记忆泄露的客观事实与证明边界
> [!CAUTION]
> **历史数据证明的本质局限**：  
> 当前主流大语言模型（GPT-4、Claude-3.5、DeepSeek-V3 等）的预训练语料库截止日期均包含了 2021 至 2024 年的互联网公开数据。模型在参数权重中已经隐式“记住了”BTC 在 2021 年突破 6.9 万、2022 年 LUNA/FTX 崩盘、2023 年底反弹以及 2024 年初 ETF 通过等重大行情结局！  
> **因此，在历史回测区间内跑出的高收益，无法证明模型具备实时动态分析能力，极大概率是模型“偷看历史剧本（Data Contamination）”的结果！**

### 2. 严格的三阶段时间切分规范

```
 2021-01 ──────────────── 2024-06 ────── 2024-12 ────── 2026-10 ─── 未来
    │                         │              │              │
    └────── 第一阶段 ─────────┘── 第二阶段 ──┴── 第三阶段 ──┴── 终极检验 ──►
        【模型开发与调试】           【受控历史验证】    【无记忆前向回放】    【前向实时模拟盘】
         Prompt/规则定稿            防工程崩溃测试      严格脱敏盲测        真金白银检验
         (完全解禁)               (不作结论证据)      (可信度一般)        (唯一黄金标准)
```

1. **第一阶段：开发区间 (Development Period)**
   - 范围：2021-01-01 至 2024-06-30
   - 用途：用于设计 Prompt 提示词、制定对照组 B 规则矩阵、调试接口。
   - **冻结红线**：在此区间结束后，所有提示词文本、B 组规则参数、JSON Schema 全部做 SHA256 哈希固化，**后续区间严禁改动任何一行代码或 Prompt**。
2. **第二阶段：历史受控验证区间 (Historical Verification)**
   - 范围：2024-07-01 至 2024-12-31
   - 用途：仅作为**工程因果性、反例容错、内存泄漏与调用稳定性测试**。
   - 证明边界：本区间的净收益与夏普比率**不得用于宣布“AI 有效”**，仅证明 AI 方案不会因为代码异常而宕机。
3. **第三阶段：纯前向实时验收区间 (Out-of-Sample Forward Walk-Forward)**
   - 范围：**当前时间起往前最近 30 天，及往后实时运行的至少 30 个自然日**（如 2026-10 至 2026-11+）。
   - 证明边界：这是**唯一具备法律效力的验收凭据**！因为该区间的未来价格尚未在历史中发生或处于模型的绝对知识盲区。
   - **冷门标的前向专列**：对于历史样本不足 180 天的新币种或次新币，统一列入“前向观察白名单”，禁止在历史回测中插值，必须通过前向纯净行情检验。

## 四、评估指标体系与严苛通过标准

严禁使用单一收益率或胜率评价策略。三组对照必须在完成相同周期的前向测试后，按照多维量化矩阵进行综合评审：

| 评估指标 | 计算口径与单位 | 最低准入红线 (通过门槛) | AI 组相对胜出标准 |
|---|---|---|---|
| **1. 净收益率 ($PnL_{net}$)** | 扣除所有手续费、滑点与资金费后的真实净收益 (%) | $\ge 0.0\%$ (绝对保本) | 必须同时显著战胜 A 组与 B 组：<br>$PnL_C - \max(PnL_A, PnL_B) > 5.0\%$ |
| **2. 最大回撤 ($MaxDD$)** | 账户动态权益峰值至谷底的最大跌幅百分比 (%) | $\le 15.0\%$ (硬性熔断门槛为 20%) | $MaxDD_C \le MaxDD_A$ 且 $MaxDD_C \le MaxDD_B$<br>(动态策略绝不能以放大回撤为代价换收益) |
| **3. 风险调整收益 (Calmar)** | 年化净收益率 / 最大回撤比值 | $\ge 1.2$ | $Calmar_C > \max(Calmar_A, Calmar_B) \times 1.25$ |
| **4. 风险暴露对等性** | 整个实验周期的日均名义杠杆占用与最大敞口 | 最大总名义 $\le 80\%$ 权益 | 三组名义敞口均值偏差 $\le 10\%$<br>(严禁 AI 组通过加杠杆“放大”收益) |
| **5. 交易频率与换手率** | 产生的总成交笔数与平均持仓周期 | 换手率不得偏离基准超过 1.5 倍 | 禁止频繁换手刷手续费，总交易次数与 A 组差异 $\le 20\%$ |
| **6. 决策成本经济性** | 运行期间累计消耗的 LLM Token 费用 (折合 USDT) | $Cost_{API} \le 50\text{ USDT / 月}$ | **净超额收益覆盖成本**：<br>$(PnL_C - PnL_B) \times Capital_{init} > 3 \times Cost_{API}$ |
| **7. 响应时延与可用性** | 决策端到端耗时 (P95) 与请求成功率 | P95 时延 $\le 15\text{s}$，可用性 $\ge 99.5\%$ | 连续超时或格式错误次数恒为 0，平滑降级至基准 |
| **8. 决策一致性与稳定性** | 在 Temperature=0 下，完全相同的输入向量重现率 | 重现率必须 $\ge 99.0\%$ | 严禁同一个市场状态前后给出截然相反的自相矛盾指令 |

> [!IMPORTANT]
> **一票否决权（Veto Rules）**：  
> 1. 若 C 组（AI 动态）扣除 API 推理费用后的净收益**低于** B 组（简单规则组），即使收益高于 A 组，亦直接判定为**不及格（无商业落地价值）**！  
> 2. 若 C 组在测试期间发生哪怕 1 次越权下单、参数越界或严重格式异常导致交易停摆，直接判定**架构不合格**！
