## 一、疑点逐项独立核查与隔离复现

### S-01 逐笔跟踪止损通道 (Trailing Stop Channel)

#### 1. 现象与代码核查
- **回测链路缺陷**：在 `策略/WyckoffMaster/event_trend_v0_1/engine_adapter.py` 第 146-168 行：
  ```python
  starts = sorted({_normalize_to_ms(c.execution_earliest_ms) for c in candidates})
  if rule == "FT-LOW4H":
      for j in range(n15):
          k = int(np.searchsorted(t4, t, side="left")) - 1
          start = None
          for s in starts:            # ← 遍历了同币的所有候选时间戳
              if s < int(t4[k]):
                  start = s
  ```
  `starts` 是该标的**全部候选**的入场时刻集合。当同一币种在历史中先后出现两个候选（例如 05:00 入场与 09:00 入场），09:00 那笔持仓在 09:15 计算跟踪止损时，由于循环检查遍历到 05:00 的 `starts[0]`，判定 `starts[0] < 08:00`（早于第 2 笔入场时刻前收盘的 4h K 线），导致第 2 笔持仓错误地将 08:00 收盘那根 4h K 线的最低点纳入了跟踪止损计算！
- **模拟盘链路历史缺陷**：此前在 `paper_engine.py:2415-2423` 曾出现入场后不满 4 小时时，`last_closed_4h` 取到入场前已收盘的 4h K 线击穿止损的因果倒置缺陷，在 `AUTO-LOOP-01` 中已打入补丁 `ref_close_ms <= entry_ts` 守卫跳过。
- **关于“逐笔通道”的澄清**：经核查，系统**从未实现过、冻结规则也未包含**所谓的“实时逐笔 ticker (trade/aggTrade) 驱动的跟踪通道”。冻结规则明文规定：**以 4h K 线收盘价推进通道候选，在 15m K 线明细上以 low 判定退出**。所谓“逐笔跟踪通道”属于将 15m 逐根退出误读为毫秒级逐笔通道的**未证实猜测**。

#### 2. 隔离副本复现证据
- **复现测试**：`probes/audit_suspects_isolated.py::audit_suspect_1_trailing_channel`
- **触发条件**：同一标的产生多个前后候选，后一个候选入场时，前一个候选的入场时间使得 `starts` 命中入场前的 4h K 线。
- **预期行为**：跟踪通道闸门必须严格绑定**当前持仓自身**的 `entry_ts`，入场前的任何 4h K 线严禁参与计算。
- **实际行为**：`engine_adapter.py` 中 `starts` 遍历标的全部候选，借用了更早候选的 4h K 线，止损线被提前抬高至入场价之上，导致后序持仓被无理由提前扫出。
- **影响范围**：官方回测 1,663 组有成交 run 中，同币多笔 859 组，涉及第 2 笔及以后共 **3,346 笔**持仓（其中带跟踪上移的 8 笔）。

### S-02 跳空成交 (Gap Execution)

#### 1. 现象与代码核查
- 在 `框架/backend/paper_engine.py`：
  - `check_position_exit_on_bar` (第 2296-2302 行)：
    ```python
    if cur_stop > 0 and low_p <= cur_stop:
        exit_triggered = True
        exit_result = close_at_price(
            arm, position_id, raw_price=cur_stop, now_ms=dec_ms,
            reason="trailing_stop_loss", bar_open_time=ref_open_ms,
            bar_close_time=ref_close_ms, exit_ts=eff_ms
        )
    ```
  - `advance_position_trailing` (第 2458-2464 行)：
    ```python
    if low_4h <= cur_stop:
        exit_triggered = True
        exit_result = close_at_price(
            arm, position_id, raw_price=cur_stop, now_ms=dec_ms,
            reason="trailing_stop_loss", bar_open_time=ref_open_ms, ...
        )
    ```
- **核心漏洞**：两处退出在发现 `low <= cur_stop` 时，均硬编码将 `raw_price = cur_stop` 传入 `close_at_price`！
- **对比权威回测契约**：在 `策略/WyckoffMaster/trading_core/policy.py` 与 `engine.py` 的执行相位定义中，明确包含 `ExecPhase.B_GAP`：当 `bar_open <= current_stop`（多头跳空跌破止损）时，触发跳空平仓，其成交基准价格**必须是开盘价 `bar_open`**！
- 模拟盘强行假设在 `cur_stop` 成交，完全抹除了**跳空缺口（Gap）带来的严重额外滑点损失**。

#### 2. 隔离副本复现证据
- **复现测试**：`probes/audit_suspects_isolated.py::audit_suspect_2_gap_execution`
- **复现数据**：
  - 持仓当前生效止损：`cur_stop = 95.0`
  - 下一根 K 线遭遇断崖跳空：`open = 90.0`, `high = 91.0`, `low = 88.0`, `close = 89.0`
  - 预期成交基准（契约）：`raw_price = 90.0`，扣除滑点后实收约 `89.955`
  - 实际模拟盘成交（代码）：`raw_price = 95.0`，扣除滑点后实收约 `94.9525`
  - **单笔失真**：虚增净值 `4.9975` 美元/单位（每单位多赚/少亏约 5.5%）。
- **影响范围**：所有遭遇夜间急跌、突发利空或流动性断裂跳空跌破止损的币种，模拟盘账本系统性粉饰净值，掩盖真实下行风险。

### S-03 漏检中间十五分钟线 (Missing Intermediate 15m Bars)

#### 1. 现象与代码核查
- 在 `框架/backend/unified_runtime.py` 第 2097-2103 行 与 `框架/backend/paper_loop.py` 第 200-215 行：
  ```python
  cur_b15 = con_mkt.execute(
      "SELECT symbol, timeframe, open_time, close_time, open, high, low, close, available_at "
      "FROM candles WHERE exchange='binance' AND market='um' AND symbol=? AND timeframe='15m' "
      "AND is_closed=1 AND open_time>? AND close_time<=? "
      "ORDER BY open_time DESC LIMIT 1",
      (sym, min_t, now_ms)
  ).fetchone()
  ```
- **核心漏洞**：SQL 语句末尾被写死为 `ORDER BY open_time DESC LIMIT 1`！
- 在持续运行状态下，若轮询间隔为 1s，通常能捕获每一根闭合 15m。但**一旦发生进程重启、GC 停顿、行情入库延迟、或者服务挂起几十分钟后恢复**：
  若在停顿期间产生了多根已闭合 15m K 线（如 Bar A: 10:00-10:15 与 Bar B: 10:15-10:30），系统**仅且只会读取最新的 Bar B**，Bar A 被永久抛弃！
- 若 Bar A 的最低价跌破了止损（应当止损离场），而 Bar B 价格反弹回到止损位之上，系统读取 Bar B 发现 `low > cur_stop`，判定无需退出！

#### 2. 隔离副本复现证据
- **复现测试**：`probes/audit_suspects_isolated.py::audit_suspect_3_missing_intermediate_15m`
- **复现数据**：
  - 持仓止损价：`100.0`
  - 停机或延迟跨越 30 分钟，生成两根 K 线：
    - Bar 1 (10:00-10:15): `open=102, low=98.0, high=103, close=99`（`low=98.0 <= 100.0`，应立即触发止损退出）
    - Bar 2 (10:15-10:30): `open=101, low=100.5, high=105, close=104`（价格反弹）
  - 预期行为：按时间顺序遍历 `[Bar 1, Bar 2]`，在 Bar 1 处立即触发平仓，退出记录 `exit_triggered=True`。
  - 实际行为：`LIMIT 1` 仅返回 Bar 2，判定 `low=100.5 > 100.0`，退出记录 `exit_triggered=False`。
- **影响范围**：所有在生产服务重启、网络波动或批处理延迟期间发生震荡破位的持仓，止损机制被彻底绕过，产生“死里逃生”的虚假胜率。

    - 第 393 行调用 `PE.enforce_drawdown(arm, T=T, log=log)`
  - `框架/backend/unified_runtime.py`（**当前实际生产统一运行主进程**）：
    - 全文搜索 `accrue_funding`：**0 处调用**！
    - 全文搜索 `enforce_drawdown`：**0 处调用**！
  - `框架/backend/paper_loop.py`：
    - 全文搜索 `accrue_funding` 与 `enforce_drawdown`：**0 处调用**！
- **后果剖析**：
  1. **资金费完全脱节**：持仓存续期间，每 8 小时一次的资金费从未被主动计提。模拟盘数据库 `paper_funding` 表长年为 **0 行**。只有在极少数手动或到期平仓的一瞬间，`close_at_price` 才会去临时补记。持仓期间的浮动盈亏与动态权益从未扣除资金费成本！

#### 2. 隔离副本复现证据
- **复现测试**：`probes/audit_suspects_isolated.py::audit_suspect_4_funding_drawdown_scheduling`
- **复现结果**：
  - `unified_runtime_accrue_funding_called`: `False`
  - `unified_runtime_enforce_drawdown_called`: `False`
  - 账本证据：`paper_3a.sqlite3` 中 `paper_funding` 行数实测恒为 **0**。
- **影响范围**：全系统级别的核心风控与费用真实性失陷。任何声称“模拟盘跑过了极端行情考验且未触发回撤”的结论均无效，因为熔断检查根本未曾运行。

### S-05 价格精度兜底 (Price Precision Fallback)

#### 1. 现象与代码核查
- 在 `框架/backend/paper_engine.py` 第 2404-2405 行：
  ```python
  limits = contract_limits(symbol) or {"price_step": 0.01}
  step_val = float(limits.get("price_step") or 0.0)
  ```
- **核心违规**：在获取标的合约规则时，代码竟然使用了静默后备值 `or {"price_step": 0.01}`！
- **违背准则**：在工程准则中多次强调“严禁静默兜底，缺失规则必须显式拒绝报错”。
  - 对 BTCUSDT：真实 `price_step = 0.1`。若使用 `0.01`，生成的止损价会出现 `65399.42` 这类亚 tick 非法价格。
  - 对 PEPE/SHIB 等超微小币种：真实 `price_step = 0.000001` 或更小。若使用 `0.01`，价格步长被放大一万倍，取整后直接导致价格归零或失真。
- **历史证据关联**：在 `evidence/PROJECT-REVIEW-07/缺陷表.md` D-08 中已查实，`paper_3a.sqlite3` 账本中曾产生过平仓价为 `81888.0355`（BTC 最小步长 0.1）的未取整失真记录。

#### 2. 隔离副本复现证据
- **复现测试**：`probes/audit_suspects_isolated.py::audit_suspect_5_price_precision_fallback`
- **复现结果**：
  - 模拟 BTCUSDT 缺失合约配置时：
    - 兜底成交价：`65399.42`（存在非法亚 tick 位数）
    - 正确成交价：`65399.40`
- **影响范围**：新上线币种、冷门标的或配置不同步时，生成不符合交易所规则的畸变订单价格。

### S-06 重启恢复信号资格 (Restart Signal Qualification)

#### 1. 现象与代码核查
- 在 `框架/backend/unified_runtime.py` 第 896-960 行 与 2233-2275 行：
  - 早期历史版本：`bootstrap` 预热时产生的候选直接一律丢弃，导致停机 5 分钟期间恰好发生的突破信号丢失。
  - 现有版本：增加 `execution_earliest_ms + PE.MAX_FILL_LAG_MS >= upto_ms` 判断，符合时效的放入 `recovered_candidates`，由 `_route_recovered_candidates` 走 `paper_pending/paper_processed/paper_position` 三重查重。
- **对 AI 动态策略的潜在隐患**：
  - 当前的恢复逻辑是**无状态静态策略**特化的。它只假定信号是由固定的 K 线状态机纯函数产出的。
  - **动态决策灾难**：如果接入 AI 动态策略（需要维护短期对话记忆、动态参数状态、调仓配额预算），当系统重启执行 `bootstrap` 时，AI 的内部动态上下文被清空。恢复出来的候选将被当作全新的无状态信号重新处理，可能引发动作失忆、参数重置或与已生效动态持仓发生逻辑冲突。

#### 2. 隔离副本复现证据
- **复现测试**：`probes/audit_suspects_isolated.py::audit_suspect_6_restart_signal_qualification`
- **定性结论**：当前静态信号恢复机制初步具备幂等过滤能力，但在**动态方案接入协议**中，缺失对“动态上下文（Context Snapshot）”的快照与恢复支撑，属于接入 AI 动态策略前的**架构阻断项**。

## 二、六大疑点排查定论与处置建议

1. **S-01 逐笔跟踪止损通道**：
   - 回测 `engine_adapter.py` 的全局 `starts` 污染必须修复为绑定单笔持仓的入场时刻；
   - 明确废除“毫秒级逐笔 ticker 跟踪止损”的未证实猜测，以 4h 抬线 + 15m 逐根退出为唯一执行事实。
2. **S-02 跳空成交**：
   - 必须在模拟盘平仓逻辑中补齐开盘跳空判断：`if bar_open <= cur_stop: raw_price = bar_open`，禁止以完美止损价假定撮合。
3. **S-03 漏检中间十五分钟线**：
   - 彻底废除 `LIMIT 1`。改为持仓持久化 `last_checked_15m_open_time`，每次拉取 `open_time > last_checked AND close_time <= now` 的所有已闭合 K 线，正序 `ASC` 逐根遍历撮合。
4. **S-04 资金费与回撤调度**：
   - 在 `UnifiedRuntime.step_once` 主循环中必须挂载 `accrue_funding`（每 8h 边界计提）与 `enforce_drawdown`（每 15m 检查并执行强平与熔断）。
5. **S-05 价格精度兜底**：
   - 删除 `or {"price_step": 0.01}`，合约规格不存在时直接抛出 `ContractSpecMissingError`，阻断非法委托。
6. **S-06 重启恢复信号资格**：
   - 确立动态策略状态落盘契约，动态决策结果必须与 `event_uid` 强绑定固化在 SQLite 表中，重启恢复时只读已持久化的决策，禁止重复推演。
