## 二、六大疑点独立审计结论摘要

经静态代码比对与隔离副本复现，六大疑点的性质判定如下：

```
                    ┌── S-01 逐笔跟踪止损通道 ──► 回测全候选 starts 漏洞为真(P0)；逐笔 ticker 通道为假
                    ├── S-02 跳空成交 ──────────► 实际缺陷(P0)：模拟盘强行按完美止损价成交，缺失跳空判断
                    ├── S-03 漏检中间15m线 ─────► 实际缺陷(P0)：ORDER BY DESC LIMIT 1 跳过中间触止损 K 线
疑点独立核查 ───────┼── S-04 资金费与回撤调度 ──► 实际缺陷(P0)：UnifiedRuntime 主循环漏挂载，熔断与计费脱幅
                    ├── S-05 价格精度兜底 ──────► 实际缺陷(P1)：or {"price_step": 0.01} 违规静默兜底
                    └── S-06 重启恢复信号资格 ──► 机制初步具备但缺乏 AI 动态上下文状态机持久化支撑
```

1. **S-01 逐笔跟踪止损通道**：
   - 回测 `engine_adapter.py` 使用了全候选集合 `starts`，导致同标的后序持仓借用了前置候选入场前已收盘的 4h K 线抬高止损（`D-03`，同币多笔暴露面 3,346 笔），属**实际缺陷**；
   - 生产环境中**不存在**毫秒级逐笔 ticker 跟踪止损，冻结规则明确定为 4h 收盘抬线 + 15m 明细判定，所谓“实时逐笔跟踪通道”系**未证实的猜测或伪概念**。
2. **S-02 跳空成交**：
   - `paper_engine.py:2299 & 2461` 在跌破止损时硬编码将 `raw_price = cur_stop` 传入平仓，完全缺少开盘跳空判断（`bar_open <= cur_stop`），导致跳空暴跌被美化为理想止损价成交，属**实际缺陷（P0 经济失真）**。
3. **S-03 漏检中间十五分钟线**：
   - `unified_runtime.py:2101` 与 `paper_loop.py:210` 强制使用 `ORDER BY open_time DESC LIMIT 1`。在服务重启、网络波动或批处理暂停跨越多根 15m 时，中间跌破止损的 K 线被彻底漏检，反弹后仓位非法存活，属**实际缺陷（P0 穿透存活漏洞）**。
4. **S-04 资金费与回撤调度**：
   - 生产主运行程序 `UnifiedRuntime.step_once` 中，`accrue_funding` 与 `enforce_drawdown` 的调用次数均为 **0**。模拟盘持仓存续期资金费从未主动计提（账本恒为 0 行），20% 账户级最大回撤熔断完全处于**脱幅裸奔状态**，属**实际缺陷（P0 核心风控脱幅）**。
5. **S-05 价格精度兜底**：
   - `paper_engine.py:2404` 存在 `limits = contract_limits(symbol) or {"price_step": 0.01}`，合约元数据缺失时静默采用 0.01，直接导致 BTC 产生非法亚 tick、小币种步长被放大万倍，违背严禁静默兜底原则，属**实际缺陷（P1 规则违例）**。
6. **S-06 重启恢复信号资格**：
   - 现有版本已引入 `MAX_FILL_LAG_MS` 时效门槛与三重表查重过滤，但当前的恢复逻辑仅适用于无状态纯函数静态策略。在接入 AI 动态决策时，缺少动态决策上下文的持久化快照，重启将引发动态逻辑失忆与决策混乱。

## 三、三组对照实验协议核心要素

1. **三组平行对照架构**：
   - **Group A (固定策略基准)**：修复执行缺陷后的 FT-LOW4H 固定参数版（$s=0.05, d=0.03, \text{risk}=0.5\%$）；
   - **Group B (规则驱动动态)**：基于可解释的 ATR 波动率比率、ER 效率比率与 BTC 大盘趋势三因子，动态自适应调仓与跟踪，**绝不故意做弱**；
   - **Group C (AI 动态策略)**：大语言模型/机器学习代理在与 Group B 完全同构的动作空间（离散档位限制在 $[-20\%, +20\%]$）和调整预算（单日最多调整 1 次，全天总调整 $\le 5$ 次）内进行决策。
2. **大语言模型历史记忆泄露防范**：
   - 历史回测数据（2021-2024）已被大部分主流 LLM 预训练吸收，历史收益**无法证明推理有效性**；
   - 必须将实验划分为“开发调试期（固化 Prompt 与规则）”、“受控历史验证期（仅测系统稳定性）”与“**纯前向实时验收期（前向至少 30 天未见行情）**”。
3. **严苛评估指标与一票否决**：
   - 净收益必须扣除所有手续费、滑点与真实资金费；
   - **AI 超额收益必须覆盖 3 倍 API Token 决策成本**；
   - 最大回撤不得劣于固定组与规则组；
   - 决策响应 P95 $\le 15\text{s}$，超时必须平滑安全降级至固定基准；
   - 发生越权调仓或格式崩溃一票否决。
