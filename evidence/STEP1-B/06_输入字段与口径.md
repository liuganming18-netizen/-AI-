## 二、周期架构与三个时点

```
snapshot_time_ms = 1h 突破 K 线的 close_time        ← 决策时刻（信号成立）
available_at_ms  = 同一个值                          ← 自证可得，不是证据
execution_earliest_ms = snapshot + 15min             ← 下一根严格更晚的 15m 开盘
```

- 状态机：`state_machine.py:540-541` 写入 `snapshot_time_ms = close_time_ms`、`available_at_ms = close_time_ms`。
- 下单帧：`engine_adapter.py:313-325` 用 `cand_map.get(t_close)` 把候选挂到 **1h bar 的收盘时刻**，
  `confirm_time = execution_earliest_ms // 1000`。
- 成交：引擎在 **15m bar 的 `open`** 上成交（`engine.py:446 raw_open`）。
- ⇒ **决策用的是已收盘 1h bar，成交用的是下一根 15m 开盘**，这一段是自洽的。

> ⚠ 与 FLOW-OI-01 的 `open_time <= ts` 前视缺陷**不是同一处**：那是特征脚本的错，
> 本策略的状态机没有这个问题。两者不能混为一谈。

## 三、OI 的 as-of 规则（最容易被误读的一处）

`features.py:78-120`：

```python
idx_curr = searchsorted(oi_ts, target_time_ms, side="right") - 1   # 取 <= target 的最近一条
if abs(target_time_ms - t_curr) > 900_000: return None             # 超过 15 分钟即判缺失
```

- 语义是「**收盘时刻之前最近的一条观测**」，不是「收盘时刻**已经发布**的最近一条」。
- 因此当 `ts` 恰好等于 `close_time` 时（`side="right"`），该观测会被当作已知。
  这条 5m bar 在物理上要到 `ts+5min` 才闭合，发布还要更晚 ⇒ **乐观读取**。
- 缺 `rate/mark`、超距、`<=0` 时一律 fail-closed（返回 `None` + 状态码），**不补 0** —— 这一点是对的。

## 四、规格资格的判定链（为什么全池 0 条 verified）

`instrument_spec.py` 要求三条**同时**成立：

1. 快照按 `serverTime` **夹住**窗口（有窗口前的快照 + 窗口后的快照）；
2. 区间内**每一份**快照逐一比较一致；
3. `spec_changes_*.json` 变更证据**覆盖整窗**。

实测（`08_scan.json.contracts`）：

| 项 | 值 |
|---|---|
| 期货 exchangeInfo 快照 | **2 份**，均为 `2026-10-05`（`015512Z` / `045328Z`） |
| `spec_changes_*.json` | **0 份** |
| 交接包 `spec_qualification` | `verified` **0** / `unverified_historical` 212 / `contradicted` 13 / `not_listed` 2 |
| 交接包 `formal_pass_allowed` | **227 全 false** |

⇒ 条件 3 从根上不成立，**任何标的都不可能 verified**。这不是「跑得不够」，是证据不存在。
护栏测试 `test_real_evidence_dir_never_yields_verified`（6 个标的参数化）就是防「为凑通过而放宽判定」。

## 五、预热与「窗口首日能不能交易」

| 周期 | 预热根数 | 效果 |
|---|---|---|
| 4h | 最多 220 根（≈36 天） | 窗口首日就有 42 根箱体 + 14 期 ATR ⇒ **首日可建档** |
| 1h | 0 | 状态机从窗口首根开始推进；`consecutive_closes_below_l` 等计数从 0 起 |
| 15m | 0 | 参与率用的「前一根 15m 成交额」在窗口首根**不存在** ⇒ 首根无法开仓（fail-closed） |

⚠ `config.atr_warmup_bars=200` 与代码实取 220 不一致，且无测试锁定。

## 六、哪些字段是「缺失」而不是「0」

| 字段 | 缺失形态 | 判定规则 |
|---|---|---|
| `funding_fee` | `funding_gaps` 有记录（交接包实测 11 次） | 记缺，不补 0；符号：正=支出 |
| `first_move_4h` | `NO_DATA` 22 条 = 未成交 22 条 | 不得判 FAIL，但条数必须等于未成交数 |
| `box_atr_formation` | 42 条空，全在窗口回放代际 | 有据的缺失（该代际箱体几何是坏的） |
| `net_pnl`（未成交行） | FE08/FE09 写 **0**，交接包是 **null** | **已知不一致**，随数据继承，需登记 |
| `max_qty` | 交易所公告从不含该字段 | 缺失即不校验，**不得当无穷大通过** |
