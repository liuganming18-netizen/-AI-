# STEP1-B / 10 · 报告、API、页面、图表分别读的是哪一份结果

> 结论先说：**同一个 run 有 4 份「结果」，来源各不相同，且互相之间没有一致性测试。**
> 谁读哪一份，必须写死；否则会出现「页面绿了、报告红了、数据对不上」的三方扯皮。

---

## 一、四份结果与各自的读者

| 层 | 产物 | 生产者 | 读者 | 是否算「事实源」 |
|---|---|---|---|---|
| ① 引擎产物 | `orders/fills/positions/trades/ledger/equity_curve.jsonl`、`summary.json`、`candidates.jsonl` | `trading_core.engine.run` + `runner._build_run_files` | 读接口、审计脚本 | **是**（唯一一手数据） |

| ③ 图表 | `chart.json`（或内存重建的同结构） | `backtest_chart.build_chart` / `_fallback_chart_cached` | 前端 K 线面板 | 否（①的 15m 副本 + 打点） |
| ④ 报告 | `evidence/**/报告.md`、`00_acceptance_table.csv`、`08_final_status.json` | 各审计窗口 | 人 | **否**（可能陈旧，见下） |

## 二、逐项对照

| 问题 | 读哪一份 | 具体入口 | 明确**不读**什么 |
|---|---|---|---|
| 页面上的批次列表/批次汇总 | ①+② | `backtest_batches.list_batches` → `BATCH_ROOT=回测日志/event_trend_v0_1`，只认 `runs` / `runs_*` | 不读 `public/all_trades.json`（已废弃）；不读 `runs` 之外的目录 |
| 页面上的 8 格指标 | ② | `backtest_api.get_metrics` → `backtest_metrics.compute_metrics`，输入是 `trades.jsonl` + `equity_curve.jsonl` | **不读** `summary.json` 的 `win_rate/max_drawdown_pct`（那里根本没有这些字段，`or 0` 会把「没算」伪装成 0） |
| 页面上的 K 线/打点/基准 | ③ | `get_chart` → `read_chart` → `_chart_window_reject_reason` → 必要时 `_fallback_chart_cached`（**内存重建，不写盘**） | 不读 `trades.jsonl` 的价格当 K 线；不把重建结果写回 run 目录 |
| 页面上的逐笔明细 | ② | `get_trades` → `ledger_links.load_ledger_facts` | 不按行号编 `trd_N`；不用 `order_id` 单键关联（会跨代际串账） |
| 单笔详情 | ② | `get_trade(run_id, trade_id)` | 不跨 run 回退（禁止 `?? displayTrades[0]`） |
| 实验列表（`GET /backtests`） | ② | `list_experiments`：`S.list_runs(回测日志/oi_resonance_v1/runs)` 后只留 `strategy_id==WX_OI_RESONANCE_V1` | **该根 0 个 run ⇒ 恒空**；页面不用它，改用批次接口 |
| 报告里的净盈亏/胜率 | ④（应回指①） | 各 `报告.md` | 不应独立计算；必须能回指机器可读产物 |
| 验收表 | ④ | `evidence/ENTRY-AUDIT-06/00_acceptance_table.csv` | 不是测试结果，是人工结论表 |

## 五、给窗口①的一条硬规则

> 读接口全绿只能证明「页面没骗人」，不能证明「回测算对了」。
> 反过来，回放数据对得上也不能证明「页面读对了」。
> **两张验收表必须分开签，禁止用一张的绿去抵另一张的红。**
