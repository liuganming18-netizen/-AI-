## 一、candidate → signal → order → fill → trade 的真实键

```
4h 箱体            event_id = ev_{strategy}_{venue}_{symbol}_{4h_close_ms}
                        │                    state_machine.py:215
                        ▼
1h 突破确认      candidate_id = cand_{event_id}_{1h_close_ms}
                        │                    state_machine.py:527
                        ▼
信号帧          signal_id  ≡  candidate_id（同值直传，不做任何换算）
                        │                    engine_adapter.py:313-325
                        ▼
订单            order_id = 'ord_' + stable_hash(strategy_key, symbol, signal_id, action, …)
                        │                    trading_core/order.py:69-71
                        ▼
成交            ORDER_FILLED.payload.order_id；Fill.order_id
                        │                    engine.py:235-247
                        ▼
平仓记录        trade rec 带 signal_id / order_id / exit_order_id
                        │                    engine.py:1053-1055
                        ▼
持仓            Position（signal_id / order_id 由开仓订单写入）
                                             position.py
```

### 三个必须写死的约束

| 约束 | 事实 | 后果 |
|---|---|---|
| **`order_id` 不含 `run_id`** | 由 `strategy_key+symbol+signal_id+action` 派生 | 同一标的同一箱体在不同回放代际生成**同名 order_id** ⇒ 单键关联会静默取错代际 |
| **`event_id` 不是唯一信号键** | 窗口代际用 `cand_exec_earliest_ms` 而非快照时刻 | 跨代际比对只能用 `signal_key = (symbol, snapshot_time_ms)`（交接包自定义） |
| **`trades.jsonl` 不带 `trade_id`** | 批次目录 666 笔全无该字段 | 读层必须走 `ledger_links`（orders/positions/ledger 关联），**禁止按行号编 `trd_N`** |

### 实测撞号规模（EA04 §1.8 已登记）

- 引擎输出层：213 条成交里有 **6 组 `signal_id` 重复、共 13 行**。
- 映射到 205 个候选后重复行数为 0 —— 不是撞号消失，而是候选映射按
  `(group, symbol, snapshot)` 选中的是**同一 run 里的另一笔**成交。
- ⇒ 任何下游关联键必须是 **`(run_id, order_id)`** 复合键。

### 逐环校验入口（代码里真实存在的）

| 环节 | 校验 | 位置 |
|---|---|---|
| 身份解析 | `resolve_candidate(signal_id)` 只按 id 精确查，查不到就拒绝发单 | `engine_adapter.py:172-175` |
| 信号 bar 一致性 | `signal_bar_open_ms == snapshot_time_ms - 3600_000` | `engine_adapter.py:192-197` |
| 成交归属 | `trades_by_signal` 严格等值索引；重复 id 记 `orphan_trades` | `engine_adapter.py:489-503` |
| 身份链结论 | `identity.chain_ok = 无 break ∧ 无 orphan ∧ 全部 ok ∧ 成交数=匹配数` | `engine_adapter.py:616-621` |

## 二、费用、滑点、资金费、净盈亏、现金、持仓的入口

| 项 | 唯一实现入口 | 公式 / 规则 | 参数来源 |
|---|---|---|---|
| **手续费** | `engine.py:265-267`（费率）、`:411`（出场）、`:423`（emit） | `fee = fill_price × qty × taker_fee_rate`；只按 taker | `config.taker_fee_bps=5.0` ⇒ `0.0005`；C 方案 10bps |
| **滑点** | `fill.py:108-139 price_breakdown` | 买：`raw×(1+slip)`；卖：`raw×(1−slip)`；**先滑点后取整** | `config.slippage_bps=3.0` ⇒ `0.0003` |
| **取整** | 同上（Decimal） | 买 `ROUND_CEILING`、卖 `ROUND_FLOOR`，步长来自规格或显式 `price_step` | `instrument_spec.price_step` |
| **资金费** | `funding.py:67-107 settle_funding` | `cost = mark_price × qty × rate × direction`；`cash -= cost` | 真实 `settled` 事件；缺字段记 gap **不补 0** |
| **毛盈亏** | `engine.py:1015` | `gross = (fill − entry_price) × qty × direction` | — |
| **净盈亏** | `engine.py:1047` | `net = gross − entry_fee − exit_fee − cum_funding_fee` | — |
| **现金** | `engine.py:313`（初值）、`:1016`（平仓加现金）、`:359`（资金费扣现金） | `cash = initial + Σgross − Σentry_fee − Σexit_fee − Σfunding` | `config.initial_equity=2000` |
| **权益曲线** | `engine.py:720-724` | `total_equity = cash + unrealized_pnl(open_positions, fee)` | 逐 15m bar |
| **持仓** | `trading_core/position.py` | `Position(direction, qty, entry_price, entry_fee, cum_funding_fee, …)` | — |
| **下单数量** | `risk.py:106-164 check_entry` | `unit_risk = |entry−stop| + (entry+stop)×fee`；`qty = min(risk_per_trade×mtm/unit_risk, 名义上限)` | `risk_budget_per_trade=0.5%` |
| **名义上限** | `engine_adapter.py:225-238` | 单仓 ≤30% 权益、总 ≤90% 权益 | `config.max_notional_per_position=0.30` / `max_total_notional=0.90` |
| **参与率上限** | `engine_adapter.py` + `engine.run` participation_rate | 订单名义 ≤ 已完成前一根 15m `quote_volume × 0.1%` | `max_participation_of_prev_15m_quote=0.001` |
| **对账块** | `engine.py:797-857` | `cash_identity_ok / equity_identity_ok / slippage_split_ok` | 自检，**不是独立复算** |

### 成本恒等式（必须逐笔成立）

```
slippage_loss = slippage_loss_pure + rounding_loss
net_pnl       = gross_pnl − fees − funding_fee
fees          = entry_fee + exit_fee
```

- 滑点与取整**已经写进成交价**，`net_pnl` **不再单独减** `slippage_loss`；
  再减一次即重复扣减（全样本会多扣 **9.519034 USDT**）。
- 账本 `FUNDING_FEE.payload.delta` 是**现金口径**（支出为负），与 `funding_fee`
  （正=支出）**符号相反**：`cum_funding_fee = −Σdelta`。

## 三、两个已知的算术缺口（不是本单修的，但必须写进验收矩阵）

### 1. 入场向上取整会撑大止损距离

- 入场买向 `CEILING` ⇒ 成交价 ≥ 信号价；止损 `P0 = Lr − 0.1A` 固定。
- 因此「实际 R」被撑大，`qty = risk/unit_risk` 变小 —— 但若取整跨了多个 tick
  （`step/raw` 最高 **1.475**），单笔实际亏损可**超过 0.5% 预算**。
- 62 腿实测：**8 条成交价越出当根 15m bar 的 [low, high]**；
  滑点段贡献 **0**，取整段贡献 **100%**。
- `strict=True` 只拦住 1/8（被拦的全是零价），其余 7 条静默通过。

### 2. R7（零容差区间校验）在架构上无处安放

- `FillAdapter` 协议（`fill.py:179-183`）**只收 `raw_price` 与 `price_step`**，
  拿不到当根 bar 的 `low/high` ⇒ 想在成交处校验区间，必须先改协议。
- 62 腿中「越界但 ≤ 容差」= **0 条** ⇒ R7 必须是零容差，没有中间地带。
- 影响面**无法影子测**（改协议即改行为），所以不许编数字。

### 3. 数量侧

- `LOT_SIZE` 恒适用；`MARKET_LOT_SIZE` 仅 MARKET 单；多步长取**最小公倍数**（已实现且有测试）。
- **`max_qty` 从未校验**（`engine.py` 无该分支）。

## 四、一句话总结

> 关联键这一段是**清楚且已修过的**（signal_id 直传 candidate_id、严格等值、拒绝时间近似）；
> 费用与现金这一段**公式唯一、可复算**，但只有引擎自检、没有独立复算器；
> 真正没解决的是**成交价越界**与**规格资格**——前者缺协议位置，后者缺历史证据。
