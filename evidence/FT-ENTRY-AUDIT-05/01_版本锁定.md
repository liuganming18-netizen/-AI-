# FT-ENTRY-AUDIT-05｜版本锁定与差分核查结论

> 目的：确认 FT-ENTRY-04（含「A 路线成交价严格 < 冻结 H」约束）相对 FT-ENTRY-03（无该约束）**除该约束外无其他变化**（工单第 1 条）。
> 方法：对 10 组逐笔 CSV、归档 zip、策略源码、config 做 SHA-256 比对，并逐 hunk 读基类 diff。

## 1. 结论

**除「A 路线成交价严格低于冻结 H」这一条外，FT-ENTRY-04 与 FT-ENTRY-03 无其他策略/参数/样本变化。第 1 条工单项满足。**

## 2. 逐项核查

| 对象 | 结论 | 证据 |
|---|---|---|
| 10 个策略子文件（含 Baseline） | **全部 SHA-256 一致** | `out/01_代码文件哈希对比_v1.csv`（`identical=True`） |
| config.json | 仅 3 个键变化 | `bot_name` / `datadir` / `user_data_dir`，均为路径或名字，无运行时逻辑影响（`out/01_config键级差异_v1.json`） |
| 基类 `WyckoffParamExplorationBase.py` | 2 个 hunk、99 行 diff，全部属于该约束 | `out/01_基类差分全文_v1.patch` |
| `code/` 运行脚本目录 | 文件名完全不同，但均为回测驱动/只读核验外壳 | 见第 3 节 |

## 3. 基类 diff 内容（2 hunk）

- **hunk 1（`__init__`）**：新增订单审计记录设施 `execution_audit_records`、防重试集合 `evaluated_candidates`、审计日志句柄 `audit_orders_{class}.csv`。
- **hunk 2（`confirm_trade_entry` A 路线分支）**：
  - `frozen_H = float(cand.box_high_h)`，`fill_price = float(rate)`；
  - `fill_price >= frozen_H → REJECT`（等于亦拒）；
  - 同一 `candidate_id` 仅评估一次（实例级 `evaluated_candidates`），被拒后绝不重试、不挂单等回落；
  - 全部决策写入 `audit_orders_*.csv`（含 `frozen_H` / `fill_price` / `decision` / `reason`）。
  - Baseline 分支保持原样（不受约束）。

## 4. `code/` 目录差异说明（不影响行为结论）

| FT-ENTRY-03 | FT-ENTRY-04 | 性质 |
|---|---|---|
| `01_run_strict_pre_bo.py` | `01_run_pre_bo_execution_constraint.py` | 同为「跑 10 组 freqtrade + 算指标 + 3×3 网格 + 旧版对照」；04 仅追加 `verify_post_fill_constraint` **检查**步骤（不删成交） |
| `02_verify_checks.py` | `00_verify_engine_paths.py` | 核验外壳 |
| `03_analyze_c_route_failure.py` | `02_candidate_reconciliation_and_attribution.py` | 候选对账/归因（只读） |
| — | `03_bias_and_lookahead_check.py` | 偏差/前视检查（只读） |

04 的 `00/02/03` 为新增**只读核验脚本**，不改动交易生成；04 的 `01_run_*` 与 03 的 `01_run_*` 功能对等。因此**回测交易数差异的唯一来源是基类约束**，运行脚本差异不改变行为结论。

- FT-ENTRY-04 为反重力产出的 10 组回测结果（逐笔 CSV + 归档 zip + 审计日志），本审核视为只读证据，不重跑、不改写。
