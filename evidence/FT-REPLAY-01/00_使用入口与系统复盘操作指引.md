## 二、入口一：系统原生回测工作台操作指引

### 1. 服务启动与访问
若本地开发服务已在后台运行（后端 `127.0.0.1:8787`，前端 `127.0.0.1:3000`）：
1. 打开浏览器访问：[http://127.0.0.1:3000/backtests](http://127.0.0.1:3000/backtests)
2. 在页面顶部或右侧的**批次选择下拉菜单（Batch Selector）**中，选择：
   `runs_ft_entry_09_research (FT-ENTRY-09 统一预热资格研究期结果（27 组 C0/C1/C2）)`

### 2. 批次与 Run 列表查看
- 系统后端将自动调用 API：
  - `GET /api/v1/backtests/batches/runs_ft_entry_09_research/summary`：返回 27 组的标准性能卡片（包含 C0/C1/C2 9组参数的胜率、净收益、交易次数等）。
  - `GET /api/v1/backtests/batches/runs_ft_entry_09_research/runs`：展示 27 组运行元数据，规范化命名为 `run_WX_EVENT_TREND_V0_1_FT09_{mode}_{suffix}`。

### 3. 查看单个 Run 交易明细与图表
- 点击任意 run 项（例如 `run_WX_EVENT_TREND_V0_1_FT09_C1_Vs06_Z04`）：
  - 系统调用 `GET /api/v1/backtests/run_WX_EVENT_TREND_V0_1_FT09_C1_Vs06_Z04/trades`：拉取该组完整的 88 笔真实成交记录，展示包含入场时间、出场时间、价格、盈亏、退出原因等标准字段。
  - 系统调用 `GET /api/v1/backtests/run_WX_EVENT_TREND_V0_1_FT09_C1_Vs06_Z04/chart`：渲染该组资产净值曲线（Equity Curve）。

## 三、入口二：专属交互式复盘工作台（Web Replay Viewer）

针对工单中关于**原信号时间、确认时间、实际成交时间、原始 P0、三模式横向对照、拒单隔离**的高标准要求，专属复盘工作台提供了完备的交互支持。

### 1. 启动与访问方式
- **直接双击文件**：直接使用 Chrome/Edge/Safari 浏览器打开项目目录下的：
  [`evidence/FT-REPLAY-01/web/index.html`](file:///Users/boos/Desktop/威科夫因子共振趋势/evidence/FT-REPLAY-01/web/index.html)
- **本地静态 HTTP 服务（推荐）**：
  ```bash
  cd evidence/FT-REPLAY-01/web
  python3 -m http.server 8089
  # 浏览器访问 http://127.0.0.1:8089
  ```

### 2. 核心界面功能与操作流

#### (1) 多维参数与状态筛选栏（Header Filter Bar）
- **模式切换**：支持全选、单独筛选 `C0 (原缩量回踩)`、`C1 (下一根1h收盘确认)`、`C2 (重心上移确认)`。
- **参数组合**：支持按 9 组经典网格（Vs: 0.4/0.6/0.8, Z: 0.2/0.4/0.6）一键过滤。
- **执行状态物理隔离**：
  - `全部状态`：查看 9,128 条全生命周期记录；
  - `真实成交 (EXECUTED)`：仅看 4,325 笔真实成交；
  - `执行拒单 (REJECTED)`：查看 45 笔因 P0 越界或合法性条件拒绝的记录；
  - `确认放弃 (UNEXECUTED)`：查看 4,758 笔因确认柱未满足缩量企稳条件而主动放弃的信号。
- **时区切换（Timezone Switcher）**：
  - 一键在 `UTC` 与 `CST (北京时间 UTC+8)` 之间切换，表格与 K 线图全部同步响应，并在详情中保留原始毫秒级时间戳。

#### (2) K 线图表四维独立标记体系
在复盘工作台中选中任意交易后，下方将自动渲染该币种在对应时间段的高精度 15 分钟 K 线图，严格呈现**四维时间因果标记**：
1. 🟡 **黄金倒三角（Signal Triggered）**：原 1 小时信号柱收盘触发时刻（如 2024-03-01 20:00:00 UTC）。
2. 🔵 **蓝色正菱形（Confirm Closed）**：确认 1 小时 K 线收盘时刻（C1/C2 为 21:00:00 UTC；C0 则与信号时刻一致）。
3. 🟢 **绿色正三角（Actual Entry）**：实际执行下单并撮合成交时刻（15m 级别的 21:15:00 UTC），**绝对不与信号时刻重叠**！
4. 🔴 **红色倒三角（Actual Exit）**：实际出场平仓时刻（带出场价格与原因）。
5. 🟣 **紫色水平虚线（P0 Baseline）**：信号触发时已冻结的基准止损位 $P0$。

#### (3) C0 / C1 / C2 三模式同候选横向对比抽屉（Cross-Mode Drawer）
- 点击明细列表右侧的 **“三模式对照”** 按钮，页面右侧将滑出横向对比抽屉：
  - 系统基于 `candidate_id`（同一币种、同一信号时刻）自动聚合 C0、C1、C2 在当前参数下的三种表现；
  - 自动呈现：
    - **C0**：是否直接开仓、开仓价格、最终盈亏；
    - **C1**：下一根 1h 确认是否通过、延迟开仓价格差、盈亏改善程度；
    - **C2**：重心上移是否满足、是否避免了假突破亏损。
  - 对照结果直观分类展示：`避免亏损`、`错过盈利`、`延迟改善`、`延迟变差`。

## 四、登记元数据与字段映射规范

在复盘明细中，所有字段严格遵循如下定义；遇历史数据未记录项，严格标明为 `未知`，绝不外推虚构：

| 字段名称 | 对应英文键 | 规范定义与取值规则 |
| :--- | :--- | :--- |
| **真实交易 ID** | `trade_id` | 关联回测引擎产生的唯一真实交易 ID（如 `t_20240301_001`）；拒单标 `REJECTED_{id}`，未成交标 `UNEXEC_{id}` |
| **候选 ID** | `candidate_id` | 同一币种在同一原信号时刻的唯一标识（格式：`CAND_{symbol}_{signal_ts}`） |
| **币种** | `symbol` | 合约标的代码（如 `BTCUSDT`, `COMPUSDT`） |
| **原信号时间** | `signal_time` | 原 1h 策略产生候选信号的 K 线收盘时间（提供 UTC、CST 与毫秒戳） |
| **确认收盘时间** | `confirm_time` | 紧接下根 1h K 线收盘判定时刻（C0 为原信号时间，C1/C2 为 +1h） |
| **实际入场时间** | `entry_time` | 实际 15m 执行撮合完成时间（若未成交则为 `null`） |
| **实际出场时间** | `exit_time` | 触发止损或规则平仓的执行时间（若未成交则为 `null`） |
| **原始止损 P0** | `p0` | 原信号生成时刻冻结的结构低点止损锚点（全生命周期不改变） |
| **入场价格** | `entry_price` | 真实成交价格（15m K 线的 open/close 撮合价） |
| **出场价格** | `exit_price` | 实际出场成交价 |
| **持仓数量** | `size` | 根据入场风险预算与初始止损距离计算得到的下单币数 |
| **实际仓位金额**| `position_val` | `entry_price * size`（USDT 计价） |
| **入场计划风险 $R$**| `planned_risk_r` | `abs(entry_price - p0) * size`（初始计划风险额，约 10 USDT） |
| **扣费后盈亏** | `net_pnl` | 扣除双边手续费后的最终净盈亏（USDT） |
| **出场原因** | `exit_reason` | `STOP_LOSS`（止损）、`TIME_LIMIT`（超时）、`FORCE_CLOSE`（区间末端）等 |
| **策略与数据版本**| `versions` | 统一标明：策略 `FT_ENTRY_09`，数据版本 `FT-FACTOR-03` |
