## 1. 目标、边界与真实含义

持续扫描实际可获取的 USDT 本位永续合约，优先寻找**潜在上涨启动前**机会，同时支持独立的下跌方向研究及双向模拟。所有输出必须展示支持/反对证据、结构失效条件、数据质量、时间和历史效果。所谓“庄家意图/聪明钱”是可证伪的市场行为假设，不得宣称知道真实交易者意图；“聪明钱均价”仅在存在可审计数据依据时展示。信号不是收益保证，模拟盈亏不等于真实可成交收益。

## 2. 产品信息架构与 UI

- 左侧可折叠菜单仅四组：**加密货币、数据监控、策略分析、历史回测**。桌面 2K/4K 优先，深色默认、可切浅色、玻璃质感；先交付真正可运行可交互的新设计，用户独立验收后才实现模块 1 功能。
- 加密货币首页：顶部 BTC/ETH、市场广度、扫描数量/进度、重要信号、数据源及 Telegram 状态；上方可排序、虚拟滚动、筛选的全量合格候选榜（约 40%），下方联动专业 K 线（约 60%），比例和面板可折叠。
- **方向独立**：默认看涨，用户可切换看跌；每个方向各有“共振候选”“早期观察候选”两标签；不得把多空评分混在同一排名。每 5 分钟重排排名，重要事件即时记账，AI 常规分析每 15 分钟、关键事件即时触发。
- 选择币种后图表默认 **1D**；支持 1D、12h、8h、4h、1h、30m、15m、5m，不含 1m。K 线、量价、指标、结构、OI、资金费率、多空比及 AI 证据联动；AI 自动绘图和人工绘图分层，重要标记默认显示，其余可切换；AI 分析面板位于图表下方且可折叠。
- 模拟持仓、止损轨迹、入场/调整/退出事件按币种叠加图表并可开关；仅对真实保留的订单明细提供完整路径。历史回放为**独立页面**。
- 数据监控为真实交互式层级架构画布：模块→服务→任务，显示真实数据流、延迟、吞吐、错误、积压、缺口、恢复和通知链路；允许权限受控的安全重试、暂停/恢复及事件追踪，禁止伪造运行状态。

## 3. 数据源、覆盖与质量门禁

- 首选 Binance USDT 永续；仅 Binance 无对应合约时，核验身份、计价、市场定义后采用 OKX 补充。保留来源，不得跨交易所无标识拼接。实际扫描数量如实报告，目标 500+ 不是虚构的保证。
- 统一 API 调度：实时优先，限流、去重、缓存、重试退避、断点续传；采集和监控共享一条数据管线，避免重复 API 请求。
- K 线自上市以来**尽可能**补齐；时间框架优先次序 1D→12h→8h→4h→1h→30m→15m→5m。保留 5m 原始历史，较高周期可在满足交易所边界和时间对齐时聚合；1h、4h、8h、1D 建缓存。原生与聚合数据明确区分。
- 原始 OHLCV 无损压缩；最近 90 天热存储，较旧冷存储；**不得静默删除原始历史**。时间段、交易所、币种、周期及质量状态可查。
- 历史覆盖热力图可按月/日/小时自适应查看缺口并链接补齐任务；自动缺口检测、API 回补、校验、故障分级、恢复检查点，支持人工介入。
- OI、资金费、多空比、主动成交历史按真实 API 可用窗口记录，不得假设全部追溯至上市。缺失/延迟数据使**受影响分析**暂停或降级，不必冻结全部市场。
- 每条证据记录 event_time（事件时间）、available_at（当时可获得时间）、ingested_at（采集时间）、decision_at（决策时间）、source、quality、dataset_version。历史回测按 available_at 和当时版本过滤，防未来数据泄漏、幸存者偏差和事后修订。

## 4. 量化、AI 与候选池

- 1D 定大方向；12h/8h 检查宏观阶段；4h/1h 判断核心结构；30m/15m/5m 辅助确认和局部精度，低周期不能单独推翻高周期。
- 两类候选：**早期观察**（中周期潜力、日线未确认）与**共振候选**（达到量化与 AI 质量门禁）。多空各自独立评分、晋升、降级、失效和排序。
- 量化给出可复算的结构、评分、价格区间及风险边界；主 AI 分析证据、反证和不确定性；重要共振由独立复核 AI 审核。冲突时经历史验证的量化规则仲裁，并保留 AI 分歧。AI 离线则量化降级，**不得推送伪称 AI 验证的高优先级信号**。
- AI 网关分别配置主/复核模型、供应商、密钥、参数、成本、调用状态；优先分析筛选后的候选，支持去重和预算约束。AI 常规报告仅保存结构化摘要；关键决策的**全量 AI 报告全局最近 100 份**，较旧全文按政策淘汰但摘要及关联版本保留，不得宣称仍能全文回放。

## 5. 唯一信号中心（禁止多套事实）

**信号必须先可靠持久化，再分发。** 首页、模拟盘、Telegram 和历史回放只消费同一个 signal_id 与版本，不得各自复制一套“信号真相”。

建议最小契约：
- `signal_id`、`opportunity_key`（同一结构机会的稳定键）、`symbol`、`venue`、`direction`（LONG/SHORT）、`strategy_version`、`data_snapshot_id`、`model_versions`；
- `state`、`version`、`score`、`evidence_refs`、`counter_evidence_refs`、`entry_range`、`target_range`、`invalidation_price`、`quality_gate`；
- `event_time`、`available_at`、`decision_at`、`created_at`、`updated_at`，及不可变事件流水。
- 价格区间由市场结构与经验证的量化规则计算，AI 负责解释和复核；禁止凭空生成价格、胜率或确定收益。

状态机：`EARLY_OBSERVATION` → `RESONANCE_CONFIRMED` → `TRACKING`，允许降级至早期观察，任一活动状态均可 `INVALIDATED`；数据异常可 `SUSPENDED_DATA` 并在重新校验后恢复或失效。这里的 `TRACKING` 是监测阶段而非另一份信号。每次晋升/降级/区间重大调整产生不可变版本事件。失效后首页标记“已失效”、清除过期价格线，历史快照保留；新独立结构才可新建 signal_id，不得换 ID 绕过冷却。

高优先级通知：经验证的观察→共振升级，以及明确允许的新独立重要信号；包含币种、方向、评分、当前价格、结构入场区间、目标/退出区间、失效价格。每币种信号状态去重与 **1 小时冷却**；普通排名变化不反复通知。看涨/看跌均推送，必须显著标注方向。

## 6. 模拟盘（不接实盘）

- 标准初始权益 **2,000 USDT**；最多 **10 个不同币种的合并仓位**，不是必须满仓。同币种加仓合并展示但每次模拟成交单独记账；动态资金分配。
- 仅模拟 1–5 倍杠杆，系统自动建议且允许人工在风险门禁内调整。每次模拟开仓必须有结构性止损；单仓、组合、相关性、同方向集中、保证金及极端行情风险共同约束。
- 模拟成交考虑盘口/价差、手续费、滑点、流动性、资金费及时间；数据不足标记成交不确定，不能“触价即成交”或凭空释放资金。
- 独立结构信号与风险复核后才可模拟加仓；结构转弱可动态比例减仓；确认失效后保守模拟平仓；强反向信号必须先确认旧仓位关闭，再独立校验新方向。
- 动态止损由量化定价和风险执行、AI 提供结构判断；每 **15 分钟**及关键事件复核，止损触发检测不依赖 AI 周期。结构显著变化可收紧或放宽止损，但放宽须重新通过风险门禁，不能撤销已触发的止损；普通调整设冷却，紧急风险不受冷却。
- 模拟账本展示权益、已实现/未实现盈亏、毛/净收益、手续费、滑点、资金费、回撤、风险调整指标、持仓和版本对比。**仅保留最近 100 条完整模拟订单明细**；更久保留经核验的按日权益/收益/回撤/成本/版本聚合，不能伪造已淘汰订单的逐笔轨迹。账户重置至 2,000U 仅经人工确认并开启新周期，旧周期聚合不清除。

## 7. Telegram 仅为通知通道

- **不建第二套信号库**。消费信号中心和模拟账本事件，使用事件 ID 做幂等入队/去重。
- 推送多空高优先级趋势信号；模拟开仓、加仓、减仓、止损调整、止盈、止损、平仓、反转及风险事件。**所有模拟事件显著标注“模拟盘”**。
- 重要模拟开仓、平仓、止损、反转、重大风险立即推送；普通加减仓及止损调整短时间聚合，内部事件不丢。
- 网络恢复后按时间补发重要事件、普通事件发汇总，并明确事件发生时间和补发时间；趋势信号冷却不影响模拟盘风险通知。
- 通知链路 `event → queue → request → Telegram API response` 接入数据监控，记录延迟、积压、重试、故障、恢复、发送状态；API 接受不等于用户已读。只保存必要投递元数据和审计引用，不另外重复保存业务信号全文。

## 8. 历史回放、策略实验室与升级门禁

- 独立回放页按历史可获得时间重演信号、AI/量化证据、K 线、模拟结果；严格区别完整报告/订单已过期时只能展示聚合摘要。
- 全系统评估方向正确性、提前量、入场/目标/失效、持续时间、风险、误报、样本量、市场阶段、AI 主审/复核/量化/联合贡献与成本。
- 策略分析下独立实验室；并行实验可配置、默认 **3**，生产扫描资源优先；Walk-Forward 加最后独立未触碰样本外测试。统一固定验收门槛，不因策略类型自行放宽；样本不足判“待积累”，不伪造通过或失败。
- 历史验证通过后还必须经过实时市场模拟验证与人工批准，才能启用新的**研究策略版本**；任何优化仅生成候选方案，禁止自动改动正式策略。保留版本、参数、对比、回滚、审批与审计。

## 9. 异常、幂等与一致性

1. 数据缺失/延迟：标记质量、隔离受影响分析、补齐并验证后恢复；历史决策不被事后改写。
2. AI/复核失败：量化降级、记录分歧；无复核不能冒称已复核。
3. 信号失效：状态事件入库，首页、模拟盘和 Telegram 各自按同一事件消费；模拟退出须遵循保守成交。
4. 模拟订单待成交：锁定相应资金/仓位状态直至核实，避免双花和超过 10 仓。
5. 消息队列/Telegram 中断：outbox、幂等键、可观测重试、补发摘要；重启从检查点恢复。
6. 策略版本变更：先实验、独立样本外、模拟验证、人工批准、可回滚；所有历史关联旧版本。
7. 对账：信号事件、模拟账本、通知投递、前端展示通过 ID 和版本核对；任何差异报警，不默默覆盖。

0. **首模块前置 UI 设计验收**：全新玻璃质感可运行交互原型、真实测试和用户确认；未通过不能进入模块 1 功能施工。

2. 专业技术分析：图表交互、指标、绘图层、证据联动。
3. 历史数据：热冷存储、缺口、回补、覆盖热力图、PIT 时间语义。
4. 全市场扫描：市场覆盖、来源回退、方向独立、五分钟排名。
5. 市场行为分析：可证伪结构规则、证据/反证。
6. AI 趋势分析：主审/复核、量化仲裁、15 分钟及事件触发。
7. 智能观察池：双标签状态、晋升降级、通知消费。
8. 历史行为画像：市场阶段、数据覆盖、样本边界。
9. 模拟仓位与风险核算：2,000U/10 币种、动态止损、完整对账。

模块编号仍按既有十模块路线图；上述第 0 项是设计前置门禁，不是第 11 个模块。**跨模块接口可先定义契约，不等于提前实施后续模块。** 每模块提交 SHA、修改清单、可复现测试、真实运行证据、未测项、回滚与用户验收；未经批准不合并 `main`，不删除旧 PR/证据。

## 12. 验收矩阵：至少应覆盖的端到端场景

- E2E-01 新币上市/交易所无合约：正确选源、标记真实覆盖、无伪造跨源历史。
- E2E-02 缺 K 线/衍生品历史：受影响信号降级、回补校验、PIT 历史结果不变。
- E2E-03 观察→共振→失效：唯一 signal_id、版本事件、首页和通知一致。
- E2E-04 多空独立：同币双方向候选分离，排名与通知方向正确。
- E2E-05 AI 主审失败/复核冲突：量化仲裁、无虚假“AI 已验证”。
- E2E-06 同事件重复投递/重启：无重复信号、模拟订单或通知。
- E2E-07 模拟止损/减仓/反转：先平后开、保守成交、10 仓与保证金约束。
- E2E-08 Telegram 断网恢复：重要补发、普通汇总、延迟/失败可追踪。
- E2E-09 100 条报告与订单保留边界：旧摘要可查，旧全文不可虚构。
- E2E-10 回测时间隔离与实验室门禁：未来数据不可用，样本不足不通过，未批准参数不得生效。
