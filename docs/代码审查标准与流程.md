# 代码审查标准与流程（WX-CODE-REVIEW v1.0）

- 生效日期：2026-10-20
- 适用工程：`威科夫因子共振趋势`（策略 / 回测 / 账本 / 前端 / 采集）
- 配套门禁：`tools/code_review_check.py`（可执行，非纸面条款）
- 制定依据：本工程 2026-10 以来真实发生的 9 类事故（见 §0.2），不是通用模板

---

## 0 为什么要这套东西

### 0.1 一句话

**本工程最贵的错误不是"代码写错"，而是"代码跑通了、数字出来了、但数字的来源不可追溯"。**
所以审查的第一目标不是找语法错，是**确认每一个数字都能回到一个可复现的输入、一个可解释的公式、一个可查的产物**。

### 0.2 已发生的九类事故（每条都对应一条硬规则）

| # | 事故 | 后果 | 对应规则 |
|---|---|---|---|
| 1 | `01_evaluate_hypotheses.py:90` 用 `timestamp < entry_ms` 取"最后一根 1h" | 读到未收盘 bar，110 笔"放量下跌"结论被污染 | **R1 PIT** |
| 2 | `backtest_store._summary_to_run_doc` 对无 `run.json` 的目录在**读取时**合成 run 文档 | 1195 个运行的 `created_at` 全等于读取时刻、`config` 是硬编码 | **R2 禁止读时兜底** |
| 3 | 7 个根目录批量脚本自己拼 `chart.json` | 344 份 `signals=[]`、`trade_id=null`，UI 画不出信号 | **R3 禁止绕过写入口** |
| 4 | 旧 `ledger.py::__init__` 里 `if path.exists(): path.unlink()` | 会删掉已有账本 | **R4 禁止删除既有产物** |
| 5 | `VOLUME-BE-01` 缩量 11 笔与 `VOLUME-BE-02` 缩量 14 笔只重叠 1 笔 | 同一概念两套实现，结论互斥 | **R5 单一实现** |
| 6 | 同一份报告里 47.9% 用 201 口径、+0.27 用 206 口径 | 数字看着都对，结论是拼的 | **R6 口径成对** |
| 7 | `trades_count=0` 但 `net_pnl≠0`、或 `wins=null` 被当成 0 | 前端显示假指标 | **R7 缺失即 null** |
| 8 | 14 笔样本（n=14）被写成"胜率高达 71.4%" | 置信区间 [41.9%, 91.6%] 覆盖基准，结论不成立 | **R8 统计门槛** |
| 9 | 回测产物 2125 个目录、实验登记库 0 条业务记录 | "跑过"与"登记过"脱节 | **R9 产物必登记** |

### 0.3 审查的三个目标（按优先级）

1. **可追溯**：每个数字能回到产物文件的具体行。
2. **可复现**：换一个人、换一台机器，同一条命令出同一个数。
3. **可证伪**：结论写清了"什么情况下它不成立"。

## 1 适用范围与角色

### 1.1 必须走审查的改动

| 类别 | 举例 | 最低级别 |
|---|---|---|
| 策略逻辑 | `event_trend_v0_1/`、`oi_resonance_v1/`、`trading_core/` | **P0 双人** |

| 回测写入口 | `backtest_store.py`、`backtest_runner.py` | **P0 双人** |
| 对外 API 契约 | `backtest_api.py`、`api/` | **P1 单人 + 契约核对** |
| 前端数据层 | `src/api/*.ts` | **P1 单人 + 真实响应核对** |

| 文档 / 报告 | `evidence/<工单>/*.md` | **P1 数字复核** |
| 批量跑数脚本（根目录） | `run_batch_*.py` | **P0 双人**（历史事故高发区） |

### 1.2 角色

| 角色 | 职责 | 不能兼任 |
|---|---|---|
| 作者 | 写代码 + 写自检 + 提供复现命令 | 不能给自己签字 |
| 审查者 | 按 §5 清单逐条打勾，提 P0/P1 | 不能是同一人 |
| 复核者 | 只对 P0 改动做第二遍，重点看"结论是否被夸大" | 不能是作者 |
| 验收者 | 跑门禁 + 核对产物落盘 | 可兼任审查者 |

**单人项目的现实处理**：作者与审查者可以是同一个人，但**必须换一个时间窗**（隔至少一次会话），并且必须**先跑门禁再看结论**，不许边写边自我确认。

## 2 问题分级

| 级别 | 定义 | 处理 |
|---|---|---|
| **P0 阻断** | 会导致数字错误、结论反转、产物丢失、账本被删 | 必须修，修完重跑，不许"下次再说" |
| **P1 必修** | 会导致不可复现、口径混用、契约漂移 | 本 PR 内修，或开单并写进 `待办` |
| **P2 建议** | 可读性、命名、重复代码 | 记录，不阻断 |

**判定口径**：只要这条改动会让"某个已发布的数字"变化，就是 P0。

## 3 十二条硬规则

> 每条都给出：规则、反例、怎么查。能自动查的已写进 `tools/code_review_check.py`。

### R1 · PIT：只能用决策时刻已闭合的数据

- **规则**：任何进入决策的特征，只能读 `close_time <= decision_time` 的行。判断"哪根 bar 是最后一根"必须用 **`close_time`**，不许用 `timestamp` / `open_time`。
- **反例**：`df_1h[df_1h["timestamp"] < entry_ms]`（入场 03:15 会取到 03:00 那根未收盘 bar）。
- **正确**：`df_1h[df_1h["close_time"] <= entry_ms]`。
- **附加**：如果一根 bar 没有 `close_time` 列，**必须显式推导**（`open + 周期`）并写注释，不许默认"timestamp 就是收盘"。
- **怎么查**：`rg 'timestamp.*<\s*(entry|decision|signal)'`；门禁 `PIT-01`。

### R2 · 禁止读时兜底（read-time fabrication）

- **规则**：读接口只返回落盘里**真实存在**的字段。缺失 ⇒ `null` + `missing_reason`。**不许**用 `utc_now_iso()`、`0.005`、`"succeeded"` 这类默认值把空补满。
- **反例**：`"created_at": sm.get("created_at") or utc_now_iso()` ⇒ 1195 个运行的创建时间全一样。
- **反例**：`"risk_budget_per_trade": 0.005` 写死在合成函数里 ⇒ 界面显示的参数不是实际跑的参数。
- **正确**：`"created_at": sm.get("created_at")`；前端显示"未记录"。
- **怎么查**：门禁 `FAB-01/02/03`。

### R3 · 禁止绕过唯一写入口

- **规则**：`run.json` / `chart.json` / `trades.jsonl` 只能由 `backtest_store` 写。批量脚本只允许**调用** `execute_run`，不许自己拼这些文件。
- **反例**：根目录 7 个 `run_batch_*.py` 手拼 `chart.json` ⇒ `signals` 全空。
- **怎么查**：`rg 'chart\.json' --glob 'run_*.py'`；门禁 `BYPASS-01`。

### R4 · 禁止删除既有产物

- **规则**：任何 `unlink` / `rmtree` / `rm -rf` 之前，路径必须在白名单内，且必须显式确认。账本、`evidence/`、`回测日志/` 一律只增不删。
- **反例**：`if self.path.exists(): self.path.unlink()`。
- **怎么查**：门禁 `DEL-01`。

### R5 · 同一概念只能有一个实现

- **规则**：PIT 读取、成交取整、均量计算、去重主键，各自只能有**一处**权威实现，其它地方 import 它。
- **反例**：缩量标签两套实现（11 笔 vs 14 笔，重叠 1 笔）。
- **反例**：逐笔匹配用 `(pair, open_timestamp)` 而不是 `enter_tag`。
- **怎么查**：人工 + `rg` 同名函数多处定义；门禁输出"同名函数多文件定义"清单供人工判。

### R6 · 口径必须成对出现

- **规则**：任何比例/占比，必须在同一句里写清**分子分母同属哪个口径**（206 候选 / 201 事件 / 296 唯一交易）。跨口径拼数视为 P0。
- **反例**："14 笔贡献 47.9%，单笔期望 +3.61 vs 基准 +0.27"（47.9% 是 201 口径，+0.27 是 206 口径）。
- **正确**："201 事件口径：+3.61 vs +0.52；206 候选口径：占 91.4%"。
- **怎么查**：人工；报告类改动必须逐句核对。

### R7 · 缺失即 null，不用 0 冒充

- **规则**：指标算不出来 ⇒ `null` + 原因。`wins` 不知道就是 `null`，不是 `0`。`net_pnl` 为 0 且 `trades_count` 为 0 是合法状态，但两者必须同时成立。
- **怎么查**：门禁 `NULL-01`（`or 0` / `else 0` 在高风险函数内）。

### R8 · 统计门槛

- **规则**：
  - `n < 30`：只能写"描述"，不能写"显著"、"证明"、"有效"。
  - 任何胜率/命中率必须同时给 **n** 和 **95% 区间**（Clopper-Pearson）。
  - 多重比较（>1 组对照）必须给校正后的 p 值。
  - 结论必须写"本结论不成立的边界"。
- **反例**：n=14 写"胜率高达 71.4%"。
- **怎么查**：人工（报告审查清单第 4 项）。

### R9 · 产物必登记

- **规则**：每一次回测必须同时落三样东西：`run.json`（状态+规格+哈希）、`manifest.json`（逐文件 sha256）、逐笔产物（`trades/orders/fills`）。
- **判定**：目录存在但无 `run.json` ⇒ 该运行**不算已记录**，UI 不得显示为"已完成"。
- **怎么查**：门禁 `REG-01..04`。

### R10 · 状态不得冒充

- **规则**：`interrupted` / `failed` / `unknown` 不许在展示层被写成 `succeeded`。进程重启后的遗留 `queued|running` 必须标 `interrupted` 并保留原因。
- **反例**：合成函数里 `"status": STATUS_SUCCEEDED` 写死。
- **怎么查**：门禁 `FAB-03`。

### R11 · 成本必须计入

- **规则**：任何"净收益"必须写明含哪些成本：双边手续费、滑点、资金费、价格取整。缺一项就必须在字段名或注释里标出来。
- **反例**：`ACCUM-STRAT-01` 原研究只有"双边手续费 0.2%"，无滑点/资金费/取整。
- **怎么查**：人工（报告审查清单第 5 项）。

### R12 · 自检不等于验证

- **规则**：程序自己写的 `reconcile_ok` / `identity.chain_ok` 只能当"内部一致性"证据，不能当"结果正确"证据。写结论时必须标明这一点。
- **怎么查**：人工（看有没有把自检当独立证据）。

## 4 审查流程（五个关卡）

```
① 提交前自检  →  ② 自动门禁  →  ③ 人工评审  →  ④ 复核（仅 P0）  →  ⑤ 合并与留痕
```

### 关卡 ① 提交前自检（作者）

作者在开 PR 前必须填完本规范附录 A（§5.1 提交前自检清单），并把结果贴进 PR 描述。
**自检不通过不许提 PR。**

### 关卡 ② 自动门禁（机器）

```bash
python tools/code_review_check.py --root . --out evidence/CODE-REVIEW-01/out
```

- 退出码 `0` = 无 P0；`1` = 有 P0，**不许合并**。
- 输出 `out/check_report.json` + `out/check_report.md`。
- 门禁只覆盖"能机械判定"的部分，**通过门禁不等于通过审查**。

### 关卡 ③ 人工评审（审查者）

按 §5.2 清单逐条打勾。重点不是看代码写得漂不漂亮，而是问四个问题：

1. 这个数字从哪来？（能不能指到文件:行）
2. 换一台机器跑，会不会不一样？（种子、时区、浮点、路径）
3. 缺数据时它返回什么？（null 还是 0 还是默认值）
4. 这个结论在什么情况下不成立？（有没有写）

### 关卡 ④ 复核（仅 P0）

复核者只看三件事：
- P0 是否真修了（不是注释掉）；
- 修完后**已发布的数字有没有变**（变了必须解释）；
- 结论有没有被悄悄放宽（"可能"变"证明"）。

### 关卡 ⑤ 合并与留痕

合并前必须存在：

```
evidence/<工单号>/
  00_报告.md           结论 + 边界 + 不成立的情况
  01_复算.py           能独立重算关键数字
  02_复算输出.txt       实际跑出来的输出
  03_实际命令.md        一行能复制的命令
  hashes.txt           输入/产物 sha256
```

**没有 `01_复算.py` 的研究结论，一律标"未独立复算"。**

## 5 三张清单

### 5.1 提交前自检（作者填，10 项）

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 我改的文件属于哪一类（§1.1）？ | 写清类别和级别 |
| 2 | 有没有新增/修改 PIT 读取？ | 全部用 `close_time <=`，并贴出代码行 |
| 3 | 有没有新增默认值兜底？ | 没有 `or 0` / `or utc_now()` / 硬编码 config |
| 4 | 有没有删文件/删目录？ | 没有；有则写明路径和白名单依据 |
| 5 | 新概念是否复用了已有实现？ | 贴出 import 路径 |
| 6 | 结论里的每个数字，分子分母同口径吗？ | 逐句核对过 |
| 7 | n 是多少？区间是多少？ | 报告里写了 |
| 8 | 成本含哪几项？ | 手续费/滑点/资金费/取整 逐项写明 |
| 9 | 复现命令能不能一行跑通？ | 自己跑过一遍 |
| 10 | 门禁跑了吗？ | `exit 0`，贴输出 |

### 5.2 人工评审清单（审查者填，15 项）

**A. 正确性（5 项）**
1. 时间语义：所有 `close_time` / `available_at` 判定是否一致？
2. 边界：空数组、单根 bar、除零、NaN、`None` 各有明确分支？
3. 浮点：金额比较是否用容差？是否用 Decimal 做取整？
4. 并发：共享状态是否有锁？线程/进程重启后状态是否可恢复？
5. 幂等：重复执行同一请求，结果是否一致？重名是否拒绝而非覆盖？

**B. 可追溯（4 项）**
6. 每个对外字段，能否指到落盘文件的哪一行？
7. 缺失字段是否返回 `null` 而非默认值？
8. 产物是否有 `manifest.json` + sha256？
9. 状态机是否只有合法迁移？有没有 `succeeded` 被写死？

**C. 口径与结论（4 项）**
10. 分子分母同口径？
11. n 与置信区间是否给出？
12. 有没有把"自检通过"写成"结果正确"？
13. 结论的失效边界写了吗？

**D. 工程卫生（2 项）**
14. 有没有 `except: pass` 吞掉异常？
15. 有没有绕过唯一写入口（手拼 json、直接写 runs 目录）？

### 5.3 合并前检查（8 项）

1. 门禁 `exit 0`
2. 自检表已填
3. 评审清单已填
4. P0 已复核
5. `evidence/<工单>/01_复算.py` 存在且能跑
6. `hashes.txt` 已生成
7. 提交信息符合 `feat(scope): 中文`
8. 只提交显式文件清单（禁止 `git add .`）

## 6 自动化门禁能查什么、不能查什么

### 6.1 能查（已实现）

| 编号 | 检查 | 判定 |
|---|---|---|
| `PIT-01` | `timestamp < entry/decision` 写法 | P0 |
| `DEL-01` | `exists()` 后 `unlink()` | P0 |
| `FAB-01` | `or utc_now_iso()` 等读时时间兜底 | P0 |
| `FAB-02` | 合成函数里的硬编码参数 | P0 |
| `FAB-03` | 硬编码 `STATUS_SUCCEEDED` | P0 |
| `BYPASS-01` | 根目录脚本手拼 `chart.json` | P0 |
| `ERR-01` | `except: pass` | P1 |
| `REG-01` | run 目录缺 `run.json` | P0 |
| `REG-02` | `trades_count>0` 但 `trades.jsonl` 空 | P0 |
| `REG-03` | `trades.jsonl` 空但 `net_pnl≠0` | P0 |
| `REG-04` | 缺 `manifest.json` | P1 |
| `REG-05` | 多个 run 的 `created_at` 完全相同 | P1 |
| `DUP-01` | 同名函数在多个文件定义 | P2（供人工判） |

### 6.2 不能查（必须人工）

- 口径是否同源（R6）
- 结论是否被夸大（R8）
- 成本是否完整（R11）
- 自检是否被当独立证据（R12）
- 业务语义是否正确（比如"放量"到底指哪根 bar）

## 7 记录与留痕规范

### 7.1 命名

- 工单目录：`evidence/<工单号>/`，工单号全大写+连字符（`VOLUME-BE-02`）。
- 报告：`00_报告.md`；复算：`01_复算.py`；输出：`02_复算输出.txt`；命令：`03_实际命令.md`。
- 日期日志：`.workbuddy-ai/memory/YYYY-MM-DD.md`（只追加）。

### 7.2 哈希纪律

- **版本只认文件 SHA-256，不认 Git HEAD。**
- 哈希由脚本算、落盘，**不手写**。
- 引用上游产物前，先记 `source_hashes_start.json`；写结论后再记 `source_hashes_end.json`；两者不一致 ⇒ 结论作废重跑。

### 7.3 提交纪律

- 格式：`feat(scope): 中文`、`fix(scope): 中文`、`docs(scope): 中文`。
- 使用**显式文件清单**，禁止 `git add .`。
- 78G 工程禁止全盘 `grep -r` / `find -exec shasum`。

## 8 例外处理

| 情况 | 处理 |
|---|---|
| 时间紧，P1 来不及修 | 开单 + 写进 `待办`，PR 描述里显式标注"已知 P1 未修" |
| P0 确实改不动（外部依赖） | 降级为"隔离"：在入口加硬拦截，让问题不可达，而不是放着 |
| 门禁误报 | 在脚本里加白名单并写明理由，**不许直接 `--no-verify`** |
| 研究结论与门禁冲突 | 以数据为准，但必须在报告里写清冲突点 |

## 9 审查有效性的度量

每季度看四个数：

| 指标 | 目标 | 说明 |
|---|---|---|
| P0 逃逸数 | 0 | 合并后才发现的数据错误 |
| 返工率 | < 20% | 因审查意见需要重跑的比例 |
| 复算覆盖率 | 100% | 有多少研究结论配了 `01_复算.py` |
