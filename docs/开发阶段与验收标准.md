# 开发阶段与验收标准（候选版）

> 此文档用于约束开发顺序与证据要求；任何阶段标注“通过”前，必须有实际验证证据及用户确认。

## 一、不可跳过的起始阶段：全新 UI 设计

先提交可运行、可点击、可交互的玻璃质感专业技术分析终端原型，供用户审查页面结构与操作体验。

至少展示：
- 代币选择和 8 个指定周期切换；
- K线主图区、成交量和技术指标控制；
- 结构标记及其图表关联；
- 持仓量、资金费率、多空比等衍生品区域（可使用明确标注的演示数据）；
- 研究假设、支持证据、反面证据和失效条件；
- 不同宽度下的布局、文字可读性、交互反馈与空状态；
- 数据真实性标识，避免把演示数据误认为实时行情。

**设计验收门槛**：交付可访问原型或真实可运行预览、完整交互清单、截图、已知限制和实际测试记录；用户明确确认设计后方可进入第一模块的功能施工。仅静态效果图、无法运行的内联可视化、或原简易页面换皮，均不通过。

## 二、后续模块顺序（名称暂定）

| 顺序 | 工作范围 | 最低验收要点 |
| --- | --- | --- |
| 一 | 项目启动与基础行情 | UI 先验收；程序可启动/重启；真实币安永续K线可切换交易对与周期；成交量与K线对应；接口失败有中文提示；无伪造数据 |
| 二 | 专业技术分析 | 缩放、拖动、十字光标、指标参数、绘图和结构标记可用；关键计算有基准测试 |
| 三 | 历史数据 | 数据来源、时间戳、缺口、断点续传和历史完整性报告；缺失明确标注 |
| 四 | 全市场扫描 | 覆盖目标与实际数量可核验；币安优先、OKX有条件回退；去重、限流、异常恢复 |
| 五 | 市场行为分析 | 每种假设有规则、支持与反对证据、失效条件和可重放样例 |
| 六 | 人工智能趋势分析 | 选择性触发；可追溯输入、模型版本、输出时间；数据不足时降级而非编造 |
| 七 | 智能观察池 | 手动与自动添加、状态变更记录、去重提醒、异常恢复 |
| 八 | 币种历史行为画像 | 长短期行为区分；样本量、覆盖时段、历史缺失和不确定性明确 |
| 九 | 模拟仓位与风险核算 | 仅模拟；费用、滑点、资金费率与资金曲线计算可复核 |
| 十 | 历史回放与预测评估 | 严格历史可获得时间；样本外评估；提前量、误报、覆盖率与稳定性统计 |

以上顺序不是批准所有模块立即施工；每个模块必须逐项解锁。

## 三、每一模块的交付包

1. 变更范围：明确本次改动文件、模块边界、未改动内容。
2. 代码定位：仓库、分支、提交 SHA、拉取请求地址；如有生成产物附校验值。
3. 可复现步骤：依赖、启动命令、测试命令、环境约束。
4. 证据：真实执行日志、自动测试、手动操作记录、截图或录像、异常路径。
5. 数据核验：真实/演示/缺失标识、来源、时间、覆盖范围；不得凭截图推断数据正确。
6. 风险与限制：已知缺陷、未测项、外部服务约束、回退方案。
7. 独立复核：验证功能、边界、回归、数据准确性；区分“实现了”与“已证明有效”。
8. 用户验收：用户确认后记录结论，未确认不视为通过。

## 四、裁决状态

- **通过**：全部强制验收条件满足，证据充分，用户明确认可；允许进入下一模块。
- **条件通过**：局部达标但仍有未关闭条件；不自动解锁下一模块。
- **返工**：存在明确缺陷或违反范围、数据、交互要求。
- **证据不足**：无法复现、缺少测试、运行失败或仅有口头声明；不视为通过。

禁止用“代码已提交”“页面已截图”“测试文件已存在”代替测试通过。

## 五、进度汇报

每次验收、裁决、进度报告附：
- 整体工程进度**估算百分比**及相对上次变化；
- 估算依据、尚未完成的门禁；
- **实际测试覆盖率**（如未统计则写“未统计”，不能以工程进度替代）；
- 当前允许施工的模块与禁止施工的模块。

## 六、合并与保护

- 使用独立分支及待审核拉取请求交付，未经用户单独批准不得合并 main。
- 保留历史证据、旧拉取请求和未验收成果；不得擅自删除。
- 涉及策略参数、数据定义、接口契约或范围的变化，先提出差异与影响，再取得批准。
- 不得以其他旧项目的代码、测试或数据作为本项目已验收的证明。
