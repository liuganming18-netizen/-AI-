## 一、真实数据接线与时点隔离

现场证据：`框架/backend/unified_runtime.py` 仍向 `process_1h_bar` 传入两个空持仓量数组；`state_machine.py` 在 `oi_available_at is None` 时才注册持仓量。新增 `oi_feed.py` 尚不代表完成接线。

1. 复用现有持仓量读取器，在实际研究判断路径中读取真实数量并更新到状态机。核验首次为空、后续到达数据，及连续决策时序列更新这两类情况。不能沿用首次注册的空或过时缓存。
2. 区分原策略既定持仓量条件与新方案的持仓量角色。接线、记录和原条件正确计算已经授权；新方案是否一票否决仍是研究待决，不能借此停止接线，也不能取消原条件。
3. `oi_feed.py` 当前以抓取时间非空判断 `available_at_proven`，但未比较抓取时间与决策时间。修正为逐条检验已知的可用时间；未知、晚到、修订数据分别标记。仅有事件时间不得自动证明历史可得；批量补抓时间也不得伪装成原始发布时间。无法证明的历史仅用于明确标记的探索研究，不进入严格防未来数据对照成绩。
4. 核查五分钟持仓量时间戳究竟代表观测时点还是区间起点，并附原始来源依据；不得未经核实统一加五分钟。单位同样追溯原始来源，不能混用张数、币数和美元价值。
5. 主动买卖、三类多空比、阶段均价须进入每个观察事件的结构化证据记录，记录实际读取值、时间范围、来源和缺失情况。实现计算/记录不需要先批准入场阈值；不得留在“库里有但未参与”的状态。
6. 提供至少一次真实数据从读取器→判断调用→事件记录的可复现追踪，以及晚到、缺失和恢复后的反例。持仓量非空样本本身不能证明端到端完成。
7. 修复报告与原始输出不一致：旧 README §4.1 声称手工重新注册后读出增长率 -0.00863777，但 `out/03_持仓量核验.json` 对应字段实际为 null，状态为观测过期一小时。保留该失败证据，重新提供同一次运行、同一决策时点的结果，不得只修改报告数字。

## 二、修复回放计算

现场证据来自 `evidence/ACCUM-EARLY-01/scripts/07_事件回放构建.py`，原产物保留，新结果写入独立版本目录。

1. 当前 `stop0` 使用原始开盘价，而含滑点成交价在后面计算。统一由最终模拟成交价计算初始止损、持仓数量、实际名义额与手续费；符合既定价格和数量精度规则。不同滑点研究口径各自完整执行，不仅在末尾改盈亏公式。
2. 当前预先构造未来三十天止损路径，页面包含平仓后的上移记录。按持仓生命周期截断展示及账本，平仓后不得继续生成该持仓止损。不要未经证据断言当前退出计算已使用未来止损；分别核验计算与展示。
3. 当前资金费为“费率合计×入场名义额”。改为按每次真实结算事件、对应持仓数量、该结算所需标记价格及合约计价规则逐笔核算，保留付款/收款符号与依据。缺失不得填零；十五分钟内退出与结算先后无法确定的，标记不确定并补更细证据或排除严格核对。
4. 参与率未通过的样例不得仍计为正常全额成交。遵循已有获批执行规则拒单或缩量；若缩量规则未批准，记录拒单/无法确认，不能替用户新增缩量规则。可保留假设全额结果，但与可执行结果严格分列，不计入策略成绩。
5. 窗口末尾尚未触发退出的持仓只计未实现估值，不记平仓、不扣尚未发生的退出手续费。估值时间使用实际取价时间，不能使用收盘价却记录为该根开盘时刻。
6. 初始止损退出与跟踪止损退出分类准确。四小时新止损只向后生效；跳空和盘中触及分开核验。
7. 跳空成交模型如缺批准依据，可交付独立敏感性对照及推荐理由，不自行替换生产模型；这不阻塞上述已经确定的计算错误修复。历史模型和修复模型结果均保留。
