# 策略研究与冻结验收规范

版本：1.0 候选；编制日期：2026-11-10。适用项目：AI 加密货币趋势研究系统。

本规范把研究方向、逐步验收、冻结版本和资源上限放在同一处。研究必须能够结束；“未找到可靠优势”是可接受的研究结论，不能为了得到盈利结果无限追加试验。已经完成并验收的数据、代码与结论直接继承。

本文件是根目录 README 所定义工程主线的研究细则，不另建或重排七个工程阶段。当前交付为规范文档；本机数据访问、配额拦截、冻结保护及业务回测是否实际实现，必须由相应工单另交实测证据，不能把文档提交写成程序已生效。

## 1. 已确认边界与本轮新增规范

### 1.1 必须继承的决定

- 使用已封存、已有合法读取权限的全市场 USDT 永续历史资产；Binance 为主源，OKX 按已确认规则独立补充。保留历史退市合约、失败和缺失记录，不跨所静默拼接。
- 数据已经封存。继承现有清单、版本、校验值及有效验收；环境读不到文件只处理访问问题，不重新安排采集、封存、打包或全量审计。
- 研究潜在吸筹早期、中期、末期的事前识别；普通横盘、下跌中继、派发、失败突破是必需对照。看涨优先，看跌按同一规范单独登记、单独统计。
- 日线提供背景，1h/4h/8h分析结构，5m只用于入场定位；不得把5m作为方向判断主依据。8h遵守已确认的币安原生约束。
- AI负责结构假设、反证与分析，程序负责可复算计算与验证，量化风险规则独立且不可绕过。
- 既有工程阶段串行推进。上一步完成、独立验收通过并获用户确认后，才解锁下一项。研究细则不授予账户写权限、部署权限或全量数据清理权限。
- 中文界面和中文验收；Ticker、标准技术字段可保留英文。既定UI布局不因本规范变更。

### 1.2 数字的效力

本文件中的实验数量、容量、保留天数、置信水平是本轮提出的可执行默认建议，不是已运行设置或行业统一合格线。研究登记时依据现有设备余量和研究目标一次确定，并随版本冻结。若已有经用户确认的更严格预算，沿用已有预算。

收益目标、最大回撤、单笔风险、最低有效样本量等未确认参数不得擅自填成“已批准”。登记表缺少这些必需数值时，可以完成规范编制，不能启动需要这些参数的正式筛选或宣布策略通过。

## 2. 标准化研究方向

研究主问题固定为：

在当时可得的量价、持仓量和资金费等证据下，能否识别潜在吸筹的早、中、末期；不同阶段分别付出多少误报、等待时间和回撤，换来多少提前量及成本后价值？

“吸筹”“派发”是待证伪行为假设，不把主观意图作为可直接观测的真值。每个研究批次只能围绕一个登记问题，采用固定数据版本、有限候选和固定结束条件。

| 方向 | 可操作的研究对象 | 必须有的对照 | 不能偷换成的结论 |
| --- | --- | --- | --- |
| 早期 | 下跌压力减弱、初步承接等当时已出现的组合证据 | 继续下跌、短暂反弹、无效横盘 | 事后完整底部的前1/3就是可提前识别的早期 |
| 中期 | 箱体持续、回踩和承接等逐步积累的证据 | 普通震荡、下跌中继、派发 | 横盘或OI增加就一定吸筹 |
| 末期 | 在预先约定“尚未明显启动”边界内出现的确认性结构 | 假突破、结构失效、向下选择 | 涨幅已出现后再把已启动样本改名为启动前 |
| 看跌 | 单独登记的潜在派发及下跌启动结构 | 上涨中继、假跌破、重新承接 | 把看涨规则简单取负就视为验证完成 |

早、中、末期的具体判定必须写成可执行谓词或状态转移，阈值只在开发区间确定。状态可以不确定、退回或失效，不要求每段行情强行分成三个阶段。事后区间长度不能作为实时阶段的输入。

观察单位以“交易所、合约、方向、独立机会区间”为基础；同一行情内多根K线的重复触发不能冒充独立样本。首次机会与二次机会分别统计。初期工程读样本可以用少量币验证接口，但不能据此宣称完成全市场研究。

## 3. 八步研究流程与逐步验收

以下R01—R08是研究子步骤，不是新的工程阶段。R01—R04属于工程阶段04的研究范围；R02继承阶段02/03的合格数据证据。R05—R07在工程阶段06解锁后执行，阶段05的既定服务/UI位置不变。R08负责结案及向阶段07交接，不自动解锁阶段07。

| 步骤 | 必交结果 | 必需验收标准 | 通过后冻结 |
| --- | --- | --- | --- |
| R01 研究登记 | 一份研究卡、候选表、指标与预算表 | 研究问题、方向、数据版本、历史可见性模式、主指标、风险限额、最低证据量、时间划分、候选数、调用/计算/存储预算、截止时间、停止条件全部具体；不能留“效果好再说” | 研究问题、评判标准、数据划分规则、候选空间、预算 |
| R02 数据准入 | 继承清单、真实读取证明、按用途划分的数据视图与覆盖表 | 原始数据只读；读到真实K线/OI/资金费及所需字段；时间和单位正确；覆盖分母含历史合约；缺失与修订显式；输入、训练/开发验证/最终盲测身份明确；未知可得时间不能冒充严格历史 | 数据对象引用、快照清单、质量规则、排除清单、时间切分 |
| R03 定义阶段和证据 | 阶段谓词、特征代码、事后标签、正反例 | 修改未来数据不能改变过去特征/判断；未收盘高周期数据不能提前使用；标签在独立命名空间且不向策略暴露；相同输入得同一结果；保留无信号与失败样本 | 阶段/特征/标签定义、单位、观察窗口、代码与依赖 |
| R04 有限候选研究 | 所有候选的开发区间比较、量化对照、AI设计、淘汰记录 | 只在登记的开发数据上发现和选择候选；所有参数、模型、提示词尝试登记；数量/时间/费用不超预算；分母与失败完整；仅产生初验候选，不宣称最终样本外有效 | 候选代码、参数、比较方案、AI输入/模型/提示词、入围名单 |
| R05 回测程序验收 | 历史时钟、成交/费用/资金费/权益的可复核用例与真实数据小规模重放 | 未来数据访问被拒；收盘信号不能在同根取得更优成交；同根止盈止损顺序按预登记保守规则或可得更细数据；费用、资金费、未实现损益与权益一致；重复事件不重复变账；运行与回测状态隔离 | 回测与风控代码、成交语义、成本表、精度、随机种子、环境锁文件 |
| R06 滚动样本外评估 | 冻结配置的时间滚动结果、统一基准、AI增量对照和压力情景 | 按时间前推，各币种采用同一日历边界；跨界标签/持仓依赖清除或隔离；预处理只拟合训练段；报告全部预登记时间折和失败；相同风险条件下比较AI前后 | 每折输入/拟合产物/输出、候选去留、最终盲测运行计划 |
| R07 最终盲测与独立复现 | 封存测试区间的固定计划结果、完整回测事件/交易明细、独立核验 | 候选/规则/指标在开封前锁定；只运行预登记矩阵；测试集不用于再选择参数；独立审核者按锁定代码和快照复算关键指标及事件；统计标准满足才可称策略通过 | 最终结果、完整证据、代码提交与标签、数据/配置/环境哈希、裁决 |
| R08 结案与冻结交接 | 一份结案回执、冻结清单、资源清理回执、后续准入状态 | 明确“候选有效／候选无效／证据不足”；已完成步骤和未执行步骤如实记录；执行已授权缓存/临时文件清理并核实保护对象；确认预算与恢复引用；下一模块仍须独立验收与用户确认 | 可复现发布版本、已结案证据及结论、受保护引用、后续候选清单 |

每步都使用同一验收过程：执行者自测和提交证据 → 未参与实施者独立复核 → 用户确认 → 冻结。自测通过不等于独立通过。不同智能体分别署名也不自动构成独立核验，复核者必须实际读取证据和复算关键结果。

如果R04没有候选，或后续出现无法满足的证据条件，可以提前提交本轮结案；未执行步骤标记未执行或不适用及理由，不能全部标通过。禁止为“做满流程”无意义增加实验。

## 4. 指标、分母和策略通过条件

### 4.1 每个阶段都必须报告

| 指标 | 统一口径 |
| --- | --- |
| 样本与覆盖 | 合格历史合约/时间范围、独立机会数、发出信号数、交易数、缺失/排除数；单列涨/跌方向和市场状态 |
| 信号准确率 | 预定义成功信号数 / 可评估信号数；未成熟或缺数据的信号单列 |
| 误报占比 | 预定义失败信号数 / 可评估信号数；不得混称为以全部负样本为分母的假阳性率 |
| 漏报率 | 未被提前识别的合格机会数 / 全部合格机会数；机会和匹配窗口提前定义，不能只从已发信号倒推机会全集 |
| 提前量与等待 | 首次合格信号到预定义启动事件的时长分布；未启动、失效与观测结束分开处理 |
| 成本后价值 | 手续费、滑点、资金费和登记成交约束后的单次期望、组合收益、资金占用与换手；资金费可收可付 |
| 风险与稳定性 | 按含未实现盈亏与资金费的权益计算最大回撤；最不利变动、最长等待、连续亏损、各时间折/币种贡献与集中度 |
| 量化和AI对照 | 相同数据时点、可交易范围、风险预算与成交条件下的成对差异，含AI延迟、调用失败、拒答和降级；不能把失败样本悄悄删掉 |

如采用R收益，1R的初始风险及止损语义须先定义；没有稳定定义时使用明确的资金收益口径，不临时换指标美化结果。

### 4.2 研究完整性和有效性分开裁决

工程/研究完整性：数据来源可查、无已知未来泄漏、计算可复现、所有试验登记、主要指标与负面结果完整。这些通过，可以说明本轮研究完成。

候选有效性：达到R01冻结的主指标、成本后价值、风险上限、最低有效证据量与稳健性门槛，才可把该候选标记为通过。没有统一适用于本项目的“胜率60%”或“夏普大于1”行业合格线。

建议的统计口径是：使用事先选定置信水平（默认建议95%）的区间估计；若主张成本后正期望，其下界应大于0；若主张优于基线，其成对增量的下界应超过预登记最小实际改善量。最大回撤不得超过预登记上限。有效样本量和检验方法依据开发区间的相关性及最小可检测改善设定。

必须按时间块、独立机会或组合收益的依赖结构评估不确定性；不能把同一市场冲击下的多币种信号全部当独立样本。候选选择涉及多次比较时，冻结多重比较处理并报告完整尝试数。DSR等方法可以辅助评估选择偏差，但不能修复未来数据泄漏。[S1]

不能为了通过而在看过最终结果后改置信水平、风险阈值、最低样本量、主指标或成本假设。样本不足结案为证据不足，不能无限等待或扩大样本直到显著。

## 5. 时间隔离与AI历史回放

1. 行情记录保留事件时间、实际可得时间、摄取时间及修订版本。策略在决策时刻只能读到已可得、已满足收盘条件的记录。
2. 历史批量下载时的摄取时间，不等于当年实际可得时间。未知可得时间的字段不能静默赋成事件时间；近似研究与严格历史验证分开标记。
3. 数据按日历时间划为训练、开发验证、最终盲测；最终区间在研究开始前隔离。全量历史用于不同角色，不意味着全部历史都拿来拟合。数据准入的真实样本读取使用训练/开发范围；最终区间只由隔离的验收流程核验身份、清单与覆盖。记录过去的研究接触历史，已经用于策略选择或反馈的区间不能仅靠重新命名恢复盲测身份。
4. 多币种采用共同时间边界；训练标签观察窗口、持仓区间不得跨入验证/测试并把结果带回训练。gap长度由最大标签/持仓依赖确定，不机械套用固定百分比。[S2]
5. 归一化、特征选择、阈值估计和任何拟合只使用对应训练段；测试段只执行已冻结转换。[S3]
6. 滚动评估中，如果结果被用来选候选，该部分属于开发验证证据，不再声称是完全未触碰的最终盲测。对已有固定参数策略，滚动只做分期稳定性验证；不能为了套用Walk-Forward名词自动新增参数寻优。
7. 最终测试只能用于预登记评估。纯基础设施重试须证明代码、输入、参数、随机性不变；修正策略、成本或引擎后重跑，应标明已开封复验，不能恢复为未触碰盲测。
8. 历史AI回放区分“当时真实留存的回答”与“今天模型重新评价过去”。关闭联网、隐藏币名或提示模型不要偷看，都不能证明消除预训练知识。[S4]
9. 无法证明模型知识时间边界的历史AI结果，只能支持探索性结论；AI真实增量需要合格的时间隔离或事前封存的前瞻观察。前瞻观察若尚未获工程主线授权，记为后续待办，不作为无限拖延本轮结案的理由。
10. 冻结具体模型标识、提示词、工具权限、输入、原始输出与运行时间；只给一个会漂移的模型别名不足以保证重新调用可复现。原始响应回放的确定性与再次请求服务的确定性分别披露。

## 6. 运行数据与回测数据的分离

核心原则：原始事实只保留一份权威资产；研究按不可变快照引用；运行与回测的可写状态完全隔离。

| 数据类别 | 读写所有者 | 增长方式 | 冻结与禁止事项 |
| --- | --- | --- | --- |
| 权威原始市场库 | 已授权采集/纠错程序写；研究/回测只读 | 受预算约束的新增行情、明确缺口补齐、带版本纠错 | 已被冻结快照引用的对象不可原地覆盖；新行情不自动进入旧回测 |
| 回测快照 | 登记/验收程序产生清单 | 新版本只增加引用与差异对象 | 指明交易所、合约、类型、周期、区间、修订、哈希和可见时间；不按每次实验复制整库 |
| 派生特征/标签 | 研究程序写隔离命名空间 | 同一输入和代码版本复用；缓存限额 | 事后标签不暴露给策略；热缓存可重建，必要冻结证据受保护 |
| 运行状态 | 运行服务专属写者 | 任务、最新信号、账户事实/授权范围内的状态和检查点 | 只使用当前已发布版本；不能接入回测订单、回测权益和事后标签 |
| 回测状态 | 回测执行器写 | 按研究编号及运行编号产生隔离账本 | 独立时钟、数据库/文件、账户、队列和输出路径；不能写入运行库或调用外部订单写接口 |
| 冻结研究成果 | 验收后只读 | 有限研究批次、有限版本 | 保存足够完整的复算明细；不因最近100条运行政策截断 |
| AI结果归档 | 经校验的分析流程写 | 内容去重、无损压缩、受总容量与调用预算限制 | 既有全量保留要求继续；满额暂停新增分析，不静默丢弃旧结果 |

逻辑隔离必须由读写权限、独立连接/路径、时钟与任务配置落实；不能只靠文件夹名字。相同业务计算和风险校验尽量共享同一个冻结代码版本，通过数据源、时钟和成交适配器区分运行/回测。

如果已有存储对象会被修改，快照必须引用稳定对象版本，或只保存受影响分区的不可变差异；不能仅记录一个会变的文件路径。压缩、合并、迁移和纠错不得删除仍被快照引用的旧对象。采用内容寻址、依赖哈希和锁文件可以复用成熟工具；不要求为此再搭建第二个数据平台。[S5]

快照清单和SHA-256证明身份与完整性，不能代替备份或恢复能力。真正备份单独登记数量、容量和恢复证据；不得把研究副本伪装成备份。

## 7. 验收完成即冻结

### 7.1 每次冻结的最小集合

- 唯一研究编号、步骤编号、版本、冻结日期、上游依赖和结论。
- 代码提交SHA、相关路径、不可变发布标识；禁止用浮动分支名代替精确提交。
- 数据快照ID、不可变对象引用与哈希、切分和排除清单；继承已有封存证据，不再复制全量原始数据。
- 特征、标签、参数、成本、风险、随机种子和模型/提示词版本。
- Python/Node等实际运行时版本、依赖锁文件、平台信息；冻结后不自动升级到“最新版”。
- 指标定义、执行计划、全部尝试索引、输出和AI原始响应引用。
- 自测证据、独立复核、用户确认、是否允许下一步。
- 保留级别、容量占用、恢复引用和清理白名单。

### 7.2 冻结之后的变更

冻结版本可以继续读取、执行和复现。修改算法、参数、数据修订、模型、提示词或会影响结果的依赖时，创建新版本，记录原因及受影响依赖；旧版本和原结论保留。只重验受影响环节，禁止无原因把所有已通过阶段归零。

新版本结果不得覆盖旧结果。发现旧版本关键缺陷时，追加“撤销/失效”记录并限制后续使用，不篡改旧验收历史。只改说明文字不触发无关市场数据重跑；是否影响结果由具体差异证明。

换聊天窗口、换执行智能体、组件发布新版本、云端暂时看不到文件，都不能自动解冻已验收资产。冻结不等于永久禁止合理维护，修改须有版本和验收路径。

## 8. 有限实验和有限存储

### 8.1 首轮建议实验预算

| 项目 | 默认建议 | 达上限后的动作 |
| --- | --- | --- |
| 同时激活研究批次 | 1个 | 当前批次结案前不自动新开 |
| 可选择配置 | 每批最多12个，包含基线、参数、特征、模型和提示词组合 | 超出须作为新研究变更，不能自动加配置 |
| 评估执行 | 每批最多60次，含失败与技术重试 | 终止新增评估并提交当前结果 |
| 同一失败任务重试 | 最多2次，仍计入总执行预算 | 登记具体阻塞，不循环重跑 |
| 最终盲测 | 一个预登记批次；最多6个已冻结配置，包含对照 | 开封后不追加候选，不修改通过线 |
| 研究截止 | 登记具体日期与计算预算 | 到期给出结案或具体阻塞，不自动续期 |
| AI调用 | 登记次数、token/费用上限及预期输出量 | 未设预算不启动批量调用，达限暂停 |
| 同输入成功任务 | 复用已有合格结果 | 无代码/数据/配置变化不重复算 |

执行键由代码、数据快照、配置、时间折、种子和AI版本等共同确定；同键复用，不能换目录名获得新配额。新的有效随机试验必须预登记；不能重抽随机种子直到结果好看。

12个配置和60次执行不是已授权调参额度：旧版本已冻结参数继续不动；如登记允许新候选，只能在隔离研究版本和开发区间内按明确候选表比较。

### 8.2 首轮建议非原始数据配额

以下建议为项目总量上限，不是每个智能体、每个目录各领一份。实际登记须计入已有占用；超过建议值不自动删除已有资料，也不把旧占用排除在统计外。

| 类别 | 建议容量上限 | 保留规则 |
| --- | --- | --- |
| 可重建特征缓存 | 10 GiB | 最久未用优先回收；仍作为唯一冻结证据的对象不属普通缓存 |
| 临时/中间文件 | 2 GiB | 最长7天，任务结束后按白名单尽快清理；使用中的文件不删除 |
| 普通诊断日志 | 1 GiB | 最长14天，时间与容量任一达到即轮转；必要审计证据另归受保护成果 |
| 冻结研究成果 | 10 GiB | 每批建议不超过2 GiB；总量满额停止新批次，保护已验收结果 |
| AI原文与结构化归档 | 5 GiB | 全量无损压缩去重；接近上限预警，满额暂停新增AI分析 |
| 运行状态/历史索引 | 2 GiB | 活跃状态、最新记录、聚合统计与检查点；按对象保留策略维护 |
| 合计 | 30 GiB | 分项额度同时生效，不能用改目录绕过 |

原始市场库与正式备份单独登记“已有受保护基线大小、允许增量、总量上限、预测增长和最低可用空间”。本规范不凭聊天记录替用户磁盘填一个虚假的实测容量，也不另建副本。原始库只允许受控新增、补缺与版本化纠错；研究程序不得写入。

如果当前磁盘无法承受建议预算，在登记前下调或改用已批准的归档位置；不得自动扩容。每个任务启动前预留预计输出容量；并发任务共享原子预算。建议各分项80%占用预警、100%拒绝新增任务；已有更严格阈值优先。允许的例行清理应实际执行，不能只生成反复审计报告。

### 8.3 两个90天与100条的准确边界

- 图表默认展示90天是展示窗口；最近90天热数据是存储分层；更早原始历史转冷，仍可研究，不按90天删除。
- 运行订单历史明细遵守最新100条的既有政策；未完成订单、当前持仓和必要恢复状态独立保存，不能为凑100条截断活跃业务。
- 全系统运行的重要信号保留最新100条及必要汇总/状态；同一信号重复投递不生成新记录。
- 超过100条的已结清运行记录，须先完成累计统计和检查点更新，再按已批准保留规则处理。仅保留聚合后，就不能承诺任意久远运行订单的逐笔回放。
- 回测验收要冻结该批次的完整事件/交易明细，受每批和项目成果总配额约束；它们不是运行库最新100条的扩容。不能只保存最后100笔却声称整段回测可审计。
- AI全文全量保留与固定磁盘容量不能靠压缩永久同时满足。达到预算时暂停新增分析；另行批准归档容量后再恢复。原始采集同样有独立容量保护，不能无限写满磁盘。

### 8.4 安全清理与达到上限

顺序为：回收未被保护引用的过期临时文件/可重建缓存 → 轮转普通日志 → 暂停超额的新实验或非必要分析 → 报告占用与具体恢复条件。

只能执行已经批准的白名单。检查对象不是符号链接绕出的路径，不在使用，不是唯一内容，不被冻结清单/活跃任务引用；需要恢复的对象须有可验证恢复方式。清理后核对实际删除清单、受保护对象、查询功能和空间变化。不得通过删冻结数据、删失败实验索引、只保留盈利结果或修改配额统计来释放空间。

原始数据所在磁盘触及既有熔断余量且无法安全回收时，应完成可恢复检查点并受控停止受影响写者，记录停写区间；不得静默丢行情或删除受保护历史来继续写。

## 9. 程序最终必须执行的门禁

本节是后续对应工单的验收要求，不表示这些功能已实现。

| 门禁 | 必须验证的失败场景 |
| --- | --- |
| 冻结身份校验 | 改一个受保护输入/配置，执行被拒绝或明确创建新版本，不能沿用旧通过标识 |
| 数据时间校验 | 注入未来可得记录、未收盘高周期、跨界标签，旧时刻输出不变或请求被拒绝 |
| 运行/回测隔离 | 回测凭据写运行库失败，回测事件不会进入运行信号/订单队列 |
| 实验预算 | 超配置数/执行数/AI调用预算的任务不能启动；换名称不能重置额度 |
| 空间预算 | 预计输出超限被拒绝；并发预留不能共同超额；冻结资产不被自动删除 |
| 幂等与恢复 | 同事件重复100次只产生一次业务变更；中断后恢复不重复费用和交易 |
| 验收状态机 | 缺独立复核、用户确认或存在必需失败项时，不能解锁下一步；已通过项无反证不重开 |

只针对影响结论、数据安全和状态隔离的关键路径验证，不为低影响文档改动重跑全量数据。验收须给实际输入、执行命令、退出码和结果，测试脚本存在或生成模拟夹具不能代替真实读取。
