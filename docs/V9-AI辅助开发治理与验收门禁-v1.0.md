# V9 AI辅助开发治理与验收门禁 v1.0

> 日期：2026-11-01
> 性质：项目开发流程规范；用户明确同意采用。此版本号仅表示**治理文档版本**，不代表量化策略参数 v1 已验证。
> 适用仓库：liuganming18-netizen/-AI-。与《统一需求与业务闭环-V1》及《V9-MCP-多智能体协作架构-v0》配套。
> 执行边界：本次仅新增文档，不批准合并 main、部署、修改正式策略、访问生产密钥或线上数据库写操作。

## 1. 总原则

**AI负责“快”，人负责“对”。** AI可辅助生成、整理、测试设计与反方检查；需求契约、验收标准、关键风险与生产权限由人最终决定。

六条原则：
1. AI只做受约束的副驾驶：人批准需求、架构、验收标准和风险规则。
2. 契约先冻结：接口、字段、时间口径、UI、权限先形成版本化契约。
3. 每模块先有验收清单：P0未关闭不得进入下一模块。
4. 小步提交、可回滚：构建或测试失败不得合并。
5. 关键路径人工审查：数据管道、PIT回测、风控、权限、密钥及部署。
6. 三条红线：AI不得操作真实下单接口、生产密钥/私钥、线上数据库写操作。

## 2. 角色边界

- **人类负责人**：目标、架构/契约批准、验收裁决、风险批准、合并/部署/回滚授权。
- **主控代理（Codex/Astra）**：按批准契约拆解和派单，核查证据、提出审核意见；无权自行扩大范围或批准上线。
- **执行代理（WorkBuddy、Antigravity等）**：仅在允许文件与分支范围内实施，提交最小差异和可复现证据，不做顺手优化。
- **独立审核代理（ChatGPT或隔离 reviewer）**：只读检查变更、测试和反例，提出 PASS / REWORK / BLOCKED / INCONCLUSIVE 建议；不能以自身判断代替人工批准。
- **禁止**：同一代理无约束地自定架构、自写实现、自评通过、自行上线。

## 3. 强制任务门禁

需求/契约 → 任务拆解 → 明确允许修改范围 → AI生成 → 构建通过 → 测试通过 → 验收清单P0通过 → 关键路径人工审查 → 获授权后合并。

任何环节缺失，标记 BLOCKED/REWORK，不得声称模块已通过或进入下一模块。需求契约变化需先审批变更，不能以代码实现反向覆盖需求。

## 4. 单一事实来源和版本

- 已批准需求、候选默认值、废弃项、待讨论项分别记录；不让聊天消息充当唯一事实源。
- 量化阈值和权重配置化、版本化，不硬编码；候选值标注 `v0 / UNVALIDATED`，不作为生产自动行为默认值。
- 研究规则升级必须经过历史验证、独立样本外、实时模拟及人工批准；批准后的研究配置标注版本、样本边界和限制，不宣称保证有效。
- 变更记录必须包含日期、旧/新规则、原因、影响模块、批准人、关联提交和回滚方案。

## 5. 工单契约

每张工单至少包含：task_id、目标、输入与依赖、需求/契约版本、允许修改的文件及分支、禁止事项、验收标准、构建/测试命令、交付证据、风险与回滚。

子代理仅回传结构化压缩摘要和证据路径；重要原始日志与工件应完整保留在可审计位置，不能因为摘要压缩而丢失关键证据。中央工单系统是状态事实源，禁止多代理抢占同一任务或自行宣布 ACCEPTED。

## 6. 代码与仓库

- 一模块一隔离分支，小提交、可追溯、可回滚；未经单独批准不得合并 main。
- 不提交真实数据、生产凭据、构建产物和不必要依赖；必要大文件经审批使用 Git LFS 或对象存储。
- 配置和代码分离；对关键参数设 schema、版本和变更审核。
- 真实数据、演示数据、测试环境、生产环境硬隔离；演示模式全局显著标记，禁止合成数据冒充市场事实。
- 现有 V9 UI 风格、三栏布局、四导航及右侧模拟盘不得被未授权重构。

## 7. 测试与验收证据

AI说“完成”不构成验收。每模块必须提交：
- 修改文件清单、diff、commit SHA、基线 SHA；
- 构建命令与真实结果；
- 自动测试命令、通过/失败/跳过数量、覆盖口径；
- 页面交互证据及真实/演示数据标记；
- P0/P1/P2缺陷、未完成项、限制；
- 关键路径端到端测试、异常与回滚测试；
- 人工审查意见及明确审批记录；
- 整体工程进度估算（百分比、较上轮变化及依据）与**实际测试覆盖率**（分母、分子、范围）分别报告。

测试未运行应写 NOT_RUN；没有覆盖率报告应写 UNKNOWN，不得用“0%”代替未知。

## 8. 安全与权限

- 开发/测试/生产分环境、分身份、分密钥；最小权限、审计、密钥轮换。
- 交易所 API 仅允许研究所需的只读市场数据访问，不接实盘下单；密钥不得进入仓库、前端、工单、日志或模型上下文。
- AI及自动化执行器不持有生产写权限；生产数据库写入、上线、回滚、事故处理和密钥轮换必须由授权人员执行。
- 外部 MCP 工具和第三方桥接组件安装前需核查来源、权限、许可证和维护状态。
- 生产安全控制需技术性强制实施，不能只依赖提示词或书面禁止。

## 9. 模块交付必答清单

1. 改了哪些文件，关联哪个提交和批准契约？
2. 构建如何执行，实际结果是什么？
3. 测试是否运行，通过、失败、跳过和覆盖范围是什么？
4. P0缺陷有哪些，是否全部关闭？
5. 哪些功能未完成或被降级？
6. 页面使用真实数据还是演示数据，如何隔离和标记？
7. 数据/PIT/模拟风控/权限等关键路径是否经过独立与人工审查？
8. 能否回滚，谁批准合并或进入下一模块？

## 10. 与现有流程的关系

本规范是**横向治理门禁**，不替代既有十模块验收路线，也不改变 V9 产品业务规则或 MCP 技术方案。文档已采纳不等于 CI、权限、审计、人工审批系统已经落地；这些必须在后续隔离工单中实现并验证。
