# AI 加密货币趋势研究系统｜项目总说明与施工流程

> **唯一正式项目入口（候选版，2026-11-05）**。本文件合并项目定位、首期范围、数据链路、七阶段顺序、工单边界和独立验收流程。当前位于 PR #10 候选分支，**未合并 main，未据此解锁业务施工**。提交审批后如有新的明确用户决定，以批准的变更 PR 更新本文件，不允许多处并行维护互相冲突的主线。

## 1. 目标：潜在吸筹阶段的事前研究

利用已授权、质量验收合格的**全市场 USDT 永续合约全部可获取历史数据**，研究震荡中的**潜在吸筹早期、中期、末期**特征，在行情尚未明显启动时评估候选机会；同时研究普通横盘、下跌中继、潜在派发、失败突破和看跌情景。研究需允许“没有统计优势”的结论。

系统只把“吸筹/主力意图”作为待证伪的**行为假设**，不能仅凭 OI 增加、价格横盘或 AI 描述就宣布发现吸筹。程序计算可复算的量价、OI、资金费率和结构证据；Data 做跨全历史的统计研究；AI 提出有出处的假设、反证及可校验的图形锚点；量化规则/风险约束独立，不能被 AI 绕过。最终有效性由独立历史回测及样本外试验裁决。

**研究与施工是两条不同序列**：业务研究链路 = 可得原始市场数据 → 质量及历史时间门禁 → Data 特征/候选假设 → AI 与量化解释 → 信号记录 → 独立历史回测 → 离线模拟核算；施工先后顺序以第 3 节七阶段为准，UI 属第 05 阶段，回测属于第 06 阶段。

## 2. 首期只做最小闭环，不再扩张

### 首期必须保留

1. **单一权威原始数据**：包含可取得的历史及退市 USDT 永续合约；Binance 为市场数据主源，OKX 只按已批准的合约可用性规则作为独立补充，不跨所静默拼接；K线 5m/15m/30m/1h/4h/8h/12h/1d，8h 仅核验币安原生，OI/资金费率等逐类标记真实覆盖。**90 天只控制热层与首次 K线展示，不限制 Data 历史研究**。
2. **一个受控只读数据接口**：已存 Parquet、SQLite 等按权威分区被引用，不为 UI、Data、回测重复复制整套原始数据；保留 event_time、available_at、ingested_at、来源及修订版本，未知数据可得时间必须显式标记。
3. **一个 Data 研究方向**：潜在吸筹早/中/末期的事前识别 + 横盘/下跌中继/潜在派发/失败案例对照；输出可复算程序、样本与研究局限，研究候选不等于策略已被证明有效。
4. **一套服务及既定 UI**：保留已确认的深蓝紫玻璃、桌面三栏、四主导航“加密货币/数据监控/策略分析/历史回测”、中部榜单与K线、下方折叠 AI 对话、右侧分析面板；Ticker 英文，其余用户界面中文。复用已确认的 UI 成果，不重做格局。
5. **一套独立回测及离线模拟验证**：在独立历史时间轴上逐根推进/回放、展示逐笔明细、费用与资金费、失败记录、样本外结果；离线模拟记录研究级虚拟决策及账本，**不接外部订单写接口**。

### 明确推迟到第二期，不作为本次模块 PASS 的隐性前置

7×24 小时自动扫描和全市场每 5 分钟刷新、Telegram 推送、双模型与大规模 AI 定时巡检、复杂多智能体协同、微服务/Redis/Kafka/Kubernetes、对外部署、全面自动交易执行、多交易所真实或模拟账户交易 API 等，均**暂缓**，不是废除历史需求。只有当前闭环通过后，才单独评估必要性与合规性；不得为追求“一步到位”扩大某个工单。交易所永续合约订单自动写入和真实资金交易均不属于当前获准实施范围。不得绕过年龄、地区、账户资格或平台限制。

**首期完成定义**：一份已验收的可查询全量数据资产、一组可复现且充分记录失败的吸筹研究、既定 UI 可展示有出处的分析、严格历史回测可审计、离线模拟账本可核对；不需要证明一定盈利，也不以模拟盘自动下单作为验收条件。

## 3. 七阶段施工顺序（用户最新决定：UI 第 05，回测第 06）

**同时最多一个激活模块。** 每个模块只执行它已授权的工单；模块内逐单验收，最后取得整个模块 PASS。任何单子有 P0 失败/未运行或缺独立复核，模块不通过，后续模块锁定。

| 模块 | 唯一目标与交付 | **必须实际验证的 P0** | 边界与停手点 |
| --- | --- | --- | --- |
| **01 代码与环境只读审查** | 旧 GM / 新 -AI- 的仓库、模块、依赖、配置、可复用/替换/保护矩阵；Mac 本机基线 | 两仓当前 SHA/工作区差异及组件清单有来源；关键代码用途与调用者可核对；本机环境证据真实；审查前后受保护文件状态可比；独立复核所有冲突 | **只读**，不改旧 GM，不启动/停止旧采集器，不清理代码/数据；仅输出审核报告 |
| **02 全量历史数据审计** | 动态合约全集（含退市）、K线/OI/资金费及其他已有数据的来源/跨度/粒度/缺口/重复/唯一资产/引用清单 | 按“交易所×合约×数据类×周期×时间”可追溯覆盖分母；缺口及冲突有分类；历史来源和可得时间可核验；不可恢复或未知唯一资产列入保护 | **只读**；不得把历史旧数量当实时数据量，不删、不补写生产库 |
| **03 整理清理与运行环境** | 单一权威数据入口、冷热管理、按范围修复、逐对象清理白名单与恢复实证、可复现本地环境 | 同一查询跨冷热结果一致；缺口/来源不被伪造；读接口能分批查询历史全集；无重复写者；恢复演练证明可用；删除项与事先批准名单一一对应，剩余数据及空间变化可测 | 只准修改**授权白名单**；不删除未经验证的唯一内容，不碰未授权旧资产；未完成恢复证据的候选继续保护 |
| **04 Data 全量研究** | 单一吸筹研究线：早/中/末期事前状态、对照样本、可复现特征与候选规则、失败/不确定性报告 | 实际扫描全部合格历史范围而不是抽样冒充全量；阶段识别不引用未来标签；成功/失败/派发/下跌中继均纳入；误报/漏报/提前量和分母可复算；报告模型/参数/时间版本 | 先满足 01—03 PASS；本模块**只发现与初验候选**，不宣传样本外验证或盈利能力已经最终通过 |
| **05 服务 + 既定 UI** | 一个最小服务/API 及四导航三栏页面，展示真实/演示区分、机会研究结果、可视画线/AI对话、数据健康；回测入口可见 | 各导航/币种/周期/筛选/缩放/错误状态浏览器验证；无凭据泄露；证据和数据源可回查；界面布局与已确认方案一致；未完成回测页面必须显示“未接入/待第06阶段”而非伪造结果 | 只做服务与页面接线；不以界面截图冒充回测或策略 PASS，不改已确认格局 |
| **06 严格历史回测与样本外** | 历史时钟、逐根快进、逐笔明细、保守成交/手续费/资金费核算、Walk-Forward 与封存样本外评估 | 未来字段/历史合约幸存偏差测试阻断；逐根回放和订单/费用/权益能复算；训练/验证/封存样本不互相污染；成功与失败样本完整，基准对照与不确定性明确 | 不为改善结果反复打开封存样本调参；若无统计优势也可工程 PASS，但策略有效性保持“未证明” |
| **07 隔离离线模拟验证** | 使用已验证规则/事件的离线自动模拟、风险规则、虚拟资金/费用/权益日志与结果对账 | 无外部订单写调用；订单事件幂等、风险失效、异常恢复、账本前后平衡与回测口径一致；逐笔记录可追溯 | 只限离线模拟；外部 Binance / OKX 模拟账户的交易写接口不属于本次实现范围，需另行资格与安全审查 |

如果某阶段有无法获得的历史数据：必须证明已统计真实可得范围、明确缺失原因与影响，才能按已冻结的**可验收覆盖范围**判断是否 PASS；不能把“数据缺失”自动填 0，也不能因为部分合约没数据就谎称全量无缺口。

## 4. 唯一工单/模块验收协议

每张工单必须使用同一份模板，**只有以下闭环才解锁**：

1. **冻结边界**：工单 ID、所属模块、当前 SHA/数据快照、输入、允许改动路径、禁止路径、必须完成的 P0、验收数据、独立审核人、停手点。越界请求另开变更，不在本单顺手改。
2. **执行留证**：操作命令与退出码、具体变更文件、前后 Git 状态/哈希、数据覆盖及来源、接口输入输出、自动化测试、浏览器证据或恢复验证（适用时）。如实区分通过、失败、未运行、跳过、阻塞。
3. **施工方自测后停手**：自测通过不代表独立 PASS。遇到未知改动、版本冲突、受保护资产风险，立即停止扩大操作，状态记为 BLOCKED。
4. **独立验收**：未参与本工单实施者复核受保护路径、输入输出、负例和失败路径，必要时在隔离环境重放；验收报告对每项必需测试给出证据路径与结论。
5. **总验收 + 用户确认**：所有 P0 PASS，关键 P1 无未批准风险，范围无越界，报告完整，独立审核 PASS，用户明确确认当前模块通过；**上述任一条件不满足，下一模块仍锁定**。
6. **合并与回滚**：代码经独立分支 + PR 审查后才合并；保护旧数据与可回滚证据。一次仅合并已批准工单，不以 CI 通过、PR 已创建、条件通过代替真实本机或研究验收。

工单结论仅用：**未开始 / 执行中 / 待验收 / 返工 / 阻塞 / 通过**。**条件通过不属于可解锁的“通过”**。进度“已通过模块数/7”、业务用例通过数、实际测试覆盖率、估计完成度要分别报告，不可互换。任何自动代理在本模块完成后必须停手，不自动领取下一模块。

**标准验收回执最小字段：**

```text
模块 / 工单：
本轮授权与禁止修改：
代码与数据基线（SHA、时间、快照）：
实际变更及来源：
P0逐条结果：通过 / 失败 / 未运行 / 阻塞
测试命令、退出码、浏览器/数据证据：
回滚与保护对象验证：
独立复核人及结论：
总验收裁决：
用户确认：是 / 否
下一模块：未解锁 / 已解锁
工程进度估算（非覆盖率）：
```
