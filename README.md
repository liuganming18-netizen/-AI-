# GM 趋势研判系统 · 只读接线候选

这是用户确认的四页面 V9 UI 的隔离工程候选，基于 first-module-running-market 候选分支增量开发，不改变受保护的 main，也不写入旧项目 GM。

## 页面与布局

- 顶部总览：176px 主导航之外固定顶栏；业务区保留左侧信号池、中间研究区、右侧模拟交易分析面板。
- 加密货币：沿用原草图七组数据列，完整显示封存索引的 549 标的（Binance 526 / OKX 23），中间连续滚动，不在表格内另加固定高度滚动条；按合约行展开 K线与独立 OI 柱形图。
- 数据监控：旧数据中心覆盖表 + 模块、服务、任务三级运行画布。只有网关等确实可验证的节点显示已连接；其余心跳、积压、延迟和告警是空态。模拟故障仅为界面演示。
- 策略分析：威科夫早/中/末期、唐奇安结构、量化规则与独立AI复核的证据槽位。尚未运行AI或策略实证。
- 历史回测：可对真实已收盘 K线按历史顺序浏览，OI按照自己的观测时间叠加；已有旧回测运行索引可只读显示。科学绩效指标未核验前全部为空，不用历史K线变化伪造收益。
- 右栏：只读模拟账户视图。仅显示计划初始资金 2,000U，账户权益未接入时显示空值，不提供下单、撤单、改仓。
- UI：中文，Ticker 英文；部分封存原生符号需映射，保留原件身份但展示“待映射”，不擅自改名。

## 本机运行（不抢占旧项目3000端口）

需要 Node.js 20+；该分支默认使用本机 3010 端口，避免与原 GM 项目 3000 端口冲突。

从新项目隔离工作树打开本分支后运行：

~~~bash
npm test
npm start
~~~

浏览器访问 http://127.0.0.1:3010 。若旧 GM 数据服务仍在同一台机器的 127.0.0.1:8787，本程序仅对 /api/v1/markets、/api/v1/signals?scope=current、/api/v1/backtests?limit=50 以及指定合约的历史K线/OI执行 GET 查询。可以通过环境变量 GM_DATA_API_URL 指定另一**本机回环**端口；不支持任意远程代理地址。

实时行情：优先从 Binance 官方公开接口获取 24h 行情、K线与近期 OI。其他周期的历史 OI、完整历史与 OKX 补位优先通过既有本机只读数据服务查询。没有真实结果就显示缺失状态，不用合成数据补缺。

## 重要边界

1. data/market-universe.json 仅是源自既有封存清单的标的身份元数据，不是历史行情数据，不含 K线/OI/资金费率原件，不算重新封存。
2. 封存的549个标的不是今日实际挂牌合约数量；实时行情是否存在须另查交易所。
3. 总 OI 不代表多空拆分；24h成交量加权均价不是聪明钱多空持仓均价。
4. Binance公开历史OI的覆盖可能短于90天；8h OI无原生公共周期时返回不可用，不能伪造8h数据。
5. 本机旧数据服务若没有运行，接线会显示“未接入”，这只说明访问受阻，不意味着原数据未封存。
6. 画布的健康状态需要真实服务任务遥测，不能把模拟节点动画作为生产健康证据。
7. 本工程当前没有连接真实AI、官方模拟账户认证或完整回测引擎；未授权真实下单、风险参数修改、生产数据库写入。
8. 主线合并、用户Mac真实启动、浏览器端到端测试、网关数据对账和独立验收尚未执行。保留G00和七阶段原有门禁，不在本分支自动解锁。

## 基础只读API

GET /api/health：只表示本服务存活。
GET /api/catalog：549标的身份索引。
GET /api/market-data：Binance实时24h数据。
GET /api/klines：Binance 5m～1d真实K线。
GET /api/oi：Binance原生历史OI。
GET /api/local/markets、/signals、/backtests、/candles、/oi：既有本机数据服务只读桥接。

任何非GET请求均返回405。默认监听127.0.0.1，不开启公网监听，不启用GitHub Actions运行服务。
