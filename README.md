## 1. 目标：潜在吸筹阶段的事前研究

利用已授权、质量验收合格的**全市场 USDT 永续合约全部可获取历史数据**，研究震荡中的**潜在吸筹早期、中期、末期**特征，在行情尚未明显启动时评估候选机会；同时研究普通横盘、下跌中继、潜在派发、失败突破和看跌情景。研究需允许“没有统计优势”的结论。

系统只把“吸筹/主力意图”作为待证伪的**行为假设**，不能仅凭 OI 增加、价格横盘或 AI 描述就宣布发现吸筹。程序计算可复算的量价、OI、资金费率和结构证据；Data 做跨全历史的统计研究；AI 提出有出处的假设、反证及可校验的图形锚点；量化规则/风险约束独立，不能被 AI 绕过。最终有效性由独立历史回测及样本外试验裁决。

**研究与施工是两条不同序列**：业务研究链路 = 可得原始市场数据 → 质量及历史时间门禁 → Data 特征/候选假设 → AI 与量化解释 → 信号记录 → 独立历史回测 → 离线模拟核算；工程位置与任务依赖以第 3 节为准，UI 属第 05 阶段，回测属于第 06 阶段；阶段编号不构成整模块互斥锁。

## 2. 首期只做最小闭环，不再扩张

### 首期必须保留

1. **单一权威原始数据**：包含可取得的历史及退市 USDT 永续合约；Binance 为市场数据主源，OKX 只按已批准的合约可用性规则作为独立补充，不跨所静默拼接；K线 5m/15m/30m/1h/4h/8h/12h/1d，8h 仅核验币安原生，OI/资金费率等逐类标记真实覆盖。**90 天只控制热层与首次 K线展示，不限制 Data 历史研究**。
2. **一个受控只读数据接口**：已存 Parquet、SQLite 等按权威分区被引用，不为 UI、Data、回测重复复制整套原始数据；保留 event_time、available_at、ingested_at、来源及修订版本，未知数据可得时间必须显式标记。
3. **一个 Data 研究方向**：潜在吸筹早/中/末期的事前识别 + 横盘/下跌中继/潜在派发/失败案例对照；输出可复算程序、样本与研究局限，研究候选不等于策略已被证明有效。
4. **一套服务及既定 UI**：保留已确认的深蓝紫玻璃、桌面三栏、四主导航“加密货币/数据监控/策略分析/历史回测”、中部榜单与K线、下方折叠 AI 对话、右侧分析面板；Ticker 英文，其余用户界面中文。复用已确认的 UI 成果，不重做格局。
5. **一套独立回测及离线模拟验证**：在独立历史时间轴上逐根推进/回放、展示逐笔明细、费用与资金费、失败记录、样本外结果；离线模拟记录研究级虚拟决策及账本，**不接外部订单写接口**。

### 明确推迟到第二期，不作为本次模块 PASS 的隐性前置

7×24 小时自动扫描和全市场每 5 分钟刷新、Telegram 推送、双模型与大规模 AI 定时巡检、复杂多智能体协同、微服务/Redis/Kafka/Kubernetes、对外部署、全面自动交易执行、多交易所真实或模拟账户交易 API 等，均**暂缓**，不是废除历史需求。只有当前闭环通过后，才单独评估必要性与合规性；不得为追求“一步到位”扩大某个工单。交易所永续合约订单自动写入和真实资金交易均不属于当前获准实施范围。不得绕过年龄、地区、账户资格或平台限制。

**首期完成定义**：一份已验收的可查询全量数据资产、一组可复现且充分记录失败的吸筹研究、既定 UI 可展示有出处的分析、严格历史回测可审计、离线模拟账本可核对；不需要证明一定盈利，也不以模拟盘自动下单作为验收条件。

## 4. 唯一工单/模块验收协议

每张工单必须使用同一份模板；**以下闭环决定该项验收、冻结及其依赖任务的准入**，独立任务可同时执行：

1. **冻结边界**：工单 ID、所属模块、当前 SHA/数据快照、输入、允许改动路径、禁止路径、必须完成的 P0、验收数据、独立审核人、停手点。越界请求另开变更，不在本单顺手改。
2. **执行留证**：操作命令与退出码、具体变更文件、前后 Git 状态/哈希、数据覆盖及来源、接口输入输出、自动化测试、浏览器证据或恢复验证（适用时）。如实区分通过、失败、未运行、跳过、阻塞。
3. **施工方自测后停手**：自测通过不代表独立 PASS。遇到未知改动、版本冲突、受保护资产风险，立即停止扩大操作，只对受影响任务标记 BLOCKED。
4. **独立验收**：未参与本工单实施者复核受保护路径、输入输出、负例和失败路径，必要时在隔离环境重放；验收报告对每项必需测试给出证据路径与结论。
5. **单项确认与阶段汇总**：该项所有P0通过、关键P1无未批准风险、范围无越界、报告完整并取得独立审核及原授权规则要求的确认，才可签该项PASS及冻结。整阶段总验收另行汇总，不阻塞已通过任务的依赖准入；**某项条件不满足，只限制该项及依赖它的任务，其他依赖就绪任务可继续**。
6. **合并与回滚**：代码经独立分支 + PR 审查后才合并；保护旧数据与可回滚证据。一次仅合并已批准工单，不以 CI 通过、PR 已创建、条件通过代替真实本机或研究验收。

工单结论仅用：**未开始 / 执行中 / 待验收 / 返工 / 阻塞 / 通过**。**条件通过不属于可解锁的“通过”**。阶段通过数、任务交付比例、验收通过比例、实际测试覆盖率分别报告，不可互换。执行者完成本任务后将其标为待验收；可以领取其他已授权、依赖满足且无写入冲突的任务，不能自行签通过或启动依赖尚未通过的任务。每次回复按第5节固定格式更新。
