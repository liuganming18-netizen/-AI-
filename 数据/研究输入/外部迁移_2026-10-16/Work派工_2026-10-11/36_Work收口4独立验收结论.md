## 阻塞1：真实门禁仍不闭环

独立负例实际结果：

| 输入 | 实际结果 | 要求 |
|---|---|---|
| 合成接受索引显式传入 isolated=False；record 的 path="synthetic"、sha=全零，与证据文件不对应 | research_pass=true | 正常模式不得接受自定义合成索引；接受记录需绑定实际证据及 run |
| 上述台账不传 run | research_pass=true，run_binding_ok=null | 缺具体 run 必须拒绝 |
| 仅替换 run_id，其他 hash 不变 | research_pass=true | 旧/未接受 run 不得借用记录 |
| 实际 wx_gate.binding 中把 code SHA 换为另一合法64位值 | all_pass=true | 重算实际源码/数据/引擎身份并拒绝错值 |

原因：新的 `门禁_真实运行绑定.py` 留在交付目录，wx_config/strategy_runner 仍调用原 wx_gate.binding。原模块仅核验 record 是否存在及 scope 覆盖，未绑定 record 的 path+sha 到证据和具体 run；新包装器也没有补上这一层。包装器允许 isolated=False 下自定义接受索引、run=None，且比较字段不含 run_id。当前生产冻结记录 scope 为空，所以真实研究仍关闭；上述为隔离负例证明未来放行链存在漏检，不能宣称发生了生产放行。

另外，包装器的数据身份只哈希 manifest、引擎 SHA 取旧 JSON 声明，不能代替实际数据文件与安装引擎代码重算；后续必须绑定具体输入，不用新一套并行门禁绕开实际调用链。
